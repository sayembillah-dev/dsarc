## কী শিখব

- কেন plain recursion-এ fib(5) বের করতে গিয়ে fib(3) দুইবার, fib(2) তিনবার হিসাব হয়
- DP-এর দুটো শর্ত: overlapping subproblems আর optimal substructure
- একই কাজ দুই দিক থেকে: top-down memoization আর bottom-up tabulation
- হাতে হাতে dry run: fib(6)-এর memo table আর climbing stairs-এর 1D dp ভরা
- চারটা classic সমস্যা: fib, stairs, coin change, knapsack; আর space O(1)-এ নামানোর কৌশল

## ধারণা

ভাবো তো, বন্ধু জিজ্ঞেস করল "১৭ গুণ ২৩ কত?" হিসাব করে বললি ৩৯১। দশ মিনিট পরে আবার সেই একই প্রশ্ন। এবার কি আবার গুনে বসবি? খাতায় লেখা আছে, তাকিয়েই বলে দিলি। Dynamic Programming-এর সারমর্ম এই এক কথায়: যা একবার হিসাব করেছি, লিখে রাখি; দ্বিতীয়বার হিসাব না করে খাতা থেকে তুলে নিই।

কম্পিউটারের ক্ষেত্রে "বারবার একই অঙ্ক" আসে recursion থেকে। fib(n) = fib(n-1) + fib(n-2) দিয়ে fib(5) বের করলে recursion tree-টা দাঁড়ায় এরকম:

```
                fib(5)
               /      \
          fib(4)        fib(3)
          /    \        /    \
      fib(3)  fib(2) fib(2) fib(1)
      /   \    /   \   /   \
   fib(2) fib(1) fib(1) fib(0) fib(1) fib(0)
    /  \
fib(1) fib(0)
```

গুনে দেখ: fib(3) পুরো দুইবার হিসাব হয়েছে, fib(2) তিনবার, fib(1) পাঁচবার। n একটু বাড়ালেই এই নষ্ট কাজ দ্বিগুণ হয়ে যায়, তাই plain recursion-এ fib চলে O(2^n)-এ। fib(50) বের করতে বসলে বিকেল পেরিয়ে যাবে। অথচ ভেবে দেখ, আলাদা আলাদা হিসাব তো মোট n+1 টাই আছে: fib(0) থেকে fib(n) পর্যন্ত। বাকি সবটা পুরোনো হিসাবেরই পুনরাবৃত্তি।

এই যে একই ছোট সমস্যা বারবার ফিরে আসছে, এটাই **overlapping subproblems**। আর ছোট সমাধান জোগাড় করে বড়টা বানানো যায় (fib(n) দুটো ছোট fib দিয়েই পাওয়া যায়), এই গুণটা **optimal substructure**। দুটোই থাকলেই DP লাগানো যায়।

কৌশলটা দুই রকমের, কাজ একই, শুধু দিকটা উল্টো:

- **Top-down (memoization):** recursion-টাই রেখে দাও, একটা memo table জুড়ে দাও। [Recursion](../recursion/recursion-intro.mdx) জানা থাকলে এই পথটাই স্বাভাবিক (বিস্তারিত আছে [memoization](../recursion/memoization.mdx) পাতায়)।
- **Bottom-up (tabulation):** recursion বাদ দিয়ে ছোট থেকে বড় ক্রমে টেবিল পূরণ করো। শেষে যেই ঘর দরকার, সেটা তৈরি হয়েই আছে।

## ধাপে ধাপে ড্রাই রান

### fib(6): memo table ভরছে কীভাবে

Top-down চালাই fib(6)-এ। শুরুতে memo খালি। কলের গভীরে গিয়ে ছোটগুলো আগে ভরে, ফেরার পথে বড়গুলো:

| ধাপ | কোন কল | কী হলো | memo-তে নতুন |
|-----|--------|--------|--------------|
| 1 | fib(6) | fib(5) আর fib(4) দরকার, আগে fib(5)-এ ডুব | - |
| 2 | fib(5) থেকে fib(2) | একদম নিচে নেমে গেল, সবই miss | - |
| 3 | fib(2) | fib(1)=1, fib(0)=0, জোড়া 1 | memo[2]=1 |
| 4 | fib(3) | memo[2] + fib(1) = 1+1 | memo[3]=2 |
| 5 | fib(4) | memo[3] + memo[2] = 2+1, দুটোই cache hit | memo[4]=3 |
| 6 | fib(5) | memo[4] + memo[3] = 3+2 | memo[5]=5 |
| 7 | fib(6) | memo[5] + memo[4] = 5+3 | memo[6]=8 |

খেয়াল করো ধাপ ৫: আগের tree-তে fib(3) আর fib(2) আবার পুরো হিসাব হচ্ছিল, এখানে শুধু memo থেকে তুলে নেওয়া হলো। মোট হিসাব 2^n থেকে নেমে এলো n-এ।

### Climbing stairs: 1D dp ভরা

সিঁড়িতে একবারে ১ বা ২ ধাপ ওঠা যায়। n তলায় ওঠার কয়টি উপায়? শেষ ধাপটা হয় ১ এর, নয় ২ এর, তাই ways(i) = ways(i-1) + ways(i-2)। n=5-এর টেবিল:

| সিঁড়ি i | 0 | 1 | 2 | 3 | 4 | 5 |
|----------|---|---|---|---|---|---|
| উপায় dp[i] | 1 | 1 | 2 | 3 | 5 | 8 |

উত্তর dp[5] = 8। দেখো, fib-এর সাথে প্রায় একই ছবি, শুধু base case আলাদা। DP শিখতে গিয়ে আসলে যা শেখা হয়, সেটা এই "ছবিটা চেনা"।

## কোড: পুরো ফাইল, চালানো যায়

```js
// ===== ১. Fibonacci: top-down (memoization) =====
function fibMemo(n, memo = new Map()) {
  if (n <= 1) return n;                  // base case
  if (memo.has(n)) return memo.get(n);   // খাতায় আছে? তুলে নাও
  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  memo.set(n, result);                   // ফেরার আগে লিখে রাখো
  return result;
}

// ===== ২. Fibonacci: bottom-up (tabulation) =====
function fibTab(n) {
  if (n <= 1) return n;
  const dp = [0, 1];                     // dp[i] = i-তম fib
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];       // ছোট থেকে বড়
  }
  return dp[n];
}

// ===== ৩. Climbing Stairs =====
function climbStairs(n) {
  if (n <= 2) return n;
  const dp = [0, 1, 2];                  // dp[i] = i-তলায় ওঠার উপায়
  for (let i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}

// ===== ৪. Coin Change: সর্বনিম্ন কয়টি মুদ্রা =====
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;                             // 0 বানাতে 0 মুদ্রা
  for (let a = 1; a <= amount; a++) {
    for (const coin of coins) {
      if (coin <= a) {
        dp[a] = Math.min(dp[a], dp[a - coin] + 1); // এই মুদ্রা শেষে নিলে?
      }
    }
  }
  return dp[amount] === Infinity ? -1 : dp[amount];
}

// ===== ডেমো =====
console.log("fibMemo(6) =", fibMemo(6));               // 8
console.log("fibMemo(50) =", fibMemo(50));             // 12586269025, মুহূর্তেই
console.log("fibTab(6) =", fibTab(6));                 // 8
console.log("climbStairs(5) =", climbStairs(5));       // 8
console.log("coinChange([1,3,4], 6) =", coinChange([1, 3, 4], 6));   // 2 (3+3)
console.log("coinChange([1,2,5], 11) =", coinChange([1, 2, 5], 11)); // 3 (5+5+1)
console.log("coinChange([2], 3) =", coinChange([2], 3));             // -1, অসম্ভব
```

## ভ্যারিয়েন্ট ১: fib, space O(1)-এ

dp[i] বানাতে শুধু শেষ দুটো ঘর লাগে, তাহলে পুরো array রেখে কী করবে? দুটো ভেরিয়েবলই যথেষ্ট:

```js
function fibO1(n) {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    const cur = prev1 + prev2;   // dp[i]
    prev2 = prev1;               // এক ঘর সরাও
    prev1 = cur;
  }
  return prev1;
}
console.log("fibO1(6) =", fibO1(6)); // 8
```

"শেষ কয়টা ঘরই লাগে" প্যাটার্নটা DP-তে প্রায়ই space O(n) থেকে O(1)-এ নামিয়ে দেয়।

## ভ্যারিয়েন্ট ২: 0/1 knapsack, 2D টেবিল

ব্যাগের ধারণক্ষমতা 7। চারটা জিনিস, প্রতিটা একবারই নেওয়া যায় (তাই নাম 0/1):

| জিনিস | 1 | 2 | 3 | 4 |
|-------|---|---|---|---|
| ওজন w | 1 | 3 | 4 | 5 |
| মূল্য v | 1 | 4 | 5 | 7 |

dp[i][c] = প্রথম i-টা জিনিস দিয়ে, capacity c-তে, সর্বোচ্চ মোট মূল্য। প্রতি ঘরে দুটো পছন্দ: i-তম জিনিস **বাদ** (তাহলে dp[i-1][c]), নয় **নাও** (তাহলে v[i] + dp[i-1][c - w[i]])। ভরা টেবিলটা:

| জিনিস \ capacity | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|------------------|---|---|---|---|---|---|---|---|
| কেউ না | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| (w1,v1) পর্যন্ত | 0 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
| +(3,4) | 0 | 1 | 1 | 4 | 5 | 5 | 5 | 5 |
| +(4,5) | 0 | 1 | 1 | 4 | 5 | 6 | 6 | 9 |
| +(5,7) | 0 | 1 | 1 | 4 | 5 | 7 | 8 | 9 |

উত্তর 9: (3,4) আর (4,5) নিলে ওজন ঠিক 7, মূল্য 9। কোড:

```js
function knapsack(weights, values, capacity) {
  const n = weights.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(capacity + 1).fill(0));
  for (let i = 1; i <= n; i++) {
    for (let c = 0; c <= capacity; c++) {
      dp[i][c] = dp[i - 1][c];                 // i-তম জিনিস বাদ
      if (weights[i - 1] <= c) {               // ব্যাগে ঢোকে?
        dp[i][c] = Math.max(dp[i][c], values[i - 1] + dp[i - 1][c - weights[i - 1]]);
      }
    }
  }
  return dp[n][capacity];
}
console.log(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7)); // 9
```

## ভ্যারিয়েন্ট ৩: grid-এ unique paths

m x n grid-এ উপরে-বাঁ কোণ থেকে নিচে-ডান কোণে, শুধু ডানে বা নিচে হাঁটা যায়। কোনো ঘরে আসা যায় হয় উপরের ঘর থেকে, নয় বাঁয়ের ঘর থেকে। তাই dp[i][j] = dp[i-1][j] + dp[i][j-1]:

```js
function uniquePaths(m, n) {
  const dp = Array.from({ length: m }, () => new Array(n).fill(1)); // প্রথম সারি-কলাম সব 1
  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
    }
  }
  return dp[m - 1][n - 1];
}
console.log(uniquePaths(3, 3)); // 6
```

## কোড ব্রেকডাউন: লাইনে লাইনে

আগে fibMemo, কোন লাইন কেন আছে:

1. `if (n <= 1) return n` : base case। এটা না থাকলে memo থাকলেও recursion থামবেই না।
2. `if (memo.has(n)) return memo.get(n)` : এই এক লাইনেই exponential থেকে linear। খাতায় থাকলে আর হিসাব নয়।
3. `const result = fibMemo(n-1, memo) + fibMemo(n-2, memo)` : আসল recursion; ছোট দুটো সমাধান জোগাড়।
4. `memo.set(n, result)` : ফেরার আগে লিখে রাখো। ভুলে গেলে পুরো memo অকেজো।
5. `memo = new Map()` default parameter : প্রথম ডাকে খাতা নিজে থেকেই বানিয়ে নেয়, বাইরে থেকে কিছু পাঠাতে হয় না।

এবার coinChange:

1. `fill(Infinity)` : "এখনো জানি না" মানে Infinity; min নেওয়ার সময় যেকোনো আসল সংখ্যাই জিতবে।
2. `dp[0] = 0` : base case, 0 টাকা বানাতে 0 মুদ্রা। এটা ভুল হলে সব ঘর ভুল হবে।
3. বাইরের loop amount-এর ওপর, ভেতরের loop coins-এর : প্রতিটা amount-এ সব মুদ্রা চেষ্টা।
4. `dp[a - coin] + 1` : coin মুদ্রাটা শেষে দিলে তার আগে দরকার ছিল (a - coin) বানানো, যা ছোট amount হওয়ায় আগেই হিসাব হয়ে গেছে। এই "আগের ঘর আগে ভরা" নিশ্চয়তার ওপরেই পুরো bottom-up দাঁড়িয়ে।
5. শেষে Infinity থাকলে মানে বানানোই যায় না, return -1।

## Complexity: হিসাব কোথা থেকে আসে

DP-এর complexity বের করার একটাই সূত্র: **state সংখ্যা গুণ প্রতি state-এর কাজ**।

- fib (memo বা tabulation): আলাদা state n+1 টা (0 থেকে n)। প্রতিটা state-এ একবারই আসল হিসাব, দুটো যোগ। Time O(n)। Space: memo-তে n+1 ঘর, আর top-down-এ recursion stack গভীরতম n, মোট O(n)। space-optimized ভ্যারিয়েন্টে O(1)। তুলনা করো: plain recursion-এ time O(2^n), stack O(n)।
- coin change: state মানে amount-গুলো, মোট amount+1 টা। প্রতি state-এ coins-টা মুদ্রা চেষ্টা। Time O(amount * coins), space O(amount)।
- knapsack: state = (কোন জিনিস পর্যন্ত ভাবছি, কত capacity বাকি), মোট (n+1) * (capacity+1) টা, প্রতি state-এ O(1) পছন্দ। Time O(n * capacity)। মজার ব্যাপার: একে pseudo-polynomial বলে। capacity যদি 10^9 হয়, জিনিস চারটাই হোক, টেবিলই বানানো যাবে না।
- unique paths: m * n টা ঘর, প্রতি ঘরে এক যোগ। Time O(m * n), space O(m * n) (চাইলে শেষ সারিটাই রেখে O(n)-এ নামানো যায়)।

## কখন DP? চার ধাপের checklist

নতুন সমস্যা দেখে নিজেকে চারটা প্রশ্ন করো:

1. **একই হিসাব বারবার আসছে?** [brute force](./brute-force.mdx) recursion লিখে tree আঁকো। একই node দুইবার দেখলেই overlapping subproblem।
2. **ছোট সমাধান দিয়ে বড়টা বানানো যায়?** এটাই optimal substructure।
3. **প্রশ্নের ধরন কি "সর্বনিম্ন কত", "সর্বোচ্চ কত", "মোট কয়টি উপায়"?** এই তিন রকম প্রশ্ন প্রায়ই DP-র দিকে ইশারা করে।
4. **Greedy-তে চলছে না তো?** স্থানীয় সেরা পছন্দ সবসময় সঠিক উত্তর দেয় না। মুদ্রা [1, 3, 4], amount 6: [greedy](./greedy.mdx) নেবে 4, তারপর 1, 1, মোট 3 মুদ্রা; অথচ সঠিক উত্তর 3+3 = 2 মুদ্রা। Greedy ভেঙে গেলে DP।

আরেকটা সীমানা মাথায় রাখো: [backtracking](./backtracking.mdx) সব সম্ভাব্য পথ ঘুরে দেখে, DP সেই পথগুলোর মধ্যে যেখানে পুনরাবৃত্তি আছে সেখানে হিসাব জমিয়ে বাঁচায়। overlap না থাকলে DP-র লাভ শূন্য।

## সাধারণ ভুল আর edge case

**১. Base case ভুল বা ভুলে যাওয়া।**
coinChange-এ dp[0] = 0 ভুলে গেলে প্রতিটা ঘর Infinity + 1 থেকে বের হবে। DP-তে পুরো টেবিল base case-এর ওপর দাঁড়িয়ে, একটা ঘর ভুল মানে সব ভুল।

**২. Greedy লাগিয়ে ফেলা যেখানে DP লাগবে।**
উপরের মুদ্রার উদাহরণটাই মনে করো। "সবচেয়ে বড়টা আগে নিই" কোনো কোনো মুদ্রা-সেটে কাজ করে, সবটায় নয়। নিশ্চিত না হলে DP নিরাপদ।

**৩. Overlap নেই অথচ DP।**
merge sort-এ দুই অর্ধেক আলাদা ডেটা নিয়ে কাজ করে, কোনো subproblem পুনরাবৃত্ত হয় না। সেখানে memoization শুধু মেমরি নষ্ট। এমন সমস্যায় [divide and conquer](./divide-and-conquer.mdx)-ই যথেষ্ট।

**৪. Tabulation-এ পূরণের ক্রম উল্টো।**
dp[i] যদি dp[i+1]-এর ওপর নির্ভর করে, ডান থেকে বাঁয়ে ভরতে হবে। নির্ভরতার দিক না ভেবে loop লিখলে এমন ঘর পড়বে যা এখনো ভরাই হয়নি। সন্দেহ হলে top-down নাও, ক্রম নিয়ে ভাবতেই হবে না।

**৫. State-এ প্রয়োজনীয় তথ্য বাদ পড়া।**
memo-র key হিসেবে শুধু index রাখলাম, অথচ উত্তর "এতক্ষণ কত ব্যয় করেছি"-এর ওপরও নির্ভর করে। key-তে যা নেই, DP তার পার্থক্য বুঝবে না, আলাদা আলাদা অবস্থাকে এক বলে ভুল উত্তর দেবে। key বানানোর সময় জিজ্ঞেস করো: "এই তথ্যগুলো জানলে কি ভবিষ্যতের সিদ্ধান্ত পুরোপুরি ঠিক হয়ে যায়?"

## অনুশীলন

- **সহজ ১:** Climbing Stairs (LeetCode 70)। হিন্ট: এই পাতার dry run-টাই; ways(i) = ways(i-1) + ways(i-2), শুধু base case ঠিক করো।
- **সহজ ২:** Min Cost Climbing Stairs (LeetCode 746)। হিন্ট: dp[i] = cost[i] + min(dp[i-1], dp[i-2]); শুরু 0 বা 1 যেকোনোটা থেকে হতে পারে।
- **মাঝারি ১:** House Robber (LeetCode 198)। পাশাপাশি দুই বাড়ি লুটা যায় না। হিন্ট: প্রতি বাড়িতে দুটো পছন্দ, লুটলে dp[i-2] + এখনকার টাকা, না লুটলে dp[i-1]; দুটোর বড়টা নাও।
- **মাঝারি ২:** Longest Increasing Subsequence (LeetCode 300)। হিন্ট: dp[i] = i-এ শেষ হওয়া সবচেয়ে লম্বা বাড়তি subsequence; আগের সব j < i যেখানে nums[j] < nums[i], তাদের dp-র সর্বোচ্চটার সাথে 1 যোগ।
- **কঠিন:** Coin Change (LeetCode 322), নিজে লিখে, এই পাতার কোড না দেখে। হিন্ট: প্রতি amount-এর জন্য সব মুদ্রা চেষ্টা; বানানো না গেলে -1।

## সারসংক্ষেপ

- DP = overlapping subproblems + optimal substructure + হিসাব জমিয়ে রাখা।
- Top-down মানে recursion + memo, bottom-up মানে ছোট থেকে বড় টেবিল। উত্তর একই, দিক আলাদা।
- Complexity-র সূত্র: state সংখ্যা গুণ প্রতি state-এর কাজ। state গোনা গেলেই complexity জানা।
- "সর্বনিম্ন / সর্বোচ্চ / কয়টি উপায়" দেখলে DP-র কথা ভাবো; greedy ভাঙলে DP-তে এসো।
- প্রায়ই পুরো টেবিল লাগে না, শেষ কয়টা ঘরই যথেষ্ট, space তখন O(n) থেকে O(1)-এ নেমে যায়।
