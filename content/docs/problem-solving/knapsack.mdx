## কী শিখব

- 0/1 knapsack সমস্যাটা আসলে কী চায়, আর "0/1" নামটা কোথা থেকে এলো
- "দামি জিনিস আগে" ধরনের greedy কেন এখানে ফেল করে - একটা পাল্টা-উদাহরণেই পরিষ্কার
- DP স্টেট: dp[i][j] = প্রথম i-টা জিনিস, j ক্যাপাসিটিতে সর্বোচ্চ মূল্য
- 2D টেবিল থেকে 1D-তে নামার কৌশল, আর j উল্টো দিকে কেন ঘোরে
- unbounded knapsack - আশ্চর্যের বিষয়, পার্থক্য মাত্র এক লাইনের
- pseudo-polynomial complexity: W বড় হলে এই DP-ও কেন থেমে যায়

## ধারণা

গভীর রাত, এক চোর ঢুকে পড়লো গ্রামের সবচেয়ে ধনী বাড়িতে। কাঁধে ঝোলা, যাতে সর্বোচ্চ **৫০ কেজি** বহন করা যায় - এক চিমটিও বেশি নয়। সামনে তিনটা জিনিস:

| জিনিস | ওজন | মূল্য |
|--------|------|--------|
| ১: রূপার থালাবাসন | ১০ কেজি | ৬০ হাজার |
| ২: পুরনো ঘড়ি | ২০ কেজি | ১০০ হাজার |
| ৩: সোনার মূর্তি | ৩০ কেজি | ১২০ হাজার |

নিয়ম কড়া: জিনিস **ভাঙা বা কাটা যাবে না** - হয় পুরোটা নেবে, নয় ছেড়ে দেবে। এই "হয় ০, নয় ১" বাধাটাই সমস্যার নাম দিয়েছে: **0/1 knapsack** (knapsack মানে পিঠের ঝোলা)।

সহজ বুদ্ধি: প্রতি কেজিতে কার দাম বেশি? থালা ৬ হাজার/কেজি, ঘড়ি ৫, মূর্তি ৪। তাহলে আগে থালা (১০ কেজি), তারপর ঘড়ি (২০ কেজি) - মোট ৩০ কেজি, ১৬০ হাজার, আর মূর্তির জন্য জায়গাই নেই। কিন্তু ঘড়ি + মূর্তি নিলে? ঠিক ৫০ কেজি, **২২০ হাজার**! অনুপাতের খেলা চোখে পুরো ধোঁকা দিলো, কারণ ফাঁকা ২০ কেজি জায়গাটা এখানে একদম নষ্ট। মজার ব্যাপার: জিনিস কাটা-ভাঙা যেত (fractional knapsack), তাহলে এই greedy-ই নির্ভুল ছিল, যেমনটা [Greedy](./greedy.mdx) পাতায় দেখেছো।

তাহলে সব সম্ভাবনা গুনে ফেলি? প্রতি জিনিসে "নাও/বাদ" - n টা জিনিসে ২^n টা combination। তিনটায় মাত্র ৮, কিন্তু ১০০ টা জিনিসে সংখ্যাটা ৩০-এর বেশি অঙ্কের; [Backtracking](./backtracking.mdx)-এর সেই পরিচিত বিস্ফোরণ। খেয়াল করো: "৩ নম্বর জিনিস পর্যন্ত ভাবা শেষ, ঝোলায় ২০ কেজি জায়গা আছে" - এই অবস্থা থেকে সেরা উত্তর কী, সেই একই subproblem-এ বারবার পৌঁছাই। Overlap আছে, optimal substructure আছে - অর্থাৎ এটা খাঁটি [Dynamic Programming](./dynamic-programming.mdx)।

## ধাপে ধাপে dry run

স্টেট: **dp[i][j] = শুধু প্রথম i-টা জিনিস ব্যবহার করে, j ক্যাপাসিটিতে সর্বোচ্চ কত মূল্য নেওয়া যায়।**

প্রতি ঘরে দুটো পছন্দ:

- **বাদ রাখি** i-তম জিনিস: dp[i][j] = dp[i-1][j]
- **নিই** (যদি ঢোকে): dp[i][j] = v[i] + dp[i-1][j - w[i]]
- ঘরের মান: দুটোর বড়টা

হিসাব সহজ রাখতে সব ওজন **১০ কেজির এককে** লিখি (৫০ কেজি → ৫, ১০ → ১, ২০ → ২, ৩০ → ৩)। টেবিল ভরি সারি ধরে:

| জিনিস \ ক্যাপাসিটি | 0 | 1 | 2 | 3 | 4 | 5 |
|--------------------|---|---|---|---|---|---|
| কেউ না | 0 | 0 | 0 | 0 | 0 | 0 |
| ১ নম্বর পর্যন্ত (w=1, v=60) | 0 | 60 | 60 | 60 | 60 | 60 |
| ২ নম্বর পর্যন্ত (w=2, v=100) | 0 | 60 | 100 | 160 | 160 | 160 |
| ৩ নম্বর পর্যন্ত (w=3, v=120) | 0 | 60 | 100 | 160 | **180** | **220** |

শেষ সারির দুটো ঘর হাতে গুণে দেখি:

- dp[3][4]: মূর্তি **বাদ** → dp[2][4] = 160। **নিলে** → dp[2][1] + 120 = 60 + 120 = 180। বড়টা 180 (থালা + মূর্তি)।
- dp[3][5]: মূর্তি **বাদ** → dp[2][5] = 160। **নিলে** → dp[2][2] + 120 = 100 + 120 = 220। বড়টা 220 (ঘড়ি + মূর্তি)।

উত্তর dp[3][5] = ২২০ হাজার - greedy-র ১৬০-কে পেছনে ফেলে।

## কোড

```js
// 2D টেবিল - dry run-এর হুবহু অনুবাদ
function knapsack(weights, values, capacity) {
  const n = weights.length;
  const dp = Array.from({ length: n + 1 }, () => new Array(capacity + 1).fill(0));
  for (let i = 1; i <= n; i++) {
    for (let j = 0; j <= capacity; j++) {
      dp[i][j] = dp[i - 1][j]; // i-তম জিনিস বাদ
      if (weights[i - 1] <= j) { // ঝোলায় ঢোকে?
        dp[i][j] = Math.max(dp[i][j], values[i - 1] + dp[i - 1][j - weights[i - 1]]);
      }
    }
  }
  return dp[n][capacity];
}

// Space-অপ্টিমাইজড: এক সারিই যথেষ্ট, তবে j ডান থেকে বাঁয়ে
function knapsack1D(weights, values, capacity) {
  const dp = new Array(capacity + 1).fill(0);
  for (let i = 0; i < weights.length; i++) {
    for (let j = capacity; j >= weights[i]; j--) {
      dp[j] = Math.max(dp[j], values[i] + dp[j - weights[i]]);
    }
  }
  return dp[capacity];
}

// আর জিনিসই যদি অসীমবার নেওয়া যায়? শুধু j-এর দিক বদলাও
function knapsackUnbounded(weights, values, capacity) {
  const dp = new Array(capacity + 1).fill(0);
  for (let i = 0; i < weights.length; i++) {
    for (let j = weights[i]; j <= capacity; j++) { // ascending!
      dp[j] = Math.max(dp[j], values[i] + dp[j - weights[i]]);
    }
  }
  return dp[capacity];
}

console.assert(knapsack([1, 2, 3], [60, 100, 120], 5) === 220, "2D classic");
console.assert(knapsack1D([1, 2, 3], [60, 100, 120], 5) === 220, "1D same answer");
console.assert(knapsackUnbounded([1, 2, 3], [60, 100, 120], 5) === 300, "unbounded: থালা 5 বার");
console.assert(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7) === 9, "DP পাতার উদাহরণ");
console.assert(knapsack([10], [500], 5) === 0, "একটাই জিনিস, সেটাই ভারী");
console.assert(knapsack([], [], 5) === 0, "খালি তালিকা");
console.log("সব assert পাস!");
```

## কোড ব্রেকডাউন, লাইনে লাইনে

**knapsack (2D):**

- `Array.from({ length: n + 1 }, () => new Array(...))` - (n+1) সারি, (capacity+1) কলাম, সব শূন্য। শূন্যম সারি মানে "কোনো জিনিস নেই", শূন্যম কলাম মানে "ক্যাপাসিটি নেই" - দুটোতেই উত্তর 0, base case ফ্রি-তে পেয়ে গেলাম। ভেতরের array-গুলো আলাদা আলাদা বানাতে হবে; `new Array(n+1).fill(একটাই array)` লিখলে সব সারি একই রেফারেন্স ধরবে, এক সারি বদলালে সব বদলে যাবে।
- বাইরের loop জিনিস ধরে, ভেতরের loop ক্যাপাসিটি ধরে - টেবিল যেভাবে ভরেছিলাম, হুবহু সেই ক্রম।
- `dp[i][j] = dp[i - 1][j]` - আগে ধরে নিই জিনিসটা বাদ। এই লাইনটাই "ভারী জিনিসের ক্ষেত্রে আগের সারি কপি" কেসটাও চুপচাপ সামলে দেয়।
- `weights[i - 1] <= j` - টেবিলের i নম্বর সারি মানে array-র i-1 ইনডেক্সের জিনিস। এই এক ঘর সরণেই সবচেয়ে বেশি ভুল হয়।
- `Math.max(...)` - নিলে মূল্য values[i-1], যোগ "বাকি জায়গায় আগের সেরা" dp[i-1][j-w]। বাদ বনাম নাও - বড়টা টিকে যায়।

**knapsack1D - কেন কাজ করে:**

- 2D-তে i-তম সারি শুধু (i-1)-তম সারি দেখে। পুরনো সারিগুলো ফেলে একটাই সারি রাখা যায় - space O(n·W) থেকে নেমে O(W)।
- কিন্তু j **ডান থেকে বাঁয়ে** কেন? descending-এ ঘোরার সময় dp[j - w]-এ **এই রাউন্ডের আপডেট এখনো পড়েনি** - অর্থাৎ সেটা "এই জিনিস ছাড়া" আগের রাউন্ডের সেরা, 0/1 নিয়ম ঠিকঠাক বজায় থাকে।
- ascending চালালে dp[j - w] এতক্ষণে এই জিনিসটা ধরেই ফেলেছে - ফলে একই জিনিস দ্বিতীয়, তৃতীয়বার ঢুকে যায়। আর সেটাই তো unbounded! এজন্যই বলেছিলাম, দুটোর পার্থক্য এক লাইনের।

## ভ্যারিয়েন্ট

- **Unbounded knapsack** (জিনিস অসীম স্টকে): উপরের তৃতীয় ফাংশন, j ascending। Coin change-এর "সর্বোচ্চ মূল্য" সংস্করণ ভেবে দেখো।
- **কোন জিনিসগুলো নিলাম?** শুধু মূল্য নয়, তালিকাও চাইলে 2D টেবিল থেকে উল্টো হাঁটো: dp[i][j] আর dp[i-1][j] আলাদা মানে i-তম জিনিস নেওয়া হয়েছে - তালিকায় ঢুকাও, j থেকে w[i] বাদ দাও, এক সারি উপরে উঠো। (অনুশীলনে দিচ্ছি।)
- **Subset-sum / Partition**: মূল্য আর ওজন একই করে দিলে knapsack-ই বলে দেয় "ক্যাপাসিটি পুরো ভরা যাবে কি না" - LeetCode 416 এই রূপেই ফিরে আসে।
- **Fractional knapsack** (জিনিস কাটা যায়): তখন DP লাগেই না; প্রতি কেজির দামে sort করে [Greedy](./greedy.mdx)-ই নির্ভুল। এই পাতার গল্পের greedy-টা ঠিক ওখানেই কাজ করে।

## Complexity

| বাস্তবায়ন | Time | Space |
|------------|------|-------|
| Brute force (সব subset) | O(2^n) | O(n) recursion stack |
| 2D টেবিল | O(n·W) | O(n·W) |
| 1D অপ্টিমাইজড | O(n·W) | O(W) |

এখানে W হলো ক্যাপাসিটির **মান**, জিনিসের সংখ্যা নয়। এজন্য knapsack-এর DP-কে বলে **pseudo-polynomial**: W = ১০^৯ হলে জিনিস ৫ টাই হোক, টেবিলের জন্যই গিগাব্যাট মেমরি লাগবে। অথচ ইনপুটে W লিখতে লাগে মাত্র ~৩০ বিট - ইনপুট সাইজের সাপেক্ষে এই রানটাইম আসলে exponential। বড় W দেখলে approximate অ্যালগরিদম বা সমস্যার অন্য কাঠামো খোঁজো।

## সাধারণ ভুল আর edge case

**১. 1D-তে j ascending ঘোরানো।**
ফলে একই জিনিস বারবার ঢুকে যায়, উত্তর চুপচাপ বড় বেরোয় - টেস্টে ধরা কঠিন। 0/1 মানে descending, unbounded মানে ascending; মুখস্থ নয়, কারণটা মনে রাখো।

**২. weights[i] বনাম weights[i-1] গুলিয়ে ফেলা।**
টেবিলের সারি ১ থেকে, array-র ইনডেক্স ০ থেকে। এই এক ঘরের সরণ ভুললে হয় এক জিনিস পুরোপুরি বাদ পড়ে, নয় এক জিনিস দুইবার বিবেচিত হয়।

**৩. ভারী জিনিসের ক্ষেত্রে আগের সারি কপি না করা।**
"ঢোকে না" মানে ঘরটা ফাঁকা নয় - সেখানে dp[i-1][j]-ই বসবে। 2D কোডের প্রথম অ্যাসাইনমেন্টটা এজন্যই শর্তের বাইরে রাখা।

**৪. Base সারি/কলাম ভুলে যাওয়া।**
জিনিস শূন্য বা ক্যাপাসিটি শূন্য হলে উত্তর 0 - কিন্তু সেটা টেবিলে না থাকলে ভেতরের ঘরগুলো ভুল ভিত্তিতে দাঁড়ায়। fill(0) দিয়ে শুরু করলে এটা ফ্রি-তে মিলে যায়; top-down লিখলে নিজে যত্ন নাও।

**৫. Greedy দিয়ে চেষ্টা করা।**
"দামি আগে", "হালকি আগে", "অনুপাতে সেরা আগে" - 0/1-এ কোনোটাই গ্যারান্টি দেয় না, এই পাতার গল্পটাই প্রমাণ। নিশ্চিত না হলে DP নিরাপদ; greedy শুধু fractional সংস্করণে।

## অনুশীলন

- **সহজ ১:** হাতে টেবিল ভরো: ওজন [3, 4, 2], মূল্য [30, 50, 40], ক্যাপাসিটি 5। উত্তর মিলিয়ে নাও: 70 (১ নম্বর + ৩ নম্বর জিনিস)।
- **সহজ ২:** 2D টেবিল থেকে উল্টো হেঁটে নেওয়া জিনিসগুলোর তালিকা ফেরত দেওয়ার ফাংশন লেখো। হিন্ট: dp[i][j] আর dp[i-1][j] তুলনা করো, আলাদা হলে i-তম জিনিস নেওয়া।
- **মাঝারি ১:** Partition Equal Subset Sum (LeetCode 416)। হিন্ট: মোট যোগফল বিজোড় হলে সোজা false; জোড় হলে target = অর্ধেক, মূল্য = ওজন ধরে knapsack চালাও - target ভরা যায় কি না দেখো।
- **মাঝারি ২:** Rod Cutting: লোহার rod কেটে টুকরো বিক্রি করা যায়, প্রতি দৈর্ঘ্যের দাম দেওয়া আছে। মডেল করো unbounded knapsack হিসেবে (টুকরোর দৈর্ঘ্য = ওজন, দাম = মূল্য)।
- **কঠিন:** Target Sum (LeetCode 494)। হিন্ট: +/- চিহ্ন দিয়ে দুই দলে ভাগ মানেই subset-sum; positive দলের যোগফল হবে (মোট + target) ভাগ 2। সেই ক্যাপাসিটিতে **কয়টি উপায়ে** ভরা যায়, সেটা গোনার DP - টেবিলের চিন্তা একই, শুধু max-এর বদলে যোগ।

## সারসংক্ষেপ

- 0/1 knapsack: প্রতি জিনিস হয় পুরো নাও, নয় বাদ - সীমিত ক্যাপাসিটিতে মূল্য সর্বোচ্চ।
- Greedy এখানে ফেল করে (অনুপাতের খেলায় 160, সঠিক 220); নিরাপদ পথ DP।
- স্টেট dp[i][j], দুই পছন্দের max; 2D টেবিল O(n·W) time ও space, 1D-তে space O(W) - তবে j descending।
- Unbounded চাইলে সেই একই কোড, শুধু j ascending - পার্থক্য এক লাইন, কারণ বুঝে গেলে মুখস্থ করার কিছু নেই।
- W-এর মান বড় হলে DP অচল - এজন্যই একে pseudo-polynomial বলে।
- DP-র সাধারণ ছাঁচটা [Dynamic Programming](./dynamic-programming.mdx) পাতায়; সেখানকার capacity-7 উদাহরণে নিজে টেবিল ভরে দেখো, উত্তর 9 আসে কি না।
- আরেকটা classic টেবিল-DP: দুই স্ট্রিং-এর মিল মাপা [LCS](./lcs.mdx) - স্টেট-চিন্তা হুবহু এই পাতার মতো, কাজে লাগে git diff-এ।
