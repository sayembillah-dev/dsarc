## কী শিখব

- Divide and conquer-এর তিন ধাপ: ভাগ করো, জয় করো, মিলাও, আর recursion-এর সাথে এর সম্পর্ক
- `[38, 27, 43, 3, 9, 82, 10]`-এর উপর merge sort-এর পুরো dry run: split tree আর merge table
- Binary search কেন D&C-এর সবচেয়ে চিকন রূপ
- T(n) = 2T(n/2) + O(n) থেকে tree-level যুক্তি দিয়ে O(n log n) বের করা
- Iterative বনাম recursive বাস্তবায়ন, আর কোন সমস্যায় D&C লাগে আর কোথায় লাগে না
- FFT: জোড়-বিজোড় ভাগের একই চিন্তায় polynomial গুণন O(n²) থেকে O(n log n)

## ধারণা

ভাবো তো, পুরনো দিনের মোটা ফোনবুকে "রহিমা খাতুন"-এর নম্বর খুঁজতে হবে, হাজার পাতার বই। কেউ কি প্রথম পাতা থেকে একে একে সব নাম পড়ে? না। তুমি বইটা মাঝখান থেকে খুলো, দেখো কোন অক্ষরে পড়েছো, তারপর বইয়ের যে অর্ধেকটা অচল হয়ে গেল সেটা ফেলে দিয়ে বাকি অর্ধেকে আবার একই কাজ। কয়েকটা লাফেই সঠিক পাতায় পৌঁছে যাও।

আরেকটা দৃশ্য ধরো: একা এক দিনে ৫০০ জনের বিরিয়ানি রাঁধা অসম্ভব। কিন্তু ১০ জন কুককে ৫০ জন করে ভাগ করে দাও, প্রত্যেকে নিজের অংশ শেষ করুক, শেষে শুধু সবার হাতের কাজ এক টেবিলে মেলাও। বিশাল কাজ আর বিশাল না রইল।

এই দুটো গল্পের কৌশলটাই **divide and conquer**, তিনটা ধাপে:

1. **ভাগ করো (Divide)**: সমস্যাটাকে একই ধরনের ছোট সাব-সমস্যায় ভাঙো
2. **জয় করো (Conquer)**: সাব-সমস্যাগুলো solve করো; এত ছোট হয়ে গেলে সরাসরি উত্তর দাও (base case), না হলে আবার ভাগ করো
3. **মিলাও (Combine)**: সাব-সমস্যার উত্তরগুলো জোড়া লাগিয়ে মূল সমস্যার উত্তর বানাও

দ্বিতীয় ধাপে "আবার ভাগ করো" লেখা আছে, মানে D&C স্বাভাবিকভাবেই recursion-এর ঘরে বসে। তাই শুরুর আগে [Recursion](../recursion/recursion-intro.mdx) আর [Call Stack](../recursion/call-stack.mdx)-এর ধারণা পরিষ্কার থাকলে এই অধ্যায় মিষ্টি হয়ে যাবে।

তবে একটা সতর্কতা: সব "ভাগ করা" সমস্যা D&C না। দুটো শর্ত মানতে হয়: সাব-সমস্যাগুলো **একই ধরনের** হবে (ছোট input-এ হুবহু একই সমস্যা) আর **পরস্পর স্বাধীন** হবে। সাব-সমস্যার মধ্যে overlap থাকলে, মানে একই সাব-সমস্যা বারবার দরকার হলে, সেটা [Dynamic Programming](./dynamic-programming.mdx)-এর জমি, D&C-এর না।

## ধাপে ধাপে ড্রাই রান

`[38, 27, 43, 3, 9, 82, 10]`-কে merge sort দিয়ে sort করি। [Merge Sort](../sorting/merge-sort.mdx) অধ্যায়ের আগে এটাকে D&C-এর চোখে দেখো: ভাগ করো = মাঝ দিয়ে অর্ধেক, জয় করো = এক-element array (নিজেই sorted, এটাই base case), মিলাও = দুটো sorted array একসাথে মেশানো।

**Divide পর্ব** (উপরে থেকে নিচে):

```
                    [38, 27, 43, 3, 9, 82, 10]
                   /                          \
          [38, 27, 43, 3]                  [9, 82, 10]
          /             \                  /         \
      [38, 27]       [43, 3]            [9]       [82, 10]
      /     \        /     \                        /    \
    [38]   [27]    [43]   [3]                     [82]   [10]
```

এক-element array নিজেই sorted, তাই এখানে ভাগ করা থামে। এবার **Combine পর্ব** (নিচে থেকে উপরে), প্রতিটা জোড়া মিলিয়ে sorted বানানো:

```
    [38]   [27]    [43]   [3]                     [82]   [10]
      \     /        \     /                        \    /
     [27, 38]       [3, 43]                       [10, 82]
        \              /                   \          /
      [3, 27, 38, 43]                      [9, 10, 82]
               \                                  /
                [3, 9, 10, 27, 38, 43, 82]
```

Combine-এর ভেতরের যন্ত্রটা খোলা যাক। ধরো `[27, 38]` আর `[3, 43]` মিলাচ্ছি। দুটোই sorted, তাই দুটো pointer রেখে প্রতিবার ছোট মাথাটা তুলে নিলেই পুরোটা sorted হয়ে যায়:

| ধাপ | বাম pointer | ডান pointer | তুলনা | নেওয়া হলো | merged |
|-----|-------------|--------------|--------|-------------|--------|
| 1 | 27 | 3 | 3 ছোট | 3 | [3] |
| 2 | 27 | 43 | 27 ছোট | 27 | [3, 27] |
| 3 | 38 | 43 | 38 ছোট | 38 | [3, 27, 38] |
| 4 | (বাম শেষ) | 43 | তুলনাই নেই | 43 | [3, 27, 38, 43] |

চারটা element মাত্র ৩-টা তুলনায় মিশে গেল, কেউ কারো সাথে দুইবার তুলনা হলো না। কারণ দুপাশ আগে থেকেই sorted। এই "দুটো sorted মাথা থেকে ছোটটা তোলা" trick-টা মনে রাখো, কঠিন অনেক সমস্যার ভেতরেই ঘুরে ফিরে এটা আসবে।

## কোড

এক ফাইলে D&C-এর দুটো রূপ: merge sort (Combine-ভারী) আর binary search (Combine-বিহীন)। পুরোটা copy করে `node divide-and-conquer.js` দিয়ে চালাও।

```js
// ============================================================
// divide-and-conquer.js : merge sort + binary search
// ============================================================

// ---- Merge Sort ----
function mergeSort(arr) {
  if (arr.length <= 1) return arr;             // base case: 0 বা 1 element নিজেই sorted

  const mid = Math.floor(arr.length / 2);      // Divide: মাঝ দিয়ে কাটো
  const left = mergeSort(arr.slice(0, mid));   // Conquer: বাম অর্ধেক
  const right = mergeSort(arr.slice(mid));     // Conquer: ডান অর্ধেক

  return merge(left, right);                   // Combine
}

// দুটো sorted array মিলিয়ে একটা sorted array
function merge(left, right) {
  const result = [];
  let i = 0, j = 0;

  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) result.push(left[i++]);  // ছোট মাথাটা আগে
    else result.push(right[j++]);
  }

  // যে পাশে মাল পড়ে রইল, সেটা পুরো বসে যায়
  while (i < left.length) result.push(left[i++]);
  while (j < right.length) result.push(right[j++]);

  return result;
}

// ---- Binary Search (recursive D&C) ----
// শর্ত: arr অবশ্যই sorted হতে হবে
function binarySearch(arr, target, low = 0, high = arr.length - 1) {
  if (low > high) return -1;                   // base case: ভাগ করার আর কিছু নেই

  const mid = Math.floor((low + high) / 2);    // Divide: মাঝখানে উঁকি

  if (arr[mid] === target) return mid;         // Conquer: পেয়ে গেছি
  if (target < arr[mid]) {
    return binarySearch(arr, target, low, mid - 1);   // ডান অর্ধেক ফেলে দাও
  }
  return binarySearch(arr, target, mid + 1, high);    // বাম অর্ধেক ফেলে দাও
}

// ----------------- demo -----------------
const data = [38, 27, 43, 3, 9, 82, 10];
const sorted = mergeSort(data);
console.log(sorted);                            // [3, 9, 10, 27, 38, 43, 82]
console.log(mergeSort([5, 2]));                 // [2, 5]
console.log(mergeSort([]));                     // []

console.log(binarySearch(sorted, 27));          // 3
console.log(binarySearch(sorted, 100));         // -1
console.log(binarySearch([1, 2, 3, 4, 5], 1));  // 0
```

দুটোর গঠন দেখো: দুটোই ভাগ করছে, কিন্তু merge sort-এ সব আসল কাজ Combine-এ, binary search-এ Combine বলে কিছুই নেই, এক পাশ পুরো ফেলে দেওয়া হয়। D&C-এর পরিবারে এটাই বড় ভিন্নতা।

## ভ্যারিয়েন্ট

### ভ্যারিয়েন্ট ১: iterative binary search

একই D&C, অন্য প্যাকেজিং: recursive call-এর বদলে while loop-এ boundary সরাও। Call stack লাগে না, তাই space O(1)।

```js
function binarySearchIter(arr, target) {
  let low = 0, high = arr.length - 1;
  while (low <= high) {
    const mid = Math.floor((low + high) / 2);
    if (arr[mid] === target) return mid;
    if (target < arr[mid]) high = mid - 1;   // ডান পাশ ফেলে দাও
    else low = mid + 1;                      // বাম পাশ ফেলে দাও
  }
  return -1;
}
console.log(binarySearchIter([3, 9, 10, 27, 38, 43, 82], 82)); // 6
```

কোনটা ভালো? Recursive-টা ধারণাটা পরিষ্কার দেখায়, iterative-টা চলনসই। দুটোই একই recurrence মানে। বিস্তারিত [Binary Search](../searching/binary-search.mdx) অধ্যায়ে।

### ভ্যারিয়েন্ট ২: count inversions (teaser)

Merge-এর মুহূর্তে একটা counter যোগ করলেই জাদু: ডান পাশের element আগে উঠলে সে বাম পাশের বাকি সবার চেয়ে ছোট, মানে ততগুলো inversion:

```js
function countInversions(arr) {
  if (arr.length <= 1) return [arr, 0];
  const mid = Math.floor(arr.length / 2);
  const [left, li] = countInversions(arr.slice(0, mid));
  const [right, ri] = countInversions(arr.slice(mid));

  let i = 0, j = 0, inv = li + ri;
  const merged = [];
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j]) merged.push(left[i++]);
    else {
      merged.push(right[j++]);
      inv += left.length - i;   // ডানটা ছোট: বামের বাকি সবার আগে উঠে গেল
    }
  }
  while (i < left.length) merged.push(left[i++]);
  while (j < right.length) merged.push(right[j++]);
  return [merged, inv];
}
console.log(countInversions([8, 4, 2, 1])[1]); // 6
```

Brute force-এ inversion গুনতে O(n²) লাগত; D&C দিয়ে O(n log n)। এটাই D&C-এর আসল জাদু: ভাগ করা আকারটা না, Combine-এর তথ্যটাই আসল সম্পদ।

### ভ্যারিয়েন্ট ৩: quicksort-এর partition

ভাগ করার স্টাইল বদলে দাও: মাঝখানে কাটার বদলে একটা pivot নাও, ছোটগুলো বামে, বড়গুলো ডানে। এখানে কাজটা Divide-এ, Combine-এ প্রায় কিছু নেই:

```js
function partition(arr, low, high) {
  const pivot = arr[high];                 // শেষ element-কে pivot ধরলাম
  let i = low;                             // ছোটদের অঞ্চলের সীমানা
  for (let j = low; j < high; j++) {
    if (arr[j] <= pivot) {
      [arr[i], arr[j]] = [arr[j], arr[i]];
      i++;
    }
  }
  [arr[i], arr[high]] = [arr[high], arr[i]];  // pivot-কে তার জায়গায় বসাও
  return i;
}
```

এই partition-টাই পরে [Quick Sort](../sorting/quick-sort.mdx)-এর ইঞ্জিন, আর [Kth Element](./kth-element.mdx)-এ quickselect হিসেবেও কাজ করে।

### ভ্যারিয়েন্ট ৪: polynomial গুণন, এক নিমেষে - FFT

দুটো polynomial গুণ করতে বলা হলো: (1 + 2x) × (3 + 4x) = 3 + 10x + 8x²। স্কুলের পদ্ধতিতে প্রতি coefficient প্রতিটার সাথে গুণ হয় - n-ঘাত দুটোর জন্য O(n²)। কিন্তু coefficient-গুলোকে জোড় আর বিজোড় ঘাতে ভাগ করলেই ছবি বদলায় - চেনা গন্ধ, তাই না? **Fast Fourier Transform (FFT)** ঠিক এই D&C চিন্তায় polynomial গুণন নামিয়ে আনে **O(n log n)**-এ। ধারণাটা তিন ধাপের: দুটো polynomial-কে বিশেষ কয়টা বিন্দুতে (n-তম roots of unity) evaluate করো (Divide + Conquer), বিন্দুভিত্তিক মান গুণ করো (এক লাইন!), তারপর উত্তরটা আবার coefficient-এ ফিরিয়ে আনো (Combine):

```js
function fft(a, invert) {
  const n = a.length;
  if (n === 1) return;
  const even = [], odd = [];
  for (let i = 0; i < n / 2; i++) {
    even.push(a[2 * i]);        // জোড় ঘাতের coefficient-গুলো
    odd.push(a[2 * i + 1]);     // বিজোড় ঘাতের coefficient-গুলো
  }
  fft(even, invert);
  fft(odd, invert);
  const ang = (2 * Math.PI / n) * (invert ? -1 : 1);
  const wn = [Math.cos(ang), Math.sin(ang)];  // জটিল ঘূর্ণন-একক
  let wr = 1, wi = 0;                         // w = 1 দিয়ে শুরু
  for (let i = 0; i < n / 2; i++) {
    const ur = even[i][0], ui = even[i][1];
    // odd[i] * w (জটিল গুণ)
    const vr = odd[i][0] * wr - odd[i][1] * wi;
    const vi = odd[i][0] * wi + odd[i][1] * wr;
    a[i]         = [ur + vr, ui + vi];  // butterfly: যোগ পাশ
    a[i + n / 2] = [ur - vr, ui - vi];  // butterfly: বিয়োগ পাশ
    const nwr = wr * wn[0] - wi * wn[1];
    wi = wr * wn[1] + wi * wn[0];
    wr = nwr;                           // w এক ধাপ ঘুরলো
  }
}

function polyMultiply(A, B) {
  let n = 1;
  while (n < A.length + B.length - 1) n *= 2;  // দুই-এর power-এ প্যাড
  const fa = Array.from({ length: n }, (_, i) => [A[i] || 0, 0]);
  const fb = Array.from({ length: n }, (_, i) => [B[i] || 0, 0]);
  fft(fa, false);
  fft(fb, false);
  for (let i = 0; i < n; i++) {
    // বিন্দুভিত্তিক জটিল গুণ
    fa[i] = [fa[i][0] * fb[i][0] - fa[i][1] * fb[i][1],
             fa[i][0] * fb[i][1] + fa[i][1] * fb[i][0]];
  }
  fft(fa, true);
  return fa.slice(0, A.length + B.length - 1)
           .map(([re]) => Math.round(re / n) || 0);  // || 0: -0 আটকাতে
}

console.log(polyMultiply([1, 2], [3, 4]));    // [3, 10, 8]
console.log(polyMultiply([1, 0, 1], [1, 1])); // [1, 1, 1, 1]
```

Recursion-টা merge sort-এর আত্মীয়: প্রতি level-এ n কাজ (butterfly জোড়া), level log n-টা, মোট O(n log n)। জটিল সংখ্যাগুলো [real, imag] জোড়া আকারে রাখা, আর শেষে divide-by-n আর rounding-এ coefficient ফিরে আসে (শেষের `|| 0`-টা ছোট্ট ফাঁদ ঢেকে রাখে: rounding মাঝে মাঝে -0 বানায়, যা 0-এর সমান হলেও test-এ ধরা খায়)। কোথায় লাগে? অডিও আর image প্রসেসিং, বিশাল পূর্ণসংখ্যার গুণ, signal filtering - যেখানেই convolution, পেছনে FFT। O(n²) থেকে O(n log n): n এক লাখ পেরোলেই ব্যবধান হাজার গুণ ছাড়িয়ে যায়।

## কোড ব্রেকডাউন

মূল ফাইলের গুরুত্বপূর্ণ line-গুলো আবার দেখি:

1. `if (arr.length <= 1) return arr;` : base case। এই line না থাকলে ভাগ করা থামে না, call stack উপচে program crash করে। Recursion-এর প্রথম নিয়ম: থামার শর্ত আগে লেখো।
2. `const mid = Math.floor(arr.length / 2);` : ভাগ করার জায়গা। Odd length হলে এক পাশ একটু বড় হয়, ক্ষতি নেই।
3. `arr.slice(0, mid)` আর `arr.slice(mid)` : দুটো স্বাধীন সাব-সমস্যা। দুটোই আসল সমস্যারই ছোট সংস্করণ: এটাই D&C-এর সংজ্ঞা পূরণ করে।
4. `mergeSort(...)` দুইবার : Conquer ধাপ। প্রতিটা call নিজের ছোট্ট tree-তে নেমে যায়; call stack-ই এই গভীরতা সামলায়।
5. `return merge(left, right);` : Combine। Merge sort-এ আসল কাজ Divide-এ না, Combine-এ।
6. `while (i < left.length && j < right.length)` : দুপাশে মাল থাকতে ছোট মাথাটা তোলো। প্রতিটা element ঠিক একবারই result-এ ঢোকে।
7. `left[i] <= right[j]`-এ `<=` : সমান হলে বামটা আগে যায়, এতে sort-টা stable থাকে (সমান element-দের আসল ক্রম বদলায় না)।
8. শেষের দুটো `while` : যে পাশে element পড়ে রইল, সেটা পুরো কপি। এগুলো ভুলে গেলে answer-এ element কম পড়ে, classic bug।
9. `if (low > high) return -1;` : ভাগ করতে করতে একসময় অঞ্চলটা খালি, মানে target নেই।
10. `mid - 1` আর `mid + 1` : mid-কে বাদই দিচ্ছি, কারণ ওটা তো এই ধাপেই চেক হয়ে গেছে। শুধু `mid` দিলে অঞ্চল ছোট হতো না, infinite recursion।

## Complexity

Merge sort-এর recurrence লিখি: **T(n) = 2T(n/2) + O(n)**। দুটো অর্ধেকে recursive call (2T(n/2)), আর merge-এ সব element একবার করে ছোঁয়া (O(n))।

এখন সংখ্যাটা বের করা যাক tree-level যুক্তি দিয়ে:

```
level 0:       [................n................]   মোট কাজ: n
level 1:       [......n/2......] [......n/2......]   মোট কাজ: n/2 + n/2 = n
level 2:       [..n/4..] [..n/4..] [..n/4..] [..n/4..]   মোট কাজ: 4 * n/4 = n
...
level log2(n):  n-টা এক-element টুকরো               মোট কাজ: n * 1 = n
```

- **প্রতি level-এ মোট কাজ ঠিক n**। নিচে যাওয়ার সাথে merge-গুলো ছোট হয়, কিন্তু সংখ্যায় বেড়ে ক্ষতিপূরণ দেয়।
- **Level কতটা?** প্রতি ধাপে অর্ধেক: n, n/2, n/4, ..., 1। 1-এ পৌঁছাতে log2(n)-টা ধাপ লাগে।
- মোট = level-এর সংখ্যা × প্রতি level-এ কাজ = **O(n log n)**। n = 10⁶ হলে মাত্র ~20-টা level, মানে ~2 × 10⁷-টা কাজ; [Brute Force](./brute-force.mdx)-ধাঁচের O(n²) হলে 10¹²-টা লাগত, প্রায় পাঁচ হাজার গুণ বেশি।

Binary search-এ recurrence আরও চিকন: **T(n) = T(n/2) + O(1)**। এক পাশ পুরো ফেলে দেওয়া হয়, তাই প্রশ্ন একটাই: কতবার অর্ধেক করা যায়? log2(n) বার, অর্থাৎ **O(log n)**। 10⁹-টা element থেকেও ~30-টা তুলনায় উত্তর।

**Space**: merge sort-এ O(n) (temp array, আর recursion depth log n)। Recursive binary search O(log n) call stack, iterative version O(1)। D&C-এ space-এর বিল বেশিরভাগ সময় Combine-এর জন্য লাগা temporary জায়গা থেকে আসে।

## সাধারণ ভুল আর edge case

**১. Base case ভুলে যাওয়া বা ভুল base case লেখা**
`low > high` না দেখা, বা merge sort-এ length চেক না করা = ভাগ করা থামে না, "Maximum call stack size exceeded"। যে recursion-ই লেখো, প্রথম line-টাই থামার শর্ত হোক।

**২. Boundary-তে ±1 গুলিয়ে infinite recursion**
Binary search-এ যেখানে `mid - 1` দরকার সেখানে `mid` লিখলে অঞ্চলটা কোনোদিন ছোট হয় না: দুটো element নিয়ে চিরকাল ঘুরতে থাকবে। নিয়ম: mid যদি এই ধাপে চেক হয়ে যায়, পরের অঞ্চল থেকে ওকে বাদ দাও।

**৩. Merge-এর leftover ভুলে যাওয়া**
প্রথম while শেষে প্রায় সবসময় এক পাশে element পড়ে থাকে। শেষের দুটো copy-loop না লিখলে answer-এ element কম পড়বে, আর bug-টা ছোট input-এ ধরাও পড়বে না। leftover নিজে থেকে আসে না, তোমাকে তুলে দিতে হয়।

**৪. D&C আর Dynamic Programming গুলিয়ে ফেলা**
Fibonacci-কে D&C ভেবে ভাগ করলে একই সাব-সমস্যা শতবার solve হবে (overlap!), কিন্তু D&C চায় স্বাধীন সাব-সমস্যা। Overlap দেখলেই থামো: সেটা [Dynamic Programming](./dynamic-programming.mdx)-এর জমি।

**৫. Precondition ভুলে যাওয়া**
Binary search unsorted array-তে চালালে ভাগ করাটাই ভুল দিকে যাবে, কারণ এর পুরো যুক্তিই দাঁড়িয়ে আছে "ডান পাশে সব বড়" ধারণার উপর। D&C algorithm-এর প্রতিটারই এমন precondition আছে; input সত্যিই sorted কি না আগে নিশ্চিত হও, না হলে আগে sort করো।

## সারসংক্ষেপ

- D&C = ভাগ করো, জয় করো, মিলাও; সাব-সমস্যা যথেষ্ট ছোট হলে base case, না হলে recursion
- Merge sort-এ কাজ Combine-এ, quicksort-এ কাজ Divide-এ, binary search-এ Combine বলে কিছু নেই
- T(n) = 2T(n/2) + O(n) মানে প্রতি level-এ n কাজ, log n-টা level, মোট O(n log n); T(n) = T(n/2) + O(1) মানে O(log n)
- Precondition মানা জরুরি: binary search চায় sorted input, প্রতিটা recursion চায় সঠিক base case
- সাব-সমস্যায় overlap দেখলেই থামো: সেটা D&C না, Dynamic Programming-এর জমি
- FFT দেখালো D&C-এর শিখর: জোড়-বিজোড় ভাগে polynomial গুণন O(n²) থেকে O(n log n) - অডিও-সিগন্যাল প্রসেসিংয়ের প্রাণ
