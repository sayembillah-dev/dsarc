## কী শিখব

- subsequence আর substring-এর পার্থক্য - ক্রম ঠিক থাকতে হবে, টানা হওয়া জরুরি নয়
- brute force কেন n = ৩০ পেরোতেই অচল
- DP স্টেট: dp[i][j] = s1-এর প্রথম i অক্ষর বনাম s2-এর প্রথম j অক্ষরের LCS-দৈর্ঘ্য
- দুই-কেসের recurrence: মিললে diagonal + 1, না মিললে max(উপরে, বাঁয়ে)
- শুধু দৈর্ঘ্য নয়, আসল subsequence-টা বের করা: টেবিলে উল্টো হাঁটা
- কোথায় কাজে লাগে: git diff, DNA তুলনা, plagiarism check

## ধারণা

তুমি একটা প্রতিবেদন লিখে বসকে পাঠিয়েছিলে। বস কিছু লাইন কেটেছেন, কিছু বদলেছেন, নতুন কয়েকটা লাইন যোগ করেছেন। এখন প্রশ্ন: মূল আর সংশোধিত - দুই ভার্সনের মধ্যে **কোন অংশগুলো হুবহু একই ক্রমে টিকে আছে**, সেই সবচেয়ে লম্বা ধারাটা কোনটা? Git ঠিক এই প্রশ্নের উত্তরেই diff দেখায়, আর জীববিজ্ঞানীরা প্রায় একই প্রশ্নে দুই DNA স্ট্র্যান্ড তুলনা করেন।

ব্যাপারটা formal করি। **Subsequence** মানে মূল স্ট্রিং থেকে কিছু অক্ষর (শূন্য বা ততোধিক) বাদ দেওয়া, কিন্তু **বাকিগুলোর ক্রম না বদলানো**। "abcdaf" থেকে "abcf" একটা subsequence - "da" বাদ দিলেই পাওয়া যায়। টানা হওয়া জরুরি নয়; টানা চাইলে সেটা substring হতো, সম্পূর্ণ আলাদা সমস্যা। আর **common subsequence** মানে যেটা দুই স্ট্রিং-এরই subsequence। আমাদের লক্ষ্য সেগুলোর মধ্যে **সবচেয়ে লম্বাটা** - Longest Common Subsequence, সংক্ষেপে LCS।

সোজা উপায়: দুই স্ট্রিং-এর সব subsequence বানিয়ে মেলাও। কিন্তু প্রতি অক্ষরে "নাও/বাদ" দুটো পছন্দ, তাই n অক্ষরে ২^n টা subsequence - n মাত্র ৩০ হলেই ১০০ কোটির বেশি। [Backtracking](./backtracking.mdx) দিয়ে বানানো যায় ঠিকই, কিন্তু বাস্তবে অচল। ভাগ্যিস overlap আছে: "s1-এর প্রথম ৩ অক্ষর বনাম s2-এর প্রথম ২ অক্ষর" - এই subproblem-এ বারবার ফিরে আসি। Overlap মানেই আবার [Dynamic Programming](./dynamic-programming.mdx)।

## ধাপে ধাপে dry run

উদাহরণ: s1 = "abcdaf", s2 = "acbcf"।

স্টেট: **dp[i][j] = s1-এর প্রথম i টা অক্ষর আর s2-এর প্রথম j টা অক্ষরের LCS-এর দৈর্ঘ্য।** প্রতি ঘরে দুই কেস:

- **মিললে** (s1-এর i-তম অক্ষর = s2-এর j-তম অক্ষর): এই অক্ষরটা LCS-এ ঢুকলো → dp[i][j] = dp[i-1][j-1] + 1
- **মিলল না**: হয় s1-এর এই অক্ষরটা বাদ, নয় s2-এরটা → dp[i][j] = max(dp[i-1][j], dp[i][j-1])

Base: যেকোনো একটার দৈর্ঘ্য 0 হলে common কিছুই নেই - শূন্যম সারি আর কলাম 0 (ε = খালি prefix)।

| s1 \ s2 | ε | a | c | b | c | f |
|---------|---|---|---|---|---|---|
| **ε** | 0 | 0 | 0 | 0 | 0 | 0 |
| **a** | 0 | 1 | 1 | 1 | 1 | 1 |
| **b** | 0 | 1 | 1 | 2 | 2 | 2 |
| **c** | 0 | 1 | 2 | 2 | 3 | 3 |
| **d** | 0 | 1 | 2 | 2 | 3 | 3 |
| **a** | 0 | 1 | 2 | 2 | 3 | 3 |
| **f** | 0 | 1 | 2 | 2 | 3 | **4** |

কয়েকটা ঘর হাতে গুণি:

- dp[3][4] (s1-এর "abc" বনাম s2-এর "acbc"): শেষ অক্ষর c = c মিলেছে → dp[2][3] + 1 = 2 + 1 = **3** ("abc"... আসলে "abc" ও "acbc"-এর LCS "abc")।
- dp[4][4] ("abcd" বনাম "acbc"): d আর c মেলেনি → max(উপরে dp[3][4] = 3, বাঁয়ে dp[4][3] = 2) = **3**।
- dp[6][5] (পুরো দুটো): শেষে f = f মিলেছে → dp[5][4] + 1 = 3 + 1 = **4**।

দৈর্ঘ্য 4। এবার subsequence-টা কোনটা? টেবিলের ডান-নিচ থেকে **উল্টো হাঁটো**: অক্ষর মিললে সেটা উত্তরে ঢুকিয়ে diagonal-এ যাও; না মিললে যেদিকের ঘর বড় (সমান হলে যেকোনো দিক), সেদিকে সরো। আমাদের পথ: (6,5)-এ f মিললো → diagonal; (5,4)-এ a বনাম c, উপরে 3 বড় → উপরে; (4,4)-এ d বনাম c, উপরে বড় → উপরে; (3,4)-এ c মিললো → diagonal; (2,3)-এ b মিললো → diagonal; (1,2)-তে বাঁয়ে 1 বড় → বাঁয়ে; (1,1)-এ a মিললো → diagonal, থাম। পেছন থেকে জমেছে f, c, b, a - উল্টে দাও: **"abcf"**।

## কোড

```js
// শুধু দৈর্ঘ্য
function lcsLength(s1, s2) {
  const m = s1.length, n = s2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (s1[i - 1] === s2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;      // মিললে diagonal + 1
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]); // না মিললে বড় পাশ
      }
    }
  }
  return dp[m][n];
}

// দৈর্ঘ্য + আসল subsequence: টেবিল ভরে উল্টো হাঁটা
function lcs(s1, s2) {
  const m = s1.length, n = s2.length;
  const dp = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0));
  for (let i = 1; i <= m; i++)
    for (let j = 1; j <= n; j++)
      dp[i][j] = s1[i - 1] === s2[j - 1]
        ? dp[i - 1][j - 1] + 1
        : Math.max(dp[i - 1][j], dp[i][j - 1]);
  let i = m, j = n;
  const out = [];
  while (i > 0 && j > 0) {
    if (s1[i - 1] === s2[j - 1]) {
      out.push(s1[i - 1]); i--; j--;        // মিলের অক্ষর ধরে diagonal
    } else if (dp[i - 1][j] >= dp[i][j - 1]) {
      i--;                                   // উপরের ঘর বড় (বা সমান)
    } else {
      j--;                                   // বাঁয়ের ঘর বড়
    }
  }
  return out.reverse().join('');
}

console.assert(lcsLength("abcdaf", "acbcf") === 4, "dry run দৈর্ঘ্য");
console.assert(lcs("abcdaf", "acbcf") === "abcf", "dry run স্ট্রিং");
console.assert(lcsLength("HELLOM", "HMLD") === 2, "HL বা HM");
console.assert(lcs("AGGTAB", "GXTXAYB") === "GTAB", "classic");
console.assert(lcs("ABC", "AC") === "AC", "ছোট");
console.assert(lcsLength("", "ABC") === 0, "একটা খালি");
console.assert(lcs("abc", "def") === "", "কোনো মিল নেই");
console.log("সব assert পাস!");
```

## কোড ব্রেকডাউন, লাইনে লাইনে

**lcsLength:**

- `Array.from({ length: m + 1 }, () => new Array(n + 1).fill(0))` - (m+1) × (n+1) টেবিল, শূন্যম সারি-কলামই base case (খালি prefix বনাম যেকোনো prefix, LCS = 0)। আগের পাতার মতোই: ভেতরের array আলাদা আলাদা বানাতে হবে, একটাই array fill করলে সব সারি একই রেফারেন্স ধরবে।
- loop 1 থেকে - 0 নম্বর সারি-কলাম তো base-এ ভরাই আছে।
- `s1[i - 1] === s2[j - 1]` - টেবিলের i মানে **দৈর্ঘ্য**, স্ট্রিং-এর ইনডেক্স তার এক কম। এই সরণটা ভুললে পুরো টেবিল এক ঘর এদিক-সেদিক হয়ে যায়।
- মিললে `dp[i-1][j-1] + 1` - এই অক্ষরটা common, তার আগের সেরার সাথে 1 যোগ। না মিললে দুই পাশের বড়টা - মানে এই দুই অক্ষর একসাথে LCS-এ নেই, যেকোনো একটা বাদ দাও।

**lcs (উল্টো হাঁটা):**

- প্রথম অংশ হুবহু একই টেবিল - শুধু এবার টেবিলটা রেখে দিই, কারণ পথ খুঁজতে লাগবে।
- `while (i > 0 && j > 0)` - কোনো একটা স্ট্রিং শেষ হলে common অক্ষর আর নেই, থাম।
- মিললে অক্ষরটা `out`-এ ঢুকিয়ে দুই দিকেই এক ঘর পিছাই - এই অক্ষর "খরচ" হয়ে গেল।
- না মিললে `dp[i-1][j] >= dp[i][j-1]` দেখে বড় দিকে সরি - মান সেখান থেকেই এসেছিল। সমান হলে উপরে যাই; বাঁয়ে গেলেও সম-দৈর্ঘ্যের আরেকটা বৈধ উত্তর পেতাম।
- শেষে `reverse()` - পেছন থেকে এগিয়েছি, উল্টে না দিলে উত্তর উল্টো থাকবে।

## ভ্যারিয়েন্ট

- **শুধু দৈর্ঘ্য লাগলে space O(n):** i-তম সারি শুধু (i-1)-তম সারি দেখে - পুরো টেবিল নয়, দুইটা array ঘুরিয়ে ফিরিয়ে ব্যবহার করলেই চলে। (অনুশীলনে দিচ্ছি।)
- **স্ট্রিং নয়, array:** int বা object-এর array-তেও একই কোড - তুলনাটা ঠিকমতো লিখলেই (=== বা key ধরে) সব চলে।
- **LIS-এর সাথে সম্পর্ক:** একটা sequence (সব উপাদান distinct) আর তার sorted অনুলিপির LCS-ই হলো সেই sequence-এর Longest Increasing Subsequence। পরের পাতায় LIS-এর সরাসরি 1D DP দেখবে।
- **বাস্তবের diff টুল:** git আসলে Myers algorithm ব্যবহার করে, আরও অপ্টিমাইজড - কিন্তু ভিত্তির ধারণা এই LCS-ই।

## Complexity

| বাস্তবায়ন | Time | Space |
|------------|------|-------|
| Brute force (সব subsequence মেলানো) | O(2^m · n) এর আশেপাশে | O(m) stack |
| DP টেবিল (দৈর্ঘ্য + reconstruction) | O(m·n) | O(m·n) |
| শুধু দৈর্ঘ্য, দুই সারি | O(m·n) | O(n) |

m আর n দুই স্ট্রিং-এর দৈর্ঘ্য। মনে রাখো: LCS-এর সমস্যাটা knapsack-এর মতো pseudo-polynomial নয় - এখানে টেবিলের মাপ সরাসরি ইনপুট সাইজের উপর, তাই O(m·n) একদম প্রactical। হ্যাঁ, reconstruction চাইলে পুরো টেবিল রাখতেই হবে; শুধু সংখ্যাটা চাইলে দুই সারিই যথেষ্ট।

## সাধারণ ভুল আর edge case

**১. subsequence-কে substring ভাবা।**
"abc" আর "acb"-এ common subsequence "ab"/"ac" (দৈর্ঘ্য 2), অথচ substring ধরলে শুধু "a" পেতে। টানা হওয়ার দরকার নেই, ক্রমই সব - এই পার্থক্যটাই পুরো সমস্যার প্রাণ।

**২. মিলের ঘরে max(উপরে, বাঁয়ে) নেওয়া।**
অক্ষর মিললে নিয়ম একটাই: diagonal + 1। পাশের ঘর দেখলেই ভুল - মিলের অক্ষরটা তোমার হাত থেকে চলে যায়, টেবিল আর LCS-এর সংজ্ঞা মিলবে না।

**৩. s1[i] বনাম s1[i-1] গুলানো।**
টেবিলের সারি-কলাম 1 থেকে গোনা হয় (0 = খালি prefix), স্ট্রিং-এর ইনডেক্স 0 থেকে। প্রতিবার তুলনায় i-1 লেখা ভুলে গেলে প্রথম অক্ষরই পরীক্ষাই হলো না।

**৪. উল্টো হাঁটার পর reverse ভুলে যাওয়া।**
উত্তর পেছন থেকে জমায় - "fcba" ফেরত দিলে অভিযোগ করবেনা কেউ, টেস্ট চুপচাপ ফেল করবে। join-এর আগে reverse বাধ্যতামূলক।

**৫. খালি স্ট্রিং edge case।**
একটা স্ট্রিং খালি হলে উত্তর 0 বা "" - base সারি-কলাম 0 দিয়ে শুরু করলে এটা ফ্রি-তে সামলানো। কিন্তু loop 0 থেকে শুরু করলে negative ইনডেক্সে ঢুকে যাবে।

## অনুশীলন

- **সহজ ১:** হাতে টেবিল ভরো: s1 = "ABBA", s2 = "BABA"। দৈর্ঘ্য আসবে 3 - আর দেখো, "ABA" আর "BBA" দুটোই বৈধ উত্তর। তোমার উল্টো-হাঁটার নিয়ম কোনটা দিচ্ছে?
- **সহজ ২:** lcsLength-কে দুই সারির array দিয়ে লেখো (space O(n))। হিন্ট: prev আর curr নামে দুইটা array রাখো, প্রতি i-তে অদলবদল করো।
- **মাঝারি ১:** Longest Common Subsequence (LeetCode 1143) - এই পাতার কোডই সরাসরি চলবে; নিজে লিখে submit করো।
- **মাঝারি ২:** Delete Operation for Two Strings (LeetCode 583)। হিন্ট: LCS ছাড়া বাকি সব অক্ষর দুই পাশ থেকে বাদ - উত্তর m + n - 2 × LCS।
- **কঠিন:** Shortest Common Supersequence (LeetCode 1092)। হিন্ট: দৈর্ঘ্য হবে m + n - LCS; আর স্ট্রিং-টা বানাতে উল্টো হাঁটার সময় না-মিলা অক্ষরগুলোও যথাক্রমে ঢুকাতে হবে।

## সারসংক্ষেপ

- Subsequence মানে ক্রম ঠিক রেখে বাদ দেওয়া - টানা হওয়া জরুরি নয়; LCS দুই স্ট্রিং-এর সবচেয়ে লম্বা common subsequence।
- Brute force ২^n; DP-তে dp[i][j], দুই কেস - মিললে diagonal + 1, না মিললে max(উপরে, বাঁয়ে); O(m·n)।
- আসল subsequence চাইলে ডান-নিচ থেকে উল্টো হাঁটো, শেষে reverse; একাধিক সম-দৈর্ঘ্যের উত্তর থাকতে পারে।
- git diff, DNA alignment - সব LCS-এরই রূপ; জায়গা কমাতে চাইলে দৈর্ঘ্যের জন্য দুই সারিই যথেষ্ট।
- এক স্ট্রিং-এর ভেতরে আরেকটা **হুবহু** আছে কি না জানতে [KMP](../searching/string-matching.mdx); আর দুটোর মিল **কতটুকু** মাপতে এই LCS।
- টেবিল-ভিত্তিক DP-র আরেক classic দেখো: [0/1 Knapsack](./knapsack.mdx) - স্টেট-চিন্তা হুবহু এই পাতার মতো।
- একই "ক্রম ঠিক" চিন্তার এক-স্ট্রিং সংস্করণ: [LIS](./lis.mdx) - sorted অনুলিপির সাথে LCS করলেও ওটা পাওয়া যায়।
- মিল নয়, **পার্থক্য** মাপতে [Edit Distance](./edit-distance.mdx) - replace নিষিদ্ধ করলে এই পাতার LCS-ই যথেষ্ট (m + n - 2 × LCS)।
