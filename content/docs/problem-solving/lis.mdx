## কী শিখব

- LIS সমস্যাটা কী: ক্রম ঠিক থাকবে, টানা হওয়া জরুরি নয়, প্রতিটা উপাদান আগেরটার চেয়ে বড়
- 1D DP স্টেট: dp[i] = i-তে শেষ হওয়া LIS-এর দৈর্ঘ্য; উত্তর max(dp), dp-এর শেষ ঘর নয়
- O(n²) থেকে O(n log n): tails array + binary search, যার আদি নাম patience sorting
- বিখ্যাত ফাঁদ: tails-এর **দৈর্ঘ্য** ঠিক, কিন্তু **contents** আসল LIS নয়
- LCS-এর সাথে সম্পর্ক: sorted অনুলিপির সাথে LCS করলেই LIS

## ধারণা

বার্ষিক ক্রীড়া দিবসের মার্চ পাস্ট। শিক্ষার্থীরা সারিবদ্ধ, কিন্তু মঞ্চ থেকে দেখতে যেন উচ্চতা ধীরে ধীরে বাড়তে থাকে - তাহলে দারুণ লাগবে। নিয়ম কড়া: **কারো জায়গা বদলানো যাবে না**, শুধু কাউকে কাউকে সারি থেকে সরিয়ে দেওয়া যায়। সর্বোচ্চ কতজনকে রাখা যায়?

উচ্চতার তালিকা ধরো: [7, 3, 8, 4, 2, 6]। সরাতে না পারলেও বাদ দিতে পারলে 3, 4, 6 রাখা যায় - বাড়তি, ৩ জন। চারজন সম্ভব? যেমন খুঁজো, পারবে না। এই "ক্রম ঠিক রেখে বাদ দিয়ে সবচেয়ে লম্বা বাড়তি ধারা"-টাই **Longest Increasing Subsequence**। শুধু মার্চ পাস্ট নয় - স্টকের দামের বিশ্লেষণ, Git-এর diff অপ্টিমাইজেশন, সবখানে এই সমস্যা।

সব subsequence গুনে ফেলা? আবার সেই ২^n। কিন্তু লক্ষ করো: "৬ দিয়ে শেষ হওয়া সেরা বাড়তি ধারা" কত? উত্তরটা নির্ভর করে শুধু আগের ছোট সংখ্যাগুলোর সেরার ওপর - overlap স্পষ্ট, অর্থাৎ [Dynamic Programming](./dynamic-programming.mdx)।

## ধাপে ধাপে dry run

স্টেট: **dp[i] = arr[i] দিয়ে শেষ হওয়া LIS-এর দৈর্ঘ্য।** (গুরুত্বপূর্ণ: "i পর্যন্ত অংশের LIS" নয় - "i-তে শেষ হওয়া"।)

Recurrence: dp[i] = 1 + max( dp[j] : j আগে এবং arr[j] ছোট arr[i]-এর চেয়ে ); কেউ না থাকলে 1।

| i | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| arr[i] | 7 | 3 | 8 | 4 | 2 | 6 |
| dp[i] | 1 | 1 | 2 | 2 | 1 | **3** |

ঘরে ঘরে:

- dp[0] = 1 - একক উপাদান নিজেই দৈর্ঘ্য-১ ধারা।
- dp[1]: আগে শুধু 7, আর 7 বড় 3-এর চেয়ে - কেউ বসতে পারে না → 1।
- dp[2]: 7 আর 3 দুটোই 8-এর ছোট, সেরা max(1, 1) + 1 → 2।
- dp[3]: ছোট শুধু 3 → dp[1] + 1 → 2।
- dp[4]: 2-এর চেয়ে ছোট কেউ নেই আগে → 1।
- dp[5]: ছোট আছে 3 (dp 1), 4 (dp 2) - সেরা 2 + 1 → **3**।

উত্তর max(dp) = 3। খেয়াল করো, সেরাটা এবার শেষ ঘরে এসেছে ঠিকই, কিন্তু ওটা কাকতাল - ধরো [1, 2, 5, 3]: LIS শেষ হয় 5-এ, শেষ ঘরে নয়। তাই ফেরত করতে হবে পুরো dp-এর সর্বোচ্চ।

## কোড

```js
// পদ্ধতি ১: O(n²) DP - dry run-এর হুবহু অনুবাদ
function lisLength(arr) {
  if (arr.length === 0) return 0;
  const dp = new Array(arr.length).fill(1); // প্রত্যেকে নিজে দৈর্ঘ্য-১
  let best = 1;
  for (let i = 1; i < arr.length; i++) {
    for (let j = 0; j < i; j++) {
      if (arr[j] < arr[i] && dp[j] + 1 > dp[i]) {
        dp[i] = dp[j] + 1;
      }
    }
    if (dp[i] > best) best = dp[i];
  }
  return best;
}

// পদ্ধতি ২: O(n log n) - tails + binary search (patience sorting)
function lisLengthFast(arr) {
  const tails = []; // tails[k] = দৈর্ঘ্য k+1-এর বাড়তি ধারার সম্ভাব্য সবচেয়ে ছোট শেষ-মান
  for (const x of arr) {
    let lo = 0, hi = tails.length; // x বসবে প্রথম যে ঘরে tails[ঘর] >= x
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1; else hi = mid;
    }
    tails[lo] = x; // কমিটি... না, শুধু শেষ-মান ছোট করে দিই (বা নতুন ধারা বাড়াই)
  }
  return tails.length;
}

console.assert(lisLength([7, 3, 8, 4, 2, 6]) === 3, "dry run");
console.assert(lisLengthFast([7, 3, 8, 4, 2, 6]) === 3, "dry run fast");
console.assert(lisLength([10, 9, 2, 5, 3, 7, 101, 18]) === 4, "LC 300");
console.assert(lisLengthFast([10, 9, 2, 5, 3, 7, 101, 18]) === 4, "LC 300 fast");
console.assert(lisLength([5, 4, 3, 2, 1]) === 1, "সব কমতি");
console.assert(lisLengthFast([1, 2, 3, 4]) === 4, "সব বাড়তি");
console.assert(lisLength([3, 3, 3]) === 1, "strictly increasing - সমান বাড়ায় না");
console.assert(lisLength([]) === 0, "খালি");
console.assert(lisLengthFast([2, 7, 1]) === 2, "tails ফাঁদের উদাহরণ");
console.log("সব assert পাস!");
```

## কোড ব্রেকডাউন, লাইনে লাইনে

**lisLength (O(n²)):**

- `fill(1)` - প্রতিটা উপাদান নিজেই দৈর্ঘ্য-১-এর বাড়তি ধারা; base case ফ্রি-তে।
- ভেতরের loop-এ আগের সব j পরীক্ষা: arr[j] ছোট arr[i]-এর চেয়ে হলেই কেবল j-এর ধারার ওপর i বসতে পারে।
- `dp[j] + 1 > dp[i]` - সেরা প্রার্থী রাখি। শুধু `arr[j] < arr[i]` দেখে যেকোনো j বসিয়ে দিলে ছোটটার দিকে ফিরে যাওয়ার ভুল হয়।
- `best` আলাদা ট্র্যাক করা - কারণ উত্তর dp-এর যেকোনো ঘরে থাকতে পারে, শেষ ঘরে নয়।

**lisLengthFast (O(n log n)) - কেন কাজ করে:**

- `tails[k]` মানে: দৈর্ঘ্য k+1-এর যেকোনো বাড়তি ধারার **সম্ভাব্য সবচেয়ে ছোট শেষ-মান**। শেষ-মান যত ছোট, ভবিষ্যতে বড় সংখ্যা বসানো তত সহজ - তাই সেরা আশা ছাড়া ছোটটা রাখি।
- নতুন x এলে সে হয় সবচেয়ে বড় tail-কেও ছাড়িয়ে যায় (নতুন দৈর্ঘ্য যোগ), নয় কোনো tail-কে ছোট করে replace করে (আরও আশাপ্রদ ভবিষ্যৎ)।
- tails সবসময় sorted থাকে - এই invariant-এর জোরেই binary search চলে। যে প্রথম ঘরে tails[ঘর] ≥ x, সেখানেই x বসে: এটাই lower_bound, যেমনটা [Binary Search Variants](../searching/binary-search-variants.mdx) পাতায় ছিল।
- [7, 3, 8, 4, 2, 6] দিয়ে চালাও: 7 → [7], 3 → [3] (7 ছোট হলো), 8 → [3, 8], 4 → [3, 4], 2 → [2, 4], 6 → [2, 4, 6]। দৈর্ঘ্য 3 - ঠিক আছে!

## ভ্যারিয়েন্ট

- **আসল subsequence-টা চাইলে:** O(n²) সংস্করণে প্রতি i-এর জন্য parent[j] মনে রাখো (কোন j থেকে এলাম), শেষে max-ঘর থেকে উল্টো হাঁটো - LCS-এর মতোই। (অনুশীলনে।)
- **Non-decreasing (সমান চলবে):** `arr[j] <= arr[i]`, আর fast-এ binary search-টা upper_bound-এ বদলে দাও - এক চিহ্নের পার্থক্য।
- **Longest Decreasing:** চিহ্ন উল্টে দাও, অথবা প্রতিটা সংখ্যা negate করে LIS চালাও।
- **LCS দিয়ে LIS:** সব উপাদান distinct হলে, মূল array আর তার sorted অনুলিপির [LCS](./lcs.mdx)-ই হলো LIS। ধারণা হিসেবে সুন্দর, কিন্তু O(n²) - তাই বাস্তবে এই পাতার পদ্ধতিই।
- **Patience sorting:** fast পদ্ধতিটা আসলে তাসের খেলা - সংখ্যা এলে বাঁদিকের প্রথম স্তূপে (যার ওপরের তাস ≥ এটা) বসাও। মোট স্তূপ সংখ্যাই LIS-এর দৈর্ঘ্য।

## Complexity

| বাস্তবায়ন | Time | Space |
|------------|------|-------|
| Brute force (সব subsequence) | O(2^n) | O(n) stack |
| 1D DP | O(n²) | O(n) |
| tails + binary search | O(n log n) | O(n) |

n = ১০^৫ পেরোলে O(n²) আর চলে না, তখন fast পদ্ধতিই একমাত্র পথ। Interview-তে আগে DP দেখাও (বোঝা সহজ), তারপর fast-এ উন্নীত করো - দুটোই জানা আছে, এটাই দেখাতে চায়।

## সাধারণ ভুল আর edge case

**১. subsequence-কে subarray ভাবা।**
LIS-এ টানা হওয়া জরুরি নয় - [7, 3, 8, 4, 2, 6]-এর 3, 4, 6 টানা নয়, তবু বৈধ। টানা চাইলে সেটা আলাদা (ও আরও সহজ) সমস্যা।

**২. dp-এর শেষ ঘর ফেরত করা।**
dp[i] সংজ্ঞা "i-তে শেষ হওয়া" - LIS যেকোনো ইনডেক্সে শেষ হতে পারে। [1, 2, 5, 3] চালিয়ে দেখো: উত্তর 3, কিন্তু dp[3] = 2। max(dp) নিতেই হবে।

**৩. Strictly বনাম non-decreasing গুলানো।**
`arr[j] < arr[i]` মানে সমান সংখ্যা ধারা বাড়ায় না: [3, 3, 3] → 1। সমানও চললে (LC-তে "non-decreasing" লেখা থাকলে) চিহ্নটা বদলাও, fast-এ lower_bound-এর বদলে upper_bound।

**৪. tails-এর contents-কেই LIS ভাবা।**
[2, 7, 1] চালাও: tails শেষে [1, 7] - কিন্তু array-তে 7 আছে 1-এর **আগে**, অর্থাৎ [1, 7] আসলে subsequence-ই নয়! দৈর্ঘ্য 2 একদম ঠিক, contents ভুয়া। আসল LIS চাইলে parent-pointer রাস্তাই যাও।

**৫. খালি array ও এক-উপাদানের edge।**
খালি array-তে উত্তর 0 - `fill(1)`-এর পর loop-ই চলবে না, কিন্তু `best = 1` আগে থেকে ধরলে ভুল 1 বেরোবে; তাই শুরুতেই খালি-চেক। এক উপাদানে উত্তর 1।

## অনুশীলন

- **সহজ ১:** হাতে dp ভরো: [2, 7, 4, 8]। উত্তর মিলাও: dp = [1, 2, 2, 3], সর্বোচ্চ 3 (2, 4, 8 অথবা 2, 7, 8)।
- **সহজ ২:** O(n²) কোডে parent array যোগ করে আসল LIS-টা ফেরত দাও। হিন্ট: প্রতিবার dp[i] আপডেট হলে parent[i] = j; শেষে max-এর ইনডেক্স থেকে পেছনে হাঁটো, তারপর reverse।
- **মাঝারি ১:** Longest Increasing Subsequence (LeetCode 300) - আগে DP দিয়ে submit, তারপর fast দিয়ে।
- **মাঝারি ২:** Number of Longest Increasing Subsequence (LeetCode 673)। হিন্ট: dp-এর পাশে count array রাখো; সমান সেরা পেলে count যোগ হয়, বড় পেলে count নতুনটার সমান।
- **কঠিন:** Russian Doll Envelopes (LeetCode 354)। হিন্ট: width-এ ascending, টাই হলে height-এ **descending** sort করো; তারপর height-গুলোয় সোজা LIS - descending-এর কারণ বুঝতে পারলে বুঝে গেলে।

## সারসংক্ষেপ

- LIS: ক্রম ঠিক রেখে বাদ দিয়ে সবচেয়ে লম্বা বাড়তি ধারা; টানা হওয়ার দরকার নেই।
- dp[i] = "i-তে শেষ হওয়া" ধারার দৈর্ঘ্য; উত্তর max(dp) - O(n²)।
- tails + binary search-এ O(n log n): tails[k] = দৈর্ঘ্য k+1 ধারার সবচেয়ে ছোট শেষ-মান, সবসময় sorted।
- tails-এর দৈর্ঘ্য ঠিক, contents নয় - আসল subsequence চাইলে parent pointer।
- একই টেবিল-চিন্তার আত্মীয়: দুই স্ট্রিং-এর মিল মাপা [LCS](./lcs.mdx) - sorted অনুলিপির সাথে LCS করলেও LIS-ই পাওয়া যায়।
- ভেতরের binary search-টা হুবহু lower_bound - ঝালিয়ে নাও [Binary Search Variants](../searching/binary-search-variants.mdx) পাতায়।
