## কী শিখব

- Prefix sum কী: একবার O(n) খরচ করে এমন একটা array বানিয়ে রাখা যাতে যেকোনো অংশের যোগফল একটা বিয়োগেই বের হয়
- কেন rangeSum(l, r) = pref[r+1] - pref[l], হাতে হাতে পুরো dry run
- Prefix sum আর hashmap জুড়ে subarray sum equals k কীভাবে O(n)-এ হয়
- তিনটা ভ্যারিয়েন্ট: running sum, 2D prefix sum, product except self
- কখন prefix sum ব্যর্থ হয়: array বদলে গেলে, আর তখন কোথায় যেতে হয়

## ধারণা

ভাবো তো, তোমার দোকানের খাতায় প্রতিদিনের বিক্রি লেখা: প্রথম দিন ২শো, দ্বিতীয় দিন ৪শো, তৃতীয় দিন ১শো, এভাবে চলছে। এখন কেউ জিজ্ঞেস করল, "তৃতীয় থেকে সপ্তম দিন পর্যন্ত মোট কত বিক্রি হলো?" তুমি কি প্রতিবার খাতা উল্টে সেই পাঁচটা সংখ্যা যোগ করবে? আজ যোগলে, কাল আবার যোগলে, পরশু আবার?

নাকি খাতার পাশে আগে থেকেই একটা কলাম লিখে রাখবে: "প্রথম দিন থেকে এ পর্যন্ত মোট"? তাহলে উত্তর বের করা একটা বিয়োগের ব্যাপার: সপ্তম দিন পর্যন্তের মোট থেকে দ্বিতীয় দিন পর্যন্তের মোট বাদ দাও, থাকে তৃতীয় থেকে সপ্তম। প্রশ্ন যতবারই আসুক, প্রতিবার একটাই বিয়োগ।

এই কলামটাই **prefix sum**। নিয়মটা এক লাইনের:

pref[i] = প্রথম i-টা element-এর যোগফল

Array-টা যদি n-ঘরের হয়, pref হবে (n+1)-ঘরের, আর pref[0] = 0 (শূন্যটা element-এর যোগফল শূন্য)। বানানো সহজ: বাম থেকে ডানে এক লুপ, প্রতি ঘরে আগের ঘরের মানের সাথে বর্তমান element যোগ।

তারপর 0-indexed array-এর l থেকে r (দুই প্রান্তসহ) পর্যন্ত যোগফল:

rangeSum(l, r) = pref[r+1] - pref[l]

কেন কাজ করে? pref[r+1] মানে শুরু থেকে r পর্যন্ত **সব**। তার ভেতরে l-এর আগের অংশটাও বসে আছে, সেটা হলো pref[l] (প্রথম l-টা element, মানে index 0 থেকে l-1)। বাদ দিলে যা থাকে, তাই l থেকে r। আর pref[0] = 0 রাখার সৌন্দর্য এখানে: l = 0 হলেও সূত্র আক্ষরে আক্ষরে কাজ করে, কোনো বিশেষ if লাগে না।

মনে রাখো, এটা "বিল্ড একবার, query অসংখ্যবার" ধরনের বিনিয়োগ। প্রশ্ন একটাই হলে লাভ নেই; প্রশ্ন হাজার হলে প্রতিটা O(1) মানে আকাশ-পাতাল পার্থক্য। এই ধারণাটা পরে [Sliding Window](./sliding-window.mdx) আর [Hash Patterns](../hash-tables/hash-patterns.mdx)-এর সাথে মিলে অনেক বড় সমস্যা ফোঁড়ে।

## ধাপে ধাপে ড্রাই রান

Array-টা ধরো: `[2, 4, 1, 3, 5]`। আগে pref array-টা বানাই, তারপর কয়েকটা query চালিয়ে দেখি।

```
index:     0    1    2    3    4
arr:       2    4    1    3    5

pref:   0    2    6    7   10   15
        ↑    ↑    ↑    ↑    ↑    ↑
      pref  pref  pref  pref  pref  pref
      [0]   [1]   [2]   [3]   [4]   [5]
```

| ধাপ | কোন ঘর | হিসাব | pref-এর মান |
|-----|---------|--------|--------------|
| 1 | pref[0] | শূন্যটা element | 0 |
| 2 | pref[1] | 0 + arr[0] = 0 + 2 | 2 |
| 3 | pref[2] | 2 + arr[1] = 2 + 4 | 6 |
| 4 | pref[3] | 6 + arr[2] = 6 + 1 | 7 |
| 5 | pref[4] | 7 + arr[3] = 7 + 3 | 10 |
| 6 | pref[5] | 10 + arr[4] = 10 + 5 | 15 |

এবার query। ধরো প্রশ্ন: index 1 থেকে 3 পর্যন্ত যোগফল? ছবিতে দেখো:

```
arr:     [2]   [4   1   3]   [5]
                ↑-------↑
               l=1     r=3

pref[r+1] = pref[4] = 10   (শুরু থেকে index 3 পর্যন্ত সব)
pref[l]   = pref[1] = 2    (l-এর আগের অংশ)
উত্তর = 10 - 2 = 8
```

আরও কয়েকটা query একই সূত্রে:

| query (l, r) | pref[r+1] | pref[l] | বিয়োগফল | সরাসরি যোগ করে যাচাই |
|--------------|-----------|---------|-----------|---------------------|
| (0, 2) | pref[3] = 7 | pref[0] = 0 | 7 | 2+4+1 = 7 |
| (1, 3) | pref[4] = 10 | pref[1] = 2 | 8 | 4+1+3 = 8 |
| (2, 4) | pref[5] = 15 | pref[2] = 6 | 9 | 1+3+5 = 9 |
| (3, 3) | pref[4] = 10 | pref[3] = 7 | 3 | 3 = 3 |
| (0, 4) | pref[5] = 15 | pref[0] = 0 | 15 | পুরোটা = 15 |

শেষের দুই সারি দেখো: একটা element-এর queryও সূত্র মানে, পুরো array-এর queryও। কোনো বিশেষ চিকিত্সা লাগেনি। pref[0] = 0 রাখার পুরো পয়সোদ্দয় এখানেই উঠে এলো।

## কোড

আগে একটা ছোট class: বিল্ড একবার, তারপর যত খুশি query। তারপর নিচে সেই বিখ্যাত সমস্যাটা: যোগফল k-এর সমান এমন subarray কয়টা (LeetCode 560)।

```js
// ---------- ১. PrefixSum class ----------

class PrefixSum {
  constructor(arr) {
    this.pref = new Array(arr.length + 1).fill(0);
    for (let i = 0; i < arr.length; i++) {
      this.pref[i + 1] = this.pref[i] + arr[i];
    }
  }

  // l থেকে r পর্যন্ত (দুই প্রান্তসহ, 0-indexed) যোগফল
  rangeSum(l, r) {
    return this.pref[r + 1] - this.pref[l];
  }
}

const ps = new PrefixSum([2, 4, 1, 3, 5]);
console.log("pref:", ps.pref);            // [0, 2, 6, 7, 10, 15]
console.log("(1,3):", ps.rangeSum(1, 3)); // 8
console.log("(0,2):", ps.rangeSum(0, 2)); // 7
console.log("(2,4):", ps.rangeSum(2, 4)); // 9
console.log("(3,3):", ps.rangeSum(3, 3)); // 3
console.log("(0,4):", ps.rangeSum(0, 4)); // 15

// ---------- ২. Subarray Sum Equals K (LeetCode 560) ----------

function subarraySum(nums, k) {
  const seen = new Map([[0, 1]]); // যোগফল 0 একবার এসেছে ধরে নিলাম
  let pref = 0;
  let count = 0;

  for (const x of nums) {
    pref += x;                     // এখান পর্যন্ত running যোগফল
    if (seen.has(pref - k)) {      // pref - k আগে এসেছিল?
      count += seen.get(pref - k); // যতবার এসেছে, ততটা subarray
    }
    seen.set(pref, (seen.get(pref) || 0) + 1);
  }
  return count;
}

console.log(subarraySum([1, 1, 1], 2));                 // 2
console.log(subarraySum([1, 2, 3], 3));                 // 2
console.log(subarraySum([3, 4, 7, 2, -3, 1, 4, 2], 7)); // 4
```

দ্বিতীয় অংশটার জাদুটা বুঝি। ধরো index i থেকে j পর্যন্ত subarray-এর যোগফল k। সূত্র বলে, pref[j+1] - pref[i] = k, মানে pref[i] = pref[j+1] - k। তাই j-এ দাঁড়িয়ে প্রশ্নটা উল্টে যায়: **এর আগে এমন কয়টা prefix আছে যাদের মান (বর্তমান pref - k)?** যতগুলো আছে, প্রতিটার পর থেকে বর্তমান জায়গা পর্যন্ত একটা করে subarray যার যোগফল k। সেই গোনাটাই map-এ জমিয়ে রাখছি।

আর `[[0, 1]]` দিয়ে শুরু কেন? সেটা না দিলে দুর্ঘটনা ঘটে। `[1, 2]`-এ k = 3 ধরো: pref চলে 1, তারপর 3। pref = 3 হলে pref - k = 0, মানে শুরু থেকে এ পর্যন্ত পুরোটাই একটা উত্তর। কিন্তু map-এ 0 নেই, তাই মিস। `[[0, 1]]` বলে দেয়, "শুরুর আগে যোগফল 0 একবার এসেছে", মানে খালি subarray-টুকু। এটা না বুঝে লিখলে উত্তর এক করে কম আসবে, আর কারণ খুঁজতে খুঁজতে চুল ছুঁটবে। নিচের ভুল-তালিকায় আবার আসছে।

## ভ্যারিয়েন্ট ১: running sum (সবচেয়ে সরল রূপ)

কেউ যদি query না করে শুধু prefix array-টাই চায়? সেটাই LeetCode 1480। এক লুপেই হয়:

```js
function runningSum(nums) {
  const out = [nums[0]];
  for (let i = 1; i < nums.length; i++) {
    out.push(out[i - 1] + nums[i]);
  }
  return out;
}

console.log(runningSum([1, 2, 3, 4])); // [1, 3, 6, 10]
```

ইনপুট array-টাকেই বদলে দিয়ে (`nums[i] += nums[i-1]`) একটু মেমরি বাঁচানো যায়, কিন্তু তাহলে আসল ডেটা হারিয়ে যায়। অন্য কোথাও মূল array লাগলে বিপদ, তাই কপিতে কাজ করা নিরাপদ।

## ভ্যারিয়েন্ট ২: 2D prefix sum (LeetCode 304-এর ভাবনা)

Matrix-এর ভেতরে যেকোনো আয়তক্ষেত্রের যোগফল? একই ধারণা, শুধু দুই মাত্রায়। p[r][c] = উপর-বাম কোণা থেকে (r, c) পর্যন্ত পুরো আয়তক্ষেত্রের যোগফল। বানানোর সময় inclusion-exclusion লাগে: উপরেরটা + বামেরটা - কোণারটা (দুইবার গোনা হয়েছে, তাই একবার ফেরত) + নিজেরটা।

```js
class MatrixSum {
  constructor(m) {
    const rows = m.length;
    const cols = m[0].length;
    this.p = Array.from({ length: rows + 1 }, () => new Array(cols + 1).fill(0));
    for (let r = 0; r < rows; r++) {
      for (let c = 0; c < cols; c++) {
        this.p[r + 1][c + 1] =
          m[r][c] + this.p[r][c + 1] + this.p[r + 1][c] - this.p[r][c];
      }
    }
  }

  // (r1, c1) থেকে (r2, c2) পর্যন্ত আয়তক্ষেত্রের যোগফল
  sumRegion(r1, c1, r2, c2) {
    return (
      this.p[r2 + 1][c2 + 1] -
      this.p[r1][c2 + 1] -
      this.p[r2 + 1][c1] +
      this.p[r1][c1]
    );
  }
}

const ms = new MatrixSum([
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
]);
console.log(ms.sumRegion(0, 0, 1, 1)); // 12 (1+2+4+5)
console.log(ms.sumRegion(1, 1, 2, 2)); // 28 (5+6+8+9)
console.log(ms.sumRegion(0, 0, 2, 2)); // 45 (পুরো matrix)
```

Query-তেও inclusion-exclusion: পুরো বড়টা - উপরের অংশ - বামের অংশ + উপর-বামের কোণা (দুইবার বাদ পড়েছে, ফেরত দাও)। 1D-এর সূত্রটাই দুই মাত্রায় ফুলে উঠেছে।

## ভ্যারিয়েন্ট ৩: product except self (ভাগ ছাড়া, LeetCode 238)

যোগের বদলে গুণ করলে ধারণাটা চেনা থাকে? প্রতিটা index-এর উত্তর = (বামের সবার গুণফল) × (ডানের সবার গুণফল)। দুই পাসেই হয়:

```js
function productExceptSelf(nums) {
  const n = nums.length;
  const ans = new Array(n).fill(1);

  let left = 1; // i-এর বামের সবার গুণফল
  for (let i = 0; i < n; i++) {
    ans[i] = left;
    left *= nums[i];
  }

  let right = 1; // i-এর ডানের সবার গুণফল
  for (let i = n - 1; i >= 0; i--) {
    ans[i] *= right;
    right *= nums[i];
  }
  return ans;
}

console.log(productExceptSelf([1, 2, 3, 4]));   // [24, 12, 8, 6]
console.log(productExceptSelf([2, 3, 0, 4]));   // [0, 0, 24, 0]
```

ভাগ দিয়ে (মোট গুণফল / নিজেরটা) করলে 0 থাকলেই বিপদ। এই পদ্ধতিতে 0-ও সমস্যা নয়। মনে রাখবে, prefix "যোগফল"-ই একমাত্র রূপ নয়: যেকোনো accumulate করা অপারেশনের ওপর এই ছাঁচ বসে।

## কোড ব্রেকডাউন

`PrefixSum` class আর `subarraySum`-এর গুরুত্বপূর্ণ লাইনগুলো:

1. `this.pref = new Array(arr.length + 1).fill(0)` : এক ঘর বাড়িয়ে নেওয়া, যাতে pref[0] = 0 জায়গা পায়। এই এক ঘরের জন্যই পরে কোনো বিশেষ if লাগে না।
2. `this.pref[i + 1] = this.pref[i] + arr[i]` : "এ পর্যন্ত মোট"-এর সংজ্ঞা কাজে লাগানো। নতুন ঘর = আগের মোট + বর্তমান element। প্রতি element একবারই ছোঁয়া হয়, তাই বিল্ড O(n)।
3. `return this.pref[r + 1] - this.pref[l]` : পুরো পাতার সার। r পর্যন্ত সব, মাইনাস l-এর আগের অংশ। দুইটা array access আর একটা বিয়োগ: O(1)।
4. `const seen = new Map([[0, 1]])` : শুরুর আগের খালি অবস্থা, যোগফল 0 একবার। শুরু থেকেই k-সমান subarray-গুলোকে ধরতে এটা বাধ্যতামূলক।
5. `pref += x` : পুরো pref array বানানোর দরকার নেই, শুধু বর্তমান running যোগফলটাই লাগে।
6. `if (seen.has(pref - k))` : প্রশ্নটা উল্টে দেওয়া: "আমার চেয়ে k কম এমন prefix আগে এসেছে কি?" এসেছে মানে সেই prefix-এর পর থেকে এ পর্যন্ত অংশের যোগফল ঠিক k।
7. `count += seen.get(pref - k)` : একই মানের prefix একাধিকবার এসে থাকতে পারে (negative সংখ্যা থাকলে বিশেষ করে), তাই ১ নয়, যতবার এসেছে তত যোগ।
8. `seen.set(pref, (seen.get(pref) || 0) + 1)` : বর্তমান pref ভবিষ্যতের index-দের জন্য গোনায় ঢুকে গেল। মনে রাখো, আগে query, তারপর নিজেকে যোগ। উল্টো করলে k = 0-এর সময় নিজে নিজের সাথে মিলে ভুয়া উত্তর বানাত।

## Complexity

হিসাবটা নিজে গুনে দেখি, মুখস্থ নয়।

**Naive পথ:** প্রতি query-তে l থেকে r পর্যন্ত লুপ চালিয়ে যোগ করা। খারাপতমে পুরো array, মানে O(n) প্রতি query। q-টা query মানে O(q × n)। সংখ্যা বসাও: n = 100000, q = 100000 হলে 10^10-টা অপারেশন।

**Prefix পথ:** বিল্ডে প্রতি element ঠিক একবার ছোঁয়া হয়, O(n)। তারপর প্রতি query দুইটা array access আর একটা বিয়োগ, O(1)। q-টা query মিলে মোট O(n + q)। একই সংখ্যায় 2 × 10^5-টা অপারেশন। আগের তুলনায় কয়েক হাজার গুণ কম।

**Space:** pref array-এর জন্য O(n)। running sum-এর মতো শুধু আউটপুট চাইলে সেটা ইনপুটের ওপরেই বানানো যায়, অতিরিক্ত O(1)।

**subarraySum:** একটাই লুপ, ভেতরে map-এর কাজগুলো গড়ে O(1), তাই মোট O(n)। Brute force করলে সব (i, j) জোড়ার যোগফল দেখতে O(n^2) লাগত, আর প্রতিবার নতুন করে যোগ করলে O(n^3) পর্যন্ত। খেয়াল করো, এখানে negative সংখ্যাও সমস্যা করে না, কারণ আমরা যোগফলের ক্রম নয়, নির্দিষ্ট মানের prefix-এর সংখ্যা গুনছি।

**2D ভ্যারিয়েন্ট:** বিল্ড O(rows × cols), query O(1), space O(rows × cols)।

## সাধারণ ভুল আর edge case

**১. Off-by-one: pref[r] - pref[l] লিখে ফেলা।**
সূত্রটা পুরোপুরি কনভেনশনের ওপর দাঁড়ানো: pref[i] = প্রথম i-টা element-এর যোগফল, তাই index i-এর element বসে pref[i+1]-এ। r পর্যন্ত নিতে চাইলে pref[r+1] লাগে, pref[r] নয়। এক ঘর এদিক-ওদিক হলেই উত্তর ভুল, আর ছোট টেস্টে ধরাও পড়ে না। নিয়ম: নিজের কনভেনশনটা মাথায় পরিষ্কার রাখো, তারপর dry run-এর টেবিলের সাথে মিলিয়ে নাও।

**২. subarraySum-এ [[0, 1]] ভুলে যাওয়া।**
উপরে দেখেছ: [1, 2] আর k = 3-তে পুরো array-টাই উত্তর, কিন্তু seed ছাড়া map-এ 0 থাকে না, তাই মিস। মনে রাখার সূত্র: "শুরুর আগে যোগফল 0 একবার এসেছে"। আরেকটা সঙ্গী ভুল: নিজেকে map-এ ঢোকানোর **আগে** query করা। উল্টো করলে k = 0 হলে প্রতিটা element নিজে নিজের সাথে মিলে ভুয়া গোনা বানায়।

**৩. Array বদলে গেলে prefix আর জলদি নয়।**
arr[2] = 99 লিখে দিলে pref[3] থেকে শুরু করে **সব** entry পুরোনো হয়ে যায়। মেরামত মানে পুরো pref আবার বানানো, O(n)। প্রতি update-এ O(n) গেলে query-সস্তা ভাবনাটাই নষ্ট। বারবার point update দরকার হলে এই কৌশল চলবে না; তখন যেতে হবে [Fenwick Tree](../advanced-structures/fenwick-tree.mdx) বা segment tree-র কাছে, যারা update আর query দুটোই O(log n)-এ করে।

**৪. ইনপুট array-টাকেই বদলে ফেলা।**
runningSum লিখতে গিয়ে nums[i] += nums[i-1] করলে ইনপুটটাই বদলে গেল। পরে মূল ডেটা লাগলে পাবে না। যতক্ষণ ডকুমেন্টে পরিষ্কার না লেখা, নতুন array-তে আউটপুট বানানো নিরাপদ।

**৫. Negative সংখ্যা দেখে sliding window-তে ঝাঁপ দেওয়া।**
"Subarray-এর যোগফল k" দেখলেই two pointer বের করা লোভ সামলাও। Sliding window কাজ করে যখন সব সংখ্যা ধনাত্মক, কারণ তখনই window বাড়ালে যোগফল নিশ্চিতভাবে বাড়ে। Negative থাকলে যোগফল ওঠানামা করে, window ভুল সিদ্ধান্ত নেয়। Prefix + hashmap এই সমস্যামুক্ত, কারণ সে ক্রমের ওপর নয়, prefix-এর মানের ওপর নির্ভর করে। পার্থক্যটা ভালো করে বুঝতে [Sliding Window](./sliding-window.mdx)-এর শর্তগুলো আবার দেখো।

## অনুশীলন

- **সহজ ১:** Range Sum Query - Immutable (LeetCode 303)। এই পাতার PrefixSum class-টাই প্রায় হুবহু উত্তর। হিন্ট: constructor-এ বিল্ড, sumRange-এ এক বিয়োগ।
- **সহজ ২:** Running Sum of 1d Array (LeetCode 1480)। হিন্ট: আউটপুটের প্রথম ঘর ইনপুটের প্রথম ঘর, তারপর প্রতি ঘরে আগের আউটপুট + বর্তমান ইনপুট।
- **মাঝারি ১:** Subarray Sum Equals K (LeetCode 560)। হিন্ট: running pref বজায় রাখো আর প্রতি ধাপে জিজ্ঞেস করো "pref - k আগে কয়বার এসেছে"; map-এ [[0, 1]] seed দিতে ভুলো না, আর নিজেকে query-র **পরে** map-এ ঢোকাও।
- **মাঝারি ২:** Product of Array Except Self (LeetCode 238)। হিন্ট: ভাগ ছাড়া। এক পাসে প্রতি ঘরে বামের গুণফল বসাও, উল্টো পাসে ডানের গুণফল দিয়ে গুণ করে দাও।
- **কঠিন:** Range Sum Query 2D - Immutable (LeetCode 304)। হিন্ট: p[r][c] বানাতে আর query-তে, দুই জায়গাতেই inclusion-exclusion: বড়টা - উপরেরটা - বামেরটা + কোণারটা। উপরের MatrixSum-কে আগে হাতে dry run করে নাও।

## সারসংক্ষেপ

- Prefix sum = "প্রথম i-টার মোট" কলাম: বিল্ড O(n), তারপর প্রতি range query O(1), মোট O(n + q)।
- সূত্র একটাই: rangeSum(l, r) = pref[r+1] - pref[l]; pref[0] = 0 রাখায় কোনো বিশেষ if লাগে না।
- Prefix + hashmap জুড়ে subarray sum equals k হয় O(n)-এ; seed [[0, 1]] আর "আগে query, পরে insert", এই দুটো ভুললেই ভুল উত্তর।
- ধারণাটা যোগের বাইরেও যায়: 2D matrix, গুণফল, সর্বত্র একই "একবার জমাও, বারবার বের করো"।
- Array বদলালে prefix বাতিল; বারবার update লাগলে পথ [Fenwick Tree](../advanced-structures/fenwick-tree.mdx)-এর দিকে।
