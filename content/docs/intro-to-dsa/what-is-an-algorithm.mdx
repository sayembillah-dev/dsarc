## কী শিখব

- Algorithm আসলে কী, আর ভালো algorithm চেনার উপায়

## ধারণা

ধরো, তোমাকে কেউ বলল চা বানাতে। তুমি মাথায় মাথায় একটা তালিকা সাজালে:

1. পানি গরম করো
2. চা পাতা দাও
3. চিনি আর দুধ মেশাও
4. ছেঁকে পরিবেশন করো

এখানেই আসল জিনিস। এই ধাপে ধাপে নির্দেশনাটাই একটা **Algorithm**। সহজ কথায়, কোনো সমস্যা সমাধানের ধাপগুলো সাজিয়ে লেখাই algorithm, ঠিক রেসিপির মতো।

সব algorithm কিন্তু সমান না। ভালো algorithm-এর কয়েকটা গুণ থাকে:

- **সঠিক (correct):** ঠিক উত্তর দেয়।
- **সুনির্দিষ্ট (unambiguous):** প্রতিটা ধাপ পরিষ্কার, দ্বিধার জায়গা নেই।
- **সসীম (finite):** একসময় শেষ হয়।
- **কার্যকর (efficient):** কম সময় আর কম জায়গায় কাজ সারে।

## সমস্যা বনাম instance

একটা সূক্ষ্ম কিন্তু গুরুত্বপূর্ণ পার্থক্য এখানেই শিখে যাও: **problem** আর **instance** এক জিনিস নয়।

ধরো, sorting-এর সমস্যাটা। একটা algorithmic problem ঠিকঠাক বর্ণনা করতে হলে দুটো জিনিস লাগে: কোন কোন input-এর ওপর কাজ করবে, আর প্রতিটা input-এর জন্য প্রত্যাশিত output কী:

- **Problem:** Sorting
- **Input:** n-টা key-এর ধারা, a₁, a₂, ..., aₙ
- **Output:** ধারাটার এমন একটা পুনর্বিন্যাস, যেখানে a'₁ ≤ a'₂ ≤ ... ≤ a'ₙ

আর **instance** হলো এই সমস্যার একটা নির্দিষ্ট পরীক্ষার খাতা: [154, 245, 1337] একটা instance, ["Haskell", "Emacs"] আরেকটা।

কেন এত আলাদা করে বললাম? কারণ algorithm লেখা হয় **পুরো problem-এর** জন্য, কোনো একটা instance-এর জন্য নয়। [154, 245, 1337] ঠিকঠাক সাজায় এমন কোড লেখা সহজ, কিন্তু সেটা sorting-এর algorithm নয়, ওই একটা খাতার উত্তর মাত্র। আসল algorithm-কে এমন সব instance-এও কাজ করতে হবে যেগুলোর কথা তুমি আজ কল্পনাও করোনি: খালি array, সব উপাদান সমান, উল্টোদিকে সাজানো বিশাল তালিকা। Interview-তে "এই ইনপুটে তো চলছে" বলা মানে problem এখনো solve হয়নি, একটা instance পার হয়েছে মাত্র।

## কোড উদাহরণ

```js
// Algorithm: array-এর সব সংখ্যার গড় বের করা
function average(numbers) {
  let total = 0;
  for (const n of numbers) total += n; // ধাপ ১: যোগ
  return total / numbers.length;        // ধাপ ২: ভাগ
}
console.log(average([10, 20, 30])); // 20
```

## কোড ব্রেকডাউন

- লক্ষ্য করো, প্রতিটা ধাপ পরিষ্কার আর নির্দিষ্ট। এটাই algorithm।
- একই সমস্যার একাধিক algorithm থাকতে পারে। কোনটা efficient, সেটাই আসল প্রশ্ন।
