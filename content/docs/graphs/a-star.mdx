## কী শিখব

- heuristic দিয়ে দ্রুত shortest path (গেম/ম্যাপ-এ)

## ধারণা

Dijkstra-র একটা দুর্বলতা আছে: সে জানেই না target কোন দিকে। তাই সব দিকে সমানভাবে ছড়িয়ে খোঁজে। **A\*** এখানেই চালাকি করে। এটা একটা **heuristic**, মানে একটা আন্দাজ (যেমন target পর্যন্ত সরলরেখা দূরত্ব) যোগ করে দেয়। ফলে খোঁজা target-এর দিকে ঝুঁকে যায়, আর অনেক কম node দেখেই উত্তর পায়। মূল সূত্রটা:

```
f(n) = g(n) + h(n)
g = start থেকে n পর্যন্ত বাস্তব খরচ
h = n থেকে target পর্যন্ত আন্দাজ খরচ (heuristic)
```

একটা শর্ত আছে: **h যেন বাস্তব খরচকে কখনো বড় করে না বলে** (এমন heuristic-কে বলে admissible)। তাহলে A\* সবচেয়ে ভালো পথই দেবে, গ্যারান্টি।

## কোড উদাহরণ (গ্রিডে, সরল কাঠামো)

```js
// গ্রিডে চারদিকের প্রতিবেশী (0 = পথ, 1 = দেয়াল)
function neighbors(grid, [r, c]) {
  const dirs = [[1, 0], [-1, 0], [0, 1], [0, -1]];
  const out = [];
  for (const [dr, dc] of dirs) {
    const nr = r + dr, nc = c + dc;
    if (nr >= 0 && nr < grid.length && nc >= 0 && nc < grid[0].length && grid[nr][nc] === 0) {
      out.push([nr, nc]);
    }
  }
  return out;
}

function aStar(grid, start, goal, h) {
  const key = ([r, c]) => `${r},${c}`;
  const open = [[h(start, goal), 0, start]]; // [f, g, node]
  const gScore = new Map([[key(start), 0]]);
  while (open.length) {
    open.sort((a, b) => a[0] - b[0]);        // ছোট f আগে
    const [, g, node] = open.shift();
    if (key(node) === key(goal)) return g;   // পৌঁছেছি
    for (const next of neighbors(grid, node)) {
      const tentative = g + 1;               // প্রতি পদক্ষেপ খরচ 1
      if (tentative < (gScore.get(key(next)) ?? Infinity)) {
        gScore.set(key(next), tentative);
        open.push([tentative + h(next, goal), tentative, next]); // f = g + h
      }
    }
  }
  return -1;
}

// Manhattan distance heuristic (গ্রিডের জন্য)
const manhattan = (a, b) => Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]);

const grid = [
  [0, 0, 0, 0],
  [1, 1, 0, 1],
  [0, 0, 0, 0],
];
console.log(aStar(grid, [0, 0], [2, 3], manhattan)); // 5
```

## কোড ব্রেকডাউন

- মজার কথা: `h = 0` করে দিলে A\* আবার Dijkstra-ই হয়ে যায়।
- heuristic যত ভালো, তত কম node দেখতে হয়, মানে তত দ্রুত।
- গেমের pathfinding বা GPS routing-এ তুমি যা দেখো, তার বেশিরভাগই A\*-এর কোনো না কোনো রূপ।

## Complexity

- heuristic-এর ওপর নির্ভর করে; ভালো h মানে Dijkstra-র চেয়ে অনেক কম node।
