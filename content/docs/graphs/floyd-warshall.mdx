## কী শিখব

- All-pairs shortest path (APSP): যেখানে প্রশ্নটাই আলাদা — এক উৎস নয়, **সব জোড়া**
- মূল ধারণা: ট্রানজিট শহর একটা একটা করে "অনুমতি" দেওয়া, আর তার DP recurrence
- কেন `k`-এর লুপ সবার বাইরে থাকতেই হবে — invariant ভাঙলে উত্তর ভেঙে যায়
- Negative edge চলে, আর diagonal দেখে negative cycle ধরা একদম ফ্রি
- কখন এটা নেবে, কখন বারবার [Dijkstra](./dijkstra.mdx) — sparse বনাম dense-এর হিসাব

## ধারণা

ডেলিভারি কোম্পানির কথা ভাবো: ওদের লাগবে **প্রতিটা** শহর থেকে **প্রতিটা** শহরের সর্বনিম্ন দূরত্বের টেবিল — রুট প্ল্যানিং, ভাড়া নির্ধারণ, সব এই টেবিল দেখে। [Dijkstra](./dijkstra.mdx) বা [Bellman-Ford](./bellman-ford.mdx) দিয়ে কাজ চালানো যায়: একটা শহরকে উৎস ধরো, হিসাব করো, পরের শহরে যাও… V বার। কিন্তু দুটো ঝামেলা: Dijkstra negative রাস্তা হজম করে না, আর প্রতিবার পুরো priority queue-র নাচ — কোডও যত্ন চায়।

Floyd-Warshall উল্টো দিক থেকে ভাবে। একটা দূরত্বের টেবিল নাও (এটাই adjacency matrix, [Graph Representation](./graph-representation.mdx)-এর দ্বিতীয় রূপ)। শুরুতে টেবিলে শুধু সরাসরি রাস্তা। এবার **ট্রানজিট শহর একটা একটা করে অনুমতি দাও**: প্রথমে বলো "শুধু শহর ০ হয়ে যেতে পারো" — প্রতিটা জোড়া (i, j)-এর জন্য দেখো, i → ০ → j দিয়ে গেলে কি ছোট হয়? তারপর শহর ১-এরও অনুমতি, তারপর ২-এর…

জাদুর বাক্যটা হলো: **k-তম ধাপ শেষে টেবিলের dist[i][j] মানে "ট্রানজিট হিসেবে শুধু ০ থেকে k পর্যন্ত শহর ব্যবহার করে" পাওয়া সেরা দূরত্ব।** সব শহরের অনুমতি পড়ে গেলে টেবিলই চূড়ান্ত উত্তর — কোনো heap নেই, কোনো visited নেই, শুধু একটা টেবিল আর এক লাইনের update।

## ধাপে ধাপে dry run

চারটা শহর, ছয়টা একমুখী রাস্তা (লক্ষ্য করো, **negative edge আছে** — এখানে Dijkstra নেই, কিন্তু এটা পারবে):

```text
রাস্তাগুলো (directed):
  0 → 1 : 3      0 → 2 : 6      0 → 3 : 15
  1 → 2 : -2     2 → 3 : 2      3 → 0 : 1
```

শুরুর টেবিল (সরাসরি রাস্তা; যা জানি না তা ∞; নিজে → নিজে 0):

| dist | 0 | 1 | 2 | 3 |
|------|---|---|---|---|
| **0** | 0 | 3 | 6 | 15 |
| **1** | ∞ | 0 | −2 | ∞ |
| **2** | ∞ | ∞ | 0 | 2 |
| **3** | 1 | ∞ | ∞ | 0 |

এবার প্রতি ধাপে একটা করে ট্রানজিট শহর অনুমতি পাচ্ছে; প্রতিটা জোড়ায় প্রশ্ন একটাই: "নতুন শহর k হয়ে গেলে কি সস্তা পড়ে, অর্থাৎ dist[i][k] + dist[k][j] < dist[i][j]?"

| ধাপ | অনুমতি পেল | ছোট হওয়া জোড়া | হিসাব |
|-----|------------|------------------|-------|
| k = 0 | শহর 0 | 3→1: ∞ → 4; 3→2: ∞ → 7 | 1+3, 1+6 |
| k = 1 | শহর 1 | 0→2: 6 → 1; 3→2: 7 → 2 | 3+(−2), 4+(−2) |
| k = 2 | শহর 2 | 0→3: 15 → 3; 1→3: ∞ → 0 | 1+2, (−2)+2 |
| k = 3 | শহর 3 | 1→0: ∞ → 1; 2→0: ∞ → 3; 2→1: ∞ → 6 | 0+1, 2+1, 2+4 |

চূড়ান্ত টেবিল:

| dist | 0 | 1 | 2 | 3 |
|------|---|---|---|---|
| **0** | 0 | 3 | **1** | **3** |
| **1** | **1** | 0 | −2 | **0** |
| **2** | **3** | **6** | 0 | 2 |
| **3** | 1 | **4** | **2** | 0 |

দেখো কীভাবে negative edge কাজে লেগেছে: 0 → 3-এর সরাসরি ভাড়া ছিল 15, কিন্তু 0 → 1 → 2 → 3 হয়ে গেলে মাত্র 3 + (−2) + 2 = **3**। আর 2 → 1-এর কোনো সরাসরি রাস্তাই নেই, অথচ শেষে পেলাম 2 → 3 → 0 → 1 = **6** — তিনটা ট্রানজিটের অনুমতি মিলেই এমন পথ বেরিয়ে এসেছে।

## কোড: পুরো implementation

```js
function floydWarshall(n, edges) {
  // dist[i][j] = এ পর্যন্ত পাওয়া সেরা i → j দূরত্ব
  const dist = Array.from({ length: n }, (_, i) =>
    Array.from({ length: n }, (_, j) => (i === j ? 0 : Infinity))
  );

  for (const [u, v, w] of edges) {          // সরাসরি রাস্তাগুলো বসাও
    if (w < dist[u][v]) dist[u][v] = w;     // দুটো রাস্তা থাকলে ছোটটা
  }

  for (let k = 0; k < n; k++) {             // ট্রানজিট অনুমতি: একটা একটা শহর
    for (let i = 0; i < n; i++) {           // প্রতিটা উৎস
      if (dist[i][k] === Infinity) continue;
      for (let j = 0; j < n; j++) {         // প্রতিটা গন্তব্য
        if (dist[k][j] === Infinity) continue;
        if (dist[i][k] + dist[k][j] < dist[i][j]) {
          dist[i][j] = dist[i][k] + dist[k][j];   // ট্রানজিটে সস্তা? তাহলে এটাই
        }
      }
    }
  }
  return dist;
}

const edges = [
  [0, 1, 3], [0, 2, 6], [0, 3, 15],
  [1, 2, -2], [2, 3, 2], [3, 0, 1],
];
const dist = floydWarshall(4, edges);
for (const row of dist) {
  console.log(row.map(x => (x === Infinity ? 'inf' : x)).join(' '));
}
// 0 3 1 3
// 1 0 -2 0
// 3 6 0 2
// 1 4 2 0

// আর negative cycle? diagonal-ই বলে দেবে:
const bad = [[0, 1, 1], [1, 2, -1], [2, 0, -1]];   // চক্রের মোট weight −1
const d2 = floydWarshall(3, bad);
console.log(d2[0][0], d2[1][1], d2[2][2]);          // -1 -1 -2 → cycle ধরা পড়ল
```

## কোড ব্রেকডাউন, লাইনে লাইনে

1. Matrix init: diagonal-এ 0, বাকি সব `Infinity` — "নিজে থেকে নিজে ফ্রি, যা জানি না তা অসীম"। এই দুটো নিয়মের একটাও বাদ পড়লে পুরো টেবিল ভুল হয়।
2. Edge বসানোর সময় `if (w < dist[u][v])` : একই জোড়ায় দুটো রাস্তা থাকলে ছোটটা থাকে।
3. `for (let k = 0; ...)` সবার বাইরে — **এটাই পুরো algorithm-এর প্রাণ**। k-তম ধাপ শেষে dist[i][j]-এর অর্থ "ট্রানজিট শুধু ০..k দিয়ে সেরা"। ক্রম বদলে i বা j কে বাইরে তুললে এই গ্যারান্টি ভেঙে যায়।
4. দুটো `Infinity` guard: যে শহরে k হয়ে যাওয়াই যায় না (বা k থেকে বেরোনো যায় না), তার হিসাব বাদ। JS-এ `Infinity + যেকোনো কিছু = Infinity` বলে এখানে বেঁচে যাও, কিন্তু C/Java-তে `INT_MAX + INT_MAX` overflow করে negative হয়ে ভুল "উন্নতি" ঘটায় — guard সব ভাষায় রাখো।
5. Update-এর লাইনটা চিনে নাও: এটা [Bellman-Ford](./bellman-ford.mdx)-এর relax-এরই জোড়া রূপ — শুধু একটা edge নয়, "i→k সেরা" আর "k→j সেরা" জোড়া লাগানো হচ্ছে।
6. একই `dist`-এ in-place লেখা নিরাপদ, কারণ k-তম ধাপে dist[i][k] আর dist[k][j] আর বদলায় না (k হয়ে k-তে যাওয়ার দাম 0)।
7. Return হচ্ছে পুরো টেবিল — V² জোড়ার উত্তর একসাথে। এক জোড়ার উত্তর দরকার হলেও পুরো দাম গুনতে হবে, এটা মাথায় রাখো।

## ভ্যারিয়েন্ট

**পথ বের করা (path reconstruction):** সাথে আরেকটা `next` matrix রাখো — শুরুতে edge থাকলে `next[i][j] = j`, প্রতি উন্নতিতে `next[i][j] = next[i][k]`। পথ চাইলে i থেকে `next` দিয়ে লাফে লাফে j পর্যন্ত যাও।

**Negative cycle ধরা:** উপরের কোডেই দেখলে — পুরো চক্রের weight negative হলে diagonal-এ negative পড়ে। তখন টেবিলের সংখ্যাগুলোর আর অর্থ নেই (চক্রটা ঘোরাতেই থাকলে দাম অসীম কমে); সংকেতটাই আসল, "এই graph-এ shortest path সংজ্ঞায়িত নয়"।

**Transitive closure:** weight-এর জায়গায় true/false, `min`/`+`-এর জায়গায় OR/AND — বেরিয়ে যায় "কে কাকে পৌঁছাতে পারে"-এর টেবিল। এটাই Warshall-এর মূল রূপ; একই হাড়, ভিন্ন মাংস।

**Sparse graph-এর বিকল্প:** graph যদি পাতলা হয় (E ≈ V), প্রতি উৎসে [Dijkstra](./dijkstra.mdx) চালালে O(V·(V+E) log V), যা V³ থেকে অনেক কম। Negative edge থাকলে Johnson's algorithm — একবার Bellman-Ford দিয়ে weight reweight করে তারপর V বার Dijkstra। নামটা জেনে রাখো।

## Complexity

| দিক | মান | কেন |
|-----|-----|-----|
| Time | O(V³) | তিনটা nested loop, কোনো best case-এর ছাড় নেই |
| Space | O(V²) | পুরো দূরত্বের টেবিলটাই রাখতে হয় |
| Negative edge | চলে | update-এ কোনো non-negative ধারণা নেই |
| Negative cycle | ধরা যায় | dist[i][i] negative পড়লেই ধরা |

তিন ভাইয়ের ভাগ-বাঁটোয়ারা তাহলে পরিষ্কার: **এক উৎস, non-negative** → [Dijkstra](./dijkstra.mdx) O((V+E) log V)। **এক উৎস, negative থাকতে পারে** → [Bellman-Ford](./bellman-ford.mdx) O(V·E)। **সব জোড়া, ছোট বা dense graph** → Floyd-Warshall O(V³) — কোড তিন লাইনের, constant ক্ষুদ্র, matrix cache-বান্ধব। V কয়েকশের মধ্যে থাকলে এই সরলতা অনেক কিছুর চেয়ে দামি।

## সাধারণ ভুল আর edge case

**১. `k`-এর লুপ ভেতরে ঢুকিয়ে ফেলা।**
`for i, for j, for k` লিখলে প্রতিটা জোড়ার জন্য সব ট্রানজিট একসাথে চেষ্টা হয় — শোনাতে যুক্তিসঙ্গত, কিন্তু DP-এর গ্যারান্টি ভেঙে যায়: যেসব মধ্যবর্তী পথ এখনো ঠিক হয়নি, সেগুলোকে ভরসা করা হয়। কিছু input-এ উত্তর ঠিকই আসবে, কিছুতে আধা-ভুল — ধরা সবচেয়ে কঠিন ভুল। মন্ত্র: **k বাইরে, i-j ভেতরে**।

**২. Infinity-এর guard বাদ দেওয়া।**
JS-এ ভাগ্যবান, C/Java-তে `INT_MAX` জুড়ে overflow করে ভুল উন্নতি। যে ভাষাতেই লেখো, `dist[i][k]` বা `dist[k][j]` অসীম হলে skip করো।

**৩. diagonal-এ 0 বসাতে ভোলা।**
নিজে → নিজে ∞ থেকে গেলে ট্রানজিটের হিসাবই গোলমাল হয়ে যায় (i → k → i-এর মতো ঘুরপথ ভুল দাম পায়), আর negative-cycle check-ও কাজ করবে না।

**৪. এক-উৎস প্রশ্নে V³ পুড়িয়ে ফেলা।**
"A থেকে B-তে সবচেয়ে কম খরচ?" — এখানে পুরো টেবিল বানানো 99% অপচয়। উৎস একটাই হলে Dijkstra/Bellman-Ford; উল্টোটাও ভুল: সব জোড়া লাগলে dense graph-এ V বার Dijkstra চালিয়ে কোড জটিল করা, যেখানে তিন লাইনের FW যথেষ্ট।

**৫. Undirected graph-এ এক দিকেই edge বসানো।**
Matrix-এ `dist[u][v]` আর `dist[v][u]` দুটোতেই weight দাও, নইলে ফেরার পথই হারিয়ে যাবে। সাথে মনে রাখো: disconnected জোড়া ∞ থেকেই যায় — প্রশ্ন পড়ে ঠিক করো ∞-এর সঙ্গে কী করতে হবে (LeetCode 1334-এ ওরা গণনায়ই আসে না)।

## অনুশীলন

- **সহজ ১:** তিনটা শহরের একটা directed graph নিজে বানাও (৪-৫টা edge, সব positive)। হাতে k = 0, 1, 2 ধাপে ধাপে টেবিল ভরো, তারপর কোড দিয়ে মিলাও।
- **সহজ ২:** উপরের negative-cycle উদাহরণে চক্রটা হুবহু কোনটা (কোন শহর দিয়ে ঘোরে)? কেন দুটো ঘর −1 আর একটা −2 হলো, নিজের কথায় ব্যাখ্যা করো।
- **মাঝারি ১:** Find the City With the Smallest Number of Neighbors at a Threshold Distance (LeetCode 1334)। হিন্ট: এটা হুবহু Floyd-Warshall — matrix বানানোই অর্ধেক কাজ; শেষে প্রতি শহরে threshold-এর ভেতরে পড়া প্রতিবেশী গুনো, tie-এ বড় index।
- **মাঝারি ২:** `next` matrix দিয়ে path reconstruction লেখো (ভ্যারিয়েন্ট ১), তারপর উপরের graph-এ 2 → 1-এর পথটা বের করো। উত্তর মিলাও: 2 → 3 → 0 → 1 আসা চাই।
- **কঠিন:** Transitive closure লেখো: একই কোডে শুধু তুলনার জায়গাটা বদলাও (`min`/`+` → OR/AND)। তারপর ভাবো, এই reachable matrix দিয়ে cycle detection বা "দুটো component-এ আছে কিনা" প্রশ্নের উত্তর কীভাবে এক নজরে পাওয়া যায়।

## সারসংক্ষেপ

- Floyd-Warshall = একটা দূরত্বের টেবিল + ট্রানজিট শহর একটা একটা করে অনুমতি; k-তম ধাপ শেষে টেবিলে "শুধু ০..k দিয়ে সেরা"।
- পুরো algorithm এক লাইনে: dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]) — শর্ত একটাই, **k-এর লুপ সবার বাইরে**।
- O(V³) সময়, O(V²) জায়গা; negative edge চলে, negative cycle diagonal-এ ধরা পড়ে।
- সব জোড়ার দূরত্ব লাগলেই এটা; এক উৎসে [Dijkstra](./dijkstra.mdx)/[Bellman-Ford](./bellman-ford.mdx)-ই যথেষ্ট, sparse graph-এ বারবার Dijkstra (বা Johnson)।
- এটাই adjacency matrix-এর আসল রাজ্য — দাম আর জয় দুটোই জানো: [Graph Representation](./graph-representation.mdx)।
