## কী শিখব

- কেন access O(1) কিন্তু মাঝে insert/delete O(n): আসল খরচটা কোথায়
- মাঝখানে insert/delete-এর পুরো dry run, উপাদান সরানোসহ
- নিজে হাতে `insertAt` আর `removeAt` লেখা, built-in-এর ভিত্তি বোঝা
- `push` O(1) বললেও মাঝে মাঝে ধীর কেন: dynamic array আর amortized খরচ
- Interview-তে ঘুরতে থাকা ভুলগুলো

## ধারণা

ব্যাপারটা হলো, সব অপারেশনের খরচ সমান না। আর খরচটা ঠিক হয় একটাই প্রশ্নে: **তুমি array-এর কোথায় হাত দিচ্ছ?**

Array মেমরিতে পাশাপাশি ঘরে বসে। এই পাশাপাশি বসার কারণেই `arr[i]` এক লাফে পাওয়া যায়: শুরুর ঠিকানা + i গুণ ঘরের সাইজ, হিসাব শেষ, একেবারে O(1)। কোথায় কী আছে খুঁজতে হয় না, সরাসরি লাফ।

কিন্তু এই পাশাপাশি বসাই ফাঁদ। মাঝখানে একটা উপাদান ঢোকাতে বা বাদ দিতে গেলে পাশাপাশি বসার শৃঙ্খলা ভাঙতে হয় না। তাই ডান পাশের **সবাইকে** এক ঘর করে সরাতে হয়। আর সেই সরানোটাই আসল খরচ: উপাদান যত, সরানো তত, মানে O(n)।

তাহলে সূত্রটা সহজ: শেষে হাত দিলে প্রায় ফ্রি (কাউকে সরাতে হয় না), শুরুতে বা মাঝে হাত দিলেই সরানোর বিল।

## ধাপে ধাপে: মাঝখানে insert-এর dry run

ধরো array-টা `[10, 20, 30, 40]`, আর তুমি index 1-এ `99` ঢোকাতে চাও। মানে ফল চাই `[10, 99, 20, 30, 40]`।

নতুন জায়গা বানাতে ডান পাশের সবাইকে এক ঘর করে সরাতে হবে। আর সরাতে হবে **ডান দিক থেকে**, নাহলে নিজের লোকের উপর দিয়েই লিখে ফেলবে:

| ধাপ | কাজ | array-এর অবস্থা |
|-----|-----|------------------|
| শুরু | - | `[10, 20, 30, 40, _]` |
| 1 | index 3-এর `40` → index 4-এ | `[10, 20, 30, 40, 40]` |
| 2 | index 2-এর `30` → index 3-এ | `[10, 20, 30, 30, 40]` |
| 3 | index 1-এর `20` → index 2-এ | `[10, 20, 20, 30, 40]` |
| 4 | index 1-এ `99` বসাও | `[10, 99, 20, 30, 40]` |

গোনো: ৪টা উপাদানের জন্য ৩টা সরানো + ১টা বসানো। n-টা উপাদান হলে খারাপ সময়ে n-টা সরানো। এই টেবিলটাই O(n)-এর প্রমাণ, চোখে দেখা।

Delete-ও ঠিক উল্টোটা: index 1 বাদ দিলে ডানের সবাইকে এক ঘর **বামে** টানতে হয়, এবার বাম দিক থেকে শুরু করে।

## কোড: নিজে বানাও insertAt আর removeAt

Built-in `splice` কী করে, সেটা না বুঝে ব্যবহার করলে খরচ চোখে পড়ে না। তাই একবার নিজে লিখে দেখি:

```js
// ধরো একটা fixed জায়গার array-এর ভেতরে কাজ করছি
function insertAt(arr, length, index, value) {
  // ডান থেকে বামে সরাও, নাহলে নিজের উপাদান নিজে মুছে ফেলবে
  for (let i = length; i > index; i--) {
    arr[i] = arr[i - 1];              // এক ঘর ডানে
  }
  arr[index] = value;
  return length + 1;                  // নতুন length
}

const a = [10, 20, 30, 40, null];
const len = insertAt(a, 4, 1, 99);
console.log(a);    // [10, 99, 20, 30, 40]
console.log(len);  // 5
```

```js
function removeAt(arr, length, index) {
  for (let i = index; i < length - 1; i++) {
    arr[i] = arr[i + 1];              // এক ঘর বামে টানো
  }
  arr[length - 1] = undefined;        // শেষ ঘর পরিষ্কার
  return length - 1;
}

const b = [10, 99, 20, 30, 40];
removeAt(b, 5, 1);
console.log(b);    // [10, 20, 30, 40, undefined]
```

দুটোতেই খেয়াল করো, সরানোর দিকটা উল্টো। Insert-এ ডান থেকে (নাহলে `arr[i+1]` লিখতে গিয়ে তাজা উপাদান মুছে যায়), delete-এ বাম থেকে। Interview-এ এই দিকভুলটা ধরতে বলা হয়।

## বাস্তব জীবনে: JavaScript-এর built-in অপারেশন

```js
const arr = [10, 20, 30];

arr.push(40);          // [10,20,30,40]   শেষে যোগ, O(1)*
arr.pop();             // [10,20,30]      শেষে বাদ, O(1)
arr.unshift(5);        // [5,10,20,30]    শুরুতে যোগ, O(n)
arr.shift();           // [10,20,30]      শুরুতে বাদ, O(n)
arr.splice(1, 0, 15);  // [10,15,20,30]   মাঝে insert, O(n)
arr.splice(1, 1);      // [10,20,30]      মাঝে delete, O(n)

console.log(arr.indexOf(20));   // 1, খোঁজা O(n)
console.log(arr.includes(99));  // false, O(n)
```

`splice(start, deleteCount, ...items)` বহুমুখী: বাদও দেয়, যোগও করে। কিন্তু বহুমুখী হলেও সে জাদু না, ভেতরে সে-ও উপাদান সরাচ্ছে, তাই খরচ সেই একই O(n)।

## push-এর রহস্য: কখনও কখনও ধীর কেন?

`push` তো O(1) বললাম। কিন্তু ভাবো তো, JavaScript-এর array-তে আগে থেকে জায়গা ঠিক করে দিতে হয় না, তাহলে ঘর শেষ হয়ে গেলে কী হয়?

সত্যিটা হলো, engine ভেতরে একটা capacity রেখে দেয়। ঘর ভরে গেলে সে চুপচাপ **দ্বিগুণ বড়** একটা জায়গা নেয়, সব উপাদান ওখানে কপি করে, তারপর নতুন উপাদানটা বসায়। সেই বারের `push` হঠাৎ O(n)।

তারপরও আমরা `push`-কে O(1) বলি। কেন? কারণ এই ব্যয়বহুল বারটা খুব কমই আসে:

| push # | capacity | সেই বারে কপি |
|--------|----------|---------------|
| 1 | 1 | 0 |
| 2 | 2 | 1 |
| 3 | 4 | 2 |
| 5 | 8 | 4 |
| 9 | 16 | 8 |

n-বার push-এ মোট কপি প্রায় n-এর কাছাকাছি (1+2+4+...+n/2 ≈ n)। মানে প্রতি push-এ গড়ে প্রায় O(1)। একে বলে **amortized O(1)**: কোনো বার ব্যয়বহুল, কিন্তু সব বার মিলিয়ে গড় খরচ সামান্য। এই শব্দটা interview-এ উড়ে বেড়ায়, মনে রেখো।

## কোড ব্রেকডাউন: insertAt, লাইনে লাইনে

1. `for (let i = length; i > index; i--)` : শুরু হচ্ছে একদম ডান প্রান্ত থেকে, index পর্যন্ত। উল্টো দিকে চললে `arr[i-1]` পড়ার আগেই সেটা নষ্ট হয়ে যেত।
2. `arr[i] = arr[i - 1]` : বামের ঘরের উপাদান ডানে সরল। প্রতি ঘুরে একজন সরে, মোট (length - index) জন।
3. `arr[index] = value` : সবাই সরে গেছে, ফাঁকা ঘরে নতুন মান বসল।
4. `return length + 1` : একজন এসেছে, length বাড়ল। JavaScript-এর আসল array নিজে length ট্র্যাক করে; আমরা শেখার জন্য নিজে করছি, যাতে fixed-size array-র (C, Java) চিন্তাটা বোঝা যায়।

## Complexity: পুরো টেবিল, কারণসহ

| অপারেশন | Complexity | কেন |
|---------|-----------|-----|
| Access `arr[i]` | O(1) | ঠিকানা সরাসরি বের হয়, কাউকে খুঁজতে হয় না |
| Update `arr[i] = x` | O(1) | একই কারণ |
| Push (শেষে যোগ) | O(1), amortized | সাধারণত কেউ সরে না; capacity ফুরালে এক বারে কপি, গড়ে সামান্য |
| Pop (শেষে বাদ) | O(1) | কাউকে সরাতে হয় না |
| Unshift (শুরুতে যোগ) | O(n) | সবাই এক ঘর ডানে |
| Shift (শুরুতে বাদ) | O(n) | সবাই এক ঘর বামে |
| Insert মাঝে | O(n) | খারাপ সময়ে প্রায় সবাই সরে |
| Delete মাঝে | O(n) | একই কারণ |
| Search (মান দিয়ে) | O(n) | সব ঘর উল্টে দেখা লাগতে পারে |

মনে রাখার সূত্র: **খরচ = কতজনকে সরাতে হচ্ছে।** কাউকে সরাতে না হলে O(1), সবাইকে সরাতে হলে O(n)। ব্যস।

## সাধারণ ভুল আর edge case

**১. `splice` কে O(1) ভাবা।**
দেখতে এক লাইনের method, কিন্তু ভেতরে সরানো চলছেই। লুপের ভেতরে `splice` চালালে তোমার loop আসলে O(n²)। খুব চেনা ভুল।

**২. লুপে ঘুরতে গিয়ে element বাদ দেওয়া।**
```js
for (let i = 0; i < arr.length; i++) {
  if (arr[i] < 0) arr.splice(i, 1);  // বিপদ!
}
```
`splice` করার পর সবাই এক ঘর বামে আসে, কিন্তু `i` বেড়ে যায়। ফলে পরের উপাদানটা চেকই হয় না। সমাধান: বাদ দিলে `i--` করো, নয়তো উল্টো দিকে ঘোরো, নয়তো নতুন array বানাও (`filter` সবচেয়ে নিরাপদ)।

**৩. সরানোর দিক উল্টে ফেলা।**
নিজে insert লিখলে বাম থেকে ডানে সরালে উপাদান নষ্ট হয় (`arr[i] = arr[i-1]` দিয়ে শুরু করলে সব একই মান হয়ে যায়)। Insert-এ ডান থেকে, delete-এ বাম থেকে।

**৪. Reference আর copy গুলিয়ে ফেলা।**
`const b = arr` লিখলে copy হয় না, একই array-এর আরেকটা নাম পায়। `b`-তে push করলে `arr`-ও বদলে যায়। আসল copy চাইলে `[...arr]` বা `arr.slice()`। (Spread-ও O(n), মনে রেখো।)

**৫. খালি array-তে pop/shift।**
ক্রাশ করে না, `undefined` দেয়। কিন্তু সেই `undefined` নিয়ে হিসাব করলে পরে NaN-এর দলা। আগে length চেক করা নিরাপদ।

## অনুশীলন

- **সহজ ১:** কাগজে dry run করো: `[5, 15, 25, 35]`-এ index 2-তে `20` insert। প্রতি ধাপে array আঁকো।
- **সহজ ২:** বন্ধুকে বোঝাও (লিখে): `push` O(1) কিন্তু `unshift` O(n) কেন?
- **মাঝারি ১:** `removeAt` লেখার পর এমনভাবে টেস্ট করো যাতে শেষ উপাদানটা বাদ দেওয়া হয়। কোনো সরানো লাগল? কেন লাগল না?
- **মাঝারি ২:** একটা sorted array দেওয়া আছে। এমন `insertSorted(arr, value)` লেখো যাতে মান ঠিক জায়গায় বসে। খরচ কত, আর কেন? (হিন্ট: খোঁজা O(n), সরানোও O(n)। Sorted থাকলে খোঁজার জন্য [Binary Search](../searching/binary-search.mdx) লাগানো যায়, কিন্তু সরানো তো লাগবেই।)
- **কঠিন:** Rotate array (LeetCode 189): array-কে k ঘর ডানে ঘোরাও, জায়গা O(1)-এ। হিন্ট: পুরোটা reverse, তারপর প্রথম k-টা reverse, তারপর বাকিটা reverse। তিনবার reverse = একবার rotate।

## সারসংক্ষেপ

- খরচের হিসাব একটাই: কতজনকে সরাতে হচ্ছে।
- শেষে সস্তা (O(1)), শুরুতে বা মাঝে দামি (O(n))।
- `push` আসলে amortized O(1): capacity দ্বিগুণ হয়ে কপি খুব কমই আসে।
- লুপের ভেতরে `splice` = লুকানো O(n²), সাবধান।
