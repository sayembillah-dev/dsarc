## কী শিখব

- B+ Tree-র আগে কী চলত, আর static index কেন আর টেকে নি

## ধারণা

ধরো একটা বড় অফিসের ফাইল ক্যাবিনেট। ফাইলগুলো বর্ণানুক্রমে সাজানো, আর সামনে ঝুলছে একটা ছোট্ট তালিকা: "A শুরু এই ড্রয়ারে, F শুরু ওই ড্রয়ারে"। "G" খুঁজতে গিয়ে তুমি পুরো ক্যাবিনেট নাড়ো না। তালিকা দেখে F-এর ড্রয়ারে গিয়ে একটু হাতড়ালেই পেয়ে যাও। ISAM (Indexed Sequential Access Method) ঠিক এভাবেই কাজ করে। B+ Tree আসার আগে disk indexing মানে এটাই ছিল, তাই B+ Tree-র পূর্বসূরি বললে ভুল হবে না।

কাঠামোটা সরল। ডেটা থাকে sorted, sequential page-এ। তার উপর বসে একটা **static (স্থির) index**, যেটা তোমাকে দ্রুত মোটামুটি page-এ পৌঁছে দেয়, তারপর সেই page ধরে sequential খোঁজো। মূল বৈশিষ্ট্য তিনটা:

- **index একদম স্থির।** একবার বানালেই শেষ, ডেটা বদলালেও ও নড়ে না।
- নতুন record? index-এ জায়গা নেই, সোজা **overflow area**-তে।
- insert বেশি হলে overflow ফুলে যায়, performance পড়ে যায়। তাই মাঝে মাঝে পুরোটা নতুন করে সাজাতে (periodic **reorganization**) হয়।

```text
Index:   [A -> page1] [F -> page2] [M -> page3]   (স্থির, sorted key থেকে page)
Data:    page1: A,B,C  |  page2: F,G  |  page3: M,N,O  |  overflow: (নতুনগুলো)
খোঁজা "G": index-এ F-এর page পাই -> page2 sequential scan -> G
```

## কোড উদাহরণ

```js
// ISAM মডেল: স্থির index + sequential data page + overflow area
const index = [                    // একবার বানানো, পরে বদলায় না (static)
  { key: "A", page: 0 },
  { key: "F", page: 1 },
  { key: "M", page: 2 },
];
const pages = [["A", "B", "C"], ["F", "G"], ["M", "N", "O"]];
const overflow = [];               // নতুন record এখানে জমে

function isamSearch(target) {
  let page = 0;                    // index থেকে মোটামুটি page
  for (const entry of index) {
    if (entry.key <= target) page = entry.page; else break;
  }
  if (pages[page].includes(target)) return `page ${page}-এ পাওয়া গেছে`;
  if (overflow.includes(target)) return "overflow area-তে পাওয়া গেছে (ধীর)";
  return "পাওয়া যায়নি";
}

console.log(isamSearch("G"));      // page 1-এ পাওয়া গেছে
overflow.push("H", "I", "J");      // নতুন insert index বদলায় না
console.log(isamSearch("I"));      // overflow area-তে পাওয়া গেছে (ধীর)
console.log(isamSearch("Z"));      // পাওয়া যায়নি
```

## কোড ব্রেকডাউন

- static index-এর জোর: সরল, আর read-heavy কাজে দ্রুত।
- দুর্বলতা: write-heavy হলেই overflow জমতে থাকে, search ধীর হয়ে পড়ে। এই সমস্যাটাই পরে B+ Tree সমাধান করেছে, dynamic আর self-balancing হয়ে।
- তাই আধুনিক DBMS-এ ISAM প্রায় দেখাই পাওয়া যায় না। তবু "dynamic index কেন দরকার" বুঝতে এর চেয়ে ভালো গল্প আর নেই।

## Complexity

- সব ঠিকঠাক থাকলে O(log n)-এর কাছাকাছি; overflow বাড়লেই অবস্থা খারাপ।
