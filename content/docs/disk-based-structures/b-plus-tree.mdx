## কী শিখব

- database আর file system-এর index আসলে কী দিয়ে দাঁড়িয়ে

## ধারণা

ধরো বিশাল একটা গ্রন্থাগারে তোমাকে একটা বই খুঁজতে হবে, আর প্রতিটা তাক খুলতে (disk read) মিনিটখানেক লেগে যায়। তুমি কি চাবে তাকগুলো লম্বা সিঁড়ির মতো একটার উপর একটা সাজানো থাকুক? নাকি চওড়া কক্ষ, যেখানে এক ঘড়িতে হাজারটা তাক চোখে পড়ে? অবশ্যই চওড়া। B-Tree ঠিক এই বুদ্ধিতেই বানানো। আগের পাতার 2-3 Tree-কেই আরও চওড়া করলেই পাও **B-Tree** (section 11.6-এ পরিচয় হয়েছে): প্রতিটা node-এ **অনেক key, অনেক চাইল্ড** (order m)। লক্ষ্য একটাই, গাছের **height যত কম** রাখা যায়। কম height মানে কম disk read, আর disk-এর জগতে এটাই আসল খরচ।

**B+ Tree** হলো B-Tree-র আরেকটু ঝকঝকে সংস্করণ, আর বাস্তবে database index মানে এটাই। পার্থক্য দুটো:

- **আসল ডেটা থাকে শুধু leaf-এ।** internal node গুলো শুধু রাস্তা দেখায় (guide key)।
- **সব leaf পরস্পর linked list দিয়ে জোড়া।** ফলে range query (`WHERE age BETWEEN 20 AND 30`) মানে এক leaf-এ নেমে পরের leaf গুলোতে হেঁটে যাওয়া, ব্যাস।

```text
B+ Tree:
            [30 | 60]              (internal: শুধু guide)
           /    |    \
     [10 20]->[30 40 50]->[60 70]  (leaf: actual data, পরস্পর linked)
```

## কোড উদাহরণ

```js
// ছোট্ট B+ Tree মডেল: internal node শুধু guide, leaf-এ data ও leaf-লিঙ্ক
class LeafNode {
  constructor(keys) { this.keys = keys; this.next = null; }
}

class BPlusTree {
  constructor() {
    this.guides = [30, 60];          // internal node-এর guide key
    this.leaves = [
      new LeafNode([10, 20]),
      new LeafNode([30, 40, 50]),
      new LeafNode([60, 70]),
    ];
    for (let i = 0; i < this.leaves.length - 1; i++) {
      this.leaves[i].next = this.leaves[i + 1];   // leaf গুলো linked
    }
  }

  _findLeaf(key) {                   // guide দিয়ে নামা (বাস্তবে O(log n))
    let i = 0;
    while (i < this.guides.length && key >= this.guides[i]) i++;
    return this.leaves[i];
  }

  rangeQuery(lo, hi) {               // SQL: WHERE age BETWEEN lo AND hi
    const result = [];
    let leaf = this._findLeaf(lo);   // lo-এর leaf খোঁজা O(log n)
    while (leaf) {                   // leaf-linked-list ধরে hi পর্যন্ত হাঁটা
      for (const k of leaf.keys) {
        if (k > hi) return result;
        if (k >= lo) result.push(k);
      }
      leaf = leaf.next;
    }
    return result;
  }
}

const tree = new BPlusTree();
// SELECT * FROM users WHERE age BETWEEN 25 AND 40;
console.log(tree.rangeQuery(25, 40));   // [ 30, 40 ]
console.log(tree.rangeQuery(10, 70));   // [ 10, 20, 30, 40, 50, 60, 70 ]
```

## কোড ব্রেকডাউন

- `_findLeaf` guide key দেখে সঠিক leaf-এ নেমে যায়; আসল B+ Tree-এ এই অংশটাই O(log n)।
- `rangeQuery` আগে 25-এর leaf খোঁজে (O(log n)), তারপর leaf-এর linked list ধরে 40 পর্যন্ত হেঁটে যায়। range scan-এর চেয়ে দক্ষ জিনিস আর কী হতে পারে?
- fan-out বড় মানে প্রচুর চাইল্ড। লাখ লাখ row থাকলেও height মাত্র ৩-৪, তাই যেকোনো row পেতে ৩-৪টা disk read-ই যথেষ্ট।
- এই linked leaf-ই sorted scan আর range query-কে এত সহজ করে দেয়। তাই MySQL (InnoDB) হোক বা PostgreSQL, সবাই B+ Tree index-ই ব্যবহার করে।

## Complexity

- search/insert/delete সব O(log n); আর disk-access-এ বাড়তি বিশাল জিত।
