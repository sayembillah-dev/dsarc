## কী শিখব

- Extract-এর তিন পর্ব: root তোলা, শেষটা উপরে বসানো, নিচে ডোবানো
- Bubble down-এর পুরো dry run, প্রতি স্তরে
- কেন swap হয় ছোট child-এর সঙ্গে, বড়ের সঙ্গে না
- [Insert](./heap-insert-bubble-up.mdx)-এর সঙ্গে সৌন্দর্যের প্রতিসাম্য
- Complexity আর পরপর extract মানে কী (heap sort-এর বীজ)

## ধারণা

Min-heap-এ সবচেয়ে ছোট মান root-এ বসে আছে, তাই তাকে বের করা সহজ: `heap[0]` তুলে নাও। কিন্তু বের করেই দুটো সমস্যা: root-এর ঘর ফাঁকা, আর গাছ দুই টুকরো। কাকে বসাবে ওখানে?

চালাকিটা অদ্ভুত শোনালেও নিখুঁত: **শেষ উপাদানটাকে তুলে root-এ বসাও**। কেন শেষটা? কারণ শেষটাকে তুললেই গাছ complete থেকে যায় (শেষ level-order ঘরটা ফাঁকা হয়, যা বৈধ)। অন্য যেকোনো ঘর তুললে মাঝখানে ফাঁক পড়ত।

এবার নতুন root প্রায় নিশ্চিতভাবেই নিয়ম ভাঙে, কারণ সে তো সবচেয়ে ছোট না। তাই তাকে নামাতে হবে: দুই child-এর মধ্যে **ছোটটার** সঙ্গে swap, নিচে নামো, আবার তুলনা। যতক্ষণ না নিয়ম মেনে যায়, ডুবতে থাকে। এই নামার নাম **bubble down** (বা heapify down, sift down)।

[Insert](./heap-insert-bubble-up.mdx)-এর সঙ্গে প্রতিসাম্যটা দেখো: insert-এ নতুনজন **শেষে বসে উপরে ভাসে**, extract-এ শেষের লোক **উপরে বসে নিচে ডোবে**। একই নিয়মের দুই দিক।

## Dry run: `[1, 3, 2, 5, 9, 6, 8]` থেকে extractMin

| ধাপ | কাজ | heap-এর অবস্থা |
|-----|-----|------------------|
| 1 | min (1) তুলে রাখো, শেষের 8 root-এ | `[8, 3, 2, 5, 9, 6]` |
| 2 | 8-এর child: 3, 2; ছোট 2 | swap হবে index 2-এর সঙ্গে |
| 3 | swap | `[2, 3, 8, 5, 9, 6]` |
| 4 | 8-এর child: 5, 9; ছোট 5 | swap index 3-এর সঙ্গে |
| 5 | swap | `[2, 3, 5, 8, 9, 6]` |

ধাপ ৫-এর পর 8-এর নিচে child নেই (index 3-এর child 7, 8, সীমার বাইরে), থামো। ফেরত মান 1, heap পুনর্গঠিত: `[2, 3, 5, 8, 9, 6]`, নতুন root 2, যা সত্যিই এখনকার সর্বনিম্ন।

গাছের চোখে:

```text
আগে:        1                 পরে:        2
          /   \                         /   \
         3     2                       3     5... 
        ...                       (8 ডুবে গিয়ে leaf-এ)
```

## কেন ছোট child-এর সঙ্গে swap?

একটা সূক্ষ্ম প্রশ্ন: দুই child-এর যেকোনো একটার সঙ্গে swap হলে না হয় কেন? ধরো 8-কে বড় child (5 নয়, 9 ধরো) -এর সঙ্গে বদলালে: 9 উপরে উঠে তার ভাই 5-এর parent হয়, কিন্তু 9 > 5, নিয়ম আবার ভাঙে। মানে **ছোট child-ই একমাত্র নিরাপদ সঙ্গী**, কারণ সে-ই দুই ভাইয়ের মধ্যে parent হওয়ার যোগ্য। এই এক নিয়মে পুরো heap ফিরে আসে, নইলে ভাঙন থেকেই যায়।

## কোড: নিজে বানাও extractMin

```js
function extractMin(heap) {
  if (heap.length === 0) return undefined;

  const min = heap[0];
  const last = heap.pop();               // শেষ ঘর ফাঁকা: complete অক্ষত

  if (heap.length > 0) {
    heap[0] = last;                      // শেষটা root-এ বসল

    let i = 0;
    const n = heap.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1;
      const right = 2 * i + 2;

      if (left < n && heap[left] < heap[smallest]) smallest = left;
      if (right < n && heap[right] < heap[smallest]) smallest = right;

      if (smallest === i) break;         // দুই child-ই ছোট না: নিয়ম ঠিক

      [heap[i], heap[smallest]] = [heap[smallest], heap[i]];
      i = smallest;
    }
  }

  return min;
}

const h = [1, 3, 2, 5, 9, 6, 8];
console.log(extractMin(h)); // 1
console.log(h);             // [2, 3, 5, 8, 9, 6]
console.log(extractMin(h)); // 2: পরের সর্বনিম্ন, নিজে থেকেই ঠিক
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `if (heap.length === 0) return undefined` : খালি heap-এ চেনা নিরাপত্তা, [Stack](../stacks/stack-lifo.mdx)-এর pop-এর মতোই।
2. `const last = heap.pop()` : শেষ ঘর তোলা। একটাই উপাদান থাকলে `heap.length` শূন্য হয়ে যায়, তাই পরের `if` দরকার।
3. `heap[0] = last` : শেষের লোক root-এ। এই মুহূর্তে নিয়ম প্রায় নিশ্চিতভাবে ভাঙা, তাই নিচের লুপ।
4. `let smallest = i` : চ্যাম্পিয়ন-প্যাটার্ন আবার, তিনজনের মধ্যে সর্বনিম্ন খোঁজা (parent + দুই child)।
5. `left < n && ...` : সীমা চেক আগে, [Heap as Array](./heap-as-array.mdx)-এর শিক্ষা। Leaf-এর child নেই, `undefined`-এর সঙ্গে তুলনা না।
6. `if (smallest === i) break` : parent-ই সর্বনিম্ন, মানে নিয়ম ফিরেছে, ডোবানো শেষ।
7. swap আর `i = smallest` : ডুবে গেলাম এক স্তর, দৃষ্টিও সঙ্গে নামল।

## Complexity

| দিক | খরচ | কেন |
|-----|------|-----|
| root তোলা | O(1) | index 0 পড়া |
| শেষটা বসানো | O(1) | pop + assignment |
| Bubble down | সর্বোচ্চ O(log n) | প্রতি swap এক স্তর নামে, height-টুকু |
| মোট | **O(log n)** | |

পরপর সবগুলো extract করলে? প্রতিটা O(log n), মোট n-টার জন্য O(n log n), আর বের হওয়া ক্রমটা হয় sorted। চেনা লাগছে? এটাই [Heap Sort](../sorting/heap-sort.mdx)-এর প্রাণ, section 11-এ ফিরে দেখেছিলে। একটা কাঠামো, দুই জগতের সেতু।

## সাধারণ ভুল আর edge case

**১. বড় child-এর সঙ্গে swap করা।**
উপরের যুক্তিটাই: ছোট child-ই একমাত্র নিরাপদ। বড়ের সঙ্গে বদলালে নতুন parent তার ভাইয়ের চেয়ে বড় হয়ে যায়, নিয়ম ভাঙা থেকে যায়। Max-heap-এ উল্টোটা: বড় child।

**২. Child নেই, তবু তুলনা।**
Leaf-এ পৌঁছে `heap[2i + 1]` হলো `undefined`, `undefined < x` সবসময় false, তাই ভুলে ভুলে ঠিকও থাকে, কিন্তু সেটা ভাগ্য, বোঝা না। সীমা চেক (`left < n`) সচেতন অভ্যাস করো।

**৩. এক উপাদানের heap-এ ভাঙা।**
`heap.pop()` করলেই heap খালি, তারপর `heap[0] = last` লিখলে আবার ঘর জন্মায়, ফেরতও ভুল হয়। `if (heap.length > 0)` চেকটা ছোট কিন্তু নির্ণায়ক।

**৪. `smallest` রিসেট না করা।**
প্রতি স্তরে চ্যাম্পিয়ন নতুন করে `i` থেকে শুরু না করলে আগের স্তরের ফল পড়ে থাকে, ভুল child বাছে। লুপের গোড়ায় `let smallest = i`।

**৫. Extract-এর পর heap ভাঙা ভাবা, "যাচাই" না করা।**
নিজের লেখা extract পরীক্ষার সহজ উপায়: পরপর কয়বার extract চালাও, ফলগুলো strictly increasing হওয়া চাই। একটা উল্টো এলেই bubble down-এ ভুল, খুঁজো swap-এর শর্তে।

## অনুশীলন

- **সহজ ১:** `[1, 4, 3, 7, 8, 5]` থেকে extractMin হাতে করো, প্রতি ধাপে array লিখো।
- **সহজ ২:** একই heap-এ আরেকবার extract করো। দুই ফল মিলে কী পেলে, আর এটা কেন sorted ক্রমের প্রমাণ?
- **মাঝারি ১:** Max-heap-এর extract লেখো। কোন শর্ত বদলালে? একই ডেটায় min আর max heap চালিয়ে বের হওয়া ক্রম দুটো তুলনা করো।
- **মাঝারি ২:** বন্ধুকে বোঝাও: কেন extract-এ শেষ উপাদানটাই root-এ বসে, আর মাঝের কোনোটা না। উত্তরে "complete" কথাটা থাকা চাই।
- **কঠিন:** `decreaseKey(i, newValue)` ভেবে দেখো: index i-এর মান কমালে heap ঠিক করতে কী লাগবে? (হিন্ট: মান কমলে ওর parent-দের সঙ্গে সমস্যা, মানে কোন দিকে যাত্রা? উপরে না নিচে? Dijkstra-তে এই অপারেশনই লাগে, [Graphs](../graphs/dijkstra.mdx)-এ মিলবে।)

## সারসংক্ষেপ

- Extract তিন পর্বের: root তোলা (O(1)), শেষটা উপরে বসানো, bubble down দিয়ে ডোবানো (O(log n))।
- Swap সবসময় ছোট child-এর সঙ্গে (min-heap-এ), নইলে নিয়ম ফেরে না।
- Complete আকৃতি বাঁচে শেষ ঘর ফাঁকা হওয়ায়; এজন্যই শেষটাই বসে।
- পরপর extract মানে sorted ক্রম, এটাই heap sort-এর বীজ।
- Insert আর extract একই মুদ্রার দুই পিঠ: একে ভাসে, অন্যটা ডোবে।
