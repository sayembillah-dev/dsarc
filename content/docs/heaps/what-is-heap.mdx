## কী শিখব

- Heap কী জিনিস, আর Min-Heap ও Max-Heap-এর নিয়মটা ঠিক কী

## ধারণা

ভাবো তো, তুমি হাসপাতালের emergency ward-এ আছ। সেখানে যে আগে এসেছে সে আগে ঢোকে না; যার অবস্থা সবচেয়ে খারাপ, সে-ই আগে যায়। মানে "সবচেয়ে জরুরি" মানুষটা সবসময় হাতের কাছে। ঠিক এই দরকার থেকেই এসেছে **Heap**।

Heap আসলে একটা **complete binary tree** (উপরের লেভেলগুলো পূর্ণ, শেষ লেভেলে node-গুলো বাঁ থেকে ডানে বসে)। পুরো কাঠামোটা চলে একটাই নিয়মে:

- **Min-Heap:** প্রতিটা parent তার চাইল্ডদের চেয়ে **ছোট/সমান**। তাহলে বলো তো, সবচেয়ে ছোট মানটা কোথায় থাকবে? ঠিকই ধরেছ, একদম root-এ।
- **Max-Heap:** উল্টোটা। প্রতিটা parent চাইল্ডদের চেয়ে **বড়/সমান**, তাই সবচেয়ে বড় মান বসে root-এ।

```
Min-Heap:      1
              / \
             3   6
            / \
           5   9
```

<Callout type="info" title="মনে রাখো: heap পুরোপুরি sorted নয়">
Heap শুধু parent আর child-এর সম্পর্কটা দেখে। তাই root-এর মান তুমি ঝটকা পেয়ে যাও, কিন্তু বাকি উপাদানগুলো কোন ক্রমে আছে, সেটা heap বলে দেয় না।
</Callout>

## কোড উদাহরণ

```js
// root সবসময় সবচেয়ে ছোট (min-heap): peek() O(1)
// insert/extract O(log n)
const minHeap = [1, 3, 6, 5, 9]; // array-রূপ, বিস্তারিত পরের পাতায়
const peek = (heap) => heap[0];
console.log(peek(minHeap)); // 1, সবচেয়ে ছোট মান মুহূর্তে
```

## কোড ব্রেকডাউন

- BST-র নিয়মটা আলাদা: সেখানে বাঁ পাশ, root, ডান পাশ, সব মিলিয়ে ক্রম মানতে হয়। Heap-এ তেমন কিছু নেই; এখানে লড়াই শুধু parent আর child-এর।
- তাই BST দিয়ে min খুঁজতে গেলে একদম বাঁ পাশে নামতে হয়, O(log n) সময় লাগে। Heap-এ min তো root-এ বসেই আছে, peek করলেই O(1)।

## Complexity

- peek মানে root-এ তাকানো, তাই O(1)। আর insert বা extract-এ সর্বোচ্চ tree-এর উচ্চতাটুকু (log n) উপরে বা নিচে যেতে হয়, O(log n)।
