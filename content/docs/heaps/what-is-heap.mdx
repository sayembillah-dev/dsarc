## কী শিখব

- Heap আসলে কী: দুই শর্তের কাঠামো, আকৃতির শর্ত আর নিয়মের শর্ত
- Min-heap বনাম max-heap, পার্থক্য একটাই চিহ্ন
- কেন heap পুরোপুরি sorted না, আর সেটা দোষ না, ডিজাইন
- BST-এর সঙ্গে তুলনা: কে কোন প্রশ্নে জেতে
- কোন array heap, কোনটা না: নিজে যাচাই করা

## ধারণা

[Priority Queue](../stacks-queues/priority-queue.mdx)-এ একটা প্রতিশ্রুতি পেয়েছিলে: জরুরি উপাদান আগে বের হবে, আর heap দিলে insert/extract দুটোই O(log n)। সেই heap-টা আসলে কী, এই পেজে তার ভিত্তি।

Heap বোঝার আগে দুই শর্ত আলাদা করে ভাবো:

1. **আকৃতির শর্ত (complete binary tree):** উপরের সব স্তর ভরা, শেষ স্তরে node-গুলো বাম থেকে ডানে, মাঝে ফাঁক নেই। মানে গাছটা যেন ভাতের থালার মতো নিচে চাপা, কোথাও হুলো নেই।
2. **নিয়মের শর্ত (heap property):** প্রতিটা parent তার child-দের সঙ্গে একটা সম্পর্ক মানে:
   - **Min-heap:** parent ≤ child (দুটোই)। ফল: সবচেয়ে ছোট মান root-এ।
   - **Max-heap:** parent ≥ child (দুটোই)। ফল: সবচেয়ে বড় মান root-এ।

```text
Min-heap:        1
               /   \
              3     6
             / \   /
            5   9 8
```

যেকোনো parent-child জোড়া নাও, নিয়ম মিলবে: 1 ≤ 3, 1 ≤ 6, 3 ≤ 5, 3 ≤ 9, 6 ≤ 8। আর সবচেয়ে ছোট মান 1 বসে আছে root-এ, ঝটকা পাওয়া যায়। এটাই heap-এর মূল প্রতিশ্রুতি: **চরম মান সবসময় হাতের কাছে, peek O(1)**।

## Heap sorted না: দোষ না, ডিজাইন

একটা সূক্ষ্ম ব্যাপার আগেই পরিষ্কার করি। উপরের heap-এ 8 আছে 9-এর **বামে**, অথচ 8 > 9? দ্বিতীয় স্তরে 6 বসে 3-এর ডানে, অর্থাৎ স্তরে স্তরে কোনো ক্রম নেই। Heap **পুরোপুরি sorted না**। নিয়ম শুধু parent আর child-এর মধ্যে; দুই sibling-এর মধ্যে কে বড়, heap জানেই না।

কেন এমন অসম্পূর্ণ নিয়ম? কারণ পুরো ক্রম ধরে রাখা দামি (BST-র মতো), আর দরকারও না। Priority queue-র কাজ হলো বারবার **চরমটা** দেওয়া, বাকিদের ক্রম জরুরি না। কম শর্ত মানে কম খরচে নিয়ম ফেরানো যায়, insert আর extract O(log n)-এ। "যতটুকু দরকার ততটুকুই শৃঙ্খলা", heap তার চমৎকার উদাহরণ।

## Dry run: কোনটা heap, কোনটা না

নিজে যাচাই করার নিয়ম: প্রতি parent-child জোড়ায় নিয়ম বসাও। `[1, 3, 6, 5, 9, 2]` কি min-heap?

| জোড়া (parent → child) | নিয়ম (parent ≤ child) | মিলল? |
|--------------------------|--------------------------|--------|
| 1 → 3, 1 → 6 | 1 ≤ 3, 1 ≤ 6 | হ্যাঁ |
| 3 → 5, 3 → 9 | হ্যাঁ | হ্যাঁ |
| 6 → 2 | 6 ≤ 2? | **না: heap ভাঙে** |

একটা জোড়াই যথেষ্ট, পুরো কাঠামো heap হওয়ার যোগ্য হলো না। যাচাই করতে গেলে সব জোড়া দেখতে হয়, O(n)। (ছবি না থাকলে array থেকে tree বানিয়ে নাও, [Heap as Array](./heap-as-array.mdx)-এর সূত্রে, পরের পেজেই সেটা।)

## BST বনাম heap: কে কোথায়

দুটোই গাছ, দুটোই "ক্রম" নিয়ে খেলে, তাই নতুনরা গুলায়। পার্থক্যটা এক টেবিলে:

| প্রশ্ন | BST | Heap |
|--------|-----|------|
| নিয়ম | বামে ছোট, ডানে বড় (পুরো subtree) | শুধু parent-child সম্পর্ক |
| চরম মান কোথায় | min একদম বামে, খুঁজে যেতে হয় O(log n) | root-এ, O(1) |
| পুরো sorted ক্রম | in-order-এ পাওয়া যায় | নেই, দেয়ও না |
| যেকোনো মান খোঁজা | O(log n), নিয়ম দিয়ে পথ বের হয় | O(n), সব ঘেঁটে দেখা লাগে |
| প্রধান কাজ | ordered dictionary (search/insert/delete) | priority queue (peek/extract) |

মনে রাখার কায়দা: **ক্রমের ব্যাপক প্রশ্নে BST, চরম মানের বারবার প্রশ্নে heap**। "সবচেয়ে ছোটটা বারবার দাও" শুনলে heap, "এই মানটা আছে কিনা" শুনলে BST (বা hash)।

## কোড: peek আর heap যাচাই

```js
const minHeap = [1, 3, 6, 5, 9, 8];

const peek = (heap) => (heap.length ? heap[0] : undefined);
console.log(peek(minHeap)); // 1: চরম মান মুহূর্তে, O(1)

// পুরোটা heap কিনা যাচাই: প্রতি parent-child জোড়া
function isMinHeap(heap) {
  for (let i = 0; i < heap.length; i++) {
    const left = 2 * i + 1;
    const right = 2 * i + 2;
    if (left < heap.length && heap[i] > heap[left]) return false;
    if (right < heap.length && heap[i] > heap[right]) return false;
  }
  return true;
}

console.log(isMinHeap(minHeap));       // true
console.log(isMinHeap([1, 3, 6, 5, 9, 2])); // false: 6 > 2
```

Index-এর সূত্র (`2i + 1` জাতীয়) এখানে উড়ে এসেছে, পরের পেজে তার পুরো দস্তুর।

## Complexity

| অপারেশন | খরচ | কেন |
|---------|------|-----|
| peek (চরম মান) | O(1) | root-এ তাকানো মাত্র |
| insert | O(log n) | গাছের height-টুকু ওঠা, [Insert](./heap-insert-bubble-up.mdx)-এ |
| extract | O(log n) | height-টুকু নামা, [Extract](./heap-extract-min.mdx)-এ |
| পুরোটা heap কিনা যাচাই | O(n) | সব জোড়া দেখা |
| যেকোনো মান খোঁজা | O(n) | ক্রমের ধারণা নেই, সব দেখা লাগে |

Height যে log n, তার ভিত্তি complete tree-এর আকৃতির শর্ত: ভরা গাছে n node মানে height ⌊log₂n⌋, [Tree Terminology](../trees/tree-terminology.mdx)-এর গোনার নিয়ম মনে আছে তো?

## সাধারণ ভুল আর edge case

**১. Heap-কে sorted array ভাবা।**
Heap-এ sibling-দের মধ্যে ক্রম নেই, দ্বিতীয় স্তরেও নেই। "Heap-এ তৃতীয় ছোটটা কোথায়?" প্রশ্নের উত্তর দিতে হলে কয়েকটা ঘর দেখতেই হয়, এক ঘরে নিশ্চয়তা নেই। ধারণাটা ঠিক করো: শুধু root-এর নিশ্চয়তা আছে।

**২. Min আর max গুলিয়ে ফেলা।**
তুলনার চিহ্ন একটাই বদলায়, কিন্তু পুরো আচরণ উল্টে যায়। Min-heap-এ ছোটটা root-এ; কোডে `<` দেখলে ভাবো "ছোট ওঠে উপরে"। শুরুতেই ঠিক করো কোনটা বানাচ্ছ।

**৩. Heap-এ যেকোনো মান O(log n)-এ খোঁজা যাবে ভাবা।**
না। নিয়মটা খোঁজার পথ বলে দেয় না, BST-র মতো "বামে যাও" নেই। Heap-এ ইচ্ছামতো মান খুঁজতে পুরো গাছ ঘোরা লাগে, O(n)। খোঁজা লাগলে heap ভুল অস্ত্র।

**৪. Complete-এর শর্ত ভুলে যাওয়া।**
Heap-এর সব হিসাব (index গণিত, O(log n)) দাঁড়িয়ে আছে গাছটা complete থাকার উপর। Insert/extract যেভাবে লিখবে, সেভাবেই আকৃতিটা complete থাকে, এটা নিজে হাতে ভাঙার চেষ্টা করবে না (মাঝখানের ঘর মুছে দেওয়া জাতীয়)।

**৫. Heap আর priority queue এক জিনিস ভাবা।**
Priority queue হলো **ধারণা** (জরুরি আগে), heap হলো তার একটা দক্ষ **বাস্তবায়ন**। [Priority Queue](../stacks-queues/priority-queue.mdx)-এ দেখেছিলে sort দিয়েও চলে, ধীরে। Heap তার দক্ষ রূপ, কিন্তু ধারণা আর কাঠামো আলাদা জিনিস।

## অনুশীলন

- **সহজ ১:** `[2, 5, 4, 9, 7, 6]` min-heap কিনা যাচাই করো হাতে, প্রতি জোড়া লিখে। ভাঙলে কোন জোড়ায়?
- **সহজ ২:** `[15, 10, 12, 4, 8]` max-heap কিনা দেখো। তারপর সেটাকে একটা মান বদলে max-heap বানাও।
- **মাঝারি ১:** বন্ধুকে বোঝাও: heap-এ কেন দ্বিতীয় ছোট মান নিশ্চিতভাবে index 1 বা 2-তেই থাকে, কিন্তু তৃতীয়টার জায়গা বলা যায় না।
- **মাঝারি ২:** একই সেট `{1, 3, 6, 5, 9, 8}` দিয়ে আরেকটা বৈধ min-heap বানাও (আকৃতি একই, বিন্যাস ভিন্ন)। কয়টা আলাদা বৈধ heap সম্ভব, ভাবো কেন।
- **কঠিন:** একটা function লেখো যা বলে দেয় কোনো array valid **max-heap** কিনা, তারপর সেটাকে এমনভাবে generalize করো যাতে comparator পাস করলেই min/max দুটোই চলে। এই comparator-ভাবনাটা পরে [MinHeap Class](./minheap-class.mdx)-এ ফিরে আসবে।

## সারসংক্ষেপ

- Heap = complete binary tree + heap property: parent আর child-এর একটাই সম্পর্ক।
- Min-heap-এ ছোটটা root-এ, max-heap-এ বড়টা; peek O(1)।
- Heap পুরো sorted না, sibling-দের ক্রম জানে না; কম শর্তেই কম খরচ।
- BST ক্রমের প্রশ্নে, heap চরম মানের প্রশ্নে; খোঁজার কাজে heap না।
- Insert/extract O(log n), কারণ ভরা গাছের height log n: পরের পেজগুলোতে সেই যান্ত্রিকতা।
