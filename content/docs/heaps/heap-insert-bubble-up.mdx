## কী শিখব

- Insert-এর দুই পর্ব: শেষে বসা, তারপর উপরে ভাসা
- Bubble up-এর পুরো dry run, প্রতি swap-এ heap কেমন দেখায়
- কেন root নয়, শেষেই বসাতে হয়: complete আকৃতি বাঁচানো
- কখন থামবে: থামার শর্ত আর তার সূক্ষ্মতা
- Complexity-র derivation আর ফাঁদগুলো

## ধারণা

ভাবো তো, একটা ভিড়ের লাইনে তুমি নতুন এসেছ। শুরুতে সবার পেছনেই দাঁড়াতে হবে, মাঝখানে ঢোকার নিয়ম নেই। Heap-এও insert শুরু হয় একইভাবে: নতুন মান বসে array-এর একদম **শেষে**, মানে গাছের পরের ফাঁকা ঘরে।

কেন মাঝে না, শেষেই? কারণ heap-কে **complete** রাখতেই হবে, আর complete গাছে নতুন ঘর একটাই জায়গায় জন্মাতে পারে: পরের level-order ঘরে, যা array-র শেষ। মাঝে ঢোকালে ফাঁক তৈরি হত, [Heap as Array](./heap-as-array.mdx)-এর সূত্রই ভেঙে যেত।

কিন্তু এখন সমস্যা: নতুন মানটা তার parent-এর চেয়ে ছোট হতে পারে (min-heap ধরছি), তাহলে নিয়ম ভাঙল। ফিক্স: parent-এর সঙ্গে swap, তারপর নতুন parent-এর সঙ্গে আবার তুলনা, দরকারে আবার swap। মানটা ফোমের মতো ভেসে ভেসে উপরে ওঠে, যতক্ষণ না নিয়ম মেনে যায়। এই প্রক্রিয়ার নাম **bubble up** (বা sift up)।

## Dry run: `[1, 3, 6, 5, 9]`-এ insert(2)

| ধাপ | কাজ | i | parent | তুলনা | heap-এর অবস্থা |
|-----|-----|---|--------|-------|------------------|
| 1 | শেষে push | 5 | - | - | `[1, 3, 6, 5, 9, 2]` |
| 2 | তুলনা | 5 | 2 (মান 6) | 6 > 2: **swap** | `[1, 3, 2, 5, 9, 6]` |
| 3 | তুলনা | 2 | 0 (মান 1) | 1 ≤ 2: নিয়ম ঠিক | অপরিবর্তিত, **থামো** |

মাত্র একটা swap। গাছের চোখে দেখো:

```text
আগে:        1              পরে:       1
          /   \                     /   \
         3     6                   3     2
        / \   /                   / \   /
       5   9 2(নতুন)             5   9 6
```

2 এসে 6-কে নিচে ঠেলে নিজে ওঠে গেল, আর গাছ complete-ই রইল, নিয়মও ফিরল।

## আরেকটা, শেষ পর্যন্ত: insert(0) একই heap-এ

| ধাপ | i | parent (মান) | তুলনা | অবস্থা |
|-----|---|--------------|-------|--------|
| push | 6 | - | - | `[1, 3, 2, 5, 9, 6, 0]` |
| 1 | 6 | 2 (মান 2) | 2 > 0: swap | `[1, 3, 0, 5, 9, 6, 2]` |
| 2 | 2 | 0 (মান 1) | 1 > 0: swap | `[0, 3, 1, 5, 9, 6, 2]` |
| 3 | 0 | - | i = 0, root | **থামো** |

0 একদম root পর্যন্ত ভেসে উঠল, দুই swap-এ। থামার দুই পথই দেখা গেল: হয় নিয়ম মিলল (আগেরটা), নয়তো root-এ পৌঁছে গেল (এটা)।

## কোড: নিজে বানাও insert

```js
function insert(heap, value) {
  heap.push(value);                  // পর্ব ১: শেষে বসাও (complete অক্ষত)

  let i = heap.length - 1;
  while (i > 0) {                    // root হলে থামো
    const p = Math.floor((i - 1) / 2); // parent-এর সূত্র

    if (heap[p] <= heap[i]) break;   // নিয়ম মিলেছে: থামো

    [heap[p], heap[i]] = [heap[i], heap[p]]; // না মিললে ভেসে ওঠো
    i = p;
  }
}

const h = [1, 3, 6, 5, 9];
insert(h, 2);
console.log(h); // [1, 3, 2, 5, 9, 6]
insert(h, 0);
console.log(h); // [0, 3, 1, 5, 9, 6, 2]
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `heap.push(value)` : পরের level-order ঘরে বসানো, মানে array-এর শেষে। আকৃতির শর্ত এই লাইনেই বেঁচে যায়।
2. `while (i > 0)` : থামার একটা পথ root। i = 0 হলে parent-ই নেই, থামতেই হবে।
3. `Math.floor((i - 1) / 2)` : [Heap as Array](./heap-as-array.mdx)-এর parent-সূত্র। সূত্র ভুললে অন্যের parent-এর সঙ্গে তুলনা চলবে, নিঃশব্দে ভুল heap।
4. `if (heap[p] <= heap[i]) break` : থামার দ্বিতীয় পথ, নিয়ম মিলে গেলে। সমানে থামাটা জরুরি: সমান মানে swap করলে অকাজে ঘোরে (আর stability-র প্রশ্নে অর্থহীন নড়াচাড়া)।
5. swap, তারপর `i = p` : মান উপরে উঠল, আর আমাদের দৃষ্টিও নতুন জায়গায় সরল, নইলে পরের তুলনা পুরনো ঘর নিয়ে চলত।

## Complexity: কেন ঠিক O(log n)

| দিক | খরচ | কেন |
|-----|------|-----|
| শেষে বসানো | O(1) amortized | `push`, [Array Operations](../arrays-strings/array-operations.mdx)-এর চেনা হিসাব |
| Bubble up | সর্বোচ্চ O(log n) | প্রতি swap এক স্তর ওঠে; গাছের height ⌊log₂n⌋, তার বেশি ওঠা অসম্ভব |
| মোট | **O(log n)** | দুটো মিলে |

Derivation-টা এক লাইনের: complete গাছে height log n, bubble up সর্বোচ্চ height-টুকু ওঠে, প্রতি স্তরে একটা তুলনা আর সর্বোচ্চ একটা swap। আর মজার ব্যাপার, বেশিরভাগ insert আসলে এক-দুই স্তরই ওঠে, কারণ নতুন মান যে root ছাড়িয়ে যাবে তার সম্ভাবনা কম। কিন্তু worst case-এর হিসাব log n-ই।

## সাধারণ ভুল আর edge case

**১. মাঝে বা শুরুতে বসানোর চেষ্টা।**
"ছোট মান, আগে বসাই" ভেবে `unshift` দিলে আকৃতি ভাঙে, সূত্র ভাঙে, সব ভাঙে। Insert-এর জায়গা একটাই: শেষ। নিয়ম ফেরানো bubble up-এর কাজ, তোমার হাতে বসানো না।

**২. `while (i >= 0)` লিখে root-এও তুলনা চালানো।**
i = 0 হলে parent সূত্র দেয় -1 জাতীয় index, `heap[-1]` হলো `undefined`, তুলনা গোলমাল। শর্ত `i > 0`, root-এ নিজে থেকেই থামো।

**৩. সমান মানে swap করা।**
`heap[p] < heap[i]` (strict) শর্তে চালালে সমান parent-childও swap হয়, অকাজে ঘোরে। নিয়মে "ছোট **বা সমান**" যথেষ্ট, `<=` দিয়ে break।

**৪. swap-এর পর `i` না বদলানো।**
মান উঠেছে, দৃষ্টি পড়ে রইল: পরের তুলনা পুরনো ঘর নিয়ে, ভুল জায়গায় থেমে যায় বা অনন্ত লুপ। প্রতি swap-এর সঙ্গে সঙ্গে `i = p`।

**৫. খালি heap-এর কেস ভুলে যাওয়া।**
প্রথম insert-এ `push` করলেই length 1, while চলেই না, ঠিক আছে। কিন্তু এটা "ভাগ্যবলে ঠিক", বোঝার জন্য নয়। খালি heap দিয়ে শুরু করে কয়েকটা insert হাতে dry run করো, প্রথম পাথরটা দেখো কেমনে বসে।

## Animation Spec

> **Animation Spec: Bubble Up**
>
> - **দৃশ্য:** tree আর array সিঙ্কে; নতুন node প্রথমে ধূসর, প্রতি swap-এ এক স্তর ওঠে, পথে হলুদ আলো।
> - **ইনপুট:** মান; speed; একটা প্রি-বানানো heap।
> - **ধাপ:** push-এ শেষে ঘর জন্মায়; তুলনা হলুদ, swap লাল ঝলক, থামলে সবুজ; পাশে swap কাউন্টার আর "সর্বোচ্চ সম্ভাব্য swap = height" দাগ।
> - **নিয়ন্ত্রণ:** step, play, reset।
> - **লক্ষ্য:** "শেষে বসো, নিয়মে ভেসে ওঠো", আর ওঠার পথ height ছাড়ে না, দুটোই চোখে দেখা।

## অনুশীলন

- **সহজ ১:** খালি heap-এ ক্রমে insert করো: 5, 3, 8, 1, 2। প্রতি ধাপে array লিখো। কোন insert-ে সবচেয়ে বেশি swap হলো?
- **সহজ ২:** `[2, 5, 4, 9, 7, 6]` heap-এ insert(1) হাতে করো: প্রতি তুলনা আর swap টেবিলে।
- **মাঝারি ১:** Max-heap-এর insert লেখো। কোন এক শর্ত বদলালে? দুই heap-এ একই সিকোয়েন্স চালিয়ে ফল তুলনা করো।
- **মাঝারি ২:** বন্ধুকে বোঝাও: কেন bubble up-এর থামার শর্ত দুটো (root বা নিয়ম-মেলা), আর একটা বাদ দিলে কী হয়।
- **কঠিন:** একটা unsorted array থেকে একে একে insert করে heap বানালে মোট খরচ কত? (হিন্ট: n-টা insert × O(log n) = O(n log n)। কিন্তু একটাই heap বানানোর আরও সস্তা উপায় আছে, O(n), heapify-পদ্ধতিতে, [Heap Sort](../sorting/heap-sort.mdx)-এর build-পর্বে সেটাই হয়। তফাতটা কেন আসে ভেবে দেখো।)

## সারসংক্ষেপ

- Insert দুই পর্বের: শেষে বসাও (complete বাঁচে), তারপর bubble up (নিয়ম বাঁচে)।
- Bubble up: parent ছোট/সমান না হলে swap, উপরে উঠতে থাকো; থামো নিয়ম মিললে বা root-এ।
- সর্বোচ্চ log n swap, কারণ পথটা গাছের height; মোট O(log n)।
- থামার দুই শর্তই জরুরি: `i > 0` আর `heap[p] <= heap[i]`; সমানে থামো।
- মাঝে বসানো নিষেধ: জায়গা বেছে নেয় কাঠামো, তুমি শুধু নিয়ম ফেরাও।
