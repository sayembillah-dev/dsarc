## কী শিখব

- heap কেন array দিয়ে বানানো হয়, আর index-এর সূত্রগুলো কী

## ধারণা

Tree বানাতে গেলে সাধারণত node, pointer, left, right এই সব লাগে, তাই না? কিন্তু heap তো একটা **complete binary tree**; কোথাও ফাঁকা ঘর থাকে না। এই একটা গুণের জন্যেই দারুণ সুবিধা মেলে: কোনো pointer ছাড়াই পুরো tree-টা একটা সাধারণ **array**-তে গুঁজে ফেলা যায়। শুধু index-এর একটু অঙ্ক জানলেই চলবে:

- index `i`-এর **বাঁ চাইল্ড:** `2i + 1`
- index `i`-এর **ডান চাইল্ড:** `2i + 2`
- index `i`-এর **parent:** `Math.floor((i - 1) / 2)`

সহজ কথায়, কোনো node কোন ঘরে বসে আছে জানলেই তার parent আর চাইল্ডরা কোথায় আছে, সেটা হিসাব করেই বের হয়ে যায়।

```
array:  [1, 3, 6, 5, 9]
index:   0  1  2  3  4
tree:        1(0)
            /     \
         3(1)     6(2)
         /  \
      5(3)  9(4)
```

## কোড উদাহরণ

```js
const heap = [1, 3, 6, 5, 9];
const i = 1;                       // মান 3
console.log(heap[2 * i + 1]);      // বাঁ চাইল্ড: 5
console.log(heap[2 * i + 2]);      // ডান চাইল্ড: 9
console.log(heap[Math.floor((i - 1) / 2)]); // parent: 1
```

## কোড ব্রেকডাউন

- array-তে উপাদানগুলো memory-তে পাশাপাশি বসে থাকে, তাই cache-এর জন্যেও দারুণ।
- আর tree-এ উপরে-নিচে ঘোরা হয় শুধু index-এর অঙ্ক দিয়ে; pointer রেখে দেওয়ার ঝামেলাই নেই।

## Complexity

- parent বা child বের করতে যা লাগে, তা দুটো গুণ-ভাগ, মানে O(1)।
