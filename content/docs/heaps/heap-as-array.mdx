## কী শিখব

- কেন heap-ই array-তে বসে, অন্য tree না
- তিনটা সূত্র: left, right, parent, আর সেগুলো কোথা থেকে আসে
- পুরো dry run: array থেকে গাছ, গাছ থেকে array
- 0-based বনাম 1-based: দুই রেওয়াজ, দুই সূত্র
- এই ম্যাপিং কেন cache-বান্ধব আর মেমরি-সাশ্রয়ী

## ধারণা

Tree বানাতে গেলে সাধারণত node, `left`, `right` pointer এইসব লাগে, [Tree](../trees/tree-terminology.mdx)-এ দেখেছ। কিন্তু heap-এর একটা বিশেষ গুণ আছে: সে **complete**, কোথাও ফাঁকা ঘর নেই। এই এক গুণের কারণেই pointer-এর ঝামেলা পুরো বাদ পড়ে যায়।

কৌশলটা সরল: গাছের node-গুলোকে **level-order-এ নম্বর দাও**, উপর থেকে নিচে, বাম থেকে ডানে, 0 থেকে শুরু করে। Complete গাছে এই নম্বরগুলো একদম গোছানো: 0, 1, 2, 3..., কোনো লাফ নেই। এবার নম্বরগুলোই array-এর index বানিয়ে দাও, গাছ বসে গেল array-তে।

```text
tree:          1              array: [ 1, 3, 6, 5, 9 ]
             /   \            index:   0  1  2  3  4
            3     6
           / \
          5   9
```

## সূত্র তিনটা, আর কোথা থেকে এল

নম্বর দেওয়ার নিয়মটাই সূত্র বানিয়ে দেয়। ভাবো, প্রতি স্তরে node দ্বিগুণ হয়: স্তর 0-এ ১টা (index 0), স্তর 1-এ ২টা (index 1, 2), স্তর 2-এ ৪টা (3, 4, 5, 6)। তাই index `i`-এর দুই child পায় পরের স্তরের পরপর দুই ঘর:

| সম্পর্ক | সূত্র | যাচাই (i = 1, মান 3) |
|---------|-------|------------------------|
| বাম child | `2i + 1` | `2×1 + 1 = 3` → মান 5 |
| ডান child | `2i + 2` | `2×1 + 2 = 4` → মান 9 |
| parent | `Math.floor((i - 1) / 2)` | `floor(0/2) = 0` → মান 1 |

উল্টো সূত্রটাও যুক্তি দিয়ে যাচাই করো: child `2i + 1` কে parent-সূত্রে ফেলো, `floor((2i + 1 - 1) / 2) = floor(2i/2) = i`, ফিরে এসে পেলে নিজেকে। দুই সূত্র একে অন্যকে মেলে ধরে।

মনে রাখার কায়দা: **দ্বিগুণ করে এক-দুই যোগ** (নামার পথে), **এক কমিয়ে অর্ধেক** (ওঠার পথে)।

## Dry run: পুরো গাছে সূত্র বসানো

`[1, 3, 6, 5, 9]`-এর প্রতি index-এ:

| index | মান | parent | left child | right child |
|-------|-----|--------|------------|-------------|
| 0 | 1 | - (root) | 1 (মান 3) | 2 (মান 6) |
| 1 | 3 | 0 (মান 1) | 3 (মান 5) | 4 (মান 9) |
| 2 | 6 | 0 (মান 1) | 5 (নেই) | 6 (নেই) |
| 3 | 5 | 1 (মান 3) | 7 (নেই) | 8 (নেই) |
| 4 | 9 | 1 (মান 3) | 9 (নেই) | 10 (নেই) |

সূত্র যে index-ই দিক, সেটা array-এর সীমার মধ্যে আছে কিনা দেখতে হয়, নইলে child নেই। এই চেক ছাড়া `heap[7]` পড়তে গিয়ে `undefined` পাবে।

## কোড: সূত্রগুলো হাতে কলমে

```js
const heap = [1, 3, 6, 5, 9];

const leftChild = (i) => 2 * i + 1;
const rightChild = (i) => 2 * i + 2;
const parent = (i) => Math.floor((i - 1) / 2);

const i = 1; // মান 3
console.log(heap[leftChild(i)]);   // 5
console.log(heap[rightChild(i)]);  // 9
console.log(heap[parent(i)]);      // 1

// নিরাপদে: সীমা চেক সহ
const child = (heap, i) =>
  i < heap.length ? heap[i] : undefined;
console.log(child(heap, leftChild(2))); // undefined: 2-এর child নেই
```

## কেন এই ম্যাপিং এত দামি

- **Pointer শূন্য:** node-এ তিনটা field (value, left, right) বাঁচল, শুধু মানটাই রইল। মেমরি কম, কোড সরল।
- **Cache-বান্ধব:** array-এ উপাদান memory-তে পাশাপাশি ([Array Basics](../arrays/array-basics.mdx)-এর contiguous কথা মনে আছে?)। নিচে নামার পথে ঘরগুলো কাছাকাছি থাকে, pointer-গাছের ছড়ানো ঘরের চেয়ে cache-এ ভালো খেলে।
- **Complete হওয়াই শর্ত:** ফাঁকা থাকলে নম্বর লাফ দেয়, সূত্র ভেঙে যায়। তাই heap-এর insert/extract এমনভাবে লেখা হয় যাতে আকৃতি complete-ই থাকে, পরের দুই পেজে সেটাই দেখবে।

## 1-based রেওয়াজ: আরেক সূত্র-সেট

কোথাও কোথাও (বই, প্রতিযোগিতার সমাধান) heap 1 থেকে গোনা হয়, index 0 ফাঁকা রেখে। তখন সূত্র আরও গোলমেলে:

```text
left = 2i, right = 2i + 1, parent = floor(i / 2)
```

দুই সেট সূত্র একই কাজ করে, শুধু গোনা কোথা থেকে। আমরা 0-based-এই থাকছি (JavaScript-এ স্বাভাবিক), কিন্তু অন্যের কোড পড়লে চিনবে: সূত্র ভিন্ন দেখালেই ভেবো না ভুল, আগে দেখো কোন রেওয়াজ।

## সাধারণ ভুল আর edge case

**১. Child সূত্রে `2i` লেখা।**
0-based-এ left child হলো `2i + 1`, `2i` না। `2i` হলো 1-based-এর সূত্র। রেওয়াজ গুললে গাছ অন্য গ্রহে চলে যায়, আর error আসে না, ফল নিঃশব্দে ভুল হয়।

**২. Parent-এ `(i / 2)` লেখা।**
দুই ভুল একসাথে: ভগ্নাংশ (`1 / 2 = 0.5`) আর ভুল অভিমুখ। নিরাপদ রূপ `Math.floor((i - 1) / 2)`। i = 0 (root) হলে ফল -0.5-এর floor = -1, মানে parent নেই, এই কেসটাও আলাদা ভাবো।

**৩. সীমা চেক না করে সূত্রে পাওয়া index পড়া।**
সূত্র index দেবেই, সেটা array-এর বাইরে হতে পারে। `heap[leftChild(i)]` পড়ার আগে `< heap.length` দেখো, নইলে `undefined` নিয়ে তুলনা চলবে, নিয়ম ভাঙা-অনুযায়ী আচরণ হবে।

**৪. ভাবা যে যেকোনো tree এভাবে বসে।**
না। Complete না হলে ফাঁকার জন্য null ঢোকাতে হয়, সূত্র আর সরাসরি থাকে না। এই কৌশল heap (এবং complete গাছ) নির্দিষ্ট, সাধারণ BST-তে না।

**৫. Min/max গুলে সূত্রও বদলে যাওয়ার ভাবনা।**
Index-গণিত heap-এর ধরনের (min/max) উপর নির্ভর করে না, ওটা শুধু তুলনার চিহ্ন। সূত্র একই, আকৃতি একই, বদলায় শুধু কে উপরে থাকে।

## অনুশীলন

- **সহজ ১:** `[10, 20, 15, 40, 50, 100]` heap ধরো। index 1 আর 2-এর parent ও child-গুলো সূত্র দিয়ে বের করো, ছবি এঁকে মিলাও।
- **সহজ ২:** শেষ উপাদানের (index n-1) parent কে? সূত্র দেখাও। এই তথ্যটা পরে insert-এ লাগবে, কেন লাগবে ভাবো।
- **মাঝারি ১:** n-টা উপাদানের heap-এ কতগুলো leaf আছে? (হিন্ট: যাদের `2i + 1 >= n`, তারা leaf। প্রথম non-leaf কোন index-এ? উত্তর: leaf প্রায় অর্ধেক, `Math.floor(n/2)` থেকে শেষ পর্যন্ত।)
- **মাঝারি ২:** 1-based রেওয়াজে একই তিন সূত্র নিজে বের করো, নম্বর দেওয়ার নিয়ম থেকে। তারপর দুই রেওয়াজে `[1, 3, 6, 5, 9]`-এর index 2-এর child বের করে দেখাও মিলে কিনা।
- **কঠিন:** প্রমাণ করো: complete binary tree-তে height = ⌊log₂n⌋। (হিন্ট: h স্তর পর্যন্ত ভরা গাছে node 2ʰ⁺¹ - 1। অসমতা লেখো 2ʰ ≤ n < 2ʰ⁺¹, তারপর log নাও।)

## সারসংক্ষেপ

- Complete গাছকে level-order-এ গুনে array-তে বসালে pointer-ই লাগে না।
- তিন সূত্র: left `2i + 1`, right `2i + 2`, parent `floor((i - 1) / 2)`; নামায় দ্বিগুণ, ওঠায় অর্ধেক।
- সূত্র সবসময় index দেয়, বৈধ কিনা সীমা দেখে নিজে চেক করা তোমার কাজ।
- 1-based রেওয়াজে সূত্র ভিন্ন (`2i`, `2i + 1`, `floor(i/2)`), কাজ একই।
- এই ম্যাপিং-ই পরের insert/extract-এর ভিত্তি, আর সেখানেই দেখবে কেন complete রাখা এত জরুরি।
