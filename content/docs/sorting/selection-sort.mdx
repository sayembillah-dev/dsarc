## কী শিখব

- Selection sort-এর নিয়ম: বাকি অংশের সর্বনিম্ন খুঁজে সামনে বসানো
- পুরো dry run: প্রতি pass-এ min খোঁজা, একবার swap
- কেন swap সর্বোচ্চ n-1 টা, কিন্তু তুলনা তবু O(n²)
- কেন selection sort unstable, একটা জ্বলন্ত উদাহরণ
- কোন বিশেষ পরিস্থিতিতে এটা আসলে দরকারি

## ধারণা

ধরো, টেবিলে কয়েনের গাদা, সাজাতে হবে ছোট থেকে বড়। তুমি পুরো গাদা ঘেঁটে সবচেয়ে ছোট কয়েনটা তুলে একদম বাঁয়ে রাখলে। তারপর বাকিগুলোর মধ্যে আবার সবচেয়ে ছোটটা খুঁজে তার পাশে বসালে। এভাবে শেষ পর্যন্ত।

Selection Sort এই কায়দাতেই চলে। [Bubble Sort](./bubble-sort.mdx)-এর সঙ্গে পার্থক্যটা ভালো করে বুঝো: bubble প্রতি তুলনায় swap করতে পারে (বড়টা ভেসে যায়), কিন্তু selection **পুরো pass জুড়ে শুধু খোঁজে**, সর্বনিম্নটা পেলে তখন একবারই swap করে। খোঁজা অনেক, সরানো কম, এই চরিত্রটাই এর পরিচয়।

## Dry run: `[64, 25, 12, 22, 11]`

| Pass | খোঁজার পরিসর | সর্বনিম্ন | swap | array-এর অবস্থা |
|------|----------------|-----------|------|------------------|
| 1 | index 0-4 | 11 (index 4) | 64 ↔ 11 | `[11, 25, 12, 22, 64]` |
| 2 | index 1-4 | 12 (index 2) | 25 ↔ 12 | `[11, 12, 25, 22, 64]` |
| 3 | index 2-4 | 22 (index 3) | 25 ↔ 22 | `[11, 12, 22, 25, 64]` |
| 4 | index 3-4 | 25 (index 3) | নিজেই নিজের জায়গায় | `[11, 12, 22, 25, 64]` |

প্রতি pass-এ দুটো ভাগ স্পষ্ট: বাম অংশ sorted (প্রতি pass-এ এক ঘর বাড়ে), ডান অংশ অসম্বলিত। আর খেয়াল করো, pass মাত্রে swap হয়েছে একটা করে, যেখানে bubble-এ একই ডেটায় অনেকগুলো swap লাগত।

## কোড: নিজে বানাও selectionSort

```js
function selectionSort(arr) {
  const n = arr.length;

  for (let i = 0; i < n - 1; i++) {
    let minIndex = i;                          // এবারের চ্যাম্পিয়ন: i নিজে

    for (let j = i + 1; j < n; j++) {          // বাকি সবার মধ্যে খোঁজ
      if (arr[j] < arr[minIndex]) {
        minIndex = j;                          // নতুন চ্যাম্পিয়ন
      }
    }

    if (minIndex !== i) {                      // দরকার হলেই শুধু swap
      [arr[i], arr[minIndex]] = [arr[minIndex], arr[i]];
    }
  }

  return arr;
}

console.log(selectionSort([64, 25, 12, 22, 11])); // [11, 12, 22, 25, 64]
```

চ্যাম্পিয়ন খোঁজার অংশটা চেনা লাগছে? এটা হুবহু [Traversal](../arrays/traversal.mdx)-এর running aggregate প্যাটার্ন: পুরো অংশ একবার ঘুরে সর্বনিম্নের index মনে রাখা।

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `let minIndex = i` : চ্যাম্পিয়ন শুরু হয় i নিজেকে ধরে, array-এর ভেতর থেকে। `0` বা অন্য কিছু ধরে শুরু করলে সেই পুরনো ফাঁদ, [Traversal](../arrays/traversal.mdx)-এর ভুলে যাওয়া কথা না।
2. ভেতরের loop `i + 1` থেকে : i-এর বামে সব sorted, সেখানে খোঁজার কিছু নেই। পরিসর প্রতি pass-এ এক ঘর করে ছোট হয়।
3. শুধু index মনে রাখা, swap না : পুরো pass জুড়ে তুলনাই চলে, হাতে কিছু নড়ে না। Swap একবার, খোঁজা শেষে।
4. `if (minIndex !== i)` : চ্যাম্পিয়ন যদি i নিজেই হয়, swap অর্থহীন। এই চেক না থাকলেও উত্তর ঠিক আসত, কিন্তু নিজের সঙ্গে নিজের swap অপ্রয়োজনী।

## Complexity

| কেস | Time | কেন |
|-----|------|-----|
| Worst | O(n²) | খোঁজা তো লাগেই |
| Average | O(n²) | একই |
| Best (ইতিমধ্যে sorted) | O(n²) | sorted হলেও সর্বনিম্ন **খুঁজতেই** হবে, early exit নেই |
| Space | O(1) | in-place |
| Swap | সর্বোচ্চ n-1 | প্রতি pass-এ একটা |

দুটো হিসাব আলাদা করে দেখো। তুলনা: pass ১-এ n-1, pass ২-এ n-2, ..., মোট n(n-1)/2 = O(n²), এটা সব কেসে একই, কারণ খোঁজা বাদ দেওয়ার উপায় নেই। কিন্তু swap সর্বোচ্চ n-1 টা। তাই যে সিস্টেমে **লেখা ব্যয়বহুল** (যেমন EEPROM, ফ্ল্যাশ মেমরি, যেখানে বারবার লিখলে জীবন কমে), সেখানে selection sort-এর এই "কম লেখা" গুণ আসল মূল্য।

আর best case-এ O(n²) থাকাটা লক্ষ করো: sorted array দিলেও এটা পুরো খোঁজা চালায়। এই দিকে [Insertion Sort](./insertion-sort.mdx) ঠিক উল্টো।

## কেন unstable: একটা প্রমাণ

ধরো `[5A, 3, 5B, 2]` (A আর B দুটো 5 চিহ্নিত)। Pass ১-এ সর্বনিম্ন 2, সে index 0-এর 5A-এর সঙ্গে swap হয়: `[2, 3, 5B, 5A]`। দেখো, 5B এখন 5A-এর **আগে** চলে গেছে, অথচ শুরুতে পিছনে ছিল। ক্রম উল্টে গেল, অর্থাৎ unstable।

কারণটা বোঝো: swap লাফ দিয়ে ঘটে, i থেকে minIndex-এ, মাঝখানের সবাইকে লাফিয়ে। এই লাফটাই সমানদের ক্রম নষ্ট করে। Bubble sort-এ swap পাশাপাশি ঘরে হয়, কাউকে লাফায় না, তাই সে stable। একই কাজ, swap-এর ধরনে স্বভাব বদলে যায়, সুন্দর পার্থক্য তাই না?

## সাধারণ ভুল আর edge case

**১. ভেতরের loop শুরু `0` থেকে করা।**
`j = 0` থেকে শুরু করলে sorted অংশের উপাদানও খোঁজায় পড়ে, আর তাদের চেয়ে ছোট কিছু পেলে sorted অংশের ভেতরেই swap ঢুকে যায়, সব নষ্ট। খোঁজা সবসময় `i + 1` থেকে।

**২. মান মনে রাখা, index না।**
`let min = arr[i]` রেখে তুলনা করলে শেষে জানো সর্বনিম্ন **কী**, কিন্তু **কোথায়** জানো না, swap করবে কার সঙ্গে? চ্যাম্পিয়নের index মনে রাখতে হয়।

**৩. ভাবা যে best case-এ দ্রুত হবে।**
Bubble-এর `swapped`-এর মতো কোনো early exit এখানে নেই। Sorted ডেটাতেও পুরো O(n²) খোঁজা চলে। "ডেটা প্রায় sorted" শুনলে selection নয়, insertion।

**৪. Stability লাগা জায়গায় selection sort লাগানো।**
Record-এর তালিকা (নাম + grade ঘরানার) সাজাতে গিয়ে selection sort সমানদের ক্রম উল্টে দেবে। Stability লাগলে merge বা insertion, বা built-in `sort()`।

**৫. n-1 pass-এর বদলে n pass চালানো।**
শেষ উপাদানের জন্য pass লাগে না, বাকি সবাই ঠিক হলে সে নিজেই ঠিক। `i < n` দিলে শেষ pass-এ `minIndex = i = n-1`, কিছুই হয় না, শুধু এক পাস অপচয়। অপরিণত ভুল, কিন্তু সীমা বোঝার লক্ষণ।

## অনুশীলন

- **সহজ ১:** `[29, 10, 14, 37, 13]`-এ প্রথম তিন pass হাতে লিখো: প্রতি pass-এ minIndex কোথায় দাঁড়াল, swap কী হলো।
- **সহজ ২:** সর্বোচ্চ কয়টা swap হতে পারে n উপাদানে? কোন input-এ তা ঘটে, একটা উদাহরণ দাও।
- **মাঝারি ১:** Selection sort-কে বদলাও যাতে প্রতি pass-এ সর্বনিম্নের বদলে **সর্বোচ্চটা শেষে** বসে। দুই রূপের তুলনা-সংখ্যা একই থাকে কিনা যুক্তি দাও।
- **মাঝারি ২:** দেখাও (উদাহরণ বানিয়ে) যে selection sort কখনও swap শূন্যটা করতে পারে sorted array-তে, তবু তুলনা পুরোই করে। এই পর্যবেক্ষণ থেকে বলো, কোন পরিস্থিতিতে selection sort-এর আসলে দাম নেই?
- **কঠিন:** Selection sort-কে stable বানানো যায়, যদি swap না করে সর্বনিম্নটাকে **সরিয়ে** সামনে ঢোকাও (বাকিরা এক ঘর ডানে)। লেখো এই version, তারপর হিসাব করো: stable হলো ঠিকই, কিন্তু কোন খরচটা এবার বাড়ল? (হিন্ট: সরানো মানে আবার O(n) প্রতি pass। মোট কী দাঁড়াল?)

## সারসংক্ষেপ

- Selection sort: প্রতি pass-এ বাকি অংশের সর্বনিম্ন খুঁজে সামনে একবার swap।
- তুলনা সব কেসে O(n²), early exit নেই; কিন্তু swap সর্বোচ্চ n-1, লেখা-ব্যয়বহুল জায়গায় এটাই মূল্য।
- লাফ দিয়ে swap হয় বলে unstable; সমান record-এর ক্রম নষ্ট হয়।
- চ্যাম্পিয়নের index মনে রাখো, মান না; খোঁজা শুরু `i + 1` থেকে।
- "প্রায় sorted" ডেটায় এর কোনো সুবিধা নেই, সেখানে পরের পেজের insertion-ই রাজা।
