## কী শিখব

- Cycle sort কেন তৈরি: যেখানে মেমরিতে **লেখা** ব্যয়বহুল, তুলনা সস্তা
- মূল কৌশল: "আমার চেয়ে ছোট কতজন" গুনে সরাসরি চূড়ান্ত ঘরে বসা, উচ্ছিষ্ট হাতে নিয়ে চক্র চালানো
- চক্র (cycle) কীভাবে ঘোরে আর কখন বন্ধ হয়, পুরো dry run
- কেন এটা তাত্ত্বিকভাবে প্রায় লেখা-ন্যূনতম, আর সেই জয়ের বিনিময়ে কী দিতে হয়
- [Cyclic Sort](../problem-solving/cyclic-sort.mdx) প্যাটার্নের সঙ্গে সামঞ্জস্য আর পার্থক্য

## ধারণা

এতদিন sort বিচার করেছ time, space, stability দিয়ে। চতুর্থ এক মাপকাঠি আছে, যেটা ভুলে যাওয়া সহজ: **মেমরিতে কতবার লেখা হলো।** Flash memory আর EEPROM-এর প্রতিটা ঘরের লেখার সীমিত জীবন — কয়েক লক্ষ বার লেখার পর ঘরটা নষ্ট। এমন জায়গায় [Quick Sort](./quick-sort.mdx)-এর swap-উৎসব আসলে হত্যাকাণ্ড: একটা swap মানে অন্তত দুই-তিনবার লেখা।

Cycle sort এই সংকটেরই সন্তান। আইডিয়া: যদি প্রতিটা উপাদানের **চূড়ান্ত ঘরটা আগেই জেনে যাই**, তাহলে তাকে সরাসরি সেখানে একবারই লিখতে পারি — swap-এর বারবার আসা-যাওয়ার দরকারই নেই। ঘর জানার উপায়টা সরল: **আমার চেয়ে ছোট যতজন, আমার ঘর তত নম্বরে।** অবশ্য যার ঘরে বসলাম, সে তখন উচ্ছিষ্ট — তাকে হাতে নিয়ে তার ঘর খুঁজে বসাতে হবে, তার উচ্ছিষ্টকে আবার... এই শৃঙ্খলটাই একটা **চক্র (cycle)**, আর চক্র বন্ধ হয় যখন কেউ এসে পড়ে সেই ঘরে, যেখান থেকে চক্র শুরু হয়েছিল।

মনে রাখো, এটা comparison-ভিত্তিক sort-ই — তুলনা দিয়েই "ছোট কতজন" গুনে। এটা [Counting](./counting-sort.mdx) বা [Bucket](./bucket-sort.mdx)-এর তুলনাহীন দলের নয়; এর জয়ের জায়গা অন্যখানে: লেখার সংখ্যা।

## ধাপে ধাপে: দুই চক্রের পুরো খেলা

Array: `[4, 3, 2, 1]`। প্রতিটা `start`-এ: item তুলে নাও, তার ডানদিকে ছোট গুনে `pos` বের করো, সেই ঘরে লেখো, উচ্ছিষ্ট হাতে নিয়ে চক্র চালাও।

| ধাপ | start | item | pos কীভাবে এলো | লেখা | array-এর অবস্থা |
|-----|-------|------|-----------------|------|------------------|
| শুরু | - | - | - | 0 | `[4, 3, 2, 1]` |
| 1 | 0 | 4 | ছোট ৩ জন → pos 3 | arr[3] ← 4 (হাতে 1) | `[4, 3, 2, 4]` |
| 2 | 0 | 1 | ছোট ০ জন → pos 0 = start, **চক্র বন্ধ** | arr[0] ← 1 (হাতে 4 — সে তো index 3-এ বসেই আছে) | `[1, 3, 2, 4]` |
| 3 | 1 | 3 | ডানে ছোট ১ জন (2) → pos 2 | arr[2] ← 3 (হাতে 2) | `[1, 3, 3, 4]` |
| 4 | 1 | 2 | ডানে ছোট ০ জন → pos 1 = start, **চক্র বন্ধ** | arr[1] ← 2 | `[1, 2, 3, 4]` |

মোট লেখা: **৪ বার**, চারটা উপাদানের জন্য। চেহারায় গোলমেলে মাঝপথের `[4, 3, 2, 4]` বা `[1, 3, 3, 4]` ভুল মনে হতে পারে — অস্থির হইও না: চক্র চলাকালীন হাতে থাকা item-টাই সেই "হারানো" উপাদান, চক্র বন্ধ হলেই সে তার ঘরে গিয়ে বসে।

প্রতি লেখায় উপাদান সরাসরি চূড়ান্ত ঘরে গিয়ে বসছে, আর সে ঘর আর কখনো ছোঁয়া হয় না। এই কারণেই মোট লেখা প্রায় n — swap-ভিত্তিক sort-এ যেখানে একই কাজে কয়েক গুণ বেশি লেখা যায় (selection sort-এর n−1 swap-ই আসলে প্রায় ২গুণ লেখা, bubble তো কথাই নেই)।

## কোড: পুরো implementation

```js
function cycleSort(arr) {
  let writes = 0;                       // লেখার হিসাব — এই sort-এর আসল ট্রফি

  for (let start = 0; start < arr.length - 1; start++) {
    let item = arr[start];

    let pos = start;                    // আমার চেয়ে ছোট কতজন?
    for (let i = start + 1; i < arr.length; i++) {
      if (arr[i] < item) pos++;
    }
    if (pos === start) continue;        // আমি আমার ঘরেই আছি, লেখা শূন্য

    while (item === arr[pos]) pos++;    // duplicate: সমানদের পরের খালি ঘরে
    [arr[pos], item] = [item, arr[pos]]; // সরাসরি চূড়ান্ত ঘরে লেখা
    writes++;

    while (pos !== start) {             // চক্র বন্ধ না হওয়া পর্যন্ত
      pos = start;
      for (let i = start + 1; i < arr.length; i++) {
        if (arr[i] < item) pos++;
      }
      while (item === arr[pos]) pos++;  // duplicate-এর একই রক্ষা
      [arr[pos], item] = [item, arr[pos]];
      writes++;
    }
  }
  return writes;
}

const a = [4, 3, 2, 1];
console.log(cycleSort(a), a);  // 4, [1, 2, 3, 4]

const sorted = [1, 2, 3, 4];
console.log(cycleSort(sorted)); // 0 — already sorted মানে একটাও লেখা নেই
```

## কোড ব্রেকডাউন, লাইনে লাইনে

1. `for (let start = 0; ...)` : প্রতিটা `start` আসলে একটা সম্ভাব্য চক্রের দরজা। `start`-এর বামের অংশ ইতিমধ্যে চূড়ান্ত — তাই ছোট গোনা হয় শুধু ডানদিকে।
2. ছোট-গোনার লুপ: `pos = start + (আমার চেয়ে ছোটদের সংখ্যা)` — এই সূত্রটাই পুরো অ্যালগরিদমের মেরুদণ্ড।
3. `if (pos === start) continue` : উপাদান আগে থেকেই ঠিক ঘরে — **শূন্য লেখা**। প্রায়-sorted ডেটায় এ জন্যই লেখা কমে যায়।
4. `while (item === arr[pos]) pos++` : সমান মান আগে থেকে বসে থাকলে পরের ঘরে যাও। এই লাইন ছাড়া duplicate input-এ উপাদান হারিয়ে যাবে।
5. `[arr[pos], item] = [item, arr[pos]]` : destructuring swap দেখায়, কিন্তু ধারণা ভুলো না — লেখা হয় একটাই ঘরে (`arr[pos]`), উচ্ছিষ্টটা রেজিস্টারের মতো হাতে (ভেরিয়েবলে) চলে যায়।
6. `while (pos !== start)` : উচ্ছিষ্টের ঘর খুঁজতে খুঁজতে কেউ যখন `start`-এ ফিরে আসে, চক্র সম্পূর্ণ — হাতে থাকা শেষ item-টাই `start`-এর আসল বাসিন্দা ছিল।

## Complexity: সময়ের বিনিময়ে লেখা-মুক্তি

| দিক | মান | কেন |
|-----|-----|-----|
| Time (সব কেসে) | O(n²) | প্রতি `start` আর চক্র-ধাপে ছোট-গোনার পুরো scan |
| Space | O(1) | পুরোপুরি in-place, বাড়তি শুধু কয়েকটা ভেরিয়েবল |
| লেখার সংখ্যা | প্রায় n (প্রতি চক্রে +১) | প্রতিটা উপাদান একবারই চূড়ান্ত ঘরে লেখা হয় |
| Stable | না | লাফ দিয়ে বসানো সমানদের ক্রম নষ্ট করে |

তাহলে কবে এটা জেতে? যখন **লেখা এত দামী যে O(n²) তুলনাও সস্তা লাগে** — EEPROM, পুরনো flash, কিংবা লেখা-গোনা হার্ডলিমিটওয়ালা embedded জগৎ। সাধারণ RAM-এর দুনিয়ায় [Selection Sort](./selection-sort.mdx)-এর O(n²) আর এর O(n²) প্রায় সমকক্ষ, আর প্রয়োজনে [Heap Sort](./heap-sort.mdx)-এর in-place O(n log n) আছেই।

আত্মীয়তার ছবিটা পরিষ্কার রাখো: [Cyclic Sort](../problem-solving/cyclic-sort.mdx) প্যাটার্ন হলো এই ধারণার বিশেষ সুখবর — range হুবহু 1..n জানা থাকলে "ছোট কতজন" গোনাই লাগে না, মান v-এর ঘর হুবহু `v - 1`, ফলে O(n) সময়। Cycle sort সাধারণ মানের জন্য, দাম O(n²), পুরস্কার লেখা-ন্যূনতমতা। আর [Counting Sort](./counting-sort.mdx)-ও মান দেখে ঘর খোঁজে, কিন্তু সে count array কিনে নেয় O(k) জায়গায় — তিনজন মিলে একই "ঘর-জ্ঞানের" তিন রকম দাম।

## সাধারণ ভুল আর edge case

**১. লেখার বদলে swap-এ ফিরে যাওয়া।**
উচ্ছিষ্টকে temp-এ রেখে পুরো swap-নৃত্য করলে লেখা দ্বিগুণ — cycle sort বানিয়ে তারই সারমর্ম নষ্ট করা। উচ্ছিষ্ট থাকবে ভেরিয়েবলে, লেখা হবে শুধু চূড়ান্ত ঘরে।

**২. Duplicate-এর `while` লাইন বাদ দেওয়া।**
সমান মান থাকলে `item === arr[pos]` ঘরে বসাতে গিয়ে উপাদান পুরোপুরি হারিয়ে ফেলবে। `[8, 5, 2, 9, 5, 6, 3]` দিয়ে টেস্ট করো — duplicate ছাড়া ভাবা cycle sort অসম্পূর্ণ।

**৩. ছোট-গোনা পুরো array-তে করা।**
`start`-এর বামের অংশ চূড়ান্ত হয়ে গেছে; সেখানে গুনলে `pos` বড় হয়ে গিয়ে উপাদান এমন ঘরে বসবে যা আবার ছুঁতে হবে — লেখা-ন্যূনতমতা চুকচুক। গোনা শুধু `start + 1` থেকে।

**৪. এটাকে "দ্রুত sort" ভাবা।**
সময় O(n²), কোনো ছাড় নেই। এর জয় মেট্রিক্স অন্য: লেখার সংখ্যা। দুটো মেট্রিক্স গুলিয়ে ফেললে interview-তেও, embedded প্রজেক্টেও বিপদ।

**৫. Stability আশা করা।**
লাফ দিয়ে সরাসরি ঘরে বসানো সমান মানের ক্রম উল্টে দিতে পারে। Stability লাগলে এই লেনে নয় — [Merge Sort](./merge-sort.mdx)।

## অনুশীলন

- **সহজ ১:** `[5, 2, 8, 3]`-এ হাতে পুরো dry run চালাও: প্রতি লেখায় array-এর অবস্থা আর মোট লেখা কত, লিখো।
- **সহজ ২:** `cycleSort`-এর `writes` মাপো তিন রকম input-এ: `[4, 3, 2, 1]`, `[1, 2, 3, 4]`, আর `[2, 1, 4, 3]`। কোনটায় লেখা শূন্য, কেন?
- **মাঝারি ১:** Input জানা আছে হুবহু 1..n-এর permutation। Cycle sort-কে ছোট-গোনা বাদ দিয়ে রূপান্তর করো — মান v সরাসরি `arr[v - 1]`-এ। কোন পাতার ছাঁচে পৌঁছালে, আর সময় কী দাঁড়াল?
- **মাঝারি ২:** ধরো লেখার দাম ১০০, তুলনার দাম ১। ছোট প্রোগ্রামে selection sort আর cycle sort-এর মোট খরচ মাপো n = 10, 100-এ। লেখার দাম ১০ হলে ফল পাল্টায় কি?
- **কঠিন:** "Sort করতে ন্যূনতম কত swap লাগে" — এই ক্লাসিক প্রশ্নটা চক্র দিয়ে ভাবো: প্রতিটা চক্রের দৈর্ঘ্য L হলে উত্তরে যোগ হয় L − 1। উপাদান→চূড়ান্ত-ঘর ম্যাপ দিয়ে cycle গুনে উত্তর বের করো (visited-marking দিয়ে)।

## সারসংক্ষেপ

- Cycle sort-এর ঘর-সূত্র: "আমার চেয়ে ছোট যত, আমার ঘর তত" — তারপর সরাসরি চূড়ান্ত ঘরে এক লেখা, উচ্ছিষ্ট নিয়ে চক্র।
- প্রতিটা উপাদান সর্বোচ্চ একবার লেখা হয়; প্রতি চক্রে বাড়তি মাত্র এক — তাই লেখা প্রায় n, তাত্ত্বিক ন্যূনতমের কাছাকাছি।
- মূল্য: সময় O(n²), জায়গা O(1), stable নয়। রাজ্য: যেখানে লেখা ভারী — flash, EEPROM।
- Duplicate-এর `while (item === arr[pos]) pos++` লাইন আর `start`-এর ডানে গোনা — দুটোই আপসহীন।
- Range 1..n জানা থাকলে সোজা [Cyclic Sort](../problem-solving/cyclic-sort.mdx)-এ — গোনা বাদ, ঘর হুবহু `v - 1`।
