## কী শিখব

- stability, in-place, comparison-ভিত্তিক ধারণা

## ধারণা

ভাবো তো, একটা ফোনবুকে কোনো নাম খুঁজছ। তুমি কি প্রথম পাতা থেকে একটা একটা করে দেখো? না, মাঝখান খুলে বুঝে নাও কোন দিকে যেতে হবে। কিন্তু এই চালাকি (binary search) তখনই চলে যখন নামগুলো আগে থেকেই sorted থাকে। শুধু খোঁজাই না, duplicate ধরা, interval merge, এমন অনেক কাজের পূর্বশর্তই হলো sorting।

তাহলে একটা sorting algorithm ভালো নাকি খারাপ, মাপবে কী দিয়ে? তিনটা জিনিস দেখি:

- **Time complexity**: কতটা দ্রুত চলে
- **Space**: in-place মানে অতিরিক্ত মেমরি প্রায় লাগেই না
- **Stability**: সমান মানের উপাদানগুলোর আপেক্ষিক ক্রম আগের মতোই থাকে কিনা

## কোড উদাহরণ

বাস্তব কাজে হাতে sort লেখার দরকার পড়ে না, JS-এর built-in-টাই ব্যবহার করি:

```js
const nums = [5, 2, 9, 1];
nums.sort((a, b) => a - b);  // ছোট থেকে বড় (comparator জরুরি!)
console.log(nums);           // [1, 2, 5, 9]
```

<Callout type="warn" title="comparator ছাড়া সংখ্যা sort কোরো না">
শুধু `nums.sort()` লিখলে JS উপাদানগুলোকে string ধরে তুলনা করে, ফলে সংখ্যায় ভুল ফল আসবেই। সংখ্যা sort করতে গেলে comparator বাধ্যতামূলক।
</Callout>

## কোড ব্রেকডাউন

- `sort((a, b) => a - b)`: ফলাফল ঋণাত্মক হলে a আগে বসে, তাই ছোট থেকে বড় সাজে।
- নিচে হাতে বানানো algorithm-গুলো শিখব বোঝার জন্য। production কোডে built-in `sort`-ই ব্যবহার করবে, এটা সাধারণত O(n log n)।

## Complexity

- built-in `sort` সাধারণত O(n log n)।
