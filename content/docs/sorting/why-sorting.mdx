## কী শিখব

- Sorting কেন শুধু "সাজানো" না, অনেক বড় সমস্যার পূর্বশর্ত
- Algorithm বিচারের তিন মাপকাঠি: time, space, stability
- Stability আসলে কী বোঝায়, একটা বাস্তব উদাহরণে
- Comparison-based sort মানে কী, আর এর একটা তাত্ত্বিক সীমা
- JavaScript-এর built-in `sort()`: string ফাঁদ আর comparator-এর সঠিক ব্যবহার

## ধারণা: sorting কেন এত গুরুত্বপূর্ণ

ভাবো তো, ফোনবুকে একটা নাম খুঁজছ। তুমি কি প্রথম পাতা থেকে এক পাতা এক পাতা উল্টাও? না, মাঝখান খুলে দেখো কোন দিকে যেতে হবে। এই চালাকি (binary search) চলে একটাই শর্তে: নামগুলো আগে থেকে sorted।

Sorted ডেটা শুধু খোঁজাই সহজ করে না। একবার সাজানো হলে একঝাঁক সমস্যা সস্তা হয়ে যায়:

- **Duplicate ধরা:** সাজানো হলে একই জিনিস পাশাপাশি চলে আসে, এক পাসে ধরা যায়।
- **কে সবচেয়ে কাছের:** দুই সংখ্যার সর্বনিম্ন ব্যবধান sorted array-তে প্রতিবেশী তুলনা মাত্র।
- **Interval merge, meeting room:** শুরুর সময়ে সাজালেই সমস্যার অর্ধেক শেষ।
- **Median, percentile, top-k:** সবই সাজানো ডেটার উপর দাঁড়িয়ে।

তাই sorting শেখা মানে একটা algorithm শেখা না, **অন্য সমস্যা সস্তা করার প্রস্তুতি** শেখা।

## তিন মাপকাঠি: কী দিয়ে algorithm বিচার করবে

এই section-এ ৬টা algorithm শিখবে। সবাই একই কাজ করে, তাহলে কাকে ভালো বলবে? তিনটা মাপকাঠি:

1. **Time complexity:** n বাড়লে কাজ কত দ্রুত বাড়ে। এখানে দুই দল: O(n²) আর O(n log n)।
2. **Space (in-place কিনা):** সাজাতে গিয়ে বাড়তি মেমরি লাগে কিনা। In-place মানে মূল array-তেই সব খেলা, O(1) বাড়তি।
3. **Stability:** সমান মানের উপাদানগুলোর আপেক্ষিক ক্রম sorting-এর পরও অক্ষত থাকে কিনা।

## Stability: একটা বাস্তব উদাহরণ

ধরো ছাত্রদের তালিকা আছে, আগে থেকে নামের ক্রমে সাজানো:

```js
const students = [
  { name: "ববি", grade: 8 },
  { name: "অনি", grade: 9 },
  { name: "রিতা", grade: 8 },
];
```

এবার grade দিয়ে sort করলে 8-প্রাপ্ত দুজনের (ববি আর রিতা) মধ্যে কে আগে থাকবে? **Stable sort**-এ আগের ক্রম বজায় থাকে, ববি আগে (নামে সে আগে ছিল)। **Unstable sort**-এ গ্যারান্টি নেই, রিতা আগে চলে আসতে পারে।

কখন লাগে? যখন একাধিক নিয়মে পর্যায়ক্রমে sort করতে হয়: আগে নামে, পরে grade-এ, ফলে একই grade-এর ভেতরে নামের ক্রম থেকে যায়। Spreadsheet-এর multi-column sort ঠিক এভাবেই কাজ করে। ছোট সংখ্যার তালিকায় পার্থক্য টের পাবে না, কিন্তু record-এর তালিকায় এটা ভুল ফল বানায়।

কোন জনপ্রিয় algorithm কোন দলে, সেটা মুখস্থ রাখার তালিকা:

| Stable | Unstable |
|--------|----------|
| Merge sort, Insertion sort, Bubble sort | Quick sort, Heap sort, Selection sort |
| Counting sort, Radix sort, Tim sort | |

Selection sort-টা হয়তো অবাক করবে: সমান উপাদানদের ক্রম ওর দূর-লাফের swap-এ উল্টে যেতে পারে, [Selection Sort](./selection-sort.mdx)-এ ওর swap কীভাবে কাজ করে দেখলেই বুঝবে। আর সুখবর: ES2019 থেকে JavaScript-এর built-in `sort()`-এর stable হওয়া **বাধ্যতামূলক**। প্রমাণ চাই? প্রথম সংখ্যা একই এমন দুটো জোড়া নিয়ে দেখো:

```js
const pairs = [[1, 2], [9, 7], [3, 4], [8, 6], [9, 3]];

pairs.sort((a, b) => a[0] - b[0]); // শুধু প্রথম সংখ্যা দেখে

console.log(pairs.map(p => p.join(",")).join("  "));
// 1,2  3,4  8,6  9,7  9,3   ← দুটো 9-যুক্ত জোড়া মূল ক্রমেই রইল
```

আরেকটা সূক্ষ্মতা: unstable sort-ও মাঝে মাঝে একই ফল দিতে পারে। পার্থক্য গ্যারান্টিতে: stable মানে **সবসময়** ক্রম বজায়, unstable মানে "হতেও পারে, নাও পারে", ভরসা করা যায় না।

## Comparison-based sort আর তাত্ত্বিক সীমা

এই section-এর সব algorithm একই খেলা খেলে: দুটো উপাদান **তুলনা** করে সিদ্ধান্ত নেয় কে আগে বসবে। এদের বলে comparison-based sort। মজার একটা তত্ত্ব আছে: এই খেলায় কোনো algorithm-ই গড়ে **O(n log n)-এর নিচে নামতে পারে না**, কারণ n-টা উপাদানের n! রকম সাজানো সম্ভব, আর প্রতি তুলনা দুই রকম উত্তর দেয়, তাই সব সাজানো আলাদা করতে কমপক্ষে log₂(n!) ≈ n log n তুলনা লাগবেই।

মানে Merge/Quick/Heap-এর O(n log n) হলো এই খেলার সিলিং। এর চেয়ে দ্রুত যেতে হলে খেলাই বদলাতে হয়, যেমন counting sort বা radix sort, যেগুলো তুলনা না করে সংখ্যার অঙ্ক নিয়ে খেলে। এদের একজন এই section-এই আছে: [Counting Sort](./counting-sort.mdx) — মানকেই index বানিয়ে বিশেষ শর্তে সোজা রৈখিক সময়ে নামে। নামগুলো জেনে রাখো, "সব sort O(n log n)-এ আটকে" ভুল ধারণা না পুষতে।

## কোড: built-in `sort()` সঠিকভাবে

বাস্তব কাজে হাতে sort লেখার দরকার পড়ে না, JS-এর built-in-টাই যথেষ্ট। কিন্তু একটা বিখ্যাত ফাঁদ আছে:

```js
const nums = [10, 9, 80, 100];

nums.sort();
console.log(nums); // [10, 100, 80, 9]: ভুল!

nums.sort((a, b) => a - b);
console.log(nums); // [9, 10, 80, 100]: ঠিক
```

কেন প্রথমটা ভুল? Comparator ছাড়া `sort()` উপাদানগুলোকে **string** বানিয়ে তুলনা করে: `"10" < "100" < "80" < "9"`, কারণ অভিধানের ক্রমে `"1"`-দিয়ে-শুরু সব `"9"`-এর আগে। Comparator `(a, b) => a - b` দিলে সংখ্যার হিসাবে তুলনা হয়: ফলাফল ঋণাত্মক হলে a আগে, ধনাত্মক হলে b আগে, শূন্য হলে সমান।

```js
// বড় থেকে ছোট: চিহ্ন উল্টাও
nums.sort((a, b) => b - a);

// object-এর তালিকা: grade দিয়ে, সমান হলে নামে
students.sort((a, b) => b.grade - a.grade || a.name.localeCompare(b.name));
```

মনে রাখো, আধুনিক JavaScript-এর `sort()` **stable**, তাই `||`-এর পরের অংশ আসলেই কাজ করে।

## Complexity আর প্রেক্ষিত

Built-in `sort()` ভেতরে সাধারণত TimSort (merge + insertion-এর সংকর), নিশ্চিত O(n log n), stable। মানে production-এ নিজের sort লেখার দরকার নেই। তাহলে ৬টা algorithm কেন শিখছি? কারণ sort-গুলোর ভেতরে লুকিয়ে আছে DSA-র মৌলিক ধারণা: divide and conquer, heap, in-place কৌশল, worst-case বিশ্লেষণ। Interview-তো বটেই, এই ধারণাগুলো পরে [Searching](../searching/binary-search.mdx), [Heaps](../heaps/what-is-heap.mdx), সর্বত্র ফিরে আসে।

## সাধারণ ভুল আর edge case

**১. সংখ্যার array-তে comparator ছাড়া `sort()` ডাকা।**
উপরের ফাঁদটাই: `[10, 9, 80, 100]` হয়ে যায় `[10, 100, 80, 9]`। কোনো error আসে না, চুপচাপ ভুল ক্রম। সংখ্যা মানে comparator বাধ্যতামূলক।

**২. `sort()` মূল array-টাই বদলে দেয়, এটা ভুলে যাওয়া।**
`sort()` in-place, মানে আসল array-ই বদলে যায়। আসলটা লাগলে আগে copy: `[...arr].sort(...)` বা নতুন `toSorted()`।

**৩. Stability-র প্রয়োজন না বুঝে multi-key sort করা।**
Object-এর তালিকায় আগে এক নিয়মে, পরে আরেক নিয়মে sort করলে দ্বিতীয় sort-টা stable না হলে প্রথম নিয়মের ক্রম নষ্ট হয়। আধুনিক JS-এ built-in stable, কিন্তু নিজের লেখা sort (quick, heap) stable না, সেক্ষেত্রে key-গুলো এক comparator-এ মিলিয়ে দাও।

**৪. Comparator-এ boolean ফেরানো।**
`(a, b) => a > b` লিখলে `true`/`false` যায়, যা 1/0 হিসেবে ব্যাখ্যা হয়, ঋণাত্মক কেসটা হারায়। ফলাফল অনির্ভরযোগ্য। সবসময় বিয়োগফল ফেরাও: সংখ্যা, সংখ্যাই ফেরত দেবে।

**৫. "সব sort O(n log n)" ধারণা।**
Comparison খেলায় সেটা সিলিং ঠিকই, কিন্তু counting/radix sort নির্দিষ্ট ধরনের ডেটায় O(n) পর্যন্ত নামে। সীমাটা খেলার নিয়মের, সব নিয়মের না।

## অনুশীলন

- **সহজ ১:** `[3, 30, 12, 1, 100, 20]` আগে শুধু `sort()` দিয়ে, পরে comparator দিয়ে চালাও। দুই ফল কেন আলাদা, নিজের কথায় লেখো।
- **সহজ ২:** একটা comparator লেখো যা জোড় সংখ্যাগুলো আগে, বিজোড় পরে রাখে, প্রতি দলের ভেতরে ছোট থেকে বড়। (হিন্ট: দুই শর্ত, `||` দিয়ে জোড়ো।)
- **মাঝারি ১:** ছাত্রদের তালিকা দেওয়া আছে (নাম, grade)। এমনভাবে sort করো যাতে grade বড় থেকে ছোট, সমান grade-এ নাম ছোট থেকে বড়। দুটো পদ্ধতিতে: (ক) দুইবার sort (stable ধরে), (খ) একটাই comparator। ফল মিলাও।
- **মাঝারি ২:** বন্ধুকে বোঝাও: "comparison sort O(n log n)-এর নিচে নামতে পারে না" কথাটা n! আর দুই-উত্তরের তুলনা দিয়ে। হিন্ট: প্রতি তুলনায় গাছ দুই ডানায় ভাগ হয়, ডিম n! টা ফল আলাদা করতে গাছের উচ্চতা কত লাগে?
- **কঠিন:** একটা ছোট experiment লেখো: ১০,০০০ এলোমেলো সংখ্যা, একই array-র copy তিনবার বানিয়ে একবার sorted, একবার near-sorted, একবার reversed অবস্থায় built-in `sort()`-এর সময় মাপো (`console.time`)। TimSort near-sorted ডেটায় দ্রুত কেন, সন্দেহ লিখো, পরে [Insertion Sort](./insertion-sort.mdx)-এ গিয়ে যুক্তিটা মিলাবে।

## সারসংক্ষেপ

- Sorting শেখা মানে অন্য সমস্যা সস্তা করার প্রস্তুতি: search, duplicate, interval সবই।
- বিচারের মাপকাঠি তিনটা: time, space (in-place), stability।
- Stability মানে সমানদের আপেক্ষিক ক্রম অক্ষত; record-এর তালিকায় এটাই জীবন-মরণ।
- Comparison খেলার সিলিং O(n log n); ভাঙতে হলে খেলা বদলাতে হয়।
- JS-এর `sort()` সংখ্যায় comparator ছাড়া চালাবে না, আর মনে রাখবে এটা in-place।
