## কী শিখব

- Bubble sort-এর নিয়ম: পাশাপাশি জোড়া তুলনা, বড়টা ডানে ঠেলা
- এক পুরো pass-এর dry run, প্রতি তুলনায় array কেমন দেখায়
- `swapped` flag: sorted array-তে থেমে যাওয়ার অপ্টিমাইজেশন
- O(n²) কেন, তুলনার হিসাব নিজে করা
- কেন bubble sort শেখার জন্য দারুণ, ব্যবহারের জন্য না

## ধারণা

ভাবো তো, ক্লাসের বাচ্চারা এলোমেলো লাইনে দাঁড়িয়ে আছে, তোমাকে উচ্চতায় সাজাতে হবে। তুমি লাইনের শুরু থেকে পাশাপাশি দুজনকে তুলনা করতে করতে এগোলে: সামনেরটা লম্বা হলে জায়গা বদল করালে। একবার শেষ পর্যন্ত হেঁটে আসতেই সবচেয়ে লম্বাটা একদম পেছনে চলে গেছে। দ্বিতীয় pass-ে দ্বিতীয় লম্বাটা তার আগের ঘরে, এভাবে চলতে থাকে।

Bubble Sort হুবহু এই খেলা। নামটা পানির বুদবুদ থেকে: বড় উপাদানটা ধাপে ধাপে ভেসে ভেসে উপরে (array-এর শেষে) উঠে যায়। প্রতি pass-এ **একটা** উপাদানের চূড়ান্ত জায়গা নিশ্চিত হয়।

## Dry run: `[5, 1, 4, 2, 8]`

প্রথম pass পুরোটা দেখি, প্রতি তুলনায়:

| ধাপ | তুলনা | swap? | array-এর অবস্থা |
|-----|-------|-------|------------------|
| শুরু | - | - | `[5, 1, 4, 2, 8]` |
| 1 | 5 > 1 | হ্যাঁ | `[1, 5, 4, 2, 8]` |
| 2 | 5 > 4 | হ্যাঁ | `[1, 4, 5, 2, 8]` |
| 3 | 5 > 2 | হ্যাঁ | `[1, 4, 2, 5, 8]` |
| 4 | 5 > 8 | না | `[1, 4, 2, 5, 8]` |

Pass ১ শেষ: সবচেয়ে বড় 8 শেষ ঘরে পৌঁছে গেল, সে এখন **চূড়ান্ত**। খেয়াল করো, 5-ও ডানে তিন ঘর সরে গেছে, পথে পথে ভেসে।

দ্বিতীয় pass-এ শেষ ঘর আর ছোঁয়া লাগে না (8 ঠিক আছে), তাই পরিসর এক ঘর কমে:

| Pass | পরিসর | শেষে চূড়ান্ত হলো | অবস্থা |
|------|--------|--------------------|--------|
| 2 | index 0-2 | 5 | `[1, 2, 4, 5, 8]` |
| 3 | index 0-1 | 4 | `[1, 2, 4, 5, 8]` |
| 4 | index 0 | কিছুই বদলায়নি | `[1, 2, 4, 5, 8]` |

Pass ৪-এ একটাও swap হয়নি, মানে array sorted, থেমে যাও। এই থামার কৌশলটা কোডে `swapped` flag দিয়ে হয়।

## কোড: নিজে বানাও bubbleSort

```js
function bubbleSort(arr) {
  const n = arr.length;

  for (let i = 0; i < n - 1; i++) {
    let swapped = false;

    for (let j = 0; j < n - 1 - i; j++) {   // -i: শেষের i-টা চূড়ান্ত
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        swapped = true;
      }
    }

    if (!swapped) break;                     // কেউ নড়েনি = sorted
  }

  return arr;
}

console.log(bubbleSort([5, 1, 4, 2, 8])); // [1, 2, 4, 5, 8]
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `for (let i = 0; i < n - 1; i++)` : সর্বোচ্চ n-1 টা pass। কেন n-1? প্রতি pass-এ একজনের চূড়ান্ত জায়গা, শেষজনের আলাদা pass লাগে না।
2. `let swapped = false` : এই pass-এ কেউ বদলেছে কিনা, খাতা।
3. `j < n - 1 - i` : ভেতরের পরিসর প্রতি pass-এ এক ঘর কমে। শেষের i-টা ঘর ইতিমধ্যে চূড়ান্ত, ওদের আবার তুলনায় টানা শুধু অপচয়।
4. `if (arr[j] > arr[j + 1])` : বামটা বড় হলেই swap। সমান হলে swap হয় না, এজন্যই bubble sort **stable**, সমানদের ক্রম কখনও বদলায় না।
5. `if (!swapped) break` : এক পুরো pass-এ কেউ নড়েনি মানে সবাই নিজের জায়গায়। এটা ছাড়া sorted array-তেও n-1 pass ঘুরত; এটা থাকায় best case O(n)-এ নেমে আসে।

## Complexity: হিসাবটা নিজে করি

| কেস | Time | কেন |
|-----|------|-----|
| Worst (উল্টো sorted) | O(n²) | প্রতি pass-এ পুরো পরিসর তুলনা |
| Average | O(n²) | একই কারণে |
| Best (ইতিমধ্যে sorted) | O(n) | একটাই pass, `swapped` false, থামো |
| Space | O(1) | জায়গা বদলায়, বাড়তি কিছু নেই, in-place |

Derivation: pass ১-এ তুলনা n-1 টা, pass ২-এ n-2 টা, ..., শেষে ১টা। মোট (n-1) + (n-2) + ... + 1 = **n(n-1)/2**, মানে n²-এর অর্ধেকের কাছাকাছি, O(n²)। লক্ষ করো, swap-এর সংখ্যা ডেটার উপর নির্ভর করে, কিন্তু তুলনা তো লাগেই, তাই average-ও O(n²)। ১০০০ উপাদানে প্রায় ৫ লাখ তুলনা, ১ লাখে ৫০০ কোটি। এজন্যই বাস্তবে bubble sort-এর নাম আসে শুধু ক্লাসরুমে।

তবু শেখার মূল্য আছে: প্রথম sort algorithm হিসেবে এতে দেখা যায় pass-ভিত্তিক চিন্তা, early exit, আর O(n²) দেখতে কেমন, যা পরে Merge/Quick-এর O(n log n)-এর আশ্চর্য বোঝায়।

## সাধারণ ভুল আর edge case

**১. `n - 1 - i` ভুলে প্রতি pass-এ পুরো array ঘোরা।**
কাজ তখনও হয়, কিন্তু চূড়ান্ত ঘরগুলো বারবার তুলনায় যায়, অর্থাৎ অপচয়। আরও খারাপ: `n` পর্যন্ত চালালে `arr[j+1]` হয় `undefined`, তুলনা গোলমাল করে। সীমাটা বুঝে লেখো: শেষের i-টা বাদ।

**২. `swapped` flag না রাখা।**
ছোট ডেটায় পার্থক্য বোঝা যায় না, কিন্তু near-sorted বড় ডেটায় নিছক flag-এর জন্য সময় দ্বিগুণ-তিনগুণ লাগে। অপ্টিমাইজেশনটা এক লাইনের, ফল বড়।

**৩. সমান মানেও swap করা (`>=` লেখা)।**
`arr[j] >= arr[j + 1]` দিলে সমান উপাদানদের ক্রম উল্টে যায়, stability নষ্ট। শুধু `>` রাখো, সমানে হাত দেবে না। এই সূক্ষ্মতাই stable/unstable-এর পার্থক্য।

**৪. Swap-এ temp হারানো বা destructuring গুলিয়ে ফেলা।**
`[arr[j], arr[j+1]] = [arr[j+1], arr[j]]` এক লাইনে নিরাপদ। কিন্তু `arr[j] = arr[j+1]; arr[j+1] = arr[j]` লিখলে প্রথম লাইনেই মান হারায়, দুটোই এক হয়ে যায়। নিজে swap লিখলে temp নিয়ে লেখো।

**৫. Bubble sort বাস্তব প্রকল্পে টেনে আনা।**
শেখা শেষে কথা দাও: production-এ built-in `sort()`, নইলে Merge/Quick। Bubble-এর কাজ ছিল O(n²) কেমন লাগে তা দেখানো, সেই কাজ শেষ।

## অনুশীলন

- **সহজ ১:** `[7, 3, 9, 1]`-এ প্রথম দুই pass হাতে dry run করো: প্রতি তুলনার পর array লিখো। কোন pass-এ কে চূড়ান্ত হলো?
- **সহজ ২:** প্রায়-sorted `[1, 2, 4, 3, 5]`-এ bubble sort চালাও (কাগজে)। কয়টা pass লাগল `swapped` flag থাকলে, আর না থাকলে?
- **মাঝারি ১:** Bubble sort-কে উল্টো দিকে চালাও: ছোটটাকে সামনে "ডুবিয়ে" আনো (ডান থেকে বামে pass)। দুই রূপের তুলনা সংখ্যা কি একই থাকে? যুক্তি দাও।
- **মাঝারি ২:** `swapped` ছাড়া আর সহ, দুই version-এই ৫০০০ উপাদানের sorted array-তে `console.time` দিয়ে মাপো। পার্থক্য কত গুণ, কেন?
- **কঠিন:** Cocktail shaker sort বানাও: bubble sort-ই, কিন্তু pass একবার ডানে, পরেরটা বামে, দুই দিকে পর্যায়ক্রমে। (হিন্ট: দুটো সীমা রাখো, বাম আর ডান, প্রতি দিকের pass শেষে সেটা এক ঘর সরে। কখন এটা সাধারণ bubble থেকে দ্রুত, ভেবে দেখো: ছোট উপাদান একদম শেষে থাকলে কী হয়?)

## সারসংক্ষেপ

- Bubble sort: পাশাপাশি তুলনা, বড়টা ডানে ভাসে, প্রতি pass-এ একজন চূড়ান্ত।
- তুলনা মোট n(n-1)/2, তাই average/worst O(n²); space O(1), stable।
- `swapped` flag দিলে sorted ডেটায় এক pass-এ থামে, best case O(n)।
- `>` না `>=`, এই এক চিহ্নেই stability বাঁচে বা নষ্ট হয়।
- শেখার জন্য চমৎকার, বাস্তবের জন্য না; এর O(n²) দেখেই পরের algorithm-গুলোর কদর বোঝো।
- এই pass-ভিত্তিক adjacent-swap কাজকেই disjoint জোড়ার দুই phase-এ সাজালে পাও [Odd-Even Sort](./odd-even-sort.mdx) — bubble-এর সমান্তরাল-প্রস্তুত ভাই।
