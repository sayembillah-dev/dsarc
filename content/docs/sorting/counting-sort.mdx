## কী শিখব

- Comparison sort-এর O(n log n) দেয়াল counting sort ঠিক কীভাবে এড়িয়ে যায়
- মূল কৌশল: মানকেই array-র index বানানো, আর frequency থেকে cumulative count-এর ভূমিকা
- Simple সংস্করণ আর stable সংস্করণের পার্থক্য: কখন কোনটা, আর উল্টো দিক থেকে বসানো কেন বাধ্যতামূলক
- Complexity O(n + k)-এর সেই k আসলে কী, কখন এটা জ্যাকপট আর কখন বিপর্যয়
- Negative বা যেকোনো range-এ offset দিয়ে সাধারণায়ন

## ধারণা

ধরো, কুইজের খাতা সাজাতে হবে: ৩০টা খাতা, প্রাপ্ত নম্বর ০ থেকে ১০-এর মধ্যে। [Quick Sort](./quick-sort.mdx) দিয়ে সাজালে খাতা-জোড়া তুলনা করতে করতে বেশ সময় যাবে। কিন্তু একটা শিক্ষক আসলে যা করেন: টেবিলে ০ থেকে ১০ পর্যন্ত এগারোটা স্তূপের জায়গা বানান, প্রতিটা খাতা তুলে সরাসরি তার নম্বরের স্তূপে ফেলেন। সব খাতা ফেলানো শেষে ০-এর স্তূপ থেকে ১০-এর স্তূপ পর্যন্ত তুলে নিলেই সাজানো তালিকা। পুরো প্রক্রিয়ায় দুই খাতার **তুলনা** একবারও হয়নি।

এটাই counting sort। [Why Sorting](./why-sorting.mdx)-এ দেখেছিলে, comparison-based sort-এর তাত্ত্বিক সিলিং O(n log n)। কিন্তু সিলিংটা আসলে সেই খেলার নিয়মের: "দুটো উপাদান তুলনা করেই সিদ্ধান্ত নিতে হবে।" Counting sort নিয়মটাই বদলে দেয় — তুলনা করে না, **মানটাকেই সরাসরি ঠিকানা (index) হিসেবে ব্যবহার করে**।

অবশ্যে মোছাফি আছে, দুটো শর্ত:

1. মান হতে হবে **পূর্ণসংখ্যা** (index-এ তো দশমিক বসে না)।
2. মানের **পরিসর (range) জানা ও ছোট** হতে হবে। মান 0 থেকে k-এর মধ্যে হলে আমাদের k+1 ঘরের একটা count array লাগবে।

শর্ত মিললে পুরস্কার বড়: সময় O(n + k)। k যদি n-এর কাছাকাছি হয়, এটা সত্যিকারের রৈখিক — comparison খেলায় যা অসম্ভব ছিল।

## ধাপে ধাপে: প্রথমে শুধু গোনা (simple সংস্করণ)

Array: `[4, 2, 2, 8, 3, 3, 1]`। সব মান 0–8-এর মধ্যে, তাই k = 8, count array-র ৯টা ঘর (index 0..8)।

**প্রথম pass — frequency গোনা:** প্রতিটা উপাদান x-এর জন্য `count[x]` এক করে বাড়াও:

| মান v | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|-------|---|---|---|---|---|---|---|---|---|
| count[v] | 0 | 1 | 2 | 2 | 1 | 0 | 0 | 0 | 1 |

**দ্বিতীয় pass — ছড়িয়ে দেওয়া:** v = 0 থেকে 8 পর্যন্ত ঘুরো, প্রতিটা v-কে যতবার গুনেছ (count[v]-বার) ততবার out-এ রাখো:

- 1 একবার → `1`
- 2 দুবার → `2, 2`
- 3 দুবার → `3, 3`
- 4 একবার → `4`
- 8 একবার → `8`

জমিয়ে পেলে `[1, 2, 2, 3, 3, 4, 8]`। Sorted, একটাও তুলনা ছাড়া।

## কোড: simple সংস্করণ

```js
function countingSortSimple(arr, k) {
  const count = new Array(k + 1).fill(0);   // মান 0..k, তাই k+1 ঘর

  for (const x of arr) count[x]++;          // frequency গোনা

  const out = [];
  for (let v = 0; v <= k; v++) {            // ছোট মান থেকে বড়ে
    for (let c = 0; c < count[v]; c++) {
      out.push(v);                          // v বসবে count[v]-বার
    }
  }
  return out;
}

console.log(countingSortSimple([4, 2, 2, 8, 3, 3, 1], 8)); // [1, 2, 2, 3, 3, 4, 8]
```

সরল, কিন্তু দুটো বড় সীমাবদ্ধতা নিয়ে জন্মেছে। প্রথম, out-এ ঢোকে শুধু **খালি মান** — বাস্তবে তো মানের সঙ্গে জিনিস জুড়ে থাকে: নম্বরের সঙ্গে খাতা, বয়সের সঙ্গে নাম। সেই সঙ্গী ডেটা (satellite data) এখানে হারিয়ে যায়। দ্বিতীয়, সমান মানের উপাদানদের মূল ক্রম ধরে রাখার কোনো ব্যবস্থাই নেই, অর্থাৎ stability নেই। [Why Sorting](./why-sorting.mdx)-এর সেই ছাত্র-তালিকার কথা মনে করো: grade-এ সমান দুজনের মধ্যে নামের ক্রমটাই আসল সম্পদ ছিল। এই দুই ঘাটতি কাটানোর জন্যই আসল সংস্করণটা একটু আলাদা।

## ধাপে ধাপে: stable সংস্করণ — cumulative count-এর জাদু

কৌশলটা চমৎকার: গোনা শেষে count array-টাকেই বদলে ফেলো এমনভাবে, যাতে `count[v]` বলে দেয় **v আর তার চেয়ে ছোট মান মিলে মোট কতটা উপাদান আছে**। প্রতিটা ঘরে নিজের বাম-পাশেরটা যোগ করতে থাকো — চেনা লাগছে? এটা হুবহু [prefix sum](../problem-solving/prefix-sum.mdx)।

| মান v | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|-------|---|---|---|---|---|---|---|---|---|
| frequency | 0 | 1 | 2 | 2 | 1 | 0 | 0 | 0 | 1 |
| cumulative count[v] | 0 | 1 | 3 | 5 | 6 | 6 | 6 | 6 | 7 |

এবার পড়ার নিয়ম: sorted array-তে মান v-এর **শেষ** উপাদানটা বসবে index `count[v] - 1`-এ। যেমন `count[3] = 5` বলছে "3 আর ছোটরা মিলে মোট ৫টা" — তাই শেষ 3-এর ঠিকানা index 4 (0-based)।

বসানোর pass-টা চলবে মূল array-র **উল্টো দিক থেকে**; কেন, তা-ই দেখা যাক। সমান মানগুলো আলাদা করতে subscript দিলাম: `2₁` হলো আগে আসা 2 (index 1-এ), `2₂` পরেরটা (index 2-এ)। একইভাবে `3₁` (index 4) আর `3₂` (index 5)।

arr = `[4, 2₁, 2₂, 8, 3₁, 3₂, 1]`, out = ৭টা খালি ঘর। প্রতি ধাপে: `out[count[x] - 1] = x`, তারপর `count[x]` এক কমাও।

| ধাপ | i | x | count[x] (বসানোর আগে) | বসল কোথায় | out-এর অবস্থা |
|-----|---|---|------|------------|----------------|
| 1 | 6 | 1 | 1 | out[0] | `[1, _, _, _, _, _, _]` |
| 2 | 5 | 3₂ | 5 | out[4] | `[1, _, _, _, 3₂, _, _]` |
| 3 | 4 | 3₁ | 4 | out[3] | `[1, _, _, 3₁, 3₂, _, _]` |
| 4 | 3 | 8 | 7 | out[6] | `[1, _, _, 3₁, 3₂, _, 8]` |
| 5 | 2 | 2₂ | 3 | out[2] | `[1, _, 2₂, 3₁, 3₂, _, 8]` |
| 6 | 1 | 2₁ | 2 | out[1] | `[1, 2₁, 2₂, 3₁, 3₂, _, 8]` |
| 7 | 0 | 4 | 6 | out[5] | `[1, 2₁, 2₂, 3₁, 3₂, 4, 8]` |

দুটো জিনিস চোখে পড়ার কথা:

**প্রথম, উল্টো দিকটা কেন জরুরি।** `3₂` আগে বসেছে out[4]-এ, তারপর `3₁` বসেছে out[3]-এ — মূল ক্রমে আগে থাকা `3₁` ফলেও আগেই রইল। উল্টো করে ভাবো: সামনে থেকে ঘুরলে `3₁` বসত out[4]-এ আর `3₂` out[3]-এ, ক্রম উল্টে যেত। "উল্টো দিক থেকে ঘোরা" আর "প্রতিবার `count[x]--`" — এই জোড়া নিয়মই counting sort-কে **stable** রাখে।

**দ্বিতীয়, বসানোর pass-এ আবারও একটাও তুলনা নেই।** প্রতিটা উপাদান তার চূড়ান্ত ঘরে সরাসরি, এক ধাপে গিয়ে বসছে — কাউকে সরানো নেই, জায়গা খোঁজা নেই। এজন্যই এই pass খাঁটি O(n)।

## কোড: পুরো stable সংস্করণ

```js
function countingSort(arr, k) {
  // শর্ত: arr-এর সব মান 0 থেকে k-এর মধ্যে পূর্ণসংখ্যা
  const count = new Array(k + 1).fill(0);

  for (const x of arr) count[x]++;            // ১) frequency

  for (let v = 1; v <= k; v++) {              // ২) cumulative (prefix sum)
    count[v] += count[v - 1];                 //     এখন count[v] = v বা ছোট মোট কতটা
  }

  const out = new Array(arr.length);
  for (let i = arr.length - 1; i >= 0; i--) { // ৩) উল্টো দিক থেকে বসানো
    const x = arr[i];
    out[count[x] - 1] = x;                    //     x-এর শেষ খালি ঘরে সোজা বসাও
    count[x]--;                               //     পরের x-এর জন্য ঘর এক কমল
  }
  return out;
}

console.log(countingSort([4, 2, 2, 8, 3, 3, 1], 8)); // [1, 2, 2, 3, 3, 4, 8]
```

Record সাজাতে চাইলে কাঠামো হুবহু এক: শুধু `out`-এ মান নয়, গোটা object বসাও — `out[count[key] - 1] = arr[i]`, যেখানে `key` হলো `arr[i].grade`-এর মতো কিছু। Index-হিসাব চলবে শুধু key দিয়ে, বসবে গোটা record-টাই।

## কোড ব্রেকডাউন: stable সংস্করণ, লাইনে লাইনে

1. `const count = new Array(k + 1).fill(0)` : মান 0..k মানে k+1 রকম, তাই k+1 ঘর। এই `+ 1`-টাই সবচেয়ে বেশি ভুল হয়।
2. `for (const x of arr) count[x]++` : মান x-কেই index ধরে তার ঘর এক বাড়াল। কোথাও তুলনা নেই, খাঁটি array indexing — এজন্যই পূর্ণসংখ্যা শর্তটা আপসহীন।
3. `count[v] += count[v - 1]` : বাম থেকে ডানে জমতে থাকা। লুপ শেষে `count[v]` মানে "v বা ছোট মোট কতটা", আর sorted array-তে v-এর শেষটার ঠিকানা `count[v] - 1`।
4. `for (let i = arr.length - 1; i >= 0; i--)` : উল্টো ঘোরা। stability-এর অর্ধেক এই এক লাইনে।
5. `out[count[x] - 1] = x` : চূড়ান্ত ঘরে সরাসরি বসানো, সরানো-তুলনার ঝামেলা নেই।
6. `count[x]--` : বসানোর পর সীমা এক কমল, ফলে পরের সমান মান ঠিক এক ঘর বামে পড়বে। stability-এর বাকি অর্ধেক।

## ভ্যারিয়েন্ট: negative বা যেকোনো range

মান 0 থেকে শুরু না হলে? ধরো −5 থেকে 5, কিংবা 90 থেকে 99। Index তো negative হতে পারে না — সমাধান **offset**: সব মান থেকে `min` বিয়োগ দিলে range হয়ে যায় 0 থেকে `max - min`:

```js
function countingSortRange(arr) {
  if (arr.length === 0) return arr;

  const min = Math.min(...arr);
  const max = Math.max(...arr);
  const k = max - min;                        // ঘর লাগবে k+1-টা

  const count = new Array(k + 1).fill(0);
  for (const x of arr) count[x - min]++;      // সব মান min ঘর সরে এলো

  for (let v = 1; v <= k; v++) count[v] += count[v - 1];

  const out = new Array(arr.length);
  for (let i = arr.length - 1; i >= 0; i--) {
    const x = arr[i] - min;                   // offset-সহ মান
    out[count[x] - 1] = arr[i];               // বসে যায় আসল মানটাই
    count[x]--;
  }
  return out;
}

console.log(countingSortRange([-2, 5, -2, 0, 3, 5])); // [-2, -2, 0, 3, 5, 5]
```

খেয়াল করো, k এখন নির্ভর করে মানের ওপর না, **range-এর ওপর**। মানগুলো −10⁹ আর 10⁹-এর ভেতর ছড়ানো হলে, array মাত্র ছয়টা element-এর হলেও count array বিশাল হয়ে যাবে। সেই হিসাবটাই এবার দেখি।

## Complexity: k-এর হিসাবটাই আসল

**Time: O(n + k), সব কেসে।** তিনটা pass আলাদা করে গুনলে: গোনা O(n), cumulative O(k), বসানো O(n); যোগ করলে O(n + k)। Input প্রায় sorted হোক বা উল্টোদিকের, একই তিন pass পুরোপুরি চলবে — এই অর্থে counting sort **adaptive নয়**, [Insertion Sort](./insertion-sort.mdx)-এর মতো প্রায়-sorted ডেটায় লাভ পায় না।

**Space: O(n + k)।** count array O(k), output array O(n)। মানে in-place নয় — [Heap Sort](./heap-sort.mdx)-এর সেই O(1) মেমরির খেলা এখানে নেই।

তাহলে লাভ-লোকসান নির্ধারণ করে **k আর n-এর সম্পর্ক**:

| পরিস্থিতি | হিসাব | রায় |
|-----------|-------|------|
| k ছোট, n-এর সমান বা কম (বয়স 0–120, গ্রেড, RGB কোড) | O(n + k) ≈ O(n) | comparison sort-কে হারিয়ে দেয় |
| k ≈ n² বা তার বড় (মান 0..10⁹, n মাত্র ১০০) | O(n + k) ≈ O(10⁹) | মেমরিই ফুরিয়ে যাবে, সোজা না |

থাম্ব রুল: **মান পূর্ণসংখ্যা আর range ছোট হলেই counting sort, নইলে না।** আর range বিশাল কিন্তু সংখ্যার digit-সংখ্যা সীমিত হলে, এই counting sort-কেই ভেতরের ইঞ্জিন বানিয়ে তার ওপর দাঁড়িয়ে থাকে **radix sort** — প্রতি digit-এ একবার করে stable counting sort। সেটা নিয়ে অনুশীলনে একটু ভাবাবে।

একটা বিশেষ কেস আলাদা করে চেনো: range যদি হুবহু 1..n হয় (প্রতিটা ঘরে ঠিক একটা করে মান), তখন count array ছাড়াই, সরাসরি swap দিয়ে প্রতিটা সংখ্যাকে নিজের index-এ বসানো যায় — সেটাই [Cyclic Sort](../problem-solving/cyclic-sort.mdx) প্যাটার্ন, missing আর duplicate ধরার অন্যতম অস্ত্র।

## সাধারণ ভুল আর edge case

**১. Range না মেপে ঝাঁপ দেওয়া।**
"O(n) sort পেলাম!" শুনে 64-bit user ID-এর তালিকায় counting sort বসালে count array গিগাবাইট খেয়ে ফেলবে। আগে `max - min` মাপো; k যদি n-এর কয়েক গুণের বেশি হয়, ফিরে যাও [Quick Sort](./quick-sort.mdx) বা [Merge Sort](./merge-sort.mdx)-এ।

**২. বসানোর pass সামনে থেকে ঘোরানো।**
`i = 0` থেকে শুরু করলেও সংখ্যা sorted আসবেই, কিন্তু সমান মানের ক্রম উল্টে যাবে — stability ভাঙা। খালি সংখ্যার টেস্টে এই বাগ ধরা পড়বে না, record-এর তালিকায় এসে ফাটবে। উল্টো ঘোরাটা সাজসজ্জা নয়, নিয়ম।

**৩. `k + 1` ভুলে যাওয়া।**
মান 0..k হলে দরকার k+1 ঘর। `new Array(k)` লিখলে সর্বোচ্চ মানটা `undefined` ঘরে `++` করতে গিয়ে `NaN` বানাবে, আর ফল আসবে চুপচাপ ভুল — কোনো error ছাড়াই।

**৪. Float বা string-এ আটকে যাওয়া।**
Index পূর্ণসংখ্যা ছাড়া চলে না। Float এলে, কিংবা মান range-এর ভেতর থাকলেও ঘন ঘন ফাঁক থাকলে, counting sort-এর জগৎ না — সেখানে range-ভাগ-করার অন্য কৌশল লাগবে — [Bucket Sort](./bucket-sort.mdx), পরের পাতাই।

**৫. Simple সংস্করণ দিয়ে record সাজানো।**
Frequency-ছড়ানো সংস্করণ out-এ শুধু মান রাখে, সঙ্গী ডেটা উধাও। খাতার সঙ্গে নম্বর রাখতে হলে stable সংস্করণই একমাত্র পথ।

**৬. "সবসময় দ্রুততম" ভাবা।**
k ছোট থাকলেও, ছোট n-এ constant factor-এর কথা ভুলো না: [সব sort-এর তুলনা টেবিল](./sorting-comparison.mdx)-এ দেখেছ, n = 20-এ insertion অনেককে হারায়। Counting sort-এর রাজ্য বড় n আর ছোট k।

## অনুশীলন

- **সহজ ১:** `[5, 2, 5, 1, 4, 2]`-এ (k = 5) হাতে পুরো dry run চালাও: আগে frequency, তারপর cumulative, তারপর উল্টো দিক থেকে বসানোর প্রতি ধাপ। প্রতি ধাপে count-এর অবস্থা লিখে রাখো — উপরের টেবিলের মতো করে।
- **সহজ ২:** Valid Anagram (LeetCode 242): দুটো string-এর অক্ষর-সংমিশ্রণ এক কিনা। হিন্ট: sort করতেই হবে এমন না — ২৬ ঘরের count array-তে প্রথম string-এর অক্ষর গুনে (বাড়িয়ে), দ্বিতীয়টার অক্ষর ঘষে (কমিয়ে) দাও; সব ঘর 0 হলেই anagram। Counting sort-এর frequency ধারণারই ছোট ভাই।
- **মাঝারি ১:** Sort Colors (LeetCode 75): array-তে শুধু 0, 1, 2। Counting sort দিয়ে করো (k = 2)। তারপর ভাবো: k এতই ছোট যে এক পাসে, তিন pointer দিয়ে in-place-ও করা যায় — সেই ছাঁচটা [Quick Sort](./quick-sort.mdx)-এর partition-এরই আত্মীয় (Dutch national flag)।
- **মাঝারি ২:** Relative Sort Array (LeetCode 1122): `arr1` সাজাতে হবে `arr2`-এর ক্রমানুসারে, যেগুলো `arr2`-তে নেই তারা শেষে ছোট-বড় ক্রমে। হিন্ট: `arr2`-এর প্রতিটা উপাদানের ক্রমাঙ্কই তার frequency-ঘর; বাকিদের জন্য চিরচেনা counting sort-এর পথ খোলা আছেই।
- **কঠিন:** Counting sort-কে subroutine বানিয়ে radix sort লিখো: অ-ঋণাত্মক 32-bit পূর্ণসংখ্যার array, প্রতিবার একটা decimal digit ধরে stable counting sort, শুরু সবচেয়ে কম গুরুত্বপূর্ণ digit থেকে। দুটো প্রশ্নের উত্তর খোঁজো: subroutine-টা stable না হলে পুরো জিনিস কেন ভেঙে যায়? আর প্রতি pass-এ k কত?

## সারসংক্ষেপ

- Counting sort তুলনাই করে না: মানকেই index বানিয়ে frequency গোনে — তাই comparison sort-এর O(n log n) সিলিং তার গায়ে লাগে না।
- তিন pass: গোনা → cumulative count → উল্টো দিক থেকে সরাসরি বসানো। সময় O(n + k), জায়গা O(n + k), সব কেসে এক।
- "উল্টো দিক" আর "`count[x]--`" — এই জুটিই তাকে stable রাখে; record-এর তালিকায় এটাই প্রাণ।
- রাজ্য: মান পূর্ণসংখ্যা, range (k) ছোট। k ≈ n হলে রৈখিক গতি; k বিশাল হলে মেমরির বিপর্যয়।
- Negative range-এ offset (`x - min`); range 1..n হলে [Cyclic Sort](../problem-solving/cyclic-sort.mdx); আর digit ধরে বারবার চালালেই তার থেকে জন্ম radix sort-এর।
