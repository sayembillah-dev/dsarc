## কী শিখব

- Monotonic stack কী: এমন stack যা সবসময় একটানা বাড়তে বা কমতে থাকে
- "Next Greater Element" সমস্যাটা কী, আর brute force কোথায় আটকায়
- এক পাসে O(n)-এ সমাধান: পুরো dry run
- কেন ভেতরে while থাকলেও এটা O(n), amortized যুক্তি
- এই এক কৌশল দিয়ে আর কোন কোন বিখ্যাত সমস্যা খোলে

## ধারণা

এক সারিতে মানুষ দাঁড়িয়ে, সবার উচ্চতা লেখা আছে: `[2, 1, 5, 6, 2, 3]`। প্রত্যেকে জানতে চায়: **আমার ডানদিকে আমার চেয়ে লম্বা প্রথম মানুষটা কে?** কেউ না থাকলে উত্তর -1।

আকর্ষণীয় উপায়ে ভাবো। প্রথম মানুষ (উচ্চতা 2) ডানদিকে তাকিয়ে আছে। 1 কে দেখল, লম্বা না। 5 কে দেখল, থামো, এই-ই উত্তর। মানে প্রতিটা মানুষের জন্য ডানদিকে স্ক্যান চালালেই উত্তর আসে। এই সরল রাস্তাটাই brute force:

```js
// Brute force: প্রত্যেকের জন্য ডানদিকে স্ক্যান
function nextGreaterSlow(arr) {
  const result = Array(arr.length).fill(-1);
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[j] > arr[i]) {
        result[i] = arr[j];
        break;
      }
    }
  }
  return result;
}
```

খরচ? প্রতি উপাদানের জন্য খারাপ সময়ে পুরো ডানটা স্ক্যান, মোট প্রায় n²/2 তুলনা, **O(n²)**। লক্ষ উপাদানে হাজার কোটি পদক্ষেপ। প্রশ্ন হলো: সবাইকে কি সত্যিই আলাদা আলাদা স্ক্যান করতে হবে? নাকি কেউ "এখনও উত্তর পাইনি" দের তালিকা রাখলে নতুনজন একাই অনেকের উত্তর হয়ে যেতে পারে?

## মূল কৌশল: অপেক্ষারতদের stack

ভাবো এভাবে। বাম থেকে ডানে হাঁটছি। কিছু মানুষ এখনও নিজের "পরের লম্বা" পায়নি, তারা একটা তালিকায় অপেক্ষা করছে। এবার নতুন একজন এল, তার উচ্চতা 5। সে তাকিয়ে দেখে: অপেক্ষারতদের মধ্যে যাদের চেয়ে আমি লম্বা, **সবার উত্তর তো আমি-ই**! তাদের উত্তর দিয়ে তালিকা থেকে বিদায় করো। যারা আমার চেয়েও লম্বা, তারা অপেক্ষায় থাকে, আর আমি নিজেও এখন অপেক্ষারত।

এই তালিকাটা যদি stack হিসেবে রাখি, মজার ব্যাপার ঘটে: stack-এর ভেতরের উচ্চতাগুলো **সবসময় ক্রমানুসারে কমতে থাকে** (তলায় সবচেয়ে লম্বা, top-এ সবচেয়ে ছোট)। কেন? কারণ নতুন কেউ এলে তার চেয়ে ছোটদের সঙ্গে সঙ্গে বিদায় করে দিই, থেকে যায় শুধু লম্বারা। যে stack সবসময় এমন একটানা ক্রম ধরে রাখে (ক্রমশ কমতে বা বাড়তে), তাকেই বলে **monotonic stack**।

## Dry run: `[2, 1, 5, 6, 2, 3]`

Stack-এ রাখছি অপেক্ষারতদের **index** (index রাখলে মানও পাই, দূরত্বও পাই)। উত্তরের array শুরুতেই -1 ভরা:

| ধাপ | i | arr[i] | while-এ যা হলো | stack (index, ডানে top) | result |
|-----|---|--------|------------------|---------------------------|--------|
| 1 | 0 | 2 | stack খালি, সরাসরি push | `[0]` | `[-1,-1,-1,-1,-1,-1]` |
| 2 | 1 | 1 | 1 < arr[0]=2, push | `[0, 1]` | অপরিবর্তিত |
| 3 | 2 | 5 | 5 > 1 → index 1-এর উত্তর 5, pop; 5 > 2 → index 0-এর উত্তর 5, pop; তারপর push | `[2]` | `[5, 5, -1, -1, -1, -1]` |
| 4 | 3 | 6 | 6 > 5 → index 2-এর উত্তর 6, pop; push | `[3]` | `[5, 5, 6, -1, -1, -1]` |
| 5 | 4 | 2 | 2 < 6, push | `[3, 4]` | অপরিবর্তিত |
| 6 | 5 | 3 | 3 > 2 → index 4-এর উত্তর 3, pop; 3 < 6, থামো; push | `[3, 5]` | `[5, 5, 6, -1, 3, -1]` |
| শেষ | - | - | stack-এ 3, 5 রয়ে গেল, তাদের -1-ই থাকে | - | `[5, 5, 6, -1, 3, -1]` |

তিনটা জিনিস ভালো করে দেখো। এক, প্রতিটা index ঠিক **একবার** ঢুকেছে, সর্বোচ্চ **একবার** বের হয়েছে। দুই, ধাপ ৩-এ একটা নতুন মান একা দুজনের উত্তর দিয়ে দিল, এটাই brute force থেকে পার্থক্য: স্ক্যান আলাদা আলাদা না, উত্তর এসে গেলে পাইকারি বিতরণ। তিন, শেষে stack-এ যারা রইল, তাদের ডানে আর কেউ বড় হয়নি, তাই -1, যেটা আমরা শুরুতেই ধরে নিয়েছিলাম।

## কোড: নিজে বানাও nextGreater

```js
function nextGreater(arr) {
  const result = Array(arr.length).fill(-1);
  const stack = []; // অপেক্ষারতদের index; মান সবসময় কমতে থাকে

  for (let i = 0; i < arr.length; i++) {
    // নতুন মান যতজন অপেক্ষারতের উত্তর, সবাইকে দিয়ে দাও
    while (stack.length > 0 && arr[i] > arr[stack[stack.length - 1]]) {
      const j = stack.pop();
      result[j] = arr[i];
    }
    stack.push(i); // আমি নিজেও এখন অপেক্ষারত
  }
  // stack-এ যারা রয়ে গেল, তাদের result আগে থেকেই -1

  return result;
}

console.log(nextGreater([2, 1, 5, 6, 2, 3])); // [5, 5, 6, -1, 3, -1]
```

## Variant: পরের ছোটটা, আর দূরত্ব

একই কঙ্কাল ঘুরিয়ে দাও, নতুন কিছু লাগে না:

```js
// Next Smaller Element: তুলনার চিহ্ন উল্টে গেল, ব্যস
function nextSmaller(arr) {
  const result = Array(arr.length).fill(-1);
  const stack = [];

  for (let i = 0; i < arr.length; i++) {
    while (stack.length > 0 && arr[i] < arr[stack[stack.length - 1]]) {
      result[stack.pop()] = arr[i];   // এবার ছোটটাই উত্তর
    }
    stack.push(i);
  }
  return result;
}
```

আর "কে উত্তর" না দিয়ে **কত দূরে উত্তর** চাইলে (যেমন Daily Temperatures-এ "কতদিন পর গরম পড়বে"), index রাখার সুবিধাটা ফুটে ওঠে: `result[j] = i - j`। মানের বদলে দূরত্ব, এক লাইনের খেলা।

## কোড ব্রেকডাউন: nextGreater, লাইনে লাইনে

1. `Array(arr.length).fill(-1)` : ডিফল্ট উত্তর -1। শেষে stack-এ থেকে যাওয়াদের জন্য আলাদা কাজ করতে হলো না, এই চালাকিটা এক লাইনে সেরে ফেললাম।
2. `const stack = []` : মান না, **index** রাখছি। কারণ উত্তর লিখতে হবে result-এর সঠিক ঘরে, আর দূরত্ব-ভিত্তিক সমস্যায় index ছাড়া পথই নেই।
3. `while (...)` : if না, while। নতুন মান একজনের না, **যতজনের পারে সবার** উত্তর। একটা pop-এর পর নতুন top-ও ছোট হতে পারে, তাই ঘুরতে থাকো যতক্ষণ top বড়।
4. `arr[stack[stack.length - 1]]` : top-এর index থেকে মান বের করা। Stack-এ index আছে বলে এই দুই ধাপে যাওয়াটা বারবার আসবে, চোখ পাকিয়ে নাও।
5. `stack.push(i)` : নিজের উত্তর এখনও আসেনি, তাই আমিও অপেক্ষারতদের সারিতে। আর যেহেতু ছোটদের সব বিদায় করে তবেই ঢুকছি, stack-এর ক্রম (ক্রমশ কমতে থাকা) অক্ষত থাকল।

## Complexity: ভেতরে while থাকলেও কেন O(n)

এটাই interview-এর প্রিয় প্রশ্ন। বাইরে for-loop O(n), ভেতরে while, দেখে মনে হয় O(n²)। কিন্তু হিসাবটা এভাবে করো:

- প্রতিটা index জীবনে ঠিক **একবার push** হয়: মোট n-বার।
- প্রতিটা index সর্বোচ্চ **একবার pop** হয় (পপ হলে আর stack-এ ফেরে না): মোট সর্বোচ্চ n-বার।

তাহলে while মিলিয়ে সারা প্রোগ্রামে সর্বোচ্চ n-বার pop, বাইরের loop n-বার, মোট কাজ প্রায় 2n, মানে **O(n)**। কোনো এক ধাপে while অনেকবার ঘুরতে পারে (ধাপ ৩-এ দুইবার ঘুরেছিল), কিন্তু সেই খরচ কারও না কারও জীবনের একমাত্র pop, আবার আসবে না। [Array Operations](../arrays/array-operations.mdx)-এর amortized যুক্তির আরেকটা জয়গান এটা। Space O(n), খারাপ সময়ে (ক্রমশ কমতে থাকা array) সবাই stack-এ জমে থাকে।

## কোথায় আরও লাগে এই কৌশল

একটা কৌশল শিখলে যে একঝাঁক বিখ্যাত সমস্যা খুলে যায়, monotonic stack তার প্রধান উদাহরণ:

- **Daily Temperatures** (LeetCode 739): কতদিন পর গরম, index-এর stack আর `i - j`।
- **Stock Span:** কত দিন ধরে দাম আজকের চেয়ে কম ছিল।
- **Largest Rectangle in Histogram** (LeetCode 84): প্রতি বারের জন্য বামে আর ডানে প্রথম ছোটটা খুঁজে আয়তন, monotonic stack ছাড়া কল্পনাই কঠিন।
- **Sliding Window Maximum** (LeetCode 239): সেখানে একই ধারণার monotonic **deque** লাগে, [Deque](../queues/deque.mdx)-এর অনুশীলনে আঘাত হেনেছিলে।

## সাধারণ ভুল আর edge case

**১. `while`-এর জায়গায় `if` লেখা।**
একটা নতুন মান কেবল একজনের উত্তর না, যতজন অপেক্ষারত তার চেয়ে ছোট সবার। `if` দিলে প্রথমজনকে উত্তর দিয়ে থেমে যাবে, বাকিরা চিরদিন অপেক্ষায়, ফলাফল ভুল। ভেতরের লুপটাই এই কৌশলের প্রাণ।

**২. Stack-এ মান রেখে index-এর দরকার পড়ে যাওয়া।**
উত্তর result-এর কোন ঘরে লিখবে? দূরত্ব কত? দুটোতেই index চাই। শুরু থেকেই index রাখো, মান লাগলে `arr[index]` বের করে নেবে।

**৩. তুলনার চিহ্ন না বদলিয়ে সমস্যা বদলানো।**
"পরের ছোটটা" চাইলে `>` থেকে `<` করতে হবে, আর সমান মানের নীতি (strictly greater না greater-or-equal) সমস্যার উপর নির্ভর করে। একই কোড copy-paste করে চিহ্ন না বদলালে নিঃশব্দ ভুল।

**৪. সমান মানের ক্ষেত্রে নীতি না ঠিক করা।**
`[2, 2, 2]`-এ "পরের বড়টা" কারও নেই, সব -1। কিন্তু সমানকে pop করলে (>= শর্তে) আলাদা আচরণ পাবে। Histogram জাতীয় সমস্যায় এই সূক্ষ্মতা উত্তর বদলে দেয়, তাই সমস্যাটা পড়ে শর্ত ঠিক করো, ইচ্ছেমতো না।

**৫. শেষে stack পরিষ্কার করতে ভুলে যাওয়া, বা অযখন করা।**
`fill(-1)` দিয়ে শুরু করলে রয়ে যাওয়াদের কিছুই করতে হয় না। কিন্তু ডিফল্ট অন্য কিছু (যেমন circular array-এর দ্বিতীয় পাস) লাগলে রয়ে যাওয়াদের নিয়ে আলাদা ভাবতে হয়। অনুশীলনে সেই রূপটা দেখবে।

## অনুশীলন

- **সহজ ১:** কাগজে dry run করো `[4, 3, 2, 5, 1]`: প্রতি ধাপে stack আর result লিখো। উত্তর মিলাও: `[5, 5, 5, -1, -1]`।
- **সহজ ২:** Brute force version আর monotonic version, দুটোই লিখে ছোট array-তে চালাও, ফল মিলাও। তারপর বড় random array-তে দুটোর সময় মাপো (`console.time`), পার্থক্য নিজের চোখে দেখো।
- **মাঝারি ১:** Previous Greater Element লেখো: প্রতিটা উপাদানের **বামদিকে** প্রথম বড়টা কে। (হিন্ট: ডান থেকে বামে হাঁটো, কৌশল সেই একই। অথবা বাম থেকেই হাঁটো কিন্তু তুলনার দিকটা ভাবো, দুই রাস্তাই আছে।)
- **মাঝারি ২:** Daily Temperatures (LeetCode 739): `[73, 74, 75, 71, 69, 72, 76, 73]` → `[1, 1, 4, 2, 1, 1, 0, 0]`। (হিন্ট: আমাদের nextGreater-ই, শুধু `result[j] = i - j`।)
- **কঠিন:** Largest Rectangle in Histogram (LeetCode 84): `[2, 1, 5, 6, 2, 3]` → 10। (হিন্ট: প্রতিটা বারকে উচ্চতা ধরো; তার বামে প্রথম ছোটটা আর ডানে প্রথম ছোটটা জানলে সে কত চওড়া হতে পারে বের হয়। দুই দিকের দুটো monotonic stack পাস, তারপর প্রতি বারের আয়তন।)

## সারসংক্ষেপ

- Monotonic stack মানে stack-এর ভেতরের মান সবসময় এক ক্রমে, ক্রমশ বাড়তে বা কমতে।
- মূল ধারণা: নতুন উপাদান এলে সে একাই অনেক অপেক্ষারতের উত্তর; যাদের উত্তর পেল তাদের বিদায়, নিজে অপেক্ষায় যোগ।
- ভেতরে while থাকলেও O(n), কারণ প্রতিটা index জীবনে একবার push, সর্বোচ্চ একবার pop।
- Stack-এ index রাখো, মান না: উত্তরের ঘরও পাবে, দূরত্বও পাবে।
- Daily temperatures, stock span, histogram: এক কৌশল, একঝাঁক বিখ্যাত সমস্যা।
