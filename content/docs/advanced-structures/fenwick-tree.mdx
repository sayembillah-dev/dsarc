## কী শিখব

- prefix sum আর update, কম কোডে O(log n)

## ধারণা

Segment Tree তুমি জানোই। এবার বলো তো, কেবল prefix sum লাগলে কি এত বড় গাছ দরকার? **Fenwick Tree** (অন্য নাম Binary Indexed Tree বা BIT) হলো ওরই হালকা ভাই। prefix sum আর point update, দুটোই O(log n), অথচ কোড লাগে অল্প, memory-ও কম।

আসল জাদুটা লুকিয়ে আছে binary-র "lowest set bit"-এ। প্রতিটা index-এ জমা থাকে একটা নির্দিষ্ট range-এর যোগফল, আর কোন index কতটুকু range ঢাকছে, সেটা বলে দেয় ওই bit-টাই।

## কোড উদাহরণ

```js
class FenwickTree {
  constructor(size) { this.tree = new Array(size + 1).fill(0); } // 1-indexed

  update(i, delta) {                   // index i-তে delta যোগ
    i++;                               // 1-indexed
    for (; i < this.tree.length; i += i & -i) this.tree[i] += delta;
  }

  prefixSum(i) {                        // 0..i পর্যন্ত যোগফল
    i++;
    let sum = 0;
    for (; i > 0; i -= i & -i) sum += this.tree[i];
    return sum;
  }

  rangeSum(l, r) { return this.prefixSum(r) - this.prefixSum(l - 1); }
}

const ft = new FenwickTree(5);
[1, 2, 3, 4, 5].forEach((v, i) => ft.update(i, v));
console.log(ft.prefixSum(2)); // 1+2+3 = 6
console.log(ft.rangeSum(1, 3)); // 2+3+4 = 9
ft.update(2, 7);              // index 2-তে +7 (3 থেকে 10)
console.log(ft.rangeSum(1, 3)); // 2+10+4 = 16
```

## কোড ব্রেকডাউন

- `i & -i` মানে সবচেয়ে ডানদিকের set bit; এই bit-টাই ঠিক করে কোন index কত বড় range ঢাকছে।
- update-এর সময় bit যোগ করে উপরে উঠি, query-র সময় bit বিয়োগ করে নিচে নামি।
- range sum চাই? সহজ, দুটো prefix sum বিয়োগ করে দাও।

## Complexity

- update/query O(log n); space O(n)।
