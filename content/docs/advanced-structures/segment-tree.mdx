## কী শিখব

- Segment tree কীভাবে প্রতিটা node-এ একটা range-এর সারাংশ জমিয়ে রাখে
- কেন update-এর সামনে prefix sum হার মানে, আর segment tree মানে না
- হাতে হাতে পুরো dry run: build, query, update তিনটাই
- তিনটা ভ্যারিয়েন্ট: range-min tree, lazy propagation-এর ধারণা, iterative bottom-up tree
- Complexity: build O(n) আর query/update O(log n) কেন, 4n জায়গাটা কোথা থেকে আসে

## ধারণা

ধরো, তুমি একটা দোকানের হিসাব রাখো। সপ্তাহের পাঁচ দিনের বিক্রি (শত টাকায়): মঙ্গল 2, বুধ 4, বৃহস্পতি 1, শুক্র 3, শনি 5। Array-তে: [2, 4, 1, 3, 5]।

বস এসে জিজ্ঞেস করল, "বুধ থেকে শুক্র, মোট কত বিক্রি?" [Prefix sum](../problem-solving/prefix-sum.mdx) বানিয়ে রাখলে উত্তর এক সেকেন্ডে: prefix[3] - prefix[0] = 10 - 2 = 8। বস খুশি, তুমি খুশি।

কিন্তু পরদিন বস এসে বলল, "ওই বৃহস্পতিবারের বিক্রিটা ভুল লেখা হয়েছিল, 1 না, আসলে 10।" এবার বিপদ। Prefix sum array-তে বৃহস্পতিবারের পরের প্রতিটা ঘর বদলে যায়, মানে পুরোটা প্রায় আবার বানাতে হবে, O(n)। মাঝে মাঝে হলে চলে, কিন্তু দিনে হাজারটা update আর হাজারটা query হলে? Prefix sum তো আর কাজ করবে না।

**Segment tree** আসে ঠিক এই ফাঁকে। ধারণাটা সাদাসিধে: প্রতিটা node একটা range-এর যোগফল ধরে রাখে। Root ধরে পুরো array-টা, তার দুই সন্তান দুই অর্ধেক, তাদের সন্তানরা আরও ছোট ছোট অংশ, একদম নিচে leaf-গুলো ধরে একেকটা element। এবার:

- **Query** করতে পুরো range ঘোরা লাগে না; কয়েকটা node-এর জমানো উত্তর মিলিয়ে দিলেই চলে।
- **Update** করতে পুরো গাছ বানানো লাগে না; শুধু যেসব node-এর range-এ ওই index পড়ে, তাদের ঠিক করলেই চলে। আর সেই পথটা root থেকে leaf পর্যন্ত, মানে গাছের উচ্চতা সমান।

অর্ধেক অর্ধেক করে ভাগার কৌশলটা চেনা লাগছে? এটা [divide and conquer](../problem-solving/divide-and-conquer.mdx)-এরই প্রয়োগ। আর node-এর সন্তানদের index বের করার নিয়মটা (i-এর সন্তান 2i আর 2i+1) একদম [heap-এর মতো](../heaps/heap-as-array.mdx)।

## ধাপে ধাপে ড্রাই রান

ওই একই array: [2, 4, 1, 3, 5], index 0 থেকে 4।

### build: গাছটা দাঁড় করানো

```
                    [0-4] = 15
                  /          \
           [0-2] = 7          [3-4] = 8
           /      \           /      \
      [0-1] = 6  [2-2] = 1  [3-3] = 3  [4-4] = 5
      /     \
  [0-0] = 2  [1-1] = 4
```

Array-তে রাখা হয় heap-style index-এ, root বসে tree[1]-এ। আর ভরা হয় নিচ থেকে উপরে:

| ধাপ | কোন slot | range | মান | হিসাব কীভাবে |
|-----|---------|-------|-----|--------------|
| 1 | tree[8] | [0-0] | 2 | leaf: arr[0] |
| 2 | tree[9] | [1-1] | 4 | leaf: arr[1] |
| 3 | tree[4] | [0-1] | 6 | tree[8] + tree[9] |
| 4 | tree[5] | [2-2] | 1 | leaf: arr[2] |
| 5 | tree[2] | [0-2] | 7 | tree[4] + tree[5] |
| 6 | tree[6] | [3-3] | 3 | leaf: arr[3] |
| 7 | tree[7] | [4-4] | 5 | leaf: arr[4] |
| 8 | tree[3] | [3-4] | 8 | tree[6] + tree[7] |
| 9 | tree[1] | [0-4] | 15 | tree[2] + tree[3] |

ভরার ক্রমটা খেয়াল করো: সন্তানরা শেষ না হলে বাবার হিসাব হয় না। [Recursion](../recursion/recursion-intro.mdx)-এর ফিরতি পথেরই খেলা এটা।

### query(1, 3): বুধ থেকে শুক্র

| ধাপ | কোন node | ওর range | query-এর সাথে সম্পর্ক | সিদ্ধান্ত |
|-----|---------|----------|------------------------|-----------|
| 1 | tree[1] | [0-4] | আংশিক | দুই সন্তানে যাও |
| 2 | tree[2] | [0-2] | আংশিক (দরকার 1-2) | দুই সন্তানে যাও |
| 3 | tree[4] | [0-1] | আংশিক (দরকার 1) | দুই সন্তানে যাও |
| 4 | tree[8] | [0-0] | একদম বাইরে | 0 ফেরত, থামো |
| 5 | tree[9] | [1-1] | পুরোটা ভেতরে | 4 নাও |
| 6 | tree[5] | [2-2] | পুরোটা ভেতরে | 1 নাও |
| 7 | tree[3] | [3-4] | আংশিক (দরকার 3) | দুই সন্তানে যাও |
| 8 | tree[6] | [3-3] | পুরোটা ভেতরে | 3 নাও |
| 9 | tree[7] | [4-4] | একদম বাইরে | 0 ফেরত, থামো |

মোট: 4 + 1 + 3 = **8**। পাঁচটা element ঘোরা লাগল না, কাজ হলো মাত্র ৩টা node-এর জমানো মান নিয়ে। Array বড় হলে এই পার্থক্য আকাশছোঁয়া, হিসাবটা complexity-তে দেখাব।

### update: বৃহস্পতিবার 1 থেকে 10

শুধু যেসব node-এর range-এ index 2 আছে, তাদেরই বদলাতে হবে:

| ধাপ | কোন slot | range | আগের মান | নতুন মান |
|-----|---------|-------|----------|----------|
| 1 | tree[5] | [2-2] | 1 | 10 |
| 2 | tree[2] | [0-2] | 7 | 16 |
| 3 | tree[1] | [0-4] | 15 | 24 |

মাত্র ৩টা node বদলাল, বাকি ৬টা হুবহু রইল। কেন মাত্র এতগুলো? কারণ root থেকে leaf পর্যন্ত পথে যতগুলো node, গাছের উচ্চতা তত। এটাই পুরো কাণ্ড।

## কোড: পুরো implementation

একটা পুরো SegmentTree class, নিচে demo সহ:

```js
class SegmentTree {
  constructor(arr) {
    this.n = arr.length;
    this.tree = new Array(4 * this.n).fill(0); // কেন 4n, complexity-তে দেখব
    this.build(arr, 1, 0, this.n - 1);          // root বসে slot 1-এ
  }

  build(arr, node, lo, hi) {                    // node দায়িত্বে [lo, hi]
    if (lo === hi) {                            // এক ঘরের range: leaf
      this.tree[node] = arr[lo];
      return;
    }
    const mid = (lo + hi) >> 1;                 // >> 1 মানে 2 দিয়ে ভাগ
    this.build(arr, 2 * node, lo, mid);         // বাম অর্ধেক
    this.build(arr, 2 * node + 1, mid + 1, hi); // ডান অর্ধেক
    this.tree[node] = this.tree[2 * node] + this.tree[2 * node + 1];
  }

  query(node, lo, hi, ql, qr) {                 // [ql, qr]-এর যোগফল
    if (qr < lo || hi < ql) return 0;           // পুরোপুরি বাইরে
    if (ql <= lo && hi <= qr) return this.tree[node]; // পুরোপুরি ভেতরে
    const mid = (lo + hi) >> 1;                 // আংশিক: ভাগ করে যোগ
    return this.query(2 * node, lo, mid, ql, qr)
             + this.query(2 * node + 1, mid + 1, hi, ql, qr);
  }

  update(node, lo, hi, idx, value) {            // arr[idx] = value
    if (lo === hi) {                            // leaf-এ পৌঁছে গেছি
      this.tree[node] = value;
      return;
    }
    const mid = (lo + hi) >> 1;
    if (idx <= mid) this.update(2 * node, lo, mid, idx, value);
    else this.update(2 * node + 1, mid + 1, hi, idx, value);
    this.tree[node] = this.tree[2 * node] + this.tree[2 * node + 1]; // ফিরতি পথে মেরামত
  }

  rangeSum(l, r) { return this.query(1, 0, this.n - 1, l, r); }
  set(idx, value) { this.update(1, 0, this.n - 1, idx, value); }
}

// ডেমো: সেই দোকানের হিসাব
const st = new SegmentTree([2, 4, 1, 3, 5]);
console.log(st.rangeSum(1, 3)); // 8  (বুধ 4 + বৃহস্পতি 1 + শুক্র 3)
console.log(st.rangeSum(0, 4)); // 15 (পুরো সপ্তাহ)
console.log(st.rangeSum(2, 2)); // 1  (একটা দিনও একটা range)

st.set(2, 10);                  // বৃহস্পতিবারের বিক্রি আসলে 10 ছিল
console.log(st.rangeSum(1, 3)); // 17 (4 + 10 + 3)
console.log(st.rangeSum(0, 4)); // 24
// sum-এর বদলে min/max চাইলে? নিচে ভ্যারিয়েন্ট ১-এ সেটাই আছে
```

## ভ্যারিয়েন্ট ১: range-min tree

হঠাৎ বস বলল, "যোগফল না, বলো তো এই range-এ সবচেয়ে কম বিক্রি কোনদিন হয়েছিল?" পুরো কাঠামো হুবহু, পার্থক্য মাত্র দুই জায়গায়: যোগের জায়গায় `Math.min`, আর "বাইরে" case-এ 0-এর জায়গায় `Infinity`। কেন Infinity? কারণ min-এর দুনিয়ায় Infinity সেই সংখ্যা যা কাউকে বদলায় না, ঠিক যেমন যোগের দুনিয়ায় 0 কাউকে বদলায় না। এই সংখ্যার নাম **identity element**, ভুলের তালিকায় একটু পরেই এর শাস্তি দেখবে।

```js
class MinSegmentTree {
  constructor(arr) {
    this.n = arr.length;
    this.tree = new Array(4 * this.n).fill(Infinity);
    this.build(arr, 1, 0, this.n - 1);
  }

  build(arr, node, lo, hi) {
    if (lo === hi) { this.tree[node] = arr[lo]; return; }
    const mid = (lo + hi) >> 1;
    this.build(arr, 2 * node, lo, mid);
    this.build(arr, 2 * node + 1, mid + 1, hi);
    this.tree[node] = Math.min(this.tree[2 * node], this.tree[2 * node + 1]);
  }

  rangeMin(l, r, node = 1, lo = 0, hi = this.n - 1) {
    if (r < lo || hi < l) return Infinity;      // min-এর identity
    if (l <= lo && hi <= r) return this.tree[node];
    const mid = (lo + hi) >> 1;
    return Math.min(
      this.rangeMin(l, r, 2 * node, lo, mid),
      this.rangeMin(l, r, 2 * node + 1, mid + 1, hi)
    );
  }
}

const mst = new MinSegmentTree([2, 4, 1, 3, 5]);
console.log(mst.rangeMin(1, 3)); // 1 (বুধ, বৃহস্পতি, শুক্রের মধ্যে সর্বনিম্ন)
console.log(mst.rangeMin(0, 4)); // 1 (পুরো সপ্তাহেও)
```

`Math.max` বসালেই range-max, gcd বসালেই range-gcd। শর্ত একটাই: অপারেশনটা এমন হতে হবে যাতে দুই অর্ধেকের উত্তর মিলিয়ে পুরোর উত্তর পাওয়া যায়।

## ভ্যারিয়েন্ট ২: lazy propagation (ধারণাটা)

এবার বসের নতুন ফরমাইন: "বুধ থেকে শুক্র, প্রতিদিনের বিক্রিতে 5 করে বোনাস যোগ করো।" একেকটা করে update করলে 3 × O(log n)। আর range-টা যদি লক্ষটা index-এর হয়? তখন তো ব্যস্ত।

Lazy কৌশলটা এমন: যে node-এর range পুরোপুরি update range-এর ভেতরে পড়ে, তার মান এক ধাপে ঠিক করে দাও (range-এর size × 5 বাড়ে), আর পাশে একটা ট্যাগ ঝুলিয়ে দাও: "আমার সন্তানদের এখনো খবর দেওয়া হয়নি, প্রত্যেকে 5 পাবে।" সন্তানদের কাছে যাওয়াই হলো না। পরে যখনই কোনো query বা update সেই সন্তানদের লাগবে, নামার আগে ট্যাগটা নিচে ঠেলে দাও (push down)। ফলে range update-ও থাকে O(log n)-এর কাছাকাছি।

সৎ থাকি: পুরো lazy implementation (ট্যাগ array, push down, query-র সাথে সমন্বয়) এই পাতার আওতার বাইরে, কোডটা মূল tree-এর প্রায় দ্বিগুণ। এখন ধারণাটা মাথায় রাখো; অনুশীলনের LC 308-এ গেলে সেদিন লাগবে।

## ভ্যারিয়েন্ট ৩: iterative bottom-up tree (টিজার)

Recursion ছাড়াও segment tree বানানো যায়। কৌশল: leaf-গুলো বসে tree[n..2n-1]-এ, তারপর নিচ থেকে উপরে। কোড অবিশ্বাস্য ছোট:

```js
class IterSegTree {
  constructor(arr) {
    this.n = arr.length;
    this.t = new Array(2 * this.n).fill(0);
    for (let i = 0; i < this.n; i++) this.t[this.n + i] = arr[i]; // leaf-গুলো
    for (let i = this.n - 1; i > 0; i--)                           // ভেতরের node
      this.t[i] = this.t[2 * i] + this.t[2 * i + 1];
  }
}

console.log(new IterSegTree([2, 4, 1, 3, 5]).t[1]); // 15, root-এ পুরো যোগফল
```

Query/update-ও লুপ দিয়ে সম্ভব, কিন্তু সেই লুপের যুক্তি নতুন করে শেখা লাগে। জানতে চাইলে LC 307-এর editorial দেখো; এই পাতায় recursive রূপটাই রইল, কারণ সেটা বোঝা সহজ, আর lazy-তেও বাড়ানো যায়।

## কোড ব্রেকডাউন: মূল SegmentTree, লাইনে লাইনে

1. `this.tree = new Array(4 * this.n)` : heap-style indexing-এ সব slot ভরে না, ফাঁকা ফাঁকা থাকে। গভীরতা অনুযায়ী সর্বোচ্চ slot number 4n-এর নিচে থাকে, তাই 4n নিরাপদ। 2n নিলে কিছু কিছু n-এর জন্য index বাইরে চলে যাবে।
2. `this.build(arr, 1, 0, this.n - 1)` : root slot 1-এ, দায়িত্ব পুরো range। slot 0 ফাঁকা, কারণ সন্তানের হিসাব 2i, 2i+1 শূন্য থেকে শুরু হলে গোলমাল হয়ে যায়।
3. `if (lo === hi)` : range এক ঘরের মানে leaf; ওখানে হিসাব নেই, arr-এর মানটাই বসে যায়।
4. `const mid = (lo + hi) >> 1` : অর্ধেক কোথায়। `>> 1` হলো 2 দিয়ে ভাগের পুরনো কায়দা, [bit manipulation](../problem-solving/bit-manipulation.mdx) পাতায় এর আরও ব্যবহার আছে।
5. `2 * node` আর `2 * node + 1` : বাম আর ডান সন্তানের slot, হুবহু heap-এর নিয়ম।
6. ফিরতি লাইন `this.tree[node] = ... + ...` : দুই সন্তানের হিসাব শেষে বাবার মান। এই এক লাইনেই পুরো গাছ "সারাংশের গাছ" হয়ে ওঠে।
7. query-এ `if (qr < lo || hi < ql) return 0` : পুরোপুরি বাইরে। sum-এর identity 0, তাই 0 ফেরত দিলে যোগফল নষ্ট হয় না।
8. `if (ql <= lo && hi <= qr) return this.tree[node]` : পুরোপুরি ভেতরে। আর নিচে নামা দরকার নেই, জমানো উত্তরই নেওয়া হলো। এটাই tree-এর আসল সাশ্রয়।
9. query-এর শেষে দুই ডাকের যোগ : আংশিক মিল মানে উত্তর দুই অর্ধে ছড়িয়ে আছে, দুটোই লাগবে।
10. update-এ শেষ লাইনটা recursion-এর **ফিরতি পথে** চলে : leaf বদলানোর পর ওই পথের প্রতিটা বাবা নতুন হিসাব পায়। এই লাইন ভুলে গেলে গাছ পুরনো মান নিয়ে বসে থাকবে।

## Complexity: হিসাবটা কোথা থেকে আসে

**build: O(n)।** হিসাবটা node গুনে: n-টা leaf, আর পুরো বাইনারি গাছে ভেতরের node leaf-এর চেয়ে এক কম, মোট প্রায় 2n-টা node। প্রতিটা node-এ constant কাজ, একটা যোগ। তাই O(n)। Level ধরে যোগ করলেও একই কথা: n + n/2 + n/4 + ... = প্রায় 2n, কখনোই n log n নয়।

**query: O(log n)।** আসল চাবিকাঠি গাছের উচ্চতা: প্রতি ভাগে range অর্ধেক হয়, n থেকে 1-এ নামতে log2(n)-টা ভাগ লাগে, তাই level আছে প্রায় log n-টা। আর প্রতি level-এ সর্বোচ্চ কয়টা node-এ কাজ হয়? query range-এর দুই সীমার পথ ছাড়া বাকি node হয় পুরো ভেতরে (আর ভাঙে না), হয় পুরো বাইরে (থেমে যায়)। ফলে প্রতি level-ে অনেক বেশি ৪টা node ছোঁয়া লাগে। level × সেই constant = O(log n)।

**update: O(log n)।** একটাই পথ, root থেকে leaf: উচ্চতা যত, কাজ তত। ফিরতি পথে প্রতি বাবায় একটা যোগ, সেটাও সেই একই পথের লম্বা।

**space: O(n), আসলে 4n।** গাছে আসল node 2n-এর কম, কিন্তু heap-style index-ে slot লাফিয়ে লাফিয়ে ব্যবহার হয়। সর্বোচ্চ slot number কখনো 4n ছাড়ায় না, তাই 4n নেওয়াই নিরাপদ রীতি।

তিন পক্ষের তুলনাটা দেখো: সাধা array-তে update O(1) কিন্তু query O(n); prefix sum-এ query O(1) কিন্তু update O(n); segment tree দুটোই O(log n) করে, কারো হাতে হার না মানলেও কারো কাছে হারেও না। এই "দুটোই ভালো" দামেই তার জন্ম। আর sum-family-র কাজ হলে [Fenwick tree](./fenwick-tree.mdx) নামে এক ভাই আছে, যে একই গতি দেয় চার ভাগের এক ভাগ মেমরিতে, ওর পাতায় এই একই দোকান আবার দেখবে।

## সাধারণ ভুল আর edge case

**১. tree-এর size 2n ধরে নেওয়া।**
Heap-style indexing-এ slot-গুলো টানা ভরে না: আমাদের ছোট্ট গাছেই tree[8], tree[9] লেগেছে, অনেক slot খালিই থাকে। 2n size নিলে কোনো না কোনো n-এর জন্য index array-র বাইরে চলে যাবে, আর JavaScript চুপচাপ undefined দিয়ে দেবে, যোগফল হবে NaN। নিয়ম মনে রাখো: recursive tree-এ 4n, iterative-এ 2n।

**২. "বাইরে" case-এ ভুল identity ফেরত দেওয়া।**
Sum tree-তে বাইরে মানে 0, ঠিক আছে। কিন্তু min tree-তে সেই অভ্যেসে 0 ফেরত দিলে? `Math.min(আসল উত্তর, 0)` সবসময় 0-কেই জিতিয়ে দেবে, সব rangeMin হয়ে যাবে 0। মনে রাখো: sum-এ 0, min-এ Infinity, max-এ -Infinity। অপারেশন বদলালে identity-ও বদলায়, এটা ভুললে কোড চুপচাপ ভুল উত্তর দেবে।

**৩. inclusive নাকি exclusive, সেটা গুলিয়ে ফেলা।**
এই পাতার কোডে rangeSum(l, r) দুই প্রান্তই ধরে, LC 307-ও এমন। কিন্তু অনেক বইয়ে [l, r) দেখবে। নিজের কোডে দুই ধরন মেশালে উত্তর এক ঘর এদিক-সেদিক হবে, আর তুমি ঘণ্টার পর ঘণ্টা ভুল খুঁজবে সেখানে যেখানে ভুল নেই।

**৪. assign আর delta update গুলিয়ে ফেলা।**
"index 2-এ 10 বসাও" আর "index 2-তে 10 যোগ করো" এক নয়। এই পাতার `set` হলো assign, leaf-এ value বসে যায়। Delta চাইলে leaf-এ `+=` লাগবে। LC 307-এর update হলো assign; আর [Fenwick](./fenwick-tree.mdx)-এর add হলো delta, দুই ভাইয়ের ভাষা এখানেই পাল্টায়।

**৫. update-এ ফিরতি পথের হিসাব ভুলে যাওয়া।**
Leaf-এ মান বসিয়ে return করে ফেললে উপরের node-গুলো পুরনো যোগফল নিয়েই বসে থাকে। তারপরের query-গুলো আসবে ভুল, আর ভুলটা দেখাবে এলোমেলো, কখনো ঠিক কখনো ভুল। শেখার সেরা উপায়: recursion-এর শেষ লাইনটা (`this.tree[node] = ...`) মুছে একবার চালিয়ে দেখো, ভুলটা চোখে দেখা যাবে।

## অনুশীলন

- **সহজ ১:** Range Sum Query - Immutable (LeetCode 303)। হিন্ট: এখানে update-ই নেই, তাই [prefix sum](../problem-solving/prefix-sum.mdx) দিয়েই O(1) query; segment tree নিলে overkill হবে, সেই পার্থক্যটা অনুভব করাই লক্ষ্য।
- **সহজ ২:** Range Sum Query - Mutable (LeetCode 307)। হিন্ট: এই পাতার SegmentTree class হুবহু চলবে; শুধু মনে রেখো ওখানকার update(index, val) হলো assign, delta নয়।
- **মাঝারি ১:** Count of Smaller Numbers After Self (LeetCode 315)। হিন্ট: মানগুলোকে ছোট সংখ্যায় চাপাও (compression), ডান থেকে বামে এসে "আমার চেয়ে ছোট কয়টা এসেছে" tree-তে গুনো; অন্য রাস্তা, [merge sort](../sorting/merge-sort.mdx)-এর merge ধাপেই এই গোনা লুকিয়ে আছে।
- **মাঝারি ২:** Count of Range Sum (LeetCode 327)। হিন্ট: আগে prefix sum বানাও, প্রশ্নটা তখন "কত জোড়া prefix-এর পার্থক্য [lower, upper]-এর ভেতরে"; prefix-গুলো compress করে segment tree বা [Fenwick](./fenwick-tree.mdx)-তে গুনো।
- **কঠিন:** Range Sum Query 2D - Mutable (LeetCode 308)। হিন্ট: প্রতি row-র জন্য একটা করে tree, অথবা tree-এর ভেতরে tree; আগে 1D-র LC 307-টা পেরে এসো, তারপর ধারণাটা দুই দিকে প্রসার করো।

## সারসংক্ষেপ

- Segment tree = প্রতিটা node তার range-এর সারাংশ ধরে; root ধরে পুরো array।
- Query মানে কয়েকটা node-এর জমানো উত্তর মেলানো, update মানে root-থেকে-leaf একটা পথ মেরামত; দুটোই O(log n)।
- build O(n), জায়গা 4n (heap-style indexing-এর নিরাপদ মাপ)।
- sum, min, max, gcd, যেকোনো "দুই অর্ধেক মেলানো যায়" এমন অপারেশন চলে; শুধু identity-টা ঠিক রাখো।
- update না থাকলে [prefix sum](../problem-solving/prefix-sum.mdx)-ই যথেষ্ট; আর শুধু sum-family লাগলে [Fenwick](./fenwick-tree.mdx) অনেক হালকা।
