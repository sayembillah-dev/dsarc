## কী শিখব

- node আর pointer দিয়ে linked list কীভাবে বানানো হয়
- array-এর contiguous memory-র সাথে scattered node-এর পার্থক্য
- head কী, আর কেন শুধু head ধরে রাখলেই পুরো লিস্ট হাতে পাওয়া যায়
- traversal-এর বেসিক ছক, যেটা পরের প্রতিটা অপারেশনে লাগবে

## ধারণা

ধরো, তুমি একটা treasure hunt খেলছ। প্রথম clue-তে শুধু লেখা আছে পরের clue কোথায় লুকানো। সেখানে গেলে আবার পরেরটার ঠিকানা। পুরো খেলাটা এভাবেই এগোয়। কেউ আগে থেকে পুরো তালিকা হাতে পায় না, শুধু "পরেরটা কোথায়" এই একটাই তথ্য ধরে এগিয়ে যায়।

Linked List-ও ঠিক এমন। এখানে প্রতিটা ঘরের নাম **node**। প্রতিটা node দুটো জিনিস ধরে রাখে: (১) নিজের **data**, (২) পরের node-এর ঠিকানা, অর্থাৎ **next pointer**। মেমরিতে node গুলো যেখানে-সেখানে ছড়িয়ে থাকতে পারে, দোষ নেই। pointer-এর টান ধরে একটার পর একটা খুঁজে পাওয়া যায়, এটাই আসল।

```
[10|•] -> [20|•] -> [30|null]
 head
```

ভাবো তো, [array-এ কী হতো](../arrays-strings/array-basics.mdx)? সব ঘর পাশাপাশি সাজানো, তাই `base_address + (i × element_size)` হিসাব করে সরাসরি যেকোনো ঘরে লাফানো যায়। Linked list-এ সেই ছক নেই। ঘরগুলো ছড়ানো, তাই "পঞ্চমটা কী?" জানতে চাইলে head থেকে একে একে হেঁটে যেতে হয়। এই একটা পার্থক্য থেকেই পরের সব সুবিধা-অসুবিধার হিসাব আসে।

## মেমরিতে আসলে কী ঘটে

ধরো, তিনটা node বানালে: 10, 20, 30। Array হলে এরা গলা-গল হয়ে বসত। কিন্তু এখানে মেমরিতে তাদের অবস্থা এমন হতে পারে:

| ধাপে কততম | node-এর address | value | next-এ কার address বসে |
|-----------|-----------------|-------|------------------------|
| 1ম | 1000 | 10 | 2040 |
| 2য় | 2040 | 20 | 1400 |
| 3য় | 1400 | 30 | null |

লক্ষ করো, address গুলোর কোনো ধারাবাহিকতা নেই। 1000-এর পর 2040, তারপর 1400। কেউ কারো পাশে নেই। তবু শৃঙ্খল অক্ষত, কারণ প্রতিটা node জানে পরেরটা কোথায়।

আর **head**? head কোনো আলাদা node নয়। head হলো শুধু প্রথম node-এর address, এখানে 1000। এই একটা সংখ্যা ধরে রাখলেই পুরো শৃঙ্খল তোমার হাতে। head হারালে পুরো লিস্ট হারানো, কারণ প্রথমটার ঠিকানা ছাড়া কারো ঠিকানাই আর জানা নেই।

## কোড উদাহরণ

```js
class Node {
  constructor(value) {
    this.value = value;   // ডেটা
    this.next = null;     // পরের node-এর দিকে তীর, শুরুতে কারো দিকে নয়
  }
}

// হাতে জোড়া লাগাই: 10 -> 20 -> 30
const a = new Node(10);
const b = new Node(20);
const c = new Node(30);
a.next = b;
b.next = c;

// head ধরে রাখি
const head = a;

// traversal: head থেকে শুরু, null না আসা পর্যন্ত হাঁটা
let current = head;
while (current !== null) {
  console.log(current.value);
  current = current.next;
}
// ছাপে: 10, 20, 30
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `class Node` বলে দিচ্ছে, প্রতিটা node-এ দুটো জিনিস থাকবে: `value` আর `next`।
2. নতুন node বানালে `this.next = null` দিয়ে শুরু। মানে এখনো সে কাউকে চেনে না।
3. `a.next = b` লাইনটাই আসল জাদু। এটা b-কে কোথাও সরায় না, শুধু a-র ভেতরে b-র ঠিকানা বসিয়ে দেয়। তীর টানা হলো।
4. `b.next = c` দিয়ে দ্বিতীয় তীর। c-র `next` কেউ ছোঁয়েনি, তাই সেটা `null`-ই আছে, মানে "এখানেই শেষ"।
5. `const head = a` মানে আমরা প্রথম node-এর ঠিকানাটা আলাদা করে মনে রাখলাম।
6. `let current = head` দিয়ে হাঁটা শুরু। `current` হলো আমাদের হাঁটার pointer, লিস্টের অংশ নয়।
7. `while (current !== null)` মানে যতক্ষণ পায়ের নিচে node আছে, ততক্ষণ হাঁটা।
8. `current = current.next` এই লাইনেই এক ঘর এগিয়ে যাওয়া। `current.next`-এ পরের node-এর ঠিকানা আছে, সেটাই নতুন `current` হলো।

## Dry run: traversal-এর ভেতরে কী হচ্ছে

উপরের traversal লুপটা ধাপে ধাপে দেখি। শর্ত `current !== null`:

| ধাপ | current কোন node | শর্ত মিলে? | ছাপে | এরপর current = current.next |
|-----|------------------|-----------|------|------------------------------|
| 1 | a (10) | হ্যাঁ | 10 | b |
| 2 | b (20) | হ্যাঁ | 20 | c |
| 3 | c (30) | হ্যাঁ | 30 | null |
| 4 | null | না, লুপ শেষ | | |

চার ধাপে কাজ শেষ। n টা node থাকলে ঠিক n ধাপ লাগে, একটাও বেশি নয়, কমও নয়, কারণ প্রতিটার ভেতর দিয়ে একবার করে যেতেই হয়।

## Complexity: কোথায় কত দাম

| কাজ | Cost | কেন |
|-----|------|-----|
| i-তম node-এ যাওয়া | O(n) | head থেকে হেঁটে যাওয়া ছাড়া পথ নেই; সরাসরি লাফানোর address-ছক নেই |
| Traversal (পুরো) | O(n) | প্রতিটা node-এ ঠিক একবার |
| শুরুতে insert/delete | O(1) | শুধু head আর একটা next pointer বদলায়, পরের পেজে বিস্তারিত |
| Extra space | O(n) | মোট n টা node, প্রতিটায় একটা করে বাড়তি next pointer |

দামটা বুঝো: array-এর O(1) index access-এর বিনিময়ে linked list দিচ্ছে শুরুতে O(1) insert/delete। কোনটা দরকার, সেটা কাজের ধরন দেখে ঠিক করতে হয়। এই লড়াইটাই শেষ পেজে গিয়ে ফয়সালা হবে: [Array vs Linked List](./array-vs-linked-list.mdx)।

## সাধারণ ভুল আর edge case

1. **head হারিয়ে ফেলা।** হেসে হেসে `head = head.next` লিখে দিলে আগের প্রথম node-এর ঠিকানা আর কারো জানা নেই। পুরো লিস্ট উধাও। হাঁটার জন্য সবসময় আলাদা `current` নাও, `head` কে অক্ষত রাখো।
2. **`null.next` পড়তে গিয়ে crash।** শর্ত `while (current)` আর `while (current.next)` এক নয়। প্রথমটা প্রতিটা node-এ ঢোকে, দ্বিতীয়টা শেষ node-এ ঢোকেই না। কোনটা চাই, ভেবে লেখো।
3. **শেষ node-এর `next` ঠিক না রাখা।** নতুন node জুড়ে তার `next` null না রাখলে বা ভুল জায়গায় দেখালে, traversal কখনো থামবে না বা ভুল জায়গায় যাবে।
4. **`current = current.next` লিখতে ভুলে যাওয়া।** লুপের ভেতরে এগিয়ে যাওয়ার লাইনটা ভুললে `current` একই node-এ আটকে থাকে, infinite loop।
5. **array-এর অভ্যাসে `list[i]` ভাবা।** linked list-এ index দিয়ে সরাসরি ঢোকার কোনো উপায় নেই। "তৃতীয়টা চাই" মানেই head থেকে দুই ধাপ হাঁটা।

## অনুশীলন

1. **সহজ:** হাতে ৪টা node জুড়ে (5, 12, 7, 9), ৩য় node-এর value ছাপাও। *Hint: `head.next.next.value`।*
2. **সহজ:** একটা while লুপ দিয়ে পুরো লিস্টের value গুলো যোগফল বের করো। *Hint: traversal ছকটা হুবহু, শুধু ভেতরে `sum += current.value`।*
3. **মাঝারি:** `countNodes(head)` ফাংশন লেখো, যেটা বলে দেয় লিস্টে কতটা node আছে। *Hint: একটা counter নিয়ে প্রতি ধাপে বাড়াও; খালি লিস্টে (head null) ফল ০।*
4. **মাঝারি:** `getAt(head, i)` লেখো, যেটা i-তম node-এর value দেয়; i লিস্টের বাইরে হলে `null` দেয়। *Hint: i বার `current = current.next` চালাও, পথে current null হয়ে গেলেই থেমে `null` ফেরত দাও।*
5. **কঠিন:** এক পাশেই লিস্টের মাঝের node খুঁজে বের করো। *Hint: দুটো pointer নাও, `slow` এক ধাপ করে, `fast` দুই ধাপ করে এগোয়। fast শেষে পৌঁছালে slow ঠিক মাঝখানে দাঁড়িয়ে। এই ছকটা পরে [linked list cycle](/docs/graphs) আর দুই-pointer প্যাটার্নে আবার লাগবে।*

## সারসংক্ষেপ

- Linked list হলো node-দের শৃঙ্খল; প্রতিটা node ধরে রাখে data আর পরের node-এর ঠিকানা (`next`)।
- মেমরিতে node গুলো ছড়ানো থাকে; জোড় শুধু pointer-এ। তাই index access O(n), কিন্তু শুরুতে insert/delete O(1)।
- `head` হলো প্রথম node-এর ঠিকানা; এটা হারালে পুরো লিস্ট হারানো।
- Traversal-এর ছক মুখস্থ রাখো: `let current = head; while (current !== null) { ...; current = current.next; }`
