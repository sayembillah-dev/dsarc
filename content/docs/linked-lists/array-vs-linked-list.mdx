## কী শিখব

- পরিস্থিতি দেখে সঠিক কাঠামো বাছাই

## ধারণা

এই লড়াইয়ের ফয়সালা আসলে একটাই প্রশ্নে: তুমি বেশি করবে কী? ঘন ঘন random access, নাকি ঘন ঘন শুরুতে-মাঝে insert-delete? আগে টেবিলটা দেখে নাও:

| দিক | Array | Linked List |
|-----|-------|-------------|
| Index access | **O(1)** | O(n) |
| শুরুতে insert/delete | O(n) | **O(1)** |
| Memory | কম, ধারাবাহিক | বেশি (pointer) |
| Cache-friendly | হ্যাঁ | না |
| আকার | সাধারণত fixed-ভিত্তিক | সহজে বাড়ে |

সহজ কথায়, random access বেশি লাগলে Array, আর শুরুতে বা মাঝে ঘন ঘন insert-delete লাগলে Linked List।

## কোড উদাহরণ

```js
// Array-এ শুরুতে insert: সবাইকে সরাতে হয়, O(n)
const arr = [2, 3, 4];
arr.unshift(1);
console.log(arr); // [1, 2, 3, 4]

// Linked List-এ শুরুতে insert: শুধু pointer বদল, O(1)
const head = { value: 2, next: { value: 3, next: { value: 4, next: null } } };
const newHead = { value: 1, next: head }; // এক ধাপেই শেষ
console.log(newHead.next.value); // 2, আগের শৃঙ্খল অটুট

// Array-এ index access সরাসরি, O(1)
console.log(arr[2]); // 3
```

## কোড ব্রেকডাউন

- `unshift` করলে শুরুতে জায়গা বানাতে গিয়ে সব উপাদান সরে যায়, তাই O(n)।
- linked list-এ নতুন node-এর `next`-এ পুরনো `head` বসালেই insert শেষ, তাই O(1)।
- কিন্তু তৃতীয় উপাদানটা চাইলে? array-তে `arr[2]` লিখেই পেয়ে গেলে, O(1)। linked list-এ head থেকে হেঁটে যেতে হয়, তাই O(n)।

## Complexity

- random access-এ array O(1) কিন্তু linked list O(n); শুরুতে insert/delete-এ linked list O(1) কিন্তু array O(n)।
