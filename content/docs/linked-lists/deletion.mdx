## কী শিখব

- pointer ঘুরিয়ে মাঝের node বাদ দেওয়া
- কেন deletion-এ টার্গেট node নয়, তার **আগের** node দরকার
- head মুছার কেস কেন আলাদা সামলাতে হয়
- খোঁজা O(n) আর rewiring O(1), দুটো মিলে মোট হিসাব কী

## ধারণা

ধরো, কয়েকজন হাত ধরে একটা শৃঙ্খল বানিয়েছে। এবার মাঝের একজনকে সরাতে হবে। কী করবে? তার **আগের** হাতটা সরাসরি **পরের** জনটাকে ধরিয়ে দেবে। মাঝের জন বাইপাস, আর সে শৃঙ্খলে নেই। লক্ষ করো, যাকে সরাচ্ছ তাকে নিয়ে কিছুই করা হলো না। কাজটা পুরোটাই হয়েছে তার আগের জনের হাত ঘুরিয়ে।

Deletion-ও ঠিক এই কাজটাই করে। মুছতে চাওয়া node-এর আগের node-এর `next` ঘুরিয়ে পরের node-এ জুড়ে দিলেই কাজ শেষ। মাঝের node বাইপাস হয়ে যায়।

```
মুছি 20:  [10|•] -> [20|•] -> [30]
পরে:      [10|•] ----------> [30]
```

ভাবো তো, কেন টার্গেট node-টা নিজে দরকার নয়? কারণ singly linked list-এ পেছনে যাওয়ার কোনো পথ নেই। টার্গেটের হাতে শুধু পরেরটার ঠিকানা আছে, আগেরটার নয়। তাই "আগের node"-টা ধরে রাখতেই হবে, তার হাতেই তো তীর ঘোরাতে হবে। এই একটা আইডিয়া বুঝে গেলে deletion-এর সব কোড পরিষ্কার হয়ে যাবে।

## কোড উদাহরণ

```js
class Node {
  constructor(value) { this.value = value; this.next = null; }
}

class LinkedList {
  constructor() { this.head = null; this.size = 0; }

  append(value) {
    const node = new Node(value);
    if (!this.head) { this.head = node; this.size++; return; }
    let current = this.head;
    while (current.next) current = current.next;
    current.next = node;
    this.size++;
  }

  // value ধারণকারী প্রথম node মুছে ফেলা
  remove(value) {
    if (!this.head) return;                       // খালি লিস্ট
    if (this.head.value === value) {              // কেস ১: head-ই মুছতে হলে
      this.head = this.head.next;
      this.size--;
      return;
    }
    // কেস ২: মাঝে বা শেষে। "আগের node" খুঁজি
    let current = this.head;
    while (current.next && current.next.value !== value) {
      current = current.next;
    }
    if (current.next) {                           // পেলে বাইপাস করি
      current.next = current.next.next;
      this.size--;
    }
    // না পেলে কিছুই করি না
  }

  print() {
    const parts = [];
    let current = this.head;
    while (current) { parts.push(current.value); current = current.next; }
    console.log(parts.join(" -> ") + " -> null");
  }
}

const list = new LinkedList();
list.append(10); list.append(20); list.append(30);
list.print();     // 10 -> 20 -> 30 -> null
list.remove(20);  // মাঝের node বাইপাস
list.print();     // 10 -> 30 -> null
list.remove(10);  // head মুছলে
list.print();     // 30 -> null
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `remove` শুরুতেই খালি লিস্টের চেক। মুছবার কিছুই নেই, চুপচাপ return।
2. এরপর head-এর আলাদা কেস। head-এর তো আগে কেউ নেই, যার হাত ঘোরাব। তাই এখানে লেবেলটাই সরে যায়: `this.head = this.head.next`। পুরনো head আর কেউ চেনে না।
3. কেস ২-এ লুপের শর্তটা ভালো করে দেখো: `current.next && current.next.value !== value`। মানে, `current`-এর **পরেরটা** আছে এবং সেটা টার্গেট নয়, তাহলেই এগোই। লুপ থামলে `current` দাঁড়িয়ে থাকে ঠিক টার্গেটের **আগের** node-এ। এই থামার জায়গাটাই সব।
4. লুপ থামার পর `current.next` null হতে পারে, মানে পুরো লিস্ট ঘুরেও value পাইনি। তাই `if (current.next)` চেক, পেলে তবেই বাইপাস করি।
5. বাইপাসের লাইন: `current.next = current.next.next`। আগের node-এর তীর এখন টার্গেটকে লাফ দিয়ে তার পরেরটাকে দেখায়। টার্গেট নিজে অক্ষতই আছে, শুধু শৃঙ্খলে আর কেউ তাকে চেনে না।
6. মুছে যাওয়া node-টা আলাদা করে "ডিলিট" করার কিছু নেই। কারো কাছে তার ঠিকানা না থাকলে JavaScript-এর garbage collector নিজেই মেমরি খালি করে দেয়।

## Dry run: 20-কে মুছি

লিস্ট: `10 -> 20 -> 30 -> null`। `remove(20)` চালাই। head-এর value 10, টার্গেট নয়, তাই কেস ২-এ ঢুকি।

| ধাপ | current | current.next | current.next.value === 20? | কী করি |
|-----|---------|--------------|-----------------------------|--------|
| 1 | node(10) | node(20) | হ্যাঁ, লুপে ঢুকবই না | থেমে যাই |
| 2 | node(10) | node(20) | | `current.next = current.next.next`, মানে 10-এর তীর এখন 30-এ |

ফল: `10 -> 30 -> null`। 20-নম্বর node মেমরিতে এখনো পড়ে আছে ঠিকই, কিন্তু তার দিকে কারো তীর নেই। পরের garbage collection-এ সে চলে যাবে।

**এবার `remove(10)`:** `head.value === 10` মিলে গেল, তাই সরাসরি `head = head.next`। ফল: `30 -> null`। head মুছতে একটাও লুপ লাগল না, শুধু একটা লেবেল সরানো। তাই head deletion O(1)।

## Complexity: কোথায় কত দাম

| কাজ | Cost | কেন |
|-----|------|-----|
| head মুছা | O(1) | শুধু `head = head.next`, লুপ লাগে না |
| মাঝের/শেষের node মুছা | O(n) | আগের node পর্যন্ত হেঁটে যেতে হয়, worst case-এ পুরো লিস্ট |
| বাইপাসের rewiring | O(1) | একটাই pointer বদল |
| Extra space | O(1) | নতুন কিছু বানাইনি, শুধু `current` নামে একটা pointer |

সারমর্ম: deletion-এ আসল pointer-কাজটা O(1), দামটা পড়ে খোঁজার হাঁটায়। তাই বলা হয়, linked list-এ delete সস্তা তখনই, যখন node-টা (বা তার আগেরটা) তোমার হাতে আগে থেকেই আছে। [Doubly linked list](./doubly-linked-list.mdx)-এ গেলে দেখব, `prev` pointer থাকলে node হাতে পেলেই O(1)-এ মোছা যায়।

## সাধারণ ভুল আর edge case

1. **টার্গেটকে ধরতে গিয়ে আগেরটা হারানো।** `while (current.value !== value) current = current.next;` লিখে টার্গেটে দাঁড়ালে কাজে কিছু আসে না, তার আগেরটার ঠিকানা আর জানা নেই। সবসময় থামো টার্গেটের **এক ঘর আগে**।
2. **head-এর আলাদা কেস না রাখা।** head মুছতে হলে "আগের node" বলে কেউ নেই, তাই মূল লুপে সেটা ধরা পড়েই না। আলাদা `if (this.head.value === value)` না থাকলে head কখনোই মোছা যাবে না।
3. **`current.next.next` পড়ার আগে null চেক না করা।** টার্গেট না পেলে লুপ শেষে `current` শেষ node-এ দাঁড়ায়, `current.next` তখন null, আর `null.next` পড়তে গেলেই TypeError। তাই `if (current.next)` চেকটা বাধ্যতামূলক।
4. **না পেলেও `size--` করে ফেলা।** বাইপাসের লাইনের বাইরে `size--` রাখলে value লিস্টে না থাকলেও size কমে যায়। তারপর `size` আর আসল node সংখ্যার কোনো মিল থাকে না।
5. **মুছে যাওয়া node-কে নিজে "পরিষ্কার" করার ভান।** `node.next = null` করে দেওয়ার দরকার নেই; শুধু শৃঙ্খলের তীর ঘোরালেই সে বাদ। বরং কেউ যদি সেই পুরনো reference ধরে রেখে থাকে, অযথা ছিঁড়ে ফেললে তার কোড ভেঙে যেতে পারে।

## অনুশীলন

1. **সহজ:** `removeFirst()` মেথড লেখো, যেটা প্রথম node মুছে দেয়। *Hint: খালি লিস্টের চেক, তারপর `head = head.next`, আর `size--` ভুলো না।*
2. **সহজ:** `removeLast()` মেথড লেখো। *Hint: `while (current.next.next)` দিয়ে দ্বিতীয়-শেষ node-এ দাঁড়াও, তারপর `current.next = null`। একটাই node থাকলে সরাসরি `head = null`।*
3. **মাঝারি:** `removeAt(index)` লেখো, যেটা index-এর node মুছে। *Hint: index 0 হলে removeFirst-এর লজিক। নাহলে index-1 পর্যন্ত হেঁটে বাইপাস। index বড় হলে কিছুই করো না।*
4. **মাঝারি:** `removeAll(value)` লেখো, একই মান যতবার আছে সবগুলো মুছে। *Hint: আগে while লুপে head-এর সব মিল মুছো (head সরে যেতে থাকবে), তারপর বাকি লিস্টে একবার ঘুরে বাইপাস চালাও।*
5. **কঠিন:** ধরো, value জানা নেই, মুছতে চাওয়া node-টাই সরাসরি হাতে দেওয়া আছে (head অ্যাক্সেস নেই)। তাকে কীভাবে মুছবে? *Hint: নিজেকে মোছা যায় না, কিন্তু নিজের ভেতরের জিনিস বদলানো যায়। পরের node-এর value আর next কপি করে নিজের ভেতরে বসাও, তারপর পরেরটাকে বাইপাস করো। ফলে তুমি "পরেরটা হয়ে গেলে", আর আসল পরেরটা বাদ পড়ল। LeetCode 237 এই প্রশ্নটাই।*

## সারসংক্ষেপ

- Deletion মানে pointer rewiring: টার্গেটের **আগের** node-এর `next` ঘুরিয়ে পরের node-এ বসানো।
- head মুছার কেস আলাদা, সেখানে লেবেল সরায়: `head = head.next`, তাই সেটা O(1)।
- মাঝের node মুছতে খোঁজার হাঁটা O(n), rewiring O(1); node হাতে থাকলে (doubly-তে) পুরোটাই O(1) হয়।
- মুছে যাওয়া node নিজে পরিষ্কার করতে হয় না, garbage collector সামলায়।

**পরের পেজ:** [Doubly Linked List: দুই দিকেই চলা](./doubly-linked-list.mdx), যেখানে `prev` pointer যোগ হওয়ায় এই পুরো deletion গল্পটা আরও সহজ হয়ে যাবে।
