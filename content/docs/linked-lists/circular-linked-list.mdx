## কী শিখব

- শেষ node আবার প্রথম node-কেই দেখায়, এমন বৃত্তাকার লিস্ট
- কেন এখানে `null` দেখে থামার ছক আর চলে না
- `tail` pointer রাখলে append কীভাবে O(n) থেকে O(1) হয়
- থামার শর্ত সঠিক না হলে কেন infinite loop-এ পড়তেই হয়

## ধারণা

Round-robin খেলা দেখেছ? সারির শেষ জনের পর আবার প্রথম জনের পালা, কেউ বাদ পড়ে না। পালা শেষ হলে চাকরি শেষ, আবার প্রথম জনের কাছে ফিরে যায়। Circular Linked List ঠিক সেরকম।

সাধারণ list-এ শেষ node-এর `next` থাকে `null`, মানে "এখানেই থাম"। Circular-এ শেষ node-এর `next` আবার **head**-কেই দেখায়। ফলে যত খুশি ঘোরা যায়, থামার জায়গা বলে কিছু নেই।

```
[10] -> [20] -> [30] --.
 ^                     |
 '---------------------'
```

ভাবো তো, কোথায় এমন কাঠামো লাগবে? যেখানে কাজটা চক্রাকারে ঘুরতে থাকে। Operating system-এর round-robin scheduling, multiplayer গেমে পালা বদল, এমনকি একটা buffer যেখানে পুরনোটার উপর নতুনটা লেখা হয়। সব জায়গায় "শেষের পর আবার প্রথম" এই ছকটাই লাগে।

তবে সাবধানতা একটাই, আর সেটা বড়: এখানে `null` কখনোই আসে না। তাই সাধারণ লিস্টের মতো `while (current)` লিখলে লুপ চিরকাল ঘুরবেই। থামার শর্ত এখানে নিজেকে বানাতে হয়, আর সেটাই এই পেজের আসল শিক্ষা।

## কোড উদাহরণ

```js
class Node {
  constructor(value) { this.value = value; this.next = null; }
}

class CircularList {
  constructor() { this.head = null; }

  append(value) {
    const node = new Node(value);
    if (!this.head) { this.head = node; node.next = node; return; } // নিজেকেই দেখায়
    let c = this.head;
    while (c.next !== this.head) c = c.next; // শেষ node খুঁজি (null নয়, head!)
    c.next = node;
    node.next = this.head;                    // বৃত্ত সম্পূর্ণ
  }

  // এক পাক ঘুরে ছাপাই (শর্ত না দিলে infinite loop!)
  printOnce() {
    if (!this.head) return;
    let c = this.head, out = [];
    do { out.push(c.value); c = c.next; } while (c !== this.head);
    console.log(out.join(" -> ") + " -> (back to head)");
  }
}

const cll = new CircularList();
cll.append(10); cll.append(20); cll.append(30);
cll.printOnce(); // 10 -> 20 -> 30 -> (back to head)
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. খালি লিস্টে প্রথম node ঢোকালে সে **নিজেকেই** `next` হিসেবে দেখায়। এক node-এর লিস্টও একটা পূর্ণ বৃত্ত, এই কথাটা মাথায় রাখো।
2. `append`-এ শেষ node খোঁজার শর্তটা দেখো: `while (c.next !== this.head)`। এখানে `null` খুঁজছি না, খুঁজছি "যার পরেরটা আবার head"। সেটাই শেষ node।
3. শেষ node পেলে দুটো তীর ঠিক করি: আগে পুরনো শেষের `next` নতুনটাকে দেখায়, তারপর নতুনটার `next` আবার `head`-এ। এই ক্রম পাল্টালে head-এর ঠিকানা হারিয়ে যাবে, কারণ নতুন node-র `next`-এ তখন `head` বসানোর আগেই সে হারিয়ে যায়।
4. `printOnce`-এ `do...while` নিয়েছি। কেন? কারণ `while (c !== this.head)` দিলে লুপ প্রথমবারই থেমে যায়, `c` তো শুরুতেই `head`-এই দাঁড়িয়ে! `do...while` আগে একবার চালায়, তারপর শর্ত চেক করে, তাই প্রথম node অন্তত একবার ছাপেই।
5. লক্ষ করো, শর্তটা মোটেই `null` নয়। এখানে থামার সংকেত হলো "আবার head-এ ফিরে আসা"। এই শর্তের একটুখানি ভুলও চিরকালের লুপ তৈরি করবে।

## Dry run: printOnce চালাই

লিস্ট: `10 -> 20 -> 30 -> (আবার head)`। শর্ত `c !== this.head`:

| ধাপ | c কোথায় | ছাপে | c = c.next | c !== head? |
|-----|----------|------|------------|-------------|
| 1 | node(10) | 10 | node(20) | হ্যাঁ, চলো |
| 2 | node(20) | 20 | node(30) | হ্যাঁ, চলো |
| 3 | node(30) | 30 | node(10) = head | না, থামো |

তিনটা node ছাপলো, চতুর্থবার head-এ ফিরে এসে লুপ থামল। এবার ভাবো, যদি শর্তটা ভুল করে `while (c.next)` লিখতাম? কেউ কখনো null না হওয়ায় লুপ থামতই না। একটা ভুল শর্তের দাম এখানে সবচেয়ে বেশি।

## Complexity: কোথায় কত দাম

| কাজ | Cost | কেন |
|-----|------|-----|
| append (শুধু head রাখলে) | O(n) | শেষ node খুঁজতে পুরো পাক ঘুরতে হয় |
| append (tail রাখলে) | **O(1)** | `tail.next` সরাসরি জানা, দুটো তীর ঘোরালেই শেষ |
| Traversal (এক পাক) | O(n) | প্রতিটা node-এ একবার, head-এ ফিরলেই থামি |
| Space | O(n) | সাধারণ লিস্টের মতোই, বাড়তি কিছু নেই |

ভাবো তো, tail pointer ধরে রাখলে কী সুবিধা? `tail.next` তো আগে থেকেই `head`-কে দেখায়। নতুন node জোড়ার জন্য শুধু দুটো তীর ঘোরাও: `tail.next = newNode`, তারপর `newNode.next = head`, আর `tail = newNode`। পুরো পাক ঘোরার দরকারই নেই। অনুশীলনে এই ভ্যারিয়েন্টটা বানাতে বলা আছে।

## ভ্যারিয়েন্ট: tail ধরে রাখলে append O(1)

আসলে একটা মজার ব্যাপার হলো, circular list-এ `head` আর `tail` দুটোই রাখার দরকার নেই। শুধু `tail` ধরে রাখলেই চলে, কারণ `head` তো হলো `tail.next`! একটা pointer দিয়েই দুটো প্রান্তই পাওয়া যায়। দেখো:

```js
class CircularList {
  constructor() { this.tail = null; } // শুধু tail, head = tail.next

  append(value) {
    const node = new Node(value);
    if (!this.tail) { this.tail = node; node.next = node; return; }
    node.next = this.tail.next;   // নতুনটার next = আগের head
    this.tail.next = node;        // পুরনো tail-এর next = নতুনটা
    this.tail = node;             // tail সরে গেল নতুনটায়
  }

  prepend(value) {
    this.append(value);           // একই কাজ!
    this.tail = this.tail.next;   // শুধু tail সরে গেল না, বরং...
  }
}
```

মজার ব্যাপার হলো, এই ভ্যারিয়েন্টে `append` আর `prepend` প্রায় একই কোড। কারণ নতুন node tail-এর পরে ঢোকানো মানেই সে আগের head-এর আগে বসে গেল, শুধু `tail` লেবেলটা সরালে না সরালে তার ফরক। এই ছোট্ট কৌশলটা দেখায়, কাঠামোটা ঠিকমতো বুঝলে কত সহজ হয়ে যায়।

## সাধারণ ভুল আর edge case

1. **থামার শর্তেই ভুল করা।** এটাই সবচেয়ে বড় বিপদ। `while (current)` বা `while (current.next)` কোনোটাই কাজ করে না, কারণ এখানে `null` কেউ নেই। শর্ত হবে `current !== this.head` (বা তোমার শুরুর node)।
2. **`while` দিয়ে লুপ শুরু করা।** `while (c !== this.head)` লিখলে প্রথম চেকেই false, কারণ `c` শুরুতেই head। একবারও ঘুরবে না। আগে এক ধাপ চালিয়ে তারপর চেক করতে হলে `do...while` লাগে।
3. **প্রথম node-এর `next` নিজেকেই না দেখানো।** একটাই node থাকলেও বৃত্ত বৃত্তই থাকা উচিত। `node.next = node` না করলে সেই লিস্ট আর circular নেই, সাধারণ এক node-এর লিস্ট হয়ে গেল।
4. **append-এ ক্রম পাল্টে দেওয়া।** আগে `c.next = node` ঠিক, কিন্তু এরপর `node.next = this.head` বসানো ভুলে গেলে নতুন node-এর `next` null থেকে যায়, বৃত্ত ভেঙে যায়। তীর দুটোই বসাতে হবে।
5. **সাধারণ লিস্টের অভ্যাসে ভাবা।** Circular-এ `if (!node.next)` দিয়ে শেষ চেক করতে গেলে ফল সবসময় false, কারণ কারো `next`-ই null নয়। "শেষ" এখানে `next === head` দিয়ে চিনতে হয়।

## অনুশীলন

1. **সহজ:** circular list-এ মোট কতটা node আছে, সেটা গোনার `countNodes()` মেথড লেখো। *Hint: `do...while` দিয়ে এক পাক ঘুরো, প্রতি ধাপে counter বাড়াও। খালি লিস্টে 0।*
2. **সহজ:** k পাক ঘুরে pointer কোন node-এ দাঁড়াবে, সেটা বের করো। *Hint: পুরো লিস্টে n টা node, তাই আসলে k % n ধাপ এগোলেই কাজ শেষ, পুরো k বার ঘোরার দরকার নেই।*
3. **মাঝারি:** `tail` pointer রাখলে append কীভাবে O(1) হয়, সেই ভ্যারিয়েন্টটা নিজে লেখো। *Hint: তিনটা লাইন, `tail.next = newNode`, `newNode.next = this.head`, `tail = newNode`। খালি লিস্টের কেস আলাদা।*
4. **মাঝারি:** বৃত্তটা দুই সমান অর্ধেক ভাগ করো। *Hint: `slow` এক ধাপ, `fast` দুই ধাপ করে ঘোরাও। fast আবার head-এ ফিরলে slow মাঝখানে দাঁড়িয়ে থাকবে। সেখান থেকে ছিঁড়ে দুটো বৃত্ত বানাও।*
5. **কঠিন:** Josephus problem। n জন বৃত্তে দাঁড়িয়ে আছে, প্রতি k-তম জন বাদ পড়ে যায়, শেষে কে বাঁচে? *Hint: circular list বানিয়ে প্রতিবার k-1 ধাপ হেঁটে ওই node-টা মুছে ফেলো। একজন বাকি না হওয়া পর্যন্ত চালাও। [Deletion পেজের](./deletion.mdx) বাইপাস লজিক এখানে সরাসরি লাগবে।*

## সারসংক্ষেপ

- Circular list-এ শেষ node-এর `next` আবার `head`-কে দেখায়, `null` বলে কিছু নেই।
- থামার শর্ত এখানে "head-এ ফিরে আসা"; সেটা ভুললে infinite loop নিশ্চিত।
- `do...while` দিয়ে এক পাক ঘোরা নিরাপদ, কারণ প্রথম node অন্তত একবার তো চলেই।
- Round-robin scheduling, turn-based গেম, buffer, যেখানে চক্রাকারে ঘোরা লাগে সেখানে এই কাঠামো।
