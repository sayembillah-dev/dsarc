## কী শিখব

- Array-এর গঠন, আর index access কেন এত দ্রুত

## ধারণা

ধরো তুমি একটা parking lot-এ গাড়ি রেখেছ। সব স্লট পাশাপাশি, প্রতিটার নম্বর করা। এখন কেউ বলল, "৭ নম্বর স্লটে কী আছ?" তুমি কি এক নম্বর থেকে গুনে গুনে যাবে? একদমই না, সরাসরি ৭ নম্বরে গিয়ে দাঁড়াবে।

Array হুবহু এই খেলাটাই খেলে। একই ধরনের ডেটার একটা ধারাবাহিক (contiguous) লিস্ট, যেখানে প্রতিটা উপাদানের একটা **index** (অবস্থান নম্বর) আছে, আর গোনা শুরু হয় **0** থেকে। মেমরিতে উপাদানগুলো **পাশাপাশি** থাকে বলেই কম্পিউটার index পেলেই সরাসরি ঠিক জায়গায় পৌঁছে যায়। এই যে সরাসরি পৌঁছে যাওয়া, এজন্যই index access **O(1)**।

```text
index:   0    1    2    3
value: [ 10 , 20 , 30 , 40 ]
```

## কোড উদাহরণ

```js
const arr = [10, 20, 30, 40];

console.log(arr[0]);       // 10, সরাসরি, O(1)
console.log(arr[2]);       // 30
console.log(arr.length);   // 4

arr[1] = 99;               // মান বদলানো, O(1)
console.log(arr);          // [10, 99, 30, 40]
```

## কোড ব্রেকডাউন

- `arr[2]` মানে কী? শুরুর ঠিকানা + (2 × প্রতি উপাদানের আকার)। হিসাব শেষ, সরাসরি পৌঁছে গেলে। তাই O(1)।
- আর মনে রাখো, index সবসময় 0 থেকে শুরু, তাই শেষ index = `length - 1`।

## Complexity

- Access আর update, দুটোই O(1)। কোনো ঝামেলা নেই।
