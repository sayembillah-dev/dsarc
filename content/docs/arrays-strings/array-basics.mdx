## কী শিখব

- Array আসলে কী: একই ধরনের ডেটা, পাশাপাশি ঘর, 0 থেকে গোনা index
- Contiguous memory মানে কী, আর সেখান থেকে `arr[i]` কেন O(1)
- Address হিসাবের পুরো গণিত: base + index × size
- কেন index শুরু হয় 0 থেকে (এটা রেওয়াজ না, হিসাবের সুবিধা)
- `length` আর capacity এক জিনিস না: fixed-size বনাম dynamic array
- কোন পরিস্থিতিতে array সেরা, কোথায় array দিয়ে কাজ চলবে না

## ধারণা

ধরো তুমি একটা parking lot-এ গাড়ি রেখেছ। সব স্লট পাশাপাশি, প্রতিটার নম্বর করা। এখন কেউ বলল, "৭ নম্বর স্লটে কী আছ?" তুমি কি ১ নম্বর থেকে গুনে গুনে যাবে? একদমই না, সরাসরি ৭ নম্বরে গিয়ে দাঁড়াবে।

Array হুবহু এই খেলাটাই খেলে। একই ধরনের ডেটার একটা ধারাবাহিক তালিকা, যেখানে প্রতিটা উপাদানের একটা **index** (অবস্থান নম্বর) আছে। মেমরিতে উপাদানগুলো **পাশাপাশি (contiguous)** থাকে বলেই কম্পিউটার index পেলেই সরাসরি ঠিক জায়গায় পৌঁছে যায়।

```text
index:   0    1    2    3
value: [ 10 , 20 , 30 , 40 ]
```

Contiguous কথাটাই আসল চাবিকাঠি। পাশাপাশি না থাকলে ৭ নম্বর স্লটে সরাসরি যাওয়ার কোনো উপায় ছিল না, গুনে গুনে যেতে হতো। পরের section-এ [Linked List](../linked-lists/what-is-linked-list.mdx) দেখবে, ওখানে ঘরগুলো ছড়িয়ে ছিটিয়ে থাকে, তাই i-তম উপাদানে যেতে হেঁটেই যেতে হয়। এই একটা পার্থক্য দুই জগতের সব খরচের হিসাব বদলে দেয়।

## Address-এর গণিত: O(1) আসলে কোথা থেকে আসে

কম্পিউটার `arr[i]` দেখলে কী করে? কোনো খোঁজাখুঁজি করে না। একটা সরল অংক করে:

```text
address(arr[i]) = base_address + (i × element_size)
```

ধরো array শুরু হয়েছে address 1000 থেকে, আর প্রতি উপাদান 4 byte-এর:

| index | হিসাব | address | value |
|-------|-------|---------|-------|
| 0 | 1000 + 0×4 | 1000 | 10 |
| 1 | 1000 + 1×4 | 1004 | 20 |
| 2 | 1000 + 2×4 | 1008 | 30 |
| 3 | 1000 + 3×4 | 1012 | 40 |

`arr[3]` চাইলে কম্পিউটার একটা গুণ আর একটা যোগ করে 1012-এ লাফ দেয়। Array-তে উপাদান ৪টা নাকি ৪০ লাখ, এই হিসাবের সময় লাগে **একই**। index যাই হোক, একটাই অংক। এজন্যই access O(1): "constant time" মানে ব্যাপারটা n-এর উপর নির্ভরই করে না।

আর এখান থেকেই 0-based indexing-এর উত্তর পাওয়া যায়। index মানে আসলে **offset**: শুরু থেকে কত ঘর এগিয়ে। প্রথম উপাদান শুরু থেকে ০ ঘর এগিয়ে, তাই index 0। 1 থেকে গোনা শুরু করলে হিসাবটা দাঁড়াতো `base + (i-1) × size`, প্রতিবার একটা বাড়তি বিয়োগ। প্রোগ্রামাররা শুরুর দিকেই এই অযথা বিয়োগটা বাদ দিয়ে দিয়েছে, আজও আমরা সেটাই পাচ্ছি।

## কোড: বানানো, পড়া, বদলানো

```js
// বানানোর সরাসরি রাস্তা: literal
const arr = [10, 20, 30, 40];

console.log(arr[0]);       // 10: O(1), সরাসরি লাফ
console.log(arr[3]);       // 40
console.log(arr.length);   // 4
console.log(arr[arr.length - 1]); // 40: শেষ উপাদানের সূত্র

arr[1] = 99;               // update-ও O(1)
console.log(arr);          // [10, 99, 30, 40]
```

```js
// আগে থেকে size জানা থাকলে: ভরাট করে বানানো
const zeros = Array(5).fill(0);        // [0, 0, 0, 0, 0]
const seats = Array.from({ length: 5 }, (_, i) => i + 1);
console.log(seats);                    // [1, 2, 3, 4, 5]
```

`Array.from`-এর দ্বিতীয় argument-টা map-এর মতো কাজ করে: প্রতিটা ঘরের জন্য index পেয়ে মান বানিয়ে দেয়। এটা শুধু সংখ্যা ভরার জন্য না, যেকোনো নিয়মে ঘর বানাতে কাজে লাগে, [2D grid](./2d-arrays.mdx)-এ গিয়ে আবার দেখা হবে।

## length আর capacity এক জিনিস না

C বা Java-তে array বানাতে গেলে আগেই বলে দিতে হয় কত ঘর লাগবে, আর পরে সেটা বদলানো যায় না। ঘর ফুরিয়ে গেলে নতুন বড় array বানিয়ে সব কপি করতে হয়, নিজে হাতে।

JavaScript-এর array **dynamic**: `push` করলেই বাড়ে। কিন্তু ভেতরে ভেতরে একই খেলা চলে। Engine একটা capacity রেখে দেয়, ফুরিয়ে গেলে চুপচাপ দ্বিগুণ বড় জায়গা নিয়ে কপি করে। এই গল্পটা [Array Operations](./array-operations.mdx)-এ amortized analysis নিয়ে বিস্তারিত আছে। এখানে শুধু মনে রাখো: **length** হলো এখন কতগুলো উপাদান বসে আছে, **capacity** হলো জায়গা আসলে কতটুকু নেওয়া। দ্বিতীয়টা সাধারণত চোখে দেখা যায় না, কিন্তু খরচের হিসাবে সেটাই আসল।

## এক ঝলকে: array বনাম object

নতুনরা প্রায়ই গুলিয়ে ফেলে, কখন array, কখন object। সূত্রটা সহজ:

- **Array:** উপাদানের ক্রম আর অবস্থানই আসল। "৩ নম্বরটা দাও", "সবগুলো ঘুরে আসি", এই ধরনের কাজ। Index সংখ্যা, ঘর পাশাপাশি, `length` নিজে গোনা রাখে।
- **Object:** প্রতিটা জিনিসের নিজস্ব নাম আছে। "তোমার `age` কত?" ধরনের কাজ। Key হলো স্ট্রিং, `length` বলে কিছু নেই, ঘোরার জন্য `Object.keys` / `for..in` লাগে।

মজার ব্যাপার হলো, ভেতরে JavaScript-এর array আসলে object-এরই এক রূপ। তবু memory layout আর engine-এর অপ্টিমাইজেশনের জন্য ক্রমযুক্ত ডেটা সবসময় array-তেই রাখো। আর "নাম দিয়ে চোখ বন্ধ করে খোঁজা" লাগলে object বা Map, যার আসল গল্প [Hash Tables](../hash-tables/hash-table-intro.mdx)-এ আসবে।

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `const arr = [10, 20, 30, 40]` : মেমরিতে পাশাপাশি ৪টা ঘর বরাদ্দ হলো, base address ধরে নেওয়া হলো। `const` মানে `arr` নামটা অন্য array-কে point করবে না, কিন্তু ভেতরের উপাদান বদলানো একদম যায়।
2. `arr[0]` : `base + 0 × size` = base-এই লাফ। প্রথম উপাদান পাওয়ার খরচ আর মিলিয়নতম উপাদান পাওয়ার খরচ সমান।
3. `arr.length` : engine নিজেই গণনা রাখে, তাই এটাও O(1)। গুনে বের করা না।
4. `arr[arr.length - 1]` : শেষ উপাদানের চেনা সূত্র। index যেহেতু 0 থেকে, শেষ index সবসময় `length - 1`। এটা ভুললেই off-by-one bug।
5. `arr[1] = 99` : address হিসাব করে সরাসরি লিখে দিল। কাউকে সরাতে হলো না, তাই O(1)।

## Complexity

| অপারেশন | Complexity | কেন |
|---------|-----------|-----|
| `arr[i]` পড়া | O(1) | একটা গুণ + একটা যোগ = সরাসরি লাফ |
| `arr[i] = x` লেখা | O(1) | একই হিসাব |
| `arr.length` | O(1) | আগে থেকেই গোনা রাখা |
| নতুন array-তে n ঘর ভরা | O(n) | n বার লিখতে হয়, অংকে পারের উপায় নেই |

Derivation-টা ছোট কিন্তু গুরুত্বপূর্ণ: O(1) কোনো কৌশল না, memory layout-এর সরাসরি ফল। পাশাপাশি ঘর + fixed ঘরসাইজ = address এক লাইনে বের হয়। যত উপাদানই থাক, হিসাবের ধাপ বাড়ে না, তাই constant।

## কখন array সঠিক পছন্দ, কখন না

Array দারুণ যখন:

- উপাদানগুলোকে index দিয়ে ঘন ঘন পড়তে হয়
- সব উপাদান একবার করে ঘুরে আসতে হয় ([Traversal](./traversal.mdx), পরের পেজেই)
- উপাদানের সংখ্যা মোটামুটি জানা থাকে বা শেষে যোগ-বাদই প্রধান কাজ

Array ঝামেলার যখন:

- মাঝখানে বারবার insert/delete লাগে (সরানোর বিল, [Array Operations](./array-operations.mdx))
- উপাদানগুলোর মধ্যে "পরেরটা কোথায়" ধরনের সম্পর্কই আসল, index না (Linked List, Graph-এর দিকে যাও)

## সাধারণ ভুল আর edge case

**১. Off-by-one: `arr[arr.length]` পড়া।**
শেষ index হলো `length - 1`, `length` না। `arr[arr.length]` দেবে `undefined`, কোনো error না। এই `undefined` নিঃশব্দে হিসাবের ভেতর ঢুকে NaN বানিয়ে ফেলে। Array নিয়ে কাজের অর্ধেক bug-ই এই এক ঘর এদিক ওদিক হওয়া।

**২. `new Array(3)` আর `[3]` গুলিয়ে ফেলা।**
`[3]` মানে একটা উপাদান 3। কিন্তু `Array(3)` মানে length 3-এর **খালি** array, কোনো উপাদানই নেই। আরও মজার ব্যাপার: `Array(3).map(x => 0)` কিছুই করে না, কারণ map খালি ঘর (hole) এড়িয়ে যায়। ভরাট করতে হলে `.fill(0)` বা `Array.from` ব্যবহার করো।

**৩. Negative index আশা করা।**
Python-এ `arr[-1]` শেষ উপাদান দেয়, JavaScript-এ দেয় `undefined`। শেষ উপাদান চাইলে `arr[arr.length - 1]` বা নতুন `arr.at(-1)`।

**৪. Reference বনাম copy ভুলে যাওয়া।**
`const b = arr` লিখলে নতুন array তৈরি হয় না, একই ঘরগুলোর দিকে আরেকটা নাম point করে। `b[0] = 999` করলে `arr[0]`-ও বদলে যাবে। সত্যিকারের copy চাইলে `[...arr]` বা `arr.slice()`।

**৫. Array কিনা চেক করতে `typeof` ব্যবহার করা।**
`typeof [1, 2, 3]` দেয় `"object"`, `"array"` না। চেক করার নিরাপদ রাস্তা `Array.isArray(arr)`। Interview-র চেনা প্রশ্ন।

> - **লক্ষ্য:** O(1) মানে "কম ঘর দেখা" না, "অংক করে সরাসরি পৌঁছে যাওয়া", এটা চোখে পড়ুক।

## অনুশীলন

- **সহজ ১:** কাগজে address হিসাব করো: base 2000, element size 8 byte হলে `arr[5]` কোন address-এ? (আগে নিজে অংক করো, তারপর মিলাও: 2040।)
- **সহজ ২:** একটা array-এর প্রথম আর শেষ উপাদানের যোগফল বের করো, `length` ব্যবহার করে। লুপ ছাড়াই হবে, ব্যাপারটা লক্ষ করো।
- **মাঝারি ১:** `Array.from` দিয়ে 1 থেকে 10 পর্যন্ত সংখ্যার বর্গের array বানাও: `[1, 4, 9, ..., 100]`।
- **মাঝারি ২:** বন্ধুকে বোঝাও (লিখে): array-তে index 0 থেকে শুরু কেন, আর `base + i × size` হিসাবটা সেখানে কীভাবে ফিট হয়।
- **কঠিন:** নিজের একটা mini fixed-size array class লেখো (ভেতরে storage হিসেবে plain array), যেখানে `get(i)`, `set(i, x)` আছে আর index বাইরে গেলে স্পষ্ট error ছুঁড়ে। তারপর ভাবো: JavaScript-এর array কেন error না দিয়ে `undefined` দেয়, এটা কী ধরনের design trade-off?

## সারসংক্ষেপ

- Array = পাশাপাশি ঘরে বসা উপাদান + 0 থেকে গোনা index।
- `arr[i]` O(1), কারণ address = base + i × size: একটাই অংক, n-এর উপর নির্ভর করে না।
- Index আসলে offset, তাই গোনা 0 থেকে, আর শেষ index = `length - 1`।
- JS-এর array dynamic, কিন্তু ভেতরে capacity বাড়ানোর খরচ আছেই।
- ভরাট array বানাতে `Array(n).fill(x)` বা `Array.from`, শুধু `Array(n)` না।
