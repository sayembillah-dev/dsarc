## কী শিখব

- Single pass দিয়ে কী কী বের করা যায়: sum, max/min, count, একসাথে সব
- `for`, `for..of`, `forEach`: কোনটা কখন, আর কোনটার কী সীমাবদ্ধতা
- Running aggregate প্যাটার্ন: "এ পর্যন্ত সেরা" ট্র্যাক করা
- Two-pointer দিয়ে in-place reverse-এর পুরো dry run
- কেন "সব উপাদান দেখা" লাগলে O(n)-এর নিচে যাওয়া অসম্ভব

## ধারণা

ভাবো তো, তোমাকে বলা হলো এক ঘর ভরা জিনিস থেকে সবচেয়ে দামি জিনিসটা খুঁজে দিতে। তুমি কী করবে? একটা একটা করে সবগুলো দেখবে, তাই না? DSA সমস্যার প্রায় ৮০% শুরু হয় ঠিক এভাবেই: array-এর উপর একবার ঘুরে আসা দিয়ে। তাই কয়েকটা দরকারি প্যাটার্ন আগেই চিনে নিই, কারণ পরের সব section-এ এই প্যাটার্নগুলোই বারবার ফিরে আসবে।

Traversal শেখার আসল পয়েন্ট loop লেখা না, loop লেখা তো তুমি জানোই। পয়েন্ট হলো **এক পাসে যত বেশি সম্ভব তথ্য তুলে আনা**, আর **দ্বিতীয় পাস বা nested loop লাগবে কিনা** সেটা চিনতে পারা।

## প্যাটার্ন ১: running aggregate, এক পাসে সব

ধরো `[5, 8, 2, 10, 1]` থেকে সর্বোচ্চটা বের করতে হবে। খেলাটা হলো একটা চ্যাম্পিয়ন ধরে রাখা: প্রতিটা নতুন উপাদান চ্যাম্পিয়নের সঙ্গে লড়বে, জিতলে মুকুট বদলাবে।

Dry run দেখো, `max` শুরু হয় প্রথম উপাদান দিয়ে:

| ধাপ | x | x > max? | max এখন |
|-----|---|----------|---------|
| শুরু | - | - | 5 |
| 1 | 8 | হ্যাঁ | 8 |
| 2 | 2 | না | 8 |
| 3 | 10 | হ্যাঁ | 10 |
| 4 | 1 | না | 10 |

৫টা উপাদান, ৪টা তুলনা, একটাই পাস। n উপাদানের জন্য n-1 তুলনা, এটাই O(n)। আর এই টেবিল থেকেই একটা গুরুত্বপূর্ণ কথা: **max কখনও 0 দিয়ে শুরু করবে না**। সব উপাদান negative হলে 0 ভুল উত্তর দেবে, কারণ 0 তো array-তেই নেই। চ্যাম্পিয়ন সবসময় array-এর ভেতর থেকে উঠে আসুক: `arr[0]`, নয়তো `-Infinity`।

## কোড: এক পাসে max, min, sum, সব

```js
const arr = [5, 8, 2, 10, 1];

let max = arr[0];
let min = arr[0];
let sum = 0;

for (const x of arr) {
  if (x > max) max = x;
  if (x < min) min = x;
  sum += x;
}

console.log(max, min, sum); // 10 1 26
```

একটাই লুপ, তিনটা তথ্য। এটাই running aggregate প্যাটার্ন: লুপের প্রতি ধাপে "এ পর্যন্তকার হিসাব" আপডেট হচ্ছে, আলাদা আলাদা পাসের দরকার নেই। Count করা (যেমন কতগুলো জোড়) তো একই খেলার আরেক রূপ, শুধু আপডেটের নিয়মটা বদলায়।

## কোন loop কখন

```js
const arr = [10, 20, 30];

// ক) index লাগলে: classic for
for (let i = 0; i < arr.length; i++) {
  console.log(i, arr[i]);
}

// খ) শুধু মান লাগলে: for..of, সবচেয়ে পরিষ্কার
for (const x of arr) console.log(x);

// গ) মান + index দুটোই, for..of রেখেই: entries()
for (const [i, x] of arr.entries()) {
  console.log(i, x);
}

// ঘ) forEach: ছোট কাজে সুন্দর, কিন্তু...
arr.forEach((x) => console.log(x));
```

সিদ্ধান্তের সূত্রটা সহজ:

- **index দরকার?** classic `for` বা `entries()`।
- **মাঝপথে থামতে (break) বা ফিরতে (return) হবে?** `for` বা `for..of`, কারণ `forEach`-এ break কাজ করে না।
- **শুধু সবগুলোর উপর একই কাজ?** `for..of` সবচেয়ে পড়তে সহজ।

আর `map`/`filter`/`reduce`? সেগুলো traversal না, নতুন জিনিস বানানোর টুল। সেখানে side-effect চালানো কোড পড়া কঠিন করে তোলে।

## প্যাটার্ন ২: two-pointer, উল্টো দিক থেকে চাপ দেওয়া

এবার একটা ক্লাসিক কাজ: array-টা **in-place** উল্টে দাও (reverse), নতুন array ছাড়া। ধারণাটা দুই প্রান্ত থেকে ধরা: বাম প্রান্ত আর ডান প্রান্তের উপাদান বদলাও, তারপর দুটোকেই এক ঘর ভেতরে ঢোকাও। মাঝে এসে মিলে গেলে থামো।

`[1, 2, 3, 4, 5]`-এর dry run:

| ধাপ | left | right | swap | array-এর অবস্থা |
|-----|------|-------|------|------------------|
| শুরু | 0 | 4 | - | `[1, 2, 3, 4, 5]` |
| 1 | 0 | 4 | 1 ↔ 5 | `[5, 2, 3, 4, 1]` |
| 2 | 1 | 3 | 2 ↔ 4 | `[5, 4, 3, 2, 1]` |
| 3 | 2 | 2 | থামো (left >= right) | `[5, 4, 3, 2, 1]` |

মোট ২টা swap, মানে প্রতি উপাদান সর্বোচ্চ একবার নড়েছে। n/2-টা swap = O(n) সময়, আর নতুন array নেই বলে O(1) জায়গা।

```js
function reverseInPlace(arr) {
  let left = 0;
  let right = arr.length - 1;

  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]]; // destructuring swap
    left++;
    right--;
  }
  return arr;
}

const a = [1, 2, 3, 4, 5];
console.log(reverseInPlace(a)); // [5, 4, 3, 2, 1]
```

দুটো pointer একই দিকে বা উল্টো দিকে চলে, এই ভাবনাটাই পরে [Two Pointer](../problem-solving/two-pointer.mdx) আর [Sliding Window](../problem-solving/sliding-window.mdx) প্যাটার্নের ভিত্তি। এখানে শুধু হাত-পয়ছা গরম করছি।

## কোড ব্রেকডাউন: reverseInPlace, লাইনে লাইনে

1. `let left = 0` : বাম pointer প্রথম উপাদানে।
2. `let right = arr.length - 1` : ডান pointer শেষে। আবার সেই `length - 1` সূত্র।
3. `while (left < right)` : দুজন মাঝে এসে মিললেই থামো। `<=` না দিয়ে `<` দেওয়াটা ইচ্ছাকৃত: সমান হলে একই ঘরে দাঁড়িয়ে আছে, নিজের সঙ্গে নিজের swap অর্থহীন।
4. `[arr[left], arr[right]] = [arr[right], arr[left]]` : destructuring দিয়ে swap, temp ভেরিয়েবল লাগল না। ভেতরে engine একটা অস্থায়ী জায়গা ব্যবহার করছেই, কিন্তু লেখা পরিষ্কার।
5. `left++; right--` : দুজন এক ঘর করে ভেতরে। কেউ আটকে থাকলে infinite loop, তাই দুজনকেই নাড়ানো জরুরি।

## Complexity

| প্যাটার্ন | Time | Space | কেন |
|-----------|------|-------|-----|
| Single pass (sum/max/min/count) | O(n) | O(1) | প্রতি উপাদান একবার, মনে রাখা হয় কয়েকটা ভেরিয়েবল |
| Two-pointer reverse | O(n) | O(1) | n/2-টা swap, কোনো বাড়তি array না |
| Nested loop (সব জোড়া দেখা) | O(n²) | O(1) | প্রতিটার সঙ্গে প্রতিটা, প্রায় n²/2 জোড়া |

শেষ প্রশ্নটা গুরুত্বপূর্ণ: traversal O(n)-এর নিচে করা যায় কি? যদি সব উপাদান দেখতেই হয়, **না**। কারণ n-টা ঘরের প্রতিটা অন্তত একবার না দেখলে উত্তর নিশ্চিত হওয়াই যায় না। এটা এক ধরনের lower bound: সমস্যার চাহিদাই এমন যে n-এর কম পড়া অসম্ভব। তাই array traversal-এ O(n) দেখলে হতাশ হবে না, বরং বুঝবে এটাই সেরা সম্ভব, আর লড়াইটা তখন O(n²) থেকে O(n)-এ নামানোর।

## সাধারণ ভুল আর edge case

**১. `max = 0` দিয়ে শুরু করা।**
`[-5, -2, -9]`-এ এই কোড 0 ফেরাবে, যা array-তে আছেই না। সূত্র মনে রাখো: চ্যাম্পিয়ন array-এর ভেতর থেকে আসবে, `arr[0]`, নয়তো `-Infinity` / `Infinity`।

**২. খালি array-তে `arr[0]` ধরে নেওয়া।**
`arr[0]` তখন `undefined`, আর `undefined` নিয়ে তুলনা চললে সব ফলাফল গোলমাল। খালি array হতে পারে কিনা, আগে একবার ভাবো। দরকার হলে গোড়াতেই `if (arr.length === 0)` চেক।

**৩. `forEach`-এ break খোঁজা।**
`forEach` সবগুলোর উপর চলবেই, মাঝে থামার উপায় নেই (`return` শুধু ওই callback থেকে বেরিয়ে আসে, loop থেকে না)। শর্ত মিললেই থামতে হলে `for..of` বা `find` / `some` ব্যবহার করো।

**৪. লুপের ভেতরে array বদলে ফেলা।**
ঘুরতে ঘুরতে `push` / `splice` করলে length পাল্টায়, index-এর ধারণা ভেঙে যায়, উপাদান skip হয় বা দুবার দেখা হয়। পরিবর্তন লাগলে হয় নতুন array বানাও (`filter` / `map`), নয়তো খুব সচেতনভাবে index নিজে নিয়ন্ত্রণ করো।

**৫. `for..in` দিয়ে array ঘোরা।**
`for..in` object-এর key ঘোরার জন্য, index স্ট্রিং হিসেবে দেয় (`"0"`, `"1"`), আর inheritance-এর ঝামেলাও আছে। Array-এর জন্য `for..of`। এক শব্দের পার্থক্য, ভিন্ন জগৎ।

> - **দৃশ্য:** একটা array; উপরে pointer-এর তীর (single মোডে একটা, two-pointer মোডে দুটো); পাশে running aggregate প্যানেল (max/min/sum লাইভ আপডেট)।
> - **ইনপুট:** pattern নির্বাচন (single pass / two-pointer reverse); নিজের array টাইপ করা; speed।

> - **নিয়ন্ত্রণ:** step, play, reset; প্রতি ধাপে "তুলনা: X, swap: Y" কাউন্টার।
> - **লক্ষ্য:** এক পাসে যে যত তথ্য তোলা যায়, আর lower bound কেন O(n), দুটোই চোখে পড়ুক।

## অনুশীলন

- **সহজ ১:** একটাই pass-এ array-র যোগফল আর গড় বের করো। (হিন্ট: গড়ের জন্য আলাদা pass লাগে না, length তো জানাই আছে।)
- **সহজ ২:** কতগুলো জোড় আর কতগুলো বিজোড়, এক লুপে গুনে দাও।
- **মাঝারি ১:** দ্বিতীয় সর্বোচ্চ (second largest) বের করো, এক পাসে। (হিন্ট: দুটো চ্যাম্পিয়ন রাখো, `max` আর `second`। নতুন x এলে সে কার মুকুট কেড়ে নেয়, সেটা ভাবো।)
- **মাঝারি ২:** `reverseInPlace` তোমার নিজের কথায় আবার লেখো, এবার destructuring ছাড়া, temp ভেরিয়েবল দিয়ে। দুজন pointer না নাড়ালে কী হয়, ইচ্ছে করে ভুলটা করে দেখো।
- **কঠিন:** Sorted array দেওয়া আছে, যেমন `[1, 3, 4, 6, 9]`। দুটো উপাদান খুঁজে বের করো যাদের যোগফল ঠিক `target`। (হিন্ট: দুই প্রান্তে pointer। যোগফল ছোট হলে বামকে এগাও, বড় হলে ডানকে পিছাও। কেন এটা কাজ করে, যুক্তি দিয়ে ভাবো।) পুরো গল্প [Two Pointer](../problem-solving/two-pointer.mdx)-এ।

## সারসংক্ষেপ

- Traversal-এর আসল খেলা: এক পাসে যত বেশি তথ্য, তত ভালো।
- Running aggregate (max/min/sum/count) একটাই লুপে সব দেয়; চ্যাম্পিয়ন সবসময় array-এর ভেতর থেকে।
- index লাগলে `for` বা `entries()`, শুধু মান লাগলে `for..of`, `forEach`-এ break নেই।
- Two-pointer দুই প্রান্ত থেকে চাপ দিয়ে reverse জাতীয় কাজ O(n) সময়, O(1) জায়গায় করে।
- সব উপাদান দেখা লাগলে O(n)-ই lower bound, এর নিচে যাওয়ার কথা ভাবাই অবৈজ্ঞানিক।
