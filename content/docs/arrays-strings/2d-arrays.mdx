## কী শিখব

- `grid[row][col]` mental model: আগে সারি, তারপর কলাম
- 2D array নিরাপদে বানানো, আর `fill`-এর reference ফাঁদ কেন বিখ্যাত
- Row-wise বনাম column-wise ঘোরা, দুটোর খরচ কিন্তু একই
- চারদিকের প্রতিবেশী বের করা: boundary check-এর প্যাটার্ন
- Diagonal আর transpose: দুটো ক্লাসিক কাজের dry run
- Grid কেন পরে graph আর island সমস্যার দরজা

## ধারণা

ধরো তুমি একটা বাসের সিট ম্যাপ বানাচ্ছ। সারি আছে, কলাম আছে। "৫ নম্বর সারির ২ নম্বর সিট" বললেই সবাই বুঝে যাবে ঠিক কোন জায়গার কথা বলছ। 2D array ঠিক এমনই: **array-এর ভেতরে array**, একটা পুরো টেবিল।

গুরুত্বপূর্ণ কথা, কম্পিউটারের কাছে "2D" বলে আলাদা কিছু নেই। বাইরের array-টা ধরে রাখে কয়েকটা সারির reference, প্রতিটা সারি নিজে একটা পুরো array। তাই `grid[1][2]` পড়তে engine আগে ১ নম্বর সারিটা খুঁজে বের করে, তারপর সেই সারির ২ নম্বর ঘরে যায়। দুই ধাপ, দুটোই O(1), মোট O(1)।

```text
        col 0   col 1   col 2
row 0: [  1  ,   2  ,   3  ]
row 1: [  4  ,   5  ,   6  ]
row 2: [  7  ,   8  ,   9  ]

grid[1][2] → 6   (আগে সারি, তারপর কলাম)
```

Image (প্রতি pixel এক ঘর), game board (chess, minesweeper), spreadsheet, পরে গিয়ে graph-এর adjacency matrix: সবই এই একই গ্রিড।

## বানানো: নিরাপদ রাস্তা আর বিখ্যাত ফাঁদ

খালি গ্রিড বানানোর সময়ই প্রথম বড় ফাঁদ। দুটো রাস্তা তুলনা করো:

```js
// ভুল রাস্তা: সব সারি আসলে একই array!
const bad = Array(3).fill(Array(3).fill(0));
bad[0][0] = 1;
console.log(bad);
// [ [1,0,0], [1,0,0], [1,0,0] ]  ← তিন সারিতেই 1!

// ঠিক রাস্তা: প্রতিটা সারি আলাদা array
const good = Array.from({ length: 3 }, () => Array(3).fill(0));
good[0][0] = 1;
console.log(good);
// [ [1,0,0], [0,0,0], [0,0,0] ]  ← শুধু প্রথম সারিতে
```

কেন এমন হয়? `fill(Array(3))` মানে তিনটা ঘরে একই array-এর **reference** বসল। একটা সারি বদলালে সব বদলায়, কারণ সবাই তো আসলে একজনই। `Array.from`-এর callback প্রতি ঘরে নতুন করে `Array(3)` বানায়, তাই সারিগুলো সত্যিকারের আলাদা। নিয়ম মনে রাখো: **2D বানাতে fill-এর ভেতরে কখনও array দেবে না**।

## ঘোরা: row-wise আর column-wise

```js
const grid = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];

// row-wise: সারি ধরে ধরে
const seen = [];
for (let r = 0; r < grid.length; r++) {
  for (let c = 0; c < grid[r].length; c++) {
    seen.push(grid[r][c]);
  }
}
console.log(seen.join(" ")); // 1 2 3 4 5 6 7 8 9

// column-wise: শুধু লুপ দুটোর ক্রম উল্টো
const seen2 = [];
for (let c = 0; c < grid[0].length; c++) {
  for (let r = 0; r < grid.length; r++) {
    seen2.push(grid[r][c]);
  }
}
console.log(seen2.join(" ")); // 1 4 7 2 5 8 3 6 9
```

দুটোতেই ভেতরের কাজ m×n বার হয়, তাই খরচ দুটোরই **O(m·n)**। পার্থক্য শুধু কোন ক্রমে ঘর দেখা হচ্ছে। বাইরের লুপ যেটা, সেটাই ধীরে বদলায়।

## প্যাটার্ন: চারদিকের প্রতিবেশী

Grid-ভিত্তিক সমস্যার প্রায় সবটাই দাঁড়ায় এক জায়গায়: একটা ঘরের **উপরে, নিচে, বামে, ডানে** কে আছে। কায়দাটা হলো দিক-জোড়ার array রাখা:

```js
const dirs = [
  [-1, 0], // উপরে
  [1, 0],  // নিচে
  [0, -1], // বামে
  [0, 1],  // ডানে
];

function neighbors(grid, r, c) {
  const result = [];
  for (const [dr, dc] of dirs) {
    const nr = r + dr;
    const nc = c + dc;
    // boundary check: গ্রিডের বাইরে পড়লে বাদ
    if (nr >= 0 && nr < grid.length && nc >= 0 && nc < grid[0].length) {
      result.push(grid[nr][nc]);
    }
  }
  return result;
}

console.log(neighbors(grid, 0, 0)); // [4, 2]: উপরে-বামে কেউ নেই
console.log(neighbors(grid, 1, 1)); // [2, 8, 4, 6]
```

কোণার ঘরের প্রতিবেশী ২টা, কিনারার ৩টা, মাঝের ৪টা। Boundary check ছাড়া চললে `grid[-1]` জাতীয় অবৈধ index-এ গিয়ে `undefined` পাবে। এই ছোট্ট প্যাটার্নটাই পরে [Island Traversal](../problem-solving/island-traversal.mdx) আর grid-এ BFS/DFS-এর হাড়।

## Dry run: মূল কর্ণের যোগফল

মূল কর্ণ (main diagonal) মানে যেসব ঘরে row আর col সমান: (0,0), (1,1), (2,2)। লক্ষ করো, লুপ দুটো লাগেই না, একটাই লুপে দুটো index একসাথে বাড়ে:

| ধাপ | i | ঘর | মান | sum |
|-----|---|-----|-----|-----|
| 1 | 0 | grid[0][0] | 1 | 1 |
| 2 | 1 | grid[1][1] | 5 | 6 |
| 3 | 2 | grid[2][2] | 9 | 15 |

```js
let sum = 0;
for (let i = 0; i < grid.length; i++) {
  sum += grid[i][i];
}
console.log(sum); // 15 (1 + 5 + 9)
```

উল্টো কর্ণ (anti-diagonal) চাইলে? সেখানে row বাড়লে col কমে: `grid[i][n - 1 - i]`। দুটো কর্ণই O(n) সময়ে, পুরো গ্রিড না ঘুরেই। সূত্র দুটো মনে রাখো: **row = col** হলে মূল কর্ণ, **row + col = n - 1** হলে উল্টো কর্ণ।

## আরেকটা ক্লাসিক: transpose

Transpose মানে সারিকে কলাম, কলামকে সারি বানিয়ে দেওয়া, মানে `grid[r][c]` যাবে `result[c][r]`-এ:

```js
function transpose(grid) {
  const rows = grid.length;
  const cols = grid[0].length;
  const result = Array.from({ length: cols }, () => Array(rows).fill(0));

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      result[c][r] = grid[r][c];
    }
  }
  return result;
}

console.log(transpose(grid));
// [ [1, 4, 7], [2, 5, 8], [3, 6, 9] ]
```

খেয়াল করো, result-এর মাত্রা উল্টে গেছে: n×m গ্রিডের transpose m×n। তাই বানানোর সময় `{ length: cols }` দিয়ে শুরু, আর ভেতরে `Array(rows)`। এই মাত্রা উল্টানোটাই transpose-এর সবচেয়ে চেনা ভুলের উৎস।

## কোড ব্রেকডাউন: neighbors, লাইনে লাইনে

1. `const dirs = [...]` : চার দিকের offset জোড়া। নতুন দিক যোগ করতে চাইলে (যেমন কর্ণীয় প্রতিবেশী) শুধু এখানে জোড়া যোগ করলেই হবে, বাকি কোড অটুট।
2. `const nr = r + dr` : বর্তমান ঘরে offset যোগ করে প্রতিবেশীর সারি।
3. `if (nr >= 0 && nr < grid.length && ...)` : চারটা শর্তই লাগে: উপরে না পড়া, নিচে না পড়া, বামে না পড়া, ডানে না পড়া। একটাও ফেললে invalid index।
4. `result.push(grid[nr][nc])` : বৈধ হলেই কেবল সংগ্রহ।
5. লুপ শেষে `result` ফেরত। প্রতি ঘরে এই কাজ ধ্রুবক ৪ বার, তাই প্রতি ঘরে O(1), পুরো গ্রিডে চালালে O(m·n)।

## Complexity

| কাজ | Time | কেন |
|-----|------|-----|
| `grid[r][c]` access | O(1) | দুটো সরাসরি লাফ: আগে সারিতে, তারপর ঘরে |
| পুরো গ্রিড traversal | O(m·n) | m সারি × n কলাম, প্রতিটা একবার |
| প্রতিবেশী বের করা (প্রতি ঘরে) | O(1) | ধ্রুবক ৪টা চেক |
| Diagonal (মূল বা উল্টো) | O(n) | প্রতি সারিতে একটাই ঘর |
| Transpose | O(m·n) | প্রতি ঘর একবার নতুন জায়গায় বসে |
| গ্রিড বানানো | O(m·n) | m×n ঘর লিখতেই হয় |

## সাধারণ ভুল আর edge case

**১. `Array(m).fill(Array(n))` দিয়ে গ্রিড বানানো।**
সব সারি একই array-এর reference, একটা বদলালে সব বদলায়। উপরে যে ফাঁদটা দেখালাম। পাল্টা: `Array.from({ length: m }, () => Array(n).fill(0))`।

**২. `grid[col][row]` লিখে ক্রম উল্টে ফেলা।**
সবসময় আগে সারি (row), তারপর কলাম। বাসের সিটের কথা মনে করো: আগে কোন সারি, তারপর সেই সারির কোন সিট। ভুলটা error দেয় না, চুপচাপ অন্য ঘর দিয়ে দেয়, তাই ধরা কঠিন।

**৩. সব সারির দৈর্ঘ্য সমান ধরে নেওয়া।**
JavaScript-এ কেউ বাধ্য করে না সব সারি সমান হতে হবে। `grid[2].length` হয়তো অন্যরকম। ভেতরের লুপে fixed `n` না দিয়ে `grid[r].length` ব্যবহার করো, যদি না তুমি নিজে গ্রিডটা বানিয়ে নিশ্চিত না হও।

**৪. Boundary check ভুলে `grid[-1]` খাওয়া।**
কোণার ঘর থেকে প্রতিবেশী খুঁজতে গিয়ে negative index, আর `grid[-1][0]` টাইপের ক্র্যাশ-অপেক্ষমাণ দৃশ্য। প্রতিবেশী প্যাটার্নে চারটা শর্তই রাখো।

**৫. Transpose-এ মাত্রা না উল্টানো।**
m×n গ্রিডের result বানাতে গিয়ে আবার m×n বানালে rectangular গ্রিডে উপাদান হারিয়ে যাবে বা undefined ভরে যাবে। Result হবে n×m, আর বর্গ (square) না হলে ভুলটা আরও স্পষ্ট।

## অনুশীলন

- **সহজ ১:** একটা 3×3 গ্রিডের দুটো কর্ণের (মূল + উল্টো) যোগফল আলাদা আলাদা বের করো। মাঝের ঘরটা দুইবার গোনা হলো কিনা খেয়াল করো, কখন হয় সেটা ভাবো।
- **সহজ ২:** গ্রিডের সব উপাদানের যোগফল বের করো একবার ঘুরে।
- **মাঝারি ১:** `transpose` না বানিয়ে, কেবল column-wise traversal দিয়ে গ্রিডের উপাদানগুলো উল্টো ক্রমে print করো। তারপর ভাবো: transpose আর column-wise ঘোরার সম্পর্কটা ঠিক কী?
- **মাঝারি ২:** প্রতিটা ঘরের জন্য গুনো কতগুলো প্রতিবেশী তার চেয়ে বড়, আর সবচেয়ে বেশি এমন প্রতিবেশী কোন ঘরের। (হিন্ট: `neighbors` ফাংশনটাই কাজে লাগবে।)
- **কঠিন:** Spiral order print: গ্রিডের ঘরগুলো ঘড়ির কাঁটার দিকে সর্পিল হয়ে বাইরে থেকে ভেতরে print করো। (হিন্ট: চারটা দেয়াল ধরে রাখো: top, bottom, left, right। একটা দিক শেষ হলে ওই দেয়াল এক ঘর ভেতরে টানো।) grid-ঘোরার এই ধরনের চর্চা পরে [Island Traversal](../problem-solving/island-traversal.mdx)-এ আরও গভীর হবে।

## সারসংক্ষেপ

- 2D array = সারির array; access-এর ক্রম সবসময় `grid[row][col]`, দুটো O(1) লাফ।
- বানাতে গেলে `Array.from({ length: m }, () => Array(n).fill(0))`; `fill`-এ array দিলে reference ফাঁদ।
- পুরোটা ঘুরলে O(m·n), diagonal-এ O(n), প্রতিবেশী প্রতি ঘরে O(1)।
- প্রতিবেশী প্যাটার্ন (dirs array + চার শর্তের boundary check) grid সমস্যার হাড়।
- Transpose-এ মাত্রা উল্টে যায়, এটা ভুললেই ঝামেলা।
