## কী শিখব

- interview-তে বারবার আসা hash প্যাটার্নগুলো

## ধারণা

এখানেই আসল জিনিস। Hash Table দিয়ে অনেক O(n²) সমস্যা O(n)-এ নামিয়ে ফেলা যায়। interview-তে তিনটা প্যাটার্ন ঘুরেফিরে আসেই:

1. **Frequency counting** (আগের পাতায় দেখে এসেছি)
2. **Seen-set** (এটা আগে দেখেছি কিনা)
3. **Complement lookup** (Two Sum-এর সেই কায়দা)

## কোড উদাহরণ

```js
// Two Sum, ক্লাসিক: target যোগফল দেয় এমন দুটো সংখ্যার index খুঁজি, O(n)
function twoSum(nums, target) {
  const seen = new Map();            // value থেকে index
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];   // যা দরকার
    if (seen.has(need)) return [seen.get(need), i]; // আগে দেখেছি?
    seen.set(nums[i], i);
  }
  return [];                         // পাওয়া যায়নি
}

console.log(twoSum([2, 7, 11, 15], 9)); // [0, 1]  (2+7=9)
```

## কোড ব্রেকডাউন

- naive উপায়টা কী হতো? nested loop, মানে O(n²)।
- এখানে কী করছি? প্রতিটা সংখ্যার "প্রয়োজনীয় জোড়া" (complement) আগে দেখা গেছে কিনা, সেটা map-এ চেক করছি। তাই পুরো কাজ O(n)-এ শেষ।
- একটা pass, একটা map। hash-এর শক্তির চেয়ে ভালো উদাহরণ কমই আছে।

## Complexity

- O(n) time, O(n) space।
