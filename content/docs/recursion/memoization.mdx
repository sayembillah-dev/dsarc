## কী শিখব

- আগে হিসাব করা ফলাফল জমিয়ে রাখা (DP-র বীজ)

## ধারণা

ভাবো তো, কেউ তোমাকে একই অঙ্ক দশবার জিজ্ঞেস করলে তুমি কী করবে? দশবার নতুন করে হিসাব করবে, নাকি প্রথমবার করে খাতায় লিখে রাখবে আর পরে শুধু খাতা থেকে পড়ে বলে দেবে? অবশ্যই দ্বিতীয়টা, তাই না?

Naive fib ঠিক প্রথমটার মতো কাজ করে, একই মান বারবার হিসাব করে, পুরো অপচয়। **Memoization** হলো দ্বিতীয় রাস্তাটা: হিসাব করা ফলাফল একটা cache-এ (Map) জমিয়ে রাখো, পরে দরকার হলে নতুন করে হিসাব না করে সরাসরি ফেরত দাও। এখানেই আসল জিনিস, এই এক কৌশলই পরে Dynamic Programming-এর ভিত্তি হয়ে দাঁড়ায় (section 16)।

## কোড উদাহরণ

```js
function fibMemo(n, cache = new Map()) {
  if (n < 2) return n;
  if (cache.has(n)) return cache.get(n);   // আগে হিসাব করা? সরাসরি দাও
  const result = fibMemo(n - 1, cache) + fibMemo(n - 2, cache);
  cache.set(n, result);                    // পরের জন্য জমা রাখি
  return result;
}

console.log(fibMemo(40)); // 102334155, সাথে সাথে (naive হলে বহু সেকেন্ড)
```

## কোড ব্রেকডাউন

- `cache.has(n)` মানে এটা আগে হিসাব করা আছে, তাই তৎক্ষণাৎ return।
- ফলে প্রতিটা `n` ঠিক একবারই হিসাব হয়, **O(2ⁿ) থেকে সোজা O(n)**-এ নেমে আসে!
- এই কৌশলেরই নাম "top-down DP"।

## Complexity

- O(n) time, O(n) space।
