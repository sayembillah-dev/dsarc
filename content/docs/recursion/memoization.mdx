## কী শিখব

- Memoization আসলে কী: একই প্রশ্নের উত্তর দুইবার হিসাব না করা
- Naive fib-এর অপচয়টা আবার দেখা, এবার সংখ্যা দিয়ে
- Cache যোগ করার পর call-এর গাছ কীভাবে শুকিয়ে যায়: পুরো dry run
- Complexity O(2ⁿ) থেকে O(n)-এ নামার সঠিক যুক্তি
- কেন এটাই Dynamic Programming-এর বীজ (top-down DP)

## ধারণা

ভাবো তো, কেউ তোমাকে একই অঙ্ক দশবার জিজ্ঞেস করলে কী করবে? প্রথমবার হিসাব করে খাতায় লিখে রাখবে, পরের নয়বার শুধু খাতা থেকে পড়ে বলবে। মাথা একবারই খাটালে, এটাই memoization।

আনুষ্ঠানিকভাবে: **ফলাফলটা একটা cache-এ জমিয়ে রাখো; একই input আবার এলে হিসাব না করে cache থেকে ফেরত দাও।** মনে করো [Recursion Examples](./recursion-examples.mdx)-এর fib-এর গাছ: `fib(2)` তিনবার হিসাব হয়েছিল। Memoized version-এ প্রথমবার হিসাব হবে, বাকি দুইবার cache থেকে আসবে, সাব-ট্রি আর ফোটেই না।

একটা কথা গুরুত্বপূর্ণ: memoization কোনো নতুন recursion না, তোমার পুরনো recursive function-এর **চারপাশে একটা খাতা জুড়ে দেওয়া** মাত্র। কোডের কঙ্কাল একই থাকে।

## কোড: নিজে বানাও fibMemo

```js
function fibMemo(n, cache = new Map()) {
  if (n < 2) return n;                    // base case, আগের মতোই

  if (cache.has(n)) return cache.get(n);  // খাতায় আছে? পড়ে দাও

  const result = fibMemo(n - 1, cache) + fibMemo(n - 2, cache);
  cache.set(n, result);                   // নতুন হিসাব: খাতায় লিখে রাখো
  return result;
}

console.log(fibMemo(40)); // 102334155, চোখের পলকে
```

খেয়াল করো, মূল দুই লাইন (`if n < 2`, আর যোগ) একদম অটুট। নতুন মাত্র দুই লাইন: ডাকার **আগে** খাতা দেখা, ফেরার **আগে** খাতায় লেখা।

## Dry run: `fibMemo(5)`-এ cache কীভাবে ভরে

| ধাপ | call | cache-এ ছিল? | কী হলো | cache-এর অবস্থা (শেষে) |
|-----|------|---------------|---------|--------------------------|
| 1 | fibMemo(5) | না | ভেতরে দুই ডানা ডাকল | - |
| 2 | fibMemo(4) | না | ডানা ডাকল | - |
| 3 | fibMemo(3) | না | ডানা ডাকল | - |
| 4 | fibMemo(2) | না | ডানা ডাকল | - |
| 5 | fibMemo(1) | base | return 1 | - |
| 6 | fibMemo(0) | base | return 0 | - |
| 7 | fibMemo(2) ফেরে | - | 1+0=1, লিখল 2→1 | `{2:1}` |
| 8 | fibMemo(3): `fibMemo(1)` | base | return 1; 3-এর হিসাব 1+1=2, লিখল | `{2:1, 3:2}` |
| 9 | fibMemo(4): `fibMemo(2)` | **হ্যাঁ** | cache থেকে 1, গাছ ফোটেনি; 4=2+1=3 | `{2:1, 3:2, 4:3}` |
| 10 | fibMemo(5): `fibMemo(3)` | **হ্যাঁ** | cache থেকে 2; 5=3+2=5 | `{..., 5:5}` |

ধাপ ৯ আর ১০-ই জাদু। Naive-এ `fibMemo(3)` আর `fibMemo(2)` নতুন করে পুরো সাব-ট্রি ফোটাত; এখানে cache থেকে তাত্ক্ষণিক মান। প্রথমবারের কাজই একমাত্র আসল কাজ, বাকি সব খাতা-পড়া।

## Complexity: O(2ⁿ) থেকে O(n), যুক্তিটা ঠিক করি

Naive-এ ছিল গাছ: প্রতি level-এ দ্বিগুণ। Memoized-এ যুক্তিটা এমন:

- সম্ভাব্য আলাদা প্রশ্ন আছে মাত্র n+1 টা: `fib(0)` থেকে `fib(n)`।
- প্রতিটা প্রশ্ন **ঠিক একবারই** আসল হিসাব করে (প্রথমবার), কারণ পরেরবার cache থেকে আসে।
- তাই মোট আসল হিসাব n+1 বার, প্রতিটা O(1) যোগ, মোটে **O(n)** time।
- Cache-এ n+1 টা এন্ট্রি, আর stack-এর গভীরতা n, মোটে **O(n)** space।

আরেকভাবে ভাবো: recursion tree-এর প্রতিটা node-এর দাম প্রথমবারই দেওয়া হয়, দ্বিতীয়বার node জন্মায়ই না। বিস্ফোরক গাছ শুকিয়ে হয়ে যায় একটা লম্বা সরল পথ, ডান দিকের শাখাগুলো cache-পড়া।

## কোড ব্রেকডাউন: fibMemo, লাইনে লাইনে

1. `cache = new Map()` default parameter : প্রথম ডাকায় খালি খাতা বানে, ভেতরের call-গুলোতে **একই খাতা** পাস হয়ে যায়। এই "একই খাতা" কথাটাই মুখ্য, প্রতি call-এ নতুন খাতা বানালে সব ভেসে যেত।
2. `if (cache.has(n)) return cache.get(n)` : হিসাবের আগে খাতা দেখা। এই লাইনটা base case-এর **পরে** রাখা হয়েছে, কারণ base case তো এমনিতেই ফ্রি, cache-এর দরকার নেই।
3. `fibMemo(n - 1, cache) + fibMemo(n - 2, cache)` : recursion অটুট, শুধু খাতা সঙ্গে যাচ্ছে।
4. `cache.set(n, result)` : ফেরার আগে লেখা। পরেরবার এই input এলে আর হিসাব হবে না।
5. `return result` : ফেরত মান আগের মতোই। খাতা বাইরের জিনিস, চুক্তি বদলায়নি।

## Memoization = Top-Down DP

এখানে একটা বড় নাম উচ্চারণ করার সময় এসেছে। তুমি যা বানালে, তার আনুষ্ঠানিক নাম **top-down dynamic programming**: বড় সমস্যা থেকে শুরু, recursion দিয়ে নিচে, পথে ফল জমিয়ে রাখা। এর উল্টো ভাই আছে, **bottom-up**, যেখানে ছোট থেকে লুপে বড় বানানো হয়, সেটা [Dynamic Programming](../problem-solving/dynamic-programming.mdx)-এ দেখবে।

মনে রাখার সূত্র: **overlapping subproblem দেখলেই** memoization ভাবো। সঙ্কেত হলো recursion tree-তে একই node বারবার ফোটা, যেমন fib-এ দেখেছিলে। না থাকলে (merge sort-এ প্রতি অর্ধেক আলাদা) cache কোনো লাভ দেয় না।

## সাধারণ ভুল আর edge case

**১. Cache পাস না করা, প্রতি call-এ নতুন খাতা।**
`fibMemo(n - 1)` লিখে `cache` না দিলে default parameter প্রতিবার নতুন Map বানায়। কোড চলবে, উত্তরও ঠিক আসবে, কিন্তু পুরো অপ্টিমাইজেশন ভেসে গেল, আর তুমি টেরও পাবে না। এটাই সবচেয়ে নিঃশব্দ ভুল।

**২. Object/array input-এর জন্য ভুল চাবি।**
Input যদি `(i, j)` জোড়া হয়, তাহলে চাবি হতে হবে দুটো মিলিয়ে, যেমন `` `${i},${j}` ``। শুধু `i` দিয়ে cache করলে ভিন্ন j-র ফল একে অন্যের হয়ে যাবে। চাবি বানানোর আগে ভাবো: input-এর কোন কোন অংশ উত্তর বদলায়?

**৩. Mutable ডেটা cache-এ রাখা।**
ফলাফল যদি array/object হয় আর ডাকার পর কেউ সেটা বদলে দেয়, পরেরবার cache দুষ্ট ফল দেবে। দরকার হলে copy রাখো, নয়তো ফলাফল immutable রাখার নিয়ম করো।

**৪. Overlapping নেই, তবু cache লাগানো।**
Merge sort-এ প্রতিটা সাব-সমস্যা আলাদা, cache শুধু memory খাবে। Memoization-এর আগে প্রশ্ন: একই input কি সত্যিই বারবার আসে? গাছ আঁকলেই দেখা যায়।

**৫. Global cache ফেলে রাখা, পরের test-এ দুষ্ট ফল।**
Function-এর বাইরে cache রাখলে এক test-এর ফল পরেরটায় ঢুকে যায়। Default parameter বা প্রতি run-এ নতুন cache নিরাপদ; class-এ রাখলে reset method ভুলো না।

## অনুশীলন

- **সহজ ১:** কাগজে `fibMemo(6)`-এর cache-এর অবস্থা ধাপে ধাপে লিখো। কোন call-গুলো cache থেকে এল চিহ্নিত করো।
- **সহজ ২:** বন্ধুকে বোঝাও: memoization-এর দুই লাইন (দেখা, লেখা) কোথায় বসে, আর কেন base case-এর পরে।
- **মাঝারি ১:** Climbing stairs লেখো: n ধাপের সিঁড়ি, একবারে ১ বা ২ ধাপ, কত উপায়ে ওঠা যায়? (হিন্ট: `ways(n) = ways(n-1) + ways(n-2)`, fib-এর ভাই। আগে naive লিখে n=40-এ ধীর দেখো, তারপর cache যোগ করো।)
- **মাঝারি ২:** `fibMemo`-কে এমনভাবে লেখো যাতে ডাকার সময় শুধু `fibMemo(n)` দিলেই চলে, cache argument লুকানো থাকে। (হিন্ট: wrapper function, ভেতরে helper-কে cache পাস করা। এই pattern টা পরে অনেক জায়গায় লাগবে।)
- **কঠিন:** Grid traveler: m×n grid-এ উপর-বাম থেকে নিচ-ডানে, শুধু ডানে বা নিচে, কত পথ? (হিন্ট: `paths(m, n) = paths(m-1, n) + paths(m, n-1)`; চাবি কী হবে ভাবো, আর কেন একটা সংখ্যার cache এখানে যথেষ্ট না। `paths(18, 18)` memo ছাড়া অসম্ভব, নিজে দেখো।)

## সারসংক্ষেপ

- Memoization = recursion + খাতা: প্রথমবার হিসাব, পরেরবার পড়া।
- দুই লাইনের জাদু: হিসাবের আগে খাতা দেখা, ফেরার আগে খাতায় লেখা।
- Naive fib O(2ⁿ) থেকে O(n), কারণ আলাদা প্রশ্ন মাত্র n+1 টা, প্রতিটা একবারই হিসাব হয়।
- Cache সব call-এ একই হতে হবে, নইলে নিঃশব্দে সব ভেসে যায়।
- Overlapping subproblem দেখলেই memoization; এটাই top-down DP, [Dynamic Programming](../problem-solving/dynamic-programming.mdx)-এর দরজা।
