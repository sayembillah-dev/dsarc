## কী শিখব

- কখন recursion, কখন loop

## ধারণা

যা কিছু recursion-এ করা যায়, তার প্রায় সবই loop-এও করা যায়। তাহলে প্রশ্ন হলো, কখন কোনটা নেব? ব্যাপারটা হলো এই:

| দিক | Recursion | Iteration (loop) |
|-----|-----------|------------------|
| পাঠযোগ্যতা | Tree/Graph-এ সুন্দর | সরল সমস্যায় সহজ |
| Memory | call stack (O(depth)) | সাধারণত O(1) |
| ঝুঁকি | stack overflow | নেই |

**নিয়মটা সহজ:** সমস্যাটা নিজে থেকেই "ছোট একই সমস্যায়" ভাঙে (যেমন tree বা divide-and-conquer) তাহলে recursion; সরল রৈখিক কাজ হলে loop।

## কোড উদাহরণ

```js
// একই factorial, দুইভাবে
// recursion
function factRec(n) { return n <= 1 ? 1 : n * factRec(n - 1); }

// iteration
function factIter(n) {
  let result = 1;
  for (let i = 2; i <= n; i++) result *= i;
  return result;                       // Space O(1), stack নেই
}
console.log(factRec(5), factIter(5)); // 120 120
```

## কোড ব্রেকডাউন

- দুটোই ঠিক, তফাত এই যে iteration-এ কোনো extra stack memory লাগে না।
- কিন্তু Tree/Graph traversal recursion-এ এত পরিষ্কার যে সেখানে সবাই recursion-ই পছন্দ করে।

## Complexity

- time দুটোই O(n); space: recursion O(n) (call stack), iteration O(1)।
