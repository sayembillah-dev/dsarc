## কী শিখব

- recursion মেমরিতে আসলে কীভাবে চলে

## ধারণা

ধরো, তুমি একটা কাজ করছিলে, এমন সময় ফোন এলো। কাজটা থামিয়ে ফোন ধরলে। কথা বলতে বলতে দরজায় কেউ এলো, ফোনটা hold করে দরজার কাজটা সারলে। তারপর ফিরে এসে ফোন শেষ করলে, সবশেষে আসল কাজে ফিরলে। খেয়াল করো, মাথার ভেতরে কাজগুলো একটা stack-এর মতো জমছিল, আর উপর থেকে একে একে খালি হচ্ছিল।

Function call-ও ঠিক এমন। প্রতিবার function ডাকলে সেটা **call stack**-এ (সত্যিই একটা stack!) জমা হয়। Base case-এ পৌঁছালে stack উপর থেকে একে একে খালি হয় (return)। সহজ কথায়, recursion পুরোটাই এই call stack-এর উপর দাঁড়িয়ে।

## কোড উদাহরণ

```js
// factorial দিয়ে stack বোঝা
function factorial(n) {
  if (n <= 1) return 1;          // base case
  return n * factorial(n - 1);   // n কে ছোট factorial দিয়ে গুণ
}

console.log(factorial(4)); // 24
/*
factorial(4) = 4 * factorial(3)
             = 4 * (3 * factorial(2))
             = 4 * (3 * (2 * factorial(1)))
             = 4 * (3 * (2 * 1)) = 24
প্রথমে নিচে নামে (call), base-এ পৌঁছে উপরে ফেরে (return)।
*/
```

## কোড ব্রেকডাউন

- প্রতিটা call নিজের `n` মনে রেখে অপেক্ষা করে, যতক্ষণ না ভেতরের call শেষ হয়।
- base case থেকে 1 return করে, তারপর পেছন থেকে একে একে গুণ হয়ে যায়।
- recursion খুব গভীরে চলে গেলে **stack overflow**, মানে মেমরি শেষ।

## Complexity

- time O(n), space O(n) (stack গভীরতা)।
