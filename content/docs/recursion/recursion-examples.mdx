## কী শিখব

- তিনটা ক্লাসিক recursion: array-এর যোগফল, string উল্টানো, fibonacci
- প্রতিটায় একই ছাপ: base case + ছোট সমস্যা, শুধু "কাজের জায়গা" বদলায়
- Recursion tree আঁকা: fib(5)-এর গাছ থেকে O(2ⁿ) কেন, নিজে প্রমাণ করা
- Overlapping subproblem: একই হিসাব বারবার, memoization-এর দরজা
- কোন উদাহরণে কত খরচ, আর কেন

## ধারণা

[Recursion Intro](./recursion-intro.mdx)-এ তিন প্রশ্নের সূত্র দেখেছিলে: ছোট রূপ কী, বড় উত্তর কীভাবে বানায়, কখন থামবে। এবার সেই সূত্রে তিনটা ক্লাসিক সমস্যা ফেলে দেখি। তিনটার গঠন তিন রকম:

- **Sum:** রৈখিক, একটাই ছোট সমস্যা (বাকি array)।
- **Reverse:** রৈখিক, কিন্তু কাজটা ফিরে আসার পথে।
- **Fibonacci:** ডানা দুটো, এক call থেকে দুইটা call, এখানেই গাছ।

## উদাহরণ ১: array-এর যোগফল

ছোট রূপ: প্রথম উপাদান বাদে বাকি array-র যোগফল। বড় উত্তর: প্রথমটা + ছোটটার উত্তর। থামবে: array খালি হলে (যোগফল 0)।

```js
function sum(arr, i = 0) {
  if (i === arr.length) return 0;   // base: শেষে পৌঁছে গেছি
  return arr[i] + sum(arr, i + 1);  // এবারেরটা + বাকির যোগফল
}

console.log(sum([1, 2, 3, 4])); // 10
```

Dry run, `sum([1, 2, 3, 4])`:

| ধাপ | call | কী ফেরায় | হিসাব |
|-----|------|-----------|-------|
| নিচে নামা | sum(i=0..4) জমতে থাকে | - | 1+?, তার ভেতরে 2+?, তার ভেতরে 3+?, তার ভেতরে 4+? |
| base | sum(i=4) | 0 | খালি, কিছু যোগ নেই |
| ফেরা ১ | sum(i=3) | 4 + 0 = 4 | |
| ফেরা ২ | sum(i=2) | 3 + 4 = 7 | |
| ফেরা ৩ | sum(i=1) | 2 + 7 = 9 | |
| ফেরা ৪ | sum(i=0) | 1 + 9 = 10 | চূড়া |

যোগফলটা ফিরে আসার পথে জড়ো হলো। Time O(n), space O(n) (n-টা frame, [Call Stack](./call-stack.mdx)-এর হিসাব)।

## উদাহরণ ২: string উল্টানো

ছোট রূপ: প্রথম অক্ষর বাদে বাকি string উল্টানো। বড় উত্তর: বাকিটার উল্টো + প্রথম অক্ষর একদম শেষে। থামবে: এক অক্ষর বা খালি হলে।

```js
function reverse(str) {
  if (str.length <= 1) return str;        // base
  return reverse(str.slice(1)) + str[0];  // বাকিটা উল্টো + প্রথমটা শেষে
}

console.log(reverse("abc")); // "cba"
```

Dry run, `reverse("abc")`:

| ধাপ | call | কী ফেরায় |
|-----|------|-----------|
| নামা | reverse("abc") → reverse("bc") → reverse("c") | অপেক্ষায় |
| base | reverse("c") | "c" |
| ফেরা ১ | reverse("bc") | "c" + "b" = "cb" |
| ফেরা ২ | reverse("abc") | "cb" + "a" = "cba" |

কাজটা পুরো ফিরে আসার পথে। মজার পয়েন্ট: `"c" + "b"` আগে, তারপর `"cb" + "a"`, অক্ষরগুলো পেছন থেকে জোড়া লাগছে, তাই উল্টো। একটা সতর্কতা: `str.slice(1)` প্রতিবার নতুন string কপি করে ([Strings](../strings/strings.mdx)-এর immutability মনে আছে?), তাই এই version-এর আসল খরচ O(n²)। দক্ষ চাইলে index দুটো পাস করো, অনুশীলনে সেটাই করবে।

## উদাহরণ ৩: Fibonacci, আর গাছ

সংজ্ঞাই recursive: `fib(n) = fib(n-1) + fib(n-2)`, থামে `fib(0)=0, fib(1)=1`-এ।

```js
function fib(n) {
  if (n < 2) return n;                 // base: fib(0)=0, fib(1)=1
  return fib(n - 1) + fib(n - 2);      // দুই ডানা
}

console.log(fib(7)); // 13
```

এবার আগের দুটোর মতো রৈখিক না: একটা call থেকে **দুটো** call বের হয়। `fib(5)`-এর পুরো গাছটা আঁকি:

```text
                fib(5)
              /        \
         fib(4)        fib(3)
         /    \        /    \
     fib(3) fib(2)  fib(2) fib(1)
     /   \   /   \   /  \
 fib(2) f(1) f(1) f(0) f(1) f(0)
 /  \
f(1) f(0)
```

এখন গোনো: `fib(2)` কতবার হিসাব হলো? তিনবার। `fib(3)`? দুবার। একই প্রশ্নের উত্তর বারবার নতুন করে হিসাব, এই অপচয়ের নাম **overlapping subproblem**।

Complexity-র derivation-টা নিজে করি। প্রতি level-এ call-এর সংখ্যা প্রায় দ্বিগুণ: level 0-এ ১টা, level 1-এ ২টা, level 2-এ ৪টা... গভীরতা n পর্যন্ত মোট call প্রায় 1+2+4+...+2ⁿ ≈ **2ⁿ**। মানে fib(40) মানে প্রায় এক ট্রিলিয়ন call, তাই ল্যাপটপও হাঁপায়। n যেখানে ৫০, সেখানে naive fib বাস্তবে অচল। আর মজার ব্যাপার, এই গাছের অর্ধেক কাজই অপ্রয়োজনীয়, কারণ একই উত্তর বারবার হিসাব হচ্ছে। ঠিক এই জায়গা থেকে [Memoization](./memoization.mdx)-এর জন্ম।

| Function | Time | Space | মন্তব্য |
|----------|------|-------|---------|
| sum | O(n) | O(n) stack | রৈখিক, এক ডানা |
| reverse (slice সহ) | O(n²) | O(n²) | slice প্রতিবার কপি করে |
| fib (naive) | O(2ⁿ) | O(n) stack | গাছ, overlapping subproblem |

Space-এ fib-এর O(n) কেন, O(2ⁿ) না? কারণ গাছে মোট node যতই হোক, **একই সঙ্গে** জীবিত frame হয় গভীরতা পর্যন্ত, আর গভীরতা n। গাছ বড়, কিন্তু লম্বা না।

## কোড ব্রেকডাউন: fib, লাইনে লাইনে

1. `if (n < 2) return n` : দুটো base case এক লাইনে, কারণ fib(0)=0 আর fib(1)=1 দুটোই n-এরই সমান। ছোট লেখা, কাজ ঠিকঠাক।
2. `fib(n - 1)` : প্রথম ডানা। এটা পুরো শেষ না হলে পরের লাইনে যায় না।
3. `fib(n - 2)` : দ্বিতীয় ডানা। প্রথমটার পুরো সাব-ট্রি শেষ হওয়ার পর এর শুরু।
4. `+` : দুই ডানার ফল ফিরলে যোগ। কাজটা ফিরে আসার পথে, sum-এর মতোই, শুধু ডানা দুটো বলে গাছ।

## সাধারণ ভুল আর edge case

**১. Fibonacci-র base case একটা রাখা।**
শুধু `n === 0` দিলে `fib(1)` কোথায় যাবে? `fib(0) + fib(-1)`, আর ঋণাত্মকে গিয়ে stack overflow। দুই ডানার recursion-এ base case-ও দুটো লাগে, এটা ভুলে যাওয়াটা স্বাভাবিক, তাই আলাদা করে মনে রাখো।

**২. `fib`-কে দ্রুত ভেবে বড় n দেওয়া।**
`fib(50)` naive-তে চালালে ট্যাব আটকে যাবে। ছোট n-এ টেস্ট করো, বড় n-এর আগে [Memoization](./memoization.mdx) পড়ে এসো।

**৩. String reverse-এ slice-এর লুকানো খরচ না বোঝা।**
`reverse` দেখতে O(n) মনে হয়, কিন্তু প্রতি call-এ `slice(1)` পুরো বাকি string কপি করে। Immutable string-এ "ছোট সমস্যা বানানো" নিজেই খরচসাপেক্ষ। Index পাস করলে কপি বন্ধ, খরচ O(n)।

**৪. Default parameter-এর ভূমিকা না বোঝা।**
`sum(arr, i = 0)`-এ দ্বিতীয় argument না দিলে i শূন্য থেকে শুরু, ডাকার সময় শুধু `sum(arr)` যথেষ্ট। কিন্তু ভেতরে থেকে ডাকার সময় `i + 1` পাস করতেই হবে, নইলে প্রতিবার গোড়া থেকে: অনন্ত লুপ।

**৫. প্রতিটা সমস্যায় recursion জোর করে লাগানো।**
Sum-এর মতো রৈখিক কাজে loop-ই সরল ও সাশ্রয়ী। Recursion-এর জোর tree-তে, গাছাকার সমস্যায়, divide-and-conquer-এ। কোথায় কী, সেটা পরের পেজ [Recursion vs Iteration](./recursion-vs-iteration.mdx)-এ।

## অনুশীলন

- **সহজ ১:** `reverse("abcd")`-এর পুরো dry run টেবিল বানাও: কোন call কী ফেরাল, কোন ক্রমে।
- **সহজ ২:** `fib(4)`-এর গাছ হাতে আঁকো। মোট কতগুলো call? `fib(2)` কতবার এল?
- **মাঝারি ১:** `sum`-কে বদলাও যাতে index পাস না করেও হয়, কিন্তু `slice` না ব্যবহার করে। (হিন্ট: helper function দরকার হতে পারে; বা ভাবো, মূল array-ই পাস করে শুধু সীমা বদলানো যায় কিনা।)
- **মাঝারি ২:** recursion দিয়ে array-এর সর্বোচ্চ বের করো, loop ছাড়া। (হিন্ট: ছোট রূপ "বাকি array-র সর্বোচ্চ", বড় উত্তর `Math.max(প্রথমটা, ছোটটার উত্তর)`। খালি array-তে কী হবে, সেটা ঠিক করা জরুরি।)
- **কঠিন:** recursion দিয়ে binary search লেখো: `bsearch(arr, target, lo, hi)`। (হিন্ট: মাঝের ঘর দেখো; ছোট হলে ডান অর্ধেকে, বড় হলে বাম অর্ধেকে নিজেকে ডাকো; lo > hi হলে -1। পুরো গল্প [Binary Search](../searching/binary-search.mdx)-এ, এই পেজে গভীরতা কত, লক্ষ করো।)

## সারসংক্ষেপ

- তিনটা উদাহরণ, একই ছাপ: base case + ছোট সমস্যা; বদলায় শুধু কাজের জায়গা আর ডানার সংখ্যা।
- রৈখিক recursion (এক ডানা) O(n) সময়; কিন্তু slice/join জাতীয় কপি খরচ আলাদা ধরতে হয়।
- দুই ডানার recursion গাছ বানায়; fib(5)-এর গাছেই দেখা গেল একই হিসাব বারবার।
- Naive fib O(2ⁿ), কারণ প্রতি level-এ call দ্বিগুণ; অপচয়ের নাম overlapping subproblem।
- এই অপচয় কাটার কৌশলই পরের পেজ: memoization।
