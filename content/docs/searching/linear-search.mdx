## কী শিখব

- Linear search-এর নিয়ম আর পুরো dry run
- Complexity-র তিন কেস: best, average, worst, আর কেন
- কখন এটাই একমাত্র উপায় (unsorted ডেটা), কখন এটাই ভুল পছন্দ
- Variant: সব মিলের index বের করা, প্রথম থেকে শেষ না পড়েও
- Built-in `indexOf`/`find` আসলে কী চালায়

## ধারণা

ধরো, মেঝেতে ছড়ানো বইয়ের সারি থেকে তোমার প্রিয় বইটা খুঁজছ। বইগুলোর কোনো ক্রম নেই। উপায় একটাই: প্রথমটা থেকে একটার পর একটা তুলে দেখা, যতক্ষণ না পাচ্ছ।

এটাই **Linear Search**: কোনো পূর্বশর্ত ছাড়া, শুরু থেকে শেষ, প্রতিটা উপাদানের সঙ্গে তুলনা। সরলতার কারণেই এটা সবচেয়ে নির্ভরযোগ্য: sorted হোক বা না, array হোক বা linked list, যেকোনো কাঠামোয় চলে।

## Dry run: `[4, 2, 7, 1, 9]`-এ 7 খোঁজা

| ধাপ | i | arr[i] | 7-এর সমান? | সিদ্ধান্ত |
|-----|---|--------|-------------|-----------|
| 1 | 0 | 4 | না | এগোয় |
| 2 | 1 | 2 | না | এগোয় |
| 3 | 2 | 7 | হ্যাঁ | **থামো, ফেরত 2** |

মাত্র তিন তুলনা। কিন্তু খারাপ ভাগ্য হলে? Target যদি 9 হয় (শেষে) বা 5 (নেই), তখন পুরো array ঘুরতেই হয়, n-টা তুলনা। Early exit-ই এখানে একমাত্র আশা: মিললেই থামো।

## কোড: নিজে বানাও

```js
function linearSearch(arr, target) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) return i;   // মিললেই থামো
  }
  return -1;                            // পুরোটা ঘুরেও নেই
}

console.log(linearSearch([4, 2, 7, 1, 9], 7)); // 2
console.log(linearSearch([4, 2, 7, 1, 9], 5)); // -1
```

## Variant: সব মিলের index

Target একাধিকবার থাকতে পারলে প্রথমটায় থামা যায় না, পুরোটা ঘুরে সব জমাতে হয়:

```js
function findAll(arr, target) {
  const found = [];
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === target) found.push(i);  // থামো না, জমাও
  }
  return found;
}

console.log(findAll([3, 1, 3, 3, 7], 3)); // [0, 2, 3]
console.log(findAll([3, 1, 3, 3, 7], 9)); // []: খালি array মানে নেই
```

খেয়াল করো, এবার early exit-এর সুযোগ নেই, কারণ শেষটা কোথায় কে জানে। একই loop, শুধু "থামো"র জায়গায় "জমাও"।

## কোড ব্রেকডাউন: linearSearch, লাইনে লাইনে

1. `for (let i = 0; i < arr.length; i++)` : পুরো পরিসর, 0 থেকে `length - 1` পর্যন্ত। `<=` লিখলে শেষে `undefined` পড়বে, চেনা off-by-one।
2. `if (arr[i] === target) return i` : মিললেই function থেকে বেরিয়ে যাওয়া, index সঙ্গে। loop-এর পরে আর কিছু চলে না, এটাই early exit।
3. `return -1` : loop শেষ হলেও ফেরা হয়নি মানে নেই। `-1` রেওয়াজ, কারণ index কখনও ঋণাত্মক হয় না, তাই "নেই" আর "0 নম্বরে আছে" গুলবে না।

## Complexity

| কেস | Time | কেন |
|-----|------|-----|
| Best | O(1) | প্রথমটাই মিলে গেল |
| Average | O(n) | গড়ে অর্ধেক ঘোরা |
| Worst | O(n) | শেষে আছে, বা নেই: পুরোটা |
| Space | O(1) | একটাই counter |

Average-এর হিসাবটা মজার: target যদি সমসম্ভাবে যে কোনো জায়গায় থাকে, গড়ে n/2 তুলনা, যা O(n)-ই। আর "নেই" কেসটা সবসময় পুরো n, কারণ না-আছে জানতেই সব দেখতে হয়।

একটা গুরুত্বপূর্ণ স্বীকৃতি: JavaScript-এর `indexOf`, `includes`, `find`, ভেতরে সবাই এই linear search-ই চালায়। তাই `arr.indexOf(x)` লিখলে মনে রেখো, এটা O(n), ফ্রি না।

## কখন এটাই ঠিক, কখন না

- **Unsorted ডেটা:** একমাত্র পথ। সাজানোর আগে খোঁজা দরকার হলে linear-ই।
- **একবারের খোঁজা, ছোট ডেটা:** sort করে তারপর binary search চালানোর ঝামেলার চেয়ে সস্তা।
- **বারবার খোঁজা, বড় ডেটা:** তখন আগে sort করে [Binary Search](./binary-search.mdx), অথবা [Hash Table](../hash-tables/hash-table-intro.mdx)-এ চলে যাও, যেখানে খোঁজা প্রায় O(1)।
- **Linked list:** random access-ই নেই, তাই ওখানে খোঁজা মানে হেঁটে যাওয়া, linear-ই ভাগ্য।

## সাধারণ ভুল আর edge case

**১. Loop-এর পরে return ভুলে যাওয়া।**
শুধু loop-এর ভেতরে `if` রেখে বাইরে কিছু না ফেরালে "নেই" কেসে `undefined` আসে। `-1` ফেরানো রেওয়াজ, আর ডাকার জায়গায় `if (i === -1)` দিয়ে চেক।

**২. `==` দিয়ে তুলনা।**
`"5" == 5` true দেয়। ডেটায় string-সংখ্যা মিশ্র থাকলে নিঃশব্দ ভুল মিল। সবসময় `===`।

**৩. Object খোঁজায় `===` আশা করা।**
`linearSearch(users, {id: 3})` কখনও মিলবে না, কারণ object-এ তুলনা হয় reference দিয়ে, ভেতরের মান দিয়ে না। Property দিয়ে তুলনা করো: `arr[i].id === 3`, অথবা `find` দাও।

**৪. "নেই" কেসে খরচ ভুল বোঝা।**
নেই জানতে পুরো scan লাগবেই, এটা কোনো দুর্বলতা না, সমস্যার চাহিদা। কেউ যদি বলে "না-আছা তাড়াতাড়ি বলো", তার উত্তর sorting বা hash, linear না।

**৫. Empty array ভুলে যাওয়া।**
খালি array-তে loop একবারও চলে না, সরাসরি `-1`, ঠিকই। কিন্তু টেস্টে না রাখলে পরে গোলমাল লাগে। Edge case হিসেবে সবসময় খালি input যাচাই করো।

## অনুশীলন

- **সহজ ১:** `[8, 3, 5, 1]`-এ target 1 আর target 9, দুটোর জন্যই কয়টা তুলনা লাগবে লিখো, কোড না চালিয়ে।
- **সহজ ২:** `findAll` দিয়ে একটা string-এর সব space-এর index বের করো। ফল খালি এলে কী বোঝায়?
- **মাঝারি ১:** এমন version লেখো যা **শেষ** মিলের index ফেরায়, পুরো array না ঘুরে। (হিন্ট: ডান থেকে বামে ঘোরো, প্রথম মিলেই থামো।)
- **মাঝারি ২:** বন্ধুকে বোঝাও: কেন বারবার খোঁজা লাগলে "আগে sort + binary search" জিতে যায়, হিসাব দাও: একবার sort O(n log n) + k-বার খোঁজা O(k log n) বনাম k-বার linear O(kn)। k কত হলে বদলাটা সাড়ে?
- **কঠিন:** Sentinel linear search পড়ে দেখো আর লেখো: শেষে target বসিয়ে দিলে প্রতি ধাপে `i < length` চেক লাগে না। লিখে benchmark করো, তারপর বলো এই কৌশল কেন আজকাল আর তেমন দরকারি না।

## সারসংক্ষেপ

- Linear search: শুরু থেকে একটার পর একটা, মিললেই থামো, শেষে -1।
- কোনো পূর্বশর্ত নেই, তাই unsorted বা যেকোনো কাঠামোয় চলে।
- Best O(1), average/worst O(n); "নেই" জানতে পুরো scan লাগবেই।
- `indexOf`/`includes`/`find` ভেতরে এটাই, O(n) মনে রেখো।
- বারবার খোঁজা হলে এর জায়গা sorting+binary বা hash table, সেদিকেই এগোচ্ছি।
