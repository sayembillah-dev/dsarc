## কী শিখব

- sorted ডেটায় অর্ধেক-অর্ধেক করে O(log n)-এ খোঁজা

## ধারণা

ভাবো তো, ডিকশনারিতে কোনো শব্দ খুঁজতে গিয়ে কি প্রথম পাতা থেকে শুরু করো? না। মাঝখানে খুলে দেখো শব্দটা আগে না পরে, তারপর ওই অর্ধেকেই আবার একই কাজ। এই কৌশলটাই **Binary Search**।

প্রতিবার মাঝের উপাদানটা দেখো:

- target mid-এর সমান হলে ব্যাস, পেয়ে গেছো
- target ছোট হলে বাঁ অর্ধেকে যাবে
- target বড় হলে ডান অর্ধেকে

প্রতি ধাপে অর্ধেক বাদ পড়ে যায়, তাই সময় O(log n)। ১০ লাখ উপাদানে মাত্র ~২০ ধাপ!

## কোড উদাহরণ

iterative সংস্করণ:

```js
function binarySearch(arr, target) {
  let low = 0, high = arr.length - 1;
  while (low <= high) {
    const mid = Math.floor((low + high) / 2); // মাঝের index
    if (arr[mid] === target) return mid;       // পেলাম
    else if (arr[mid] < target) low = mid + 1; // ডান অর্ধেক
    else high = mid - 1;                        // বাঁ অর্ধেক
  }
  return -1;
}
const sorted = [1, 3, 5, 7, 9, 11, 13];
console.log(binarySearch(sorted, 9)); // 4
console.log(binarySearch(sorted, 4)); // -1
```

## কোড ব্রেকডাউন

- `low` আর `high` দিয়ে খোঁজার পরিসর ঠিক করা, `mid` হলো মাঝখানটা।
- প্রতিবার মিলিয়ে দেখে অর্ধেক বাদ দিই। এখানেই আসল জিনিস, log n-এর রহস্য।
- `mid = Math.floor((low + high) / 2)`। বড় সংখ্যায় overflow এড়াতে চাইলে `low + Math.floor((high - low) / 2)`-ও লিখতে পারো।

<Callout type="warn" title="পূর্বশর্ত: sorted array">
Binary search-এর **একটাই শর্ত: array আগে থেকে sorted থাকতে হবে।** unsorted ডেটায় ফল ভুল আসবে, সেক্ষেত্রে linear search-ই ভরসা।
</Callout>

## Complexity

- সময় O(log n); space O(1)।
