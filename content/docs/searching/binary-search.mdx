## কী শিখব

- Binary search-এর নিয়ম আর একটাই পূর্বশর্ত: sorted ডেটা
- পুরো dry run: low, high, mid প্রতি ধাপে কেমন বদলায়
- Iterative আর recursive, দুই রূপই লেখা
- O(log n) কেন: অর্ধেকে ভাগের হিসাব নিজে করা
- বিখ্যাত ফাঁদগুলো: mid overflow, `low = mid` অনন্ত লুপ, `low <= high` বনাম `<`

## ধারণা

ভাবো তো, ডিকশনারিতে "কুকুর" শব্দটা খুঁজছ। প্রথম পাতা থেকে শুরু করো না, মাঝখান খুলে দেখো কোন অক্ষরে আছে। "কুকুর" যদি মাঝের শব্দের পরে হয়, বাম অর্ধেকের সব পাতা তুমি আর জীবনেও খুলবে না। এক দৃষ্টিতে অর্ধেক বাদ।

এটাই **Binary Search**। প্রতি ধাপে মাঝের উপাদান দেখো:

- সমান হলে: পেয়ে গেছো।
- target ছোট হলে: বাম অর্ধেকে যাও, ডান অর্ধেক চিরকালের জন্য বাদ।
- target বড় হলে: ডান অর্ধেকে যাও, বামটা বাদ।

শর্ত একটাই, কিন্তু বাধ্যতামূলক: **array sorted হতেই হবে**। না হলে "কোন অর্ধেকে যাব" বলার ভিত্তিই থাকে না।

## Dry run: `[1, 3, 5, 7, 9, 11, 13]`-এ 9 খোঁজা

| ধাপ | low | high | mid | arr[mid] | সিদ্ধান্ত |
|-----|-----|------|-----|----------|-----------|
| 1 | 0 | 6 | 3 | 7 | 9 বড়, ডানে: low = 4 |
| 2 | 4 | 6 | 5 | 11 | 9 ছোট, বামে: high = 4 |
| 3 | 4 | 4 | 4 | 9 | **মিলল, ফেরত 4** |

৭টা উপাদানে মাত্র ৩টা তুলনা। Linear search-এ খারাপ সময়ে ৭টা লাগত। পার্থক্যটা n বাড়ার সঙ্গে বিস্ফোরক: ১০ লাখ উপাদানে binary search লাগে সর্বোচ্চ প্রায় ২০ ধাপ, যেখানে linear-এ ১০ লাখ।

আরেকটা দেখি, যেটা **নেই**: target 4:

| ধাপ | low | high | mid | arr[mid] | সিদ্ধান্ত |
|-----|-----|------|-----|----------|-----------|
| 1 | 0 | 6 | 3 | 7 | ছোট, high = 2 |
| 2 | 0 | 2 | 1 | 3 | বড়, low = 2 |
| 3 | 2 | 2 | 2 | 5 | ছোট, high = 1 |
| 4 | 2 | 1 | - | - | low > high: **নেই, ফেরত -1** |

"নেই" জানতেও মাত্র ৩ ধাপ, কারণ পরিসর শূন্য হয়ে গেলেই উত্তর নিশ্চিত।

## কোড: iterative (প্রধান রূপ)

```js
function binarySearch(arr, target) {
  let low = 0;
  let high = arr.length - 1;           // দুই প্রান্তই অন্তর্ভুক্ত

  while (low <= high) {
    const mid = Math.floor((low + high) / 2);

    if (arr[mid] === target) {
      return mid;                      // মিলল
    } else if (arr[mid] < target) {
      low = mid + 1;                   // ডান অর্ধেকে
    } else {
      high = mid - 1;                  // বাম অর্ধেকে
    }
  }

  return -1;                           // পরিসর শেষ, নেই
}

const sorted = [1, 3, 5, 7, 9, 11, 13];
console.log(binarySearch(sorted, 9)); // 4
console.log(binarySearch(sorted, 4)); // -1
```

## Variant: recursive

একই যুক্তি, recursion-এর গলায়:

```js
function binarySearchRec(arr, target, low = 0, high = arr.length - 1) {
  if (low > high) return -1;           // base: পরিসর খালি

  const mid = Math.floor((low + high) / 2);

  if (arr[mid] === target) return mid;
  if (arr[mid] < target) {
    return binarySearchRec(arr, target, mid + 1, high);   // ডানে
  }
  return binarySearchRec(arr, target, low, mid - 1);      // বামে
}
```

দুটোর time একই O(log n)। তফাত space-এ: recursive version-এ গভীরতা log n-এর frame জমে ([Call Stack](../recursion/call-stack.mdx) মনে আছে?), iterative-এ O(1)। তাই বাস্তবে iterative-ই প্রধান।

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `high = arr.length - 1` : আমরা দুই প্রান্তই অন্তর্ভুক্ত রাখছি (inclusive)। এই চুক্তির কারণেই পরে `low <= high` আর `mid ± 1` সব ঠিক থাকে। চুক্তি বদলালে সব বদলায়।
2. `while (low <= high)` : পরিসরে অন্তত একটা ঘর থাকতে চলে। `low < high` দিলে এক-ঘরের পরিসর (`low === high`) চেকই হয় না, সেই ঘরেই target থাকলে মিস।
3. `mid = Math.floor((low + high) / 2)` : মাঝের index। ভগ্নাংশ হলে বাম দিকেরটা। (অন্য ভাষায় `low + high` overflow করে, সেখানে `low + Math.floor((high - low) / 2)` লিখো; JS-এ সংখ্যা বড় হলেও নিরাপদ, তবু দ্বিতীয় রূপটা জেনে রাখো।)
4. `low = mid + 1` : mid চেক হয়ে গেছে, ওকে আর পরিসরে রাখা যায় না। `low = mid` লিখলে পরিসর কমে না, অনন্ত লুপ।
5. `high = mid - 1` : একই কারণে। এই দুই `± 1`-ই binary search-এর প্রাণ, ভুললে সব ভাঙে।

## Complexity: O(log n) কেন, হিসাব করি

প্রতি ধাপে পরিসর অর্ধেক হয়। শুরুতে n, তারপর n/2, n/4, ... যতক্ষণ না 1:

```text
n → n/2 → n/4 → ... → 1: মোট k ধাপে, যেখানে n / 2ᵏ = 1, অর্থাৎ k = log₂n
```

মানে সর্বোচ্চ প্রায় log₂n তুলনা। কয়টা উদাহরণে অনুভব করো:

| n | সর্বোচ্চ ধাপ (log₂n) |
|---|----------------------|
| ১০০ | ~৭ |
| ১০,০০০ | ~১৪ |
| ১০ লাখ | ~২০ |
| ১০০ কোটি | ~৩০ |

ডেটা দ্বিগুণ হলে ধাপ বাড়ে মাত্র একটা। এই ধীরে বাংলার কারণেই binary search "প্রায় ফ্রি" মনে হয়, আর এটাই [Linear Search](./linear-search.mdx)-এর O(n)-এর বিপরীত চরম।

## সাধারণ ভুল আর edge case

**১. Unsorted array-তে চালানো।**
সবচেয়ে ভয়ংকর, কারণ error আসে না, কখনও ঠিক উত্তরও আসে, কখনও ভুল। শর্ত মনে রাখো: sorted না হলে আগে sort করো, নয়তো linear।

**২. `low = mid` বা `high = mid` লেখা।**
পরিসর আর কমে না, `low === high` থেকে আর নড়ে না, অনন্ত লুপ। mid চেক হয়ে গেছে বলে `± 1` বাধ্যতামূলক (আমাদের চুক্তিতে)।

**৩. `while (low < high)` লিখে এক-ঘরের পরিসর মিস করা।**
আমাদের inclusive চুক্তিতে `<=`। `[5]`-এর মতো এক-উপাদান array-তে 5 খুঁজলে `<` দিলে loop-ই চলে না, ভুল -1। চুক্তি আর শর্ত মিলিয়ে লেখো।

**৪. `mid` ভগ্নাংশ রেখে দেওয়া।**
`const mid = (low + high) / 2` দিয়ে `arr[mid]` লিখলে `arr[3.5]` হয়ে `undefined`। `Math.floor` বাধ্যতামূলক, নইলা index-ই নেই।

**৫. Duplicate থাকলে কোনটা ফিরবে, সেটা না ভাবা।**
`[1, 2, 2, 2, 3]`-এ 2 খুঁজলে কোন 2 ফিরবে? যেকোনো একটা, গ্যারান্টি নেই প্রথমটা। প্রথম/শেষ দরকার হলে পরের পেজ, [Variants](./binary-search-variants.mdx)।

## অনুশীলন

- **সহজ ১:** `[2, 5, 8, 12, 16, 23, 38]`-এ target 23 খোঁজার dry run টেবিল বানাও: প্রতি ধাপে low, high, mid।
- **সহজ ২:** একই array-তে target 10-এর dry run করো। কোন ধাপে পরিসর খালি হলো?
- **মাঝারি ১:** Recursive আর iterative, দুটোতেই একটা counter যোগ করে তুলনা-সংখ্যা গুনো। n = 1, 2, 4, 8, ..., 1024-এর জন্য লিখো, তারপর log₂n-এর সঙ্গে মিলাও।
- **মাঝারি ২:** বন্ধুকে বোঝাও: কেন `low = mid` দিলে অনন্ত লুপ হয়। `[3, 7]`-এ target 7 দিয়ে দেখাও, ধাপে ধাপে।
- **কঠিন:** Rotated sorted array-তে search (LeetCode 33): `[4, 5, 6, 7, 0, 1, 2]`-তে 0 খুঁজো। (হিন্ট: প্রতি mid-এ অন্তত এক অর্ধেক sorted থাকেই। আগে ঠিক করো কোন অর্ধেকটা sorted, তারপর দেখো target ওই অর্ধেকের পরিসরে পড়ে কিনা। একটাই লুকানো sorted ভাগ থাকলেও চলে।)

## সারসংক্ষেপ

- Binary search: sorted array-তে প্রতি ধাপে মাঝ দেখে অর্ধেক চিরতরে বাদ।
- একটাই পূর্বশর্ত, sorted ডেটা; unsorted-এ চুপচাপ ভুল দেয়।
- O(log n): ডেটা দ্বিগুণ, ধাপ মাত্র এক বাড়ে; ১০ লাখে প্রায় ২০ ধাপ।
- ফাঁদ তিনটা: `mid ± 1` ভুলে যাওয়া, `<=` বনাম `<` গুলানো, `Math.floor` না করা।
- Duplicate-এর প্রথম/শেষ, insert-পয়েন্ট: সবই পরের পেজে, একই ভিত্তিতে।
