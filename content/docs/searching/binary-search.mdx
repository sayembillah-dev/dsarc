## কী শিখব

- sorted ডেটায় অর্ধেক-অর্ধেক করে O(log n)-এ খোঁজা

## ধারণা

প্রতিবার মাঝের উপাদান দেখি:

- target mid-এর সমান হলে পেলাম
- target ছোট হলে বাঁ অর্ধেকে খুঁজি
- target বড় হলে ডান অর্ধেকে খুঁজি

প্রতি ধাপে অর্ধেক বাদ যায়, তাই O(log n)। ১০ লাখ উপাদানে মাত্র ~২০ ধাপ!

## কোড উদাহরণ

iterative সংস্করণ:

```js
function binarySearch(arr, target) {
  let low = 0, high = arr.length - 1;
  while (low <= high) {
    const mid = Math.floor((low + high) / 2); // মাঝের index
    if (arr[mid] === target) return mid;       // পেলাম
    else if (arr[mid] < target) low = mid + 1; // ডান অর্ধেক
    else high = mid - 1;                        // বাঁ অর্ধেক
  }
  return -1;
}
const sorted = [1, 3, 5, 7, 9, 11, 13];
console.log(binarySearch(sorted, 9)); // 4
console.log(binarySearch(sorted, 4)); // -1
```

## কোড ব্রেকডাউন

- `low`/`high` খোঁজার পরিসর; `mid` মাঝ।
- মিলিয়ে দেখে অর্ধেক বাদ দিই, এটাই log n-এর রহস্য।
- `mid = Math.floor((low + high) / 2)`, বড় সংখ্যায় overflow এড়াতে `low + Math.floor((high - low) / 2)`-ও লেখা যায়।

<Callout type="warn" title="পূর্বশর্ত: sorted array">
Binary search-এর **পূর্বশর্ত: array sorted থাকতে হবে**; unsorted ডেটায় ভুল ফল আসবে, তখন linear search ব্যবহার করো।
</Callout>

## Complexity

- O(log n); space O(1)।
