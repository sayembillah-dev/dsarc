## কী শিখব

- LIFO (Last In, First Out) নীতিটা আসলে কী বলে, আর কেন এটাই কম্পিউটারের সবচেয়ে আদরের কাঠামো
- push/pop/peek অপারেশনের পুরো dry run
- নিজে হাতে `Stack` class লেখা, আর সরাসরি array দিয়েও কাজ চালানো
- কেন সব অপারেশন O(1): খরচের হিসাবটা আবার সেই "সরানো"র গল্প
- Undo, back button, call stack: বাস্তবে stack কোথায় কোথায়
- Interview-তে ঘুরতে থাকা ভুলগুলো

## ধারণা

ধরো, ধোয়া থালাগুলো একটার উপর একটা রেখে স্তূপ করছ। এখন থালা লাগলে কোনটা আগে তোলো? সবার উপরেরটা, যেটা তুমি একদম শেষে রেখেছ। আর নতুন থালা রাখতে গেলে কোথায় রাখো? আবার সবার উপরে। মানে ঢোকাও এক প্রান্তে, বের করাও সেই এক প্রান্তে।

এটাই Stack, আর এই নীতির নাম **LIFO (Last In, First Out)**: শেষে ঢোকা জিনিস আগে বের হয়। যে প্রান্তে সব নাড়াচাড়া হয়, তাকে বলে **top**।

```text
        ┌─────┐
        │  30 │  ← top (সব কাজ এখানেই)
        ├─────┤
        │  20 │
        ├─────┤
        │  10 │
        └─────┘
```

মজার ব্যাপার হলো, তুমি stack চেনো না বললেও সারাদিন stack-ই ব্যবহার করো। Ctrl+Z চাপলে সবচেয়ে সাম্প্রতিক কাজটাই আগে আনডু হয়। ব্রাউজারের back button শেষে দেখা পেজটাই আগে ফেরায়। আর প্রতিটা function call-এর ভেতরে যে call stack কাজ করে, সেটার নামের মাঝেই উত্তর লেখা আছে, [Recursion](../recursion/call-stack.mdx)-এ গিয়ে সেই গল্পটা খুলব।

## Dry run: push আর pop-এর এক পুরো দিন

ধরো এই ক্রমে অপারেশন চলছে: `push(10)`, `push(20)`, `push(30)`, `pop()`, `push(40)`, `pop()`। প্রতি ধাপে stack-এর অবস্থা খেয়াল করো, top সবসময় ডান প্রান্তে ধরা:

| ধাপ | অপারেশন | stack (বামে তলা, ডানে top) | ফেরত মান |
|-----|---------|------------------------------|----------|
| শুরু | - | `[ ]` | - |
| 1 | push(10) | `[10]` | - |
| 2 | push(20) | `[10, 20]` | - |
| 3 | push(30) | `[10, 20, 30]` | - |
| 4 | pop() | `[10, 20]` | 30 |
| 5 | push(40) | `[10, 20, 40]` | - |
| 6 | pop() | `[10, 20]` | 40 |

দুটো জিনিস চোখে পড়ার কথা। এক, 30 সবচেয়ে আগে বের হলো, কারণ সে-ই শেষে ঢুকেছিল, LIFO ঠিকঠাক কাজ করছে। দুই, প্রতি অপারেশনে শুধু ডান প্রান্তটাই নড়ল, বাকি কেউ জায়গা বদলাল না। এই দ্বিতীয় পয়েন্টটাই পরে complexity-র উত্তর হয়ে যাবে।

## কোড: নিজে বানাও Stack

JavaScript array-এর `push`/`pop` একদম শেষ প্রান্তে কাজ করে, তাই stack বানানোর জন্য এর চেয়ে আদর্শ উপাদান আর নেই:

```js
class Stack {
  constructor() {
    this.items = [];
  }

  push(x) {
    this.items.push(x);                    // top-এ রাখো
  }

  pop() {
    if (this.isEmpty()) return undefined;  // খালি stack-এ নিরাপত্তা
    return this.items.pop();               // top থেকে তোলো
  }

  peek() {
    if (this.isEmpty()) return undefined;
    return this.items[this.items.length - 1]; // top-টা শুধু দেখো
  }

  isEmpty() {
    return this.items.length === 0;
  }

  size() {
    return this.items.length;
  }
}

const s = new Stack();
s.push(10);
s.push(20);
s.push(30);
console.log(s.peek());   // 30: দেখলাম, বের করলাম না
console.log(s.pop());    // 30: শেষে ঢুকেছিল, আগে বের হলো
console.log(s.pop());    // 20
console.log(s.size());   // 1
```

ছোট সমস্যায় আলাদা class না বানিয়ে সরাসরি array-কেই stack হিসেবে ব্যবহার করা চলে, competitive programming-এ এটাই রেওয়াজ:

```js
const stack = [];
stack.push("ক");
stack.push("খ");
console.log(stack.pop()); // "খ"
```

তাহলে class কেন? কারণ class-টা **নিয়মটা জোর করে**: কেউ ভুলে `stack[0]` ছুঁয়ে তলার জিনিস নাড়তে পারে না, `shift()` চালিয়ে O(n) ফাঁদেও পড়ে না। Stack-এর শক্তি হলো এর সীমাবদ্ধতা, মনে রেখো।

আরেকটা রূপ জেনে রাখো: [Linked List](../linked-lists/singly-linked-list.mdx) দিয়েও stack বানানো যায়, শুধু সব অপারেশন head-এ করলেই হবে। ধারণা একই, ভেতরের গঠন ভিন্ন। ছোট্ট কাজে array version-ই সহজ আর cache-বান্ধব।

## কোড ব্রেকডাউন: Stack class, লাইনে লাইনে

1. `this.items = []` : ভেতরের সংগ্রহশালা। Array-এর শেষ প্রান্তটাকেই আমরা top ধরছি, এটা মনে রাখা জরুরি, কারণ উল্টোটা ধরলেই সব O(n) হয়ে যেত।
2. `push(x)` : array-এর নিজের `push` ডাকল। শেষে বসানো মানে কাউকে সরাতে হয় না, তাই O(1) (amortized, কথাটা [Array Operations](../arrays-strings/array-operations.mdx)-এ গিয়েছিল)।
3. `pop()` : আগে খালি কিনা দেখল, না হলে শেষ উপাদানটা তুলে ফেরত দিল। শেষ থেকে তোলাতেও কেউ সরে না, O(1)।
4. `peek()` : `items[length - 1]`, আবার সেই শেষ index-এর চেনা সূত্র। শুধু পড়া, কোনো পরিবর্তন না।
5. `isEmpty()` : `length === 0`। এই চেকটা ছোট দেখালেও নিচের ভুলগুলোর অর্ধেক এখান থেকেই জন্ম নেয়।

## Complexity: কেন সব O(1)

| অপারেশন | Complexity | কেন |
|---------|-----------|-----|
| push | O(1), amortized | শেষে বসানো, কাউকে সরাতে হয় না |
| pop | O(1) | শেষ থেকে তোলা, কাউকে সরাতে হয় না |
| peek | O(1) | শেষ index-এর সরাসরি access |
| isEmpty / size | O(1) | length আগে থেকেই গোনা |

Derivation-টা পুরানো পরিচিত: [Array Operations](../arrays-strings/array-operations.mdx)-এ দেখেছিলে, খরচ = কতজনকে সরাতে হচ্ছে। Stack-এর সব কাজ এক প্রান্তে, তাই সরানোর সংখ্যা প্রতিবার **শূন্য**, n যাই হোক। এজন্যই বলা যায়, stack আসলে array-এর ওপর একটা শৃঙ্খলা: সুবিধা বাড়ায় না, ফাঁদ বন্ধ করে। আর সেই শৃঙ্খলার বিনিময়ে পাওয়া O(1) গ্যারান্টিই বাস্তব জগতে (undo, parsing, DFS) এর দাম।

## বাস্তবে stack কোথায় কোথায়

- **Undo/Redo:** প্রতিটা কাজ stack-এ ঢোকে, Ctrl+Z মানে top থেকে উল্টো কাজটা বের করা।
- **Back button:** প্রতিটা পেজ visit stack-এ জমা হয়, back চাপলে সাম্প্রতিক পেজটাই আগে ওঠে।
- **Call stack:** function ডাকলে তার অবস্থা stack-এ চাপে, return-এ ওঠে। Recursion-এর প্রাণ এটাই।
- **Bracket matching, expression evaluation:** পরের পেজ [Balanced Parentheses](./balanced-parentheses.mdx)-এই প্রথম বাস্তব প্রয়োগ।
- **DFS:** [Graph](../graphs/dfs.mdx)-এর depth-first খোঁজ সরাসরি stack দিয়ে চলে।
- **Monotonic stack:** একটা সাজানো রূপ, "পরের বড়টা কে" ধরনের সমস্যার অস্ত্র, [Monotonic Stack](./monotonic-stack.mdx)-এ পুরো গল্প।

## সাধারণ ভুল আর edge case

**১. খালি stack-এ `pop()` বা `peek()` করা।**
JavaScript ক্রাশ করে না, নিরবে `undefined` দেয়। সেই `undefined` হিসাবের ভেতর ঢুকে NaN বানায়। নিয়ম করো: pop/peek-এর আগে `isEmpty()` চেক, বা এমনভাবে লেখো যাতে খালি হওয়াই অসম্ভব।

**২. `peek()` আর `pop()` গুলিয়ে ফেলা।**
`peek` শুধু দেখে, উপাদান জায়গায়ই থাকে। "দেখে নিলাম" ভেবে কাজ চালালে একই উপাদান দুবার প্রক্রিয়া হবে। দেখা লাগলে `peek`, সরানো লাগলে `pop`, দুটো আলাদা verb।

**৩. Array-এর ভুল প্রান্ত দিয়ে stack বানানো।**
`unshift()`/`shift()` দিয়ে top বানালে প্রতি অপারেশনে সবাই এক ঘর সরে, O(n)। top সবসময় শেষ প্রান্তে, যেখানে `push`/`pop` সস্তা।

**৪. Stack-এর ভেতরে random access বা iterate করা।**
`stack.items[0]` ঘেঁটে দেখা বা loop চালানো মানে abstraction ভাঙা। সত্যিই সব উপাদান ঘুরে দেখা লাগলে তোমার দরকার ছিল array, stack না। কাঠামো বাছাই ভুল, কোড ভুল না, এটা design-এর প্রশ্ন।

**৫. Recursion-এ stack overflow ভুলে যাওয়া।**
তোমার লেখা stack যেমন memory খায়, তেমনি প্রতিটা function call-ও call stack-এ জায়গা খায়। Base case ভুললে বা অতিরিক্ত গভীর recursion হলে `Maximum call stack size exceeded`, এটাও আসলে stack-এরই সীমা ফুরিয়ে যাওয়া।

## অনুশীলন

- **সহজ ১:** কাগজে dry run করো: `push(5)`, `push(9)`, `pop()`, `push(7)`, `peek()`, `pop()`, `pop()`। প্রতি ধাপে stack আঁকো, শেষে কী ফেরত পাবে লিখো।
- **সহজ ২:** stack দিয়ে একটা string উল্টাও: `"bangla"` → `"algnab"`। (হিন্ট: সব character push করো, তারপর খালি না হওয়া পর্যন্ত pop করে জোড়ো। মনে আছে তো, লুপে string জোড়ার বদলে কী করতে বলেছিলাম [Strings](../arrays-strings/strings.mdx)-এ?)
- **মাঝারি ১:** MinStack বানাও: সাধারণ stack-এর সব অপারেশনের পাশে `getMin()`-ও O(1)। (হিন্ট: পাশে আরেকটা stack রাখো যেখানে "এ পর্যন্তকার সর্বনিম্ন" জমা থাকে। push-এর সময় ভাবো, নতুন মান কি সেই stack-এও যাবে?)
- **মাঝারি ২:** ব্রাউজারের history বানাও: `visit(url)`, `back()`, `forward()`। (হিন্ট: দুটো stack লাগবে, একটা past-এর, একটা forward-এর। নতুন পেজ visit করলে forward stack-এর কী হওয়া উচিত, ভাবো।)
- **কঠিন:** Postfix expression evaluate করো, যেমন `"2 3 + 4 *"` থেকে 20। (হিন্ট: সংখ্যা পেলে push, operator পেলে দুটো pop করে হিসাব করে ফল আবার push। কেন stack এখানে নিখুঁতভাবে ফিট হয়, যুক্তি দাও।)

## সারসংক্ষেপ

- Stack = এক প্রান্তের খেলা: ঢোকাও top-এ, বের করাও top থেকে, নিয়মের নাম LIFO।
- সব মূল অপারেশন O(1), কারণ কাউকে সরাতে হয় না, খরচের হিসাব array-এরই।
- JavaScript array-এর শেষ প্রান্তই আদর্শ top; সামনের প্রান্ত ধরলেই O(n) ফাঁদ।
- Undo, back button, call stack, bracket matching: সব জায়গায় একই নীতি।
- Stack-এর শক্তি তার সীমাবদ্ধতায়: যে কাজে সব উপাদান access দরকার, সেখানে stack না, array।
