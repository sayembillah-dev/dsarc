## কী শিখব

- কেন nested কাঠামো মানেই stack: LIFO আর বন্ধনীর জোড়ার গভীর সম্পর্ক
- পুরো algorithm-এর dry run, সঠিক আর ভুল, দুই রকম string-এই
- নিজে হাতে `isBalanced` লেখা, আর শুধু `()`-এর জন্য counter-ভিত্তিক সরল রূপ
- Complexity-র derivation আর space-এর খরচ কোথায় যায়
- Interview-র প্রিয় edge case-গুলো

## ধারণা

ভাবো তো, সামনে লেখা আছে `({[]})`। সব বন্ধনী কি ঠিকঠাক জোড়ায় আছে? চোখে মেলাতে গেলে একটু পরপরই মাথা ঘোরে। কিন্তু একটা নিয়ম খেয়াল করো: **যে বন্ধনী সবচেয়ে শেষে খুলেছে, সে-ই আগে বন্ধ হতে হবে**। `({[]})`-এ শেষ খুলেছে `[`, আর প্রথমে বন্ধ হয়েছে সে-ই।

শেষে খোলা, আগে বন্ধ: এ তো হুবহু LIFO! মানে বন্ধনী মেলানোর জন্য stack-এর চেয়ে প্রাকৃতিক কাঠামো আর কিছু নেই। নিয়মটা তিন লাইনের:

- খোলা বন্ধনী পেলে stack-এ ঢুকিয়ে রাখো (অপেক্ষায় রাখো)।
- বন্ধ বন্ধনী পেলে stack-এর top-এর সঙ্গে মেলাও; মিললে জোড়া শেষ, না মিললে ভুল।
- সব character শেষে stack খালি থাকলে balanced, না হলে কোনো খোলা বন্ধনী এখনও স্বামীহারা।

## Dry run ১: সঠিক string, `({[]})`

| ধাপ | char | কাজ | stack (ডানে top) |
|-----|------|-----|--------------------|
| শুরু | - | - | `[ ]` |
| 1 | `(` | push | `[ ( ]` |
| 2 | `{` | push | `[ (, { ]` |
| 3 | `[` | push | `[ (, {, [ ]` |
| 4 | `]` | top `[` মিলল, pop | `[ (, { ]` |
| 5 | `}` | top `{` মিলল, pop | `[ ( ]` |
| 6 | `)` | top `(` মিলল, pop | `[ ]` |
| শেষ | - | stack খালি | **balanced: true** |

দেখো, বন্ধ বন্ধনী প্রতিবার ঠিক তখনই এসেছে যখন তার জোড়া top-এ বসে আছে। Stack এখানে একটা "অপেক্ষারত খোলা বন্ধনীদের তালিকা", নতুন খোলা এলে তালিকার উপরে চাপে, বন্ধ এলে সবচেয়ে সাম্প্রতিক অপেক্ষারতের হিসাব কিটে যায়।

## Dry run ২: ভুল string, `([)]`

| ধাপ | char | কাজ | stack |
|-----|------|-----|-------|
| 1 | `(` | push | `[ ( ]` |
| 2 | `[` | push | `[ (, [ ]` |
| 3 | `)` | top হলো `[`, জোড়া মেলে না | **false, এখানেই থামো** |

গিনিসটা সূক্ষ্ম। `(` আর `)` আছে, `[` আর `]`-ও আছে, সংখ্যা মিলে গেছে। তবু এটা ভুল, কারণ nested জোড়া আড়াল হতে পারে না: `[` বন্ধ হওয়ার আগে `(` বন্ধ হয়ে গেছে। সংখ্যা গোনা এই ক্রমটা ধরতে পারে না, stack পারে, কারণ stack ক্রমটাই মনে রাখে। Early exit-টাও লক্ষণীয়: একটা অমিল মানেই উত্তর false, বাকি string দেখার দরকার নেই।

## কোড: নিজে বানাও isBalanced

```js
function isBalanced(str) {
  const stack = [];
  const pairs = { ")": "(", "]": "[", "}": "{" }; // বন্ধ → খোলা

  for (const ch of str) {
    if (ch === "(" || ch === "[" || ch === "{") {
      stack.push(ch);                          // খোলা: অপেক্ষায় রাখো
    } else if (ch in pairs) {
      if (stack.pop() !== pairs[ch]) {         // বন্ধ: top-এর সঙ্গে মেলাও
        return false;                          // অমিল বা খালি stack
      }
    }
    // অন্য character (অক্ষর, সংখ্যা, operator) উপেক্ষা
  }

  return stack.length === 0;                   // সব জোড়া মিলেছে?
}

console.log(isBalanced("({[]})"));      // true
console.log(isBalanced("([)]"));        // false
console.log(isBalanced("((("));         // false: খোলা রয়ে গেছে
console.log(isBalanced("(a + b) * [c]")); // true: অন্য character সমস্যা না
```

## Variant: শুধু `()` থাকলে counter-ই যথেষ্ট

এক ধরনের বন্ধনী থাকলে stack-এর জায়গায় একটা গোনক-ই কাজ করে, জায়গা O(1)-এ নেমে আসে:

```js
function isBalancedSimple(str) {
  let open = 0;

  for (const ch of str) {
    if (ch === "(") open++;
    else if (ch === ")") open--;

    if (open < 0) return false;  // বন্ধ এসে গেছে খোলার আগে: ")( "
  }

  return open === 0;
}

console.log(isBalancedSimple("(())")); // true
console.log(isBalancedSimple(")("));   // false: সংখ্যা মিললেও ক্রম ভুল
```

`open < 0` চেকটাই এখানে প্রাণ। `")("`-এ শেষে গোনা শূন্য, তবু মাঝপথে বন্ধ বন্ধনী খোলার আগে এসেছিল, সেটা counter ঋণাত্মক হয়েই জানিয়ে দেয়। কিন্তু মনে রাখো, দুই ধরনের বন্ধনী এলেই এই কৌশল শেষ, কারণ counter ক্রম মনে রাখতে পারে না, আবার stack-এই ফিরতে হবে।

## কোড ব্রেকডাউন: isBalanced, লাইনে লাইনে

1. `const pairs = { ")": "(", ... }` : map-টা **বন্ধ থেকে খোলা** দিকে রাখা। বন্ধ বন্ধনী হাতে পেলে এক লাফে জানতে পারি তার জোড়া কোনটা।
2. `for (const ch of str)` : একটাই পাস, character একবারই দেখা হচ্ছে।
3. খোলা হলে `stack.push(ch)` : ভবিষ্যতে যে বন্ধ বন্ধনী আসবে, তার সঙ্গে মেলানোর জন্য অপেক্ষায় রাখা।
4. `stack.pop() !== pairs[ch]` : খালি stack-এ `pop()` দেয় `undefined`, যা কোনো খোলা বন্ধনীর সঙ্গে মেলে না, তাই `")"` দিয়ে শুরু হওয়া string-ও এই লাইনেই ধরা পড়ে। এক পাথরে দুই পাখি।
5. `return stack.length === 0` : সব character মিলেও stack-এ কিছু থাকলে বুঝব কোনো খোলা বন্ধনীর জোড়া আসেনি, যেমন `"((("`।

## Complexity

| দিক | খরচ | কেন |
|-----|------|-----|
| Time | O(n) | প্রতিটা character একবার scan, সর্বোচ্চ একবার push, সর্বোচ্চ একবার pop |
| Space | O(n) | খারাপ সময়ে সবই খোলা বন্ধনী, পুরোটা stack-এ জমে, যেমন `"((((("` |

Time derivation-এ সূক্ষ্ম একটা পয়েন্ট আছে। বাইরে একটা loop, ভেতরে push/pop মিলে মনে হতে পারে অনেক কাজ। কিন্তু প্রতিটা character সারা জীবনে সর্বোচ্চ একবার stack-এ ঢোকে আর একবার বের হয়, তাই মোট stack অপারেশন 2n-এর বেশি হতে পারে না। এই "জীবনকাল ধরে একবার" যুক্তিটা পরে [Monotonic Stack](./monotonic-stack.mdx)-এও ফিরে আসবে। Space-এর বেলায় counter variant মনে রেখো: এক ধরনের বন্ধনী হলে O(1)।

## সাধারণ ভুল আর edge case

**১. শুধু সংখ্যা মেলানো।**
"খোলা কত, বন্ধ কত" গুনে মিলালে `")("` পাস করে যাবে। বন্ধনীর সমস্যা ক্রমের সমস্যা, সংখ্যার না। এই ভুলটা interview-এ প্রথমেই ধরতে চাওয়া হয়।

**২. খালি stack-এ বন্ধ বন্ধনী পাওয়া।**
String-ই যদি `")"` দিয়ে শুরু হয়? `pop()` করলে `undefined` আসে। আমাদের কোডে `undefined !== "("` ধরে false দিয়ে দিচ্ছে, কিন্তু নিজের কোডে এই পথটা সচেতনভাবে ভাবো, নাহলে অন্য implementation-এ বিস্ফোরণ।

**৩. শেষে stack খালি চেক করা ভুলে যাওয়া।**
`"((("` বা `"(()"`: প্রতিটা বন্ধ বন্ধনী মিলেছে ঠিকই, কিন্তু খোলা রয়ে গেছে। Return-এর আগে `stack.length === 0` চেক না করলে এগুলো ভুলভাল true দেবে।

**৪. Pair map-এর দিক উল্টে ফেলা।**
`pairs`-টা বন্ধ → খোলা রাখতে হবে, কারণ বন্ধ বন্ধনী হাতে পেয়ে খোলাটা খোঁজা হয়। উল্টো লিখে তারপর push-এর জায়গায় lookup গুলিয়ে ফেললে পুরো যুক্তি ভেঙে যায়। Map লেখার পর একটা উদাহরণ দিয়ে মিলিয়ে নেওয়া নিরাপদ।

**৫. অন্য character-এ গুলিয়ে যাওয়া।**
আসল প্রয়োগে string-এ বন্ধনী ছাড়াও থাকে: `"(a + b) * [c]"`। এইগুলো উপেক্ষা করতে হবে, নইলে ভেবে বসবে সব অমিল। আমাদের কোডে খোলা-বন্ধ কোনোটাই না হলে চুপচাপ skip, এই নীরবতাটাই ঠিক আচরণ।

## Animation Spec

> **Animation Spec: Bracket Matcher**
>
> - **দৃশ্য:** উপরে string, প্রতিটা character-এর নিচে index; নিচে stack-এর উল্লম্ব স্তূপ; পাশে "অপেক্ষারত জোড়া" কাউন্টার।
> - **ইনপুট:** bracket string টাইপ করা; ready-made উদাহরণ (সঠিক, nested ভুল, খালি-থেকে-বন্ধ, রয়ে-যাওয়া খোলা)।
> - **ধাপ:** খোলা এলে character উজ্জ্বল হয়ে stack-এ নামে; বন্ধ এলে top-এর দিকে একটা রেখা টানা হয়, মিললে দুজন সবুজ হয়ে একসাথে উধাও, না মিললে লাল flash-এ থামা। শেষে খালি stack-এ "balanced" ব্যানার।
> - **নিয়ন্ত্রণ:** step, play, reset; ভুলের ধাপে auto-pause টগল।
> - **লক্ষ্য:** "শেষে খোলা, আগে বন্ধ" মানে stack-ই, আর stack যে ক্রম মনে রাখে, দুটোই চোখে দেখা।

## অনুশীলন

- **সহজ ১:** কাগজে dry run করো `"{[()]}"` আর `"[(])"`: প্রতি ধাপে stack লিখো, দ্বিতীয়টা কোন ধাপে false দেয় চিহ্নিত করো।
- **সহজ ২:** `isBalancedSimple`-এ `open < 0` চেকটা বাদ দিলে কোন input ভুল উত্তর দেবে? উদাহরণ বানাও, তারপর চালিয়ে মিলাও।
- **মাঝারি ১:** `isBalanced` বাড়িয়ে এমন করো যাতে false-এর বদলে **প্রথম ভুলের index** ফেরায়: `"({[]})"` → -1, `"([)]"` → 2। (হিন্ট: stack-এ character না রেখে index রাখো, বা দুটোই।)
- **মাঝারি ২:** এমন একটা function লেখো যা বলে দেয় সর্বনিম্ন কয়টা বন্ধনী উল্টালে string balanced হবে, শুধু `()` ঘরানার, যেমন `"))(("` → 2। (হিন্ট: প্রথমে `isBalancedSimple`-এর মতো scan করো, অতিরিক্ত বন্ধ ফেলে দাও; শেষে যা রইল তার অর্ধেক জোড়া উল্টালেই চলে।)
- **কঠিন:** সবচেয়ে লম্বা valid (balanced) parentheses substring-এর দৈর্ঘ্য বের করো, যেমন `"(()()"` → 4 (LeetCode 32)। (হিন্ট: stack-এ বন্ধনী নয়, **index** রাখো; শুরুতে -1 push করে রাখো, প্রতি মিলানোয় দৈর্ঘ্য = বর্তমান index - stack-এর নতুন top। এটা কেন কাজ করে, dry run করে দেখো।)

## সারসংক্ষেপ

- Nested মানেই stack: শেষে খোলা আগে বন্ধ হবে, এটা LIFO-র সংজ্ঞা।
- খোলায় push, বন্ধে top-এর সঙ্গে মিলিয়ে pop, শেষে stack খালি কিনা দেখো: তিনটা নিয়মেই পুরো সমস্যা।
- Time O(n), কারণ প্রতি character জীবনে একবার ঢোকে, একবার বের হয়।
- এক ধরনের বন্ধনী হলে counter দিয়ে O(1) জায়গায় চলে, তবে `open < 0` চেক ভুললে `")("` ফাঁদে পড়বে।
- সংখ্যা মেলানো না, ক্রম মেলানোই আসল, stack সেই ক্রমটাই মনে রাখে।
