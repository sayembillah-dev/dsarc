## কী শিখব

- কেন "কত সেকেন্ড লাগল" দিয়ে মাপা যায় না

## ধারণা

ধরো, তোমার লেখা code তোমার laptop-এ চলতে নেয় ৩ সেকেন্ড। তোমার বন্ধুর পুরোনো PC-তে সেই একই code নেয় ৮ সেকেন্ড। এবার বলো তো, code-টা আসলে দ্রুত নাকি ধীর?

ব্যাপারটা হলো, seconds দিয়ে algorithm মাপা যায় না। machine বদলালেই সংখ্যাটা পাল্টে যায়। তাই আমরা মাপি অন্য একটা জিনিস: **input বড় হলে কাজের পরিমাণ কত দ্রুত বাড়ে।**

এই বৃদ্ধির হারের ভাষাটার নাম **Big-O**, input `n` বাড়ার সাথে সাথে algorithm-এর গতি কেমন পাল্টায় সেটা বলার একটা উপায়।

## কোড উদাহরণ

```js
// n যত বড়, কাজ তত বেশি; কতটা বেশি সেটাই প্রশ্ন
function printAll(n) {
  for (let i = 0; i < n; i++) {  // n বার চলে, অর্থাৎ কাজ n-এর সমানুপাতিক
    console.log(i);
  }
}
// n = 10 হলে 10 বার; n = 1000 হলে 1000 বার, অর্থাৎ O(n)
```

## কোড ব্রেকডাউন

- Big-O হার্ডওয়্যার-নিরপেক্ষ, এটা শুধু **বৃদ্ধির হার** মাপে।
- আর আমরা সবসময় **worst case** ধরি, মানে সবচেয়ে খারাপ পরিস্থিতিটা।

## Animation Spec

> **Animation Spec: Growth Race**
>
> - **দৃশ্য:** একটা গ্রাফ, x-অক্ষ = n, y-অক্ষ = operations; কয়েকটা curve (O(1), O(n), O(n²)...)।
> - **ইনপুট:** n বাড়ানোর slider।
> - **ধাপ:** n বাড়ালে curve গুলো ভিন্ন গতিতে উঠবে; O(n²) দ্রুত আকাশে উঠবে।
> - **লক্ষ্য:** বৃদ্ধির হারের পার্থক্য চোখে দেখা।
