কোনো algorithm "ভালো" না "খারাপ" তা মাপার উপায় হলো complexity analysis। এই section-টা DSA-র সবচেয়ে গুরুত্বপূর্ণ ভিত্তি, এখানে ভালো করে সময় দাও।

**Section Roadmap:** Complexity কেন, তারপর Time vs Space, তারপর কীভাবে হিসাব, তারপর Asymptotic Notation (Big-O, θ, Ω), শেষে Common Runtimes (Constant থেকে Factorial)।

## এই Chapter-এ যা যা আছে

1. [Complexity কেন লাগে?](./why-complexity.mdx): কেন সেকেন্ড দিয়ে মাপা যায় না, Big-O কী
2. [Time vs Space Complexity](./time-vs-space.mdx): সময় বনাম মেমরি, দুই ধরনের খরচ ও trade-off
3. [কীভাবে Complexity হিসাব করব](./how-to-calculate.mdx): কোড দেখে Big-O বের করার ৩টা সহজ নিয়ম
4. [Asymptotic Notation](./asymptotic-notation.mdx): Big-O, Big-θ, Big-Ω তিনটা notation-এর পার্থক্য
5. [Common Runtimes](./common-runtimes.mdx): O(1) থেকে O(n!) পর্যন্ত সব দরকারি runtime

## সারাংশ

Complexity = বৃদ্ধির হার (হার্ডওয়্যার-নিরপেক্ষ)। Time vs Space trade-off আছে। নিয়ম: ধ্রুবক বাদ, বড় term রাখো, loop গোনো। Big-O (worst) সবচেয়ে ব্যবহৃত। runtime ক্রম: O(1) থেকে O(n!)।
