একই runtime-কে তিন রকম বাক্যে বলা যায়; কোন বাক্যটা কখন, সেটাই এই পাতা।

## কী শিখব

- O, Ω, Θ: upper, lower, tight, তিন রকম bound বলার ভাষা
- c আর n0 দিয়ে formal সংজ্ঞাটা আসলে কী বলছে
- f(n) = 3n + 5 দিয়ে হাতে হাতে bound যাচাই: কোন c-তে টেকে, কোন n0 থেকে
- কেন interview আর বই Big-O দিয়েই ভরসা করে
- 1 থেকে n! পর্যন্ত growth-এর পুরো শ্রেণিবিন্যাস
- limit দেখে এক নিমেষে রায়: কখন Θ, কখন o, কখন ω

## ধারণা

ভাবো তো, হাটে গিয়ে একটা ব্যাগের দরদাম চলছে। তুমি বললে, "সর্বোচ্চ ৫০০, এর বেশি দেবো না।" দোকানদার বলল, "ভাই, ২০০-এর নিচে সম্ভবই না।" আসল দাম এই দুই দেয়ালের মাঝে কোথাও ঠিক হবে। আর যদি দুজনেই ৩৫০ বলে রাজি হয়ে যাও? সেটা tight: উপর থেকেও ৩৫০, নিচ থেকেও ৩৫০।

Algorithm-এর runtime নিয়ে কথা বলতেও ঠিক এই তিন রকম বাক্য লাগে:

- **Big-O (upper bound):** "এর বেশি বাড়বে না।" f(n) = O(g(n)) মানে f, g-এর চেয়ে দ্রুত বাড়ে না (ধীরে হতে পারে, সমানও পারে)।
- **Big-Omega (lower bound):** "এর কম তো লাগবেই।" f(n) = Ω(g(n)) মানে f অন্তত g-এর হারে বাড়ে।
- **Big-Theta (tight bound):** দুই দেয়ালই মিলে গেছে। f(n) = Θ(g(n)) মানে দুটো একই হারে বাড়ে, পার্থক্য শুধু ধ্রুবক গুণকে।

আরেকটু formal করে বললে: f(n) = O(g(n)) বলা যায় যদি এমন একটা ধ্রুবক c > 0 আর একটা সীমা n0 থাকে যাতে **n ≥ n0 হলেই** f(n) ≤ c · g(n)। বাক্যের দুটো অংশই জরুরি: c বলছে "ধ্রুবক গুণক পর্যন্ত মিললেই চলবে", আর n0 বলছে "ছোট n-এর দুষ্টুমি মাফ"। Asymptotic মানেই এই: n যথেষ্ট বড় হলে কী ঘটে, সেটাই বিচার। Ω-তে চিহ্নটা উল্টে যায়: f(n) ≥ c · g(n)। আর Θ মানে দুটোই একসাথে, দুই দিকে দুটো ধ্রুবক c₁ আর c₂ দিয়ে।

ছোট ভাইদেরও নাম জেনে রাখো: **little-o** মানে কঠোরভাবে ধীরে বাড়ে (f/g শূন্যের দিকে যায়), **little-omega** মানে কঠোরভাবে দ্রুত। Big-O-তে সমানও চলে, little-o-তে চলে না। চর্চায় ওরা কম আসে, কিন্তু বইয়ে চোখ পড়লে চিনতে পারবে।

একটা চমক দেখাই: একই f-এর অনেক O-বিবৃতি সত্য হতে পারে। f(n) = 3n + 5 ধরো। এটা O(n), ঠিক। কিন্তু O(n²)-ও ঠিক! O(2^n)-ও! "এর বেশি না" বাক্যটা আলগা, তাই ঢিলা bound-ও সত্য। কিন্তু Θ শুধু একটাই: Θ(n)। এই জন্যই বলা হয়, tight-টাই বলো; ঢিলা upper bound সত্য হলেও কারও কাজে আসে না। [আগের পাতায়](./how-to-calculate.mdx) যেভাবে ছোট term ফেলে ফেলে n²-এ পৌঁছেছিলে, সেটা আসলে এই tight bound-টাই খুঁজে বের করা ছিল।

## ধাপে ধাপে: c আর n0 খোঁজা

দাবি: f(n) = 3n + 5 হলো O(n)। প্রমাণ মানে এক জোড়া (c, n0) দেখানো যাতে n ≥ n0 হলে 3n + 5 ≤ c · n হয়।

চেষ্টা ১: c = 2। শর্তটা দাঁড়ায় 3n + 5 ≤ 2n, মানে n ≤ -5। কখনোই না! c = 2 দিয়ে bound টেকে না, কারণ f-এ n-এর সহগ 3, যা 2-এর চেয়ে বড়।

চেষ্টা ২: c = 4। শর্ত 3n + 5 ≤ 4n, মানে n ≥ 5। ব্যাস, n0 = 5 পেয়ে গেলাম।

সংখ্যা দিয়ে যাচাই করো:

| n | f(n) = 3n + 5 | 2n | f ≤ 2n? | 4n | f ≤ 4n? |
|---|---------------|-----|---------|-----|---------|
| 1 | 8 | 2 | না | 4 | না |
| 2 | 11 | 4 | না | 8 | না |
| 5 | 20 | 10 | না | 20 | হ্যাঁ (সমান) |
| 10 | 35 | 20 | না | 40 | হ্যাঁ |
| 100 | 305 | 200 | না | 400 | হ্যাঁ |
| 1000 | 3005 | 2000 | না | 4000 | হ্যাঁ |

টেবিলেই দেখা যাচ্ছে: c = 2-এর কলাম কোনোদিন "হ্যাঁ" বলে না (2n সবসময় 3n + 5-এর নিচে), আর c = 4-এর কলাম n = 5 থেকে চিরকাল "হ্যাঁ"। সুতরাং সাক্ষী জোড়া (c = 4, n0 = 5): **3n + 5 = O(n) প্রমাণিত।**

Ω-এর দিকটা আরও সহজ: 3n + 5 ≥ 3n সব n-এ, তাই (c = 3, n0 = 1) দিয়ে 3n + 5 = Ω(n)। দুই দিক মিলে গেল: **3n + 5 = Θ(n)**। আর সাধারণত আমরা এইটাই বলি।

## কোড: bound যাচাইয়ের যন্ত্র

"কোনো একটা n0 থেকে bound আর ভাঙে না", এই বাক্যটাই প্রোগ্রামে ফেলি। `holdsFrom` খুঁজে দেয় সবচেয়ে ছোট n0, যেখান থেকে (200 পর্যন্ত স্ক্যান করে) f(n) ≤ c · g(n) সর্বত্র টিকে যায়; না পেলে `firstBreak` বলে দেয় প্রথম কোথায় ভাঙে:

```js
function holdsFrom(f, g, c, maxN = 200) {
  for (let n0 = 1; n0 <= maxN; n0++) {
    let ok = true;
    for (let n = n0; n <= maxN; n++) {
      if (f(n) > c * g(n)) { ok = false; break; } // ভাঙলেই এই n0 অযোগ্য
    }
    if (ok) return n0;   // এই n0 থেকে শেষ পর্যন্ত টিকে গেছে
  }
  return null;           // maxN-এর ভেতরে কোনো n0 পাওয়া গেল না
}

function firstBreak(f, g, c, maxN = 200) {
  for (let n = 1; n <= maxN; n++) {
    if (f(n) > c * g(n)) return n;   // প্রথম যেখানে bound ভাঙে
  }
  return null;
}

const tests = [
  { name: "3n + 5",  f: n => 3 * n + 5,      g: n => n,      gName: "n",   c: 4 },
  { name: "3n + 5",  f: n => 3 * n + 5,      g: n => n,      gName: "n",   c: 2 },
  { name: "n^2+10n", f: n => n * n + 10 * n, g: n => n * n,  gName: "n^2", c: 2 },
  { name: "2^n",     f: n => 2 ** n,         g: n => n ** 3, gName: "n^3", c: 1000 },
];

const pad = (s, w) => String(s).padEnd(w);
console.log(pad("f(n)", 10) + pad("g(n)", 6) + pad("c", 6) + "রায়");
console.log("-".repeat(52));

for (const t of tests) {
  const n0 = holdsFrom(t.f, t.g, t.c);
  let verdict;
  if (n0 !== null) {
    verdict = "টিকে আছে: n0 = " + n0 + " (n = " + n0 + "..200 সর্বত্র মেনেছে)";
  } else {
    verdict = "ব্যর্থ: n = " + firstBreak(t.f, t.g, t.c) + "-এ প্রথম ভাঙে";
  }
  console.log(pad(t.name, 10) + pad(t.gName, 6) + pad(t.c, 6) + verdict);
}
```

চারটা সারির গল্প আলাদা আলাদা:

- প্রথম সারিতে n0 = 5 বেরোবে: আমাদের হাতের হিসাবের সাথে হুবহু মিল।
- দ্বিতীয়টায় c = 2 অপুর্যাপ: প্রথম ঘরেই ভাঙে, কখনো টেকে না।
- তৃতীয়টায় n² + 10n ≤ 2n² মানে n ≥ 10, তাই n0 = 10।
- চতুর্থটা শিক্ষণীয়: c = 1000 দিলেও 2^n-কে n³ দিয়ে বাঁধা যায় না। n = 23 পর্যন্ত ঠিকই মানে, কিন্তু n = 24-এ প্রথম ভাঙে, আর এরপর আর ফেরে না। কোনো ধ্রুবক c-ই exponential-কে বহুপদীর ফাঁদে আটকাতে পারে না; 200-এর বদলে 2000 পর্যন্ত স্ক্যান করলেও উত্তর একই থাকবে, শুধু ভাঙনটা দেরিতে আসবে।

মনে রাখো, এই যন্ত্র প্রমাণ নয়, শক্ত ইঙ্গিত: "200 পর্যন্ত টিকেছে" বলে "অসীম পর্যন্ত টিকবে" নিশ্চিত হয় না। কিন্তু প্রার্থী c বাছাই করার আগে ভুল দাবি বাদ দেওয়ার জন্য এটা দারুণ ছাঁকনি।

## ভ্যারিয়েন্ট ১: পাঁচটা notation এক টেবিলে

| Notation | মানে এক লাইনে | দরদামের ভাষায় |
|----------|----------------|-----------------|
| f = O(g) | f সর্বোচ্চ g-এর হারে বাড়ে (সমান চলে) | "এর বেশি না" |
| f = Ω(g) | f অন্তত g-এর হারে বাড়ে | "এর কমও না" |
| f = Θ(g) | দুটোই একই হার, ধ্রুবক পর্যন্ত | "ঠিক এতটাই" |
| f = o(g) | f কঠোরভাবে ধীরে (ratio → 0) | "অনেক কমই" |
| f = ω(g) | f কঠোরভাবে দ্রুত (ratio → ∞) | "অনেক বেশিই" |

মনে রাখার সহজ ছাঁচ: সংখ্যার তুলনার সাথে মেলাও। O হলো **≤**-এর আত্মীয় (f সর্বোচ্চ g পর্যন্ত), Ω হলো **≥**-এর, Θ হলো **=**-এর, o হলো কঠোর ছোট-চিহ্নের (strictly less), আর ω হলো কঠোর বড়-চিহ্নের (strictly greater)। ছাঁচটা কাজেও লাগে: যেমন ৫ ≤ ৫ সত্য, তেমনি O-তে সমানও ঢুকে যায়; আর কঠোর ছোট যেমন সমানকে বাদ দেয়, o-ও তাই।

পরীক্ষায় মাঝে মাঝে জিজ্ঞেস হয় n = o(n²) কিনা। হ্যাঁ: n / n² = 1/n শূন্যের দিকে যায়। কিন্তু n = o(n) নয়, ratio থেমে যায় 1-এ।

## ভ্যারিয়েন্ট ২: কেন interview-তে Big-O-ই রাজা

কারণ Big-O দিয়ে **worst case-এর গ্যারান্টি** বলা যায়, আর সিস্টেম ডিজাইনে সেটাই দরকার: "ইনপুট যত খারাপই হোক, এর বেশি লাগবে না।" Ω দিয়ে সেরা দিনের কথা বলা যায়, কিন্তু সেরা দিনের ভরসায় কেউ সার্ভার কেনে না। [কেন Complexity](./why-complexity.mdx)-এর পুরো যুক্তিটাই এই গ্যারান্টির ওপর দাঁড়িয়ে।

একটা সূক্ষ্ম কথা: interview-র ভাষায় "এটা O(n)" বললে আসলে বোঝানো হয় Θ(n), tight bound-টাই। ঢিলা বলে লাভ নেই, যতটা পারো tight বলো। আর মনে রাখো, Big-O আর "worst case" সমার্থক নয়; এই ভুলটা নিচে আলাদা করে ভাঙছি।

## ভ্যারিয়েন্ট ৩: growth-এর শ্রেণিবিন্যাস

ছোট থেকে বড় সাজালে:

```
1 < log n < n < n log n < n^2 < 2^n < n!
```

সংখ্যা দিলে ছবিটা পরিষ্কার:

| f(n) | n = 10 | n = 100 | n = 1000 |
|------|--------|---------|----------|
| 1 | 1 | 1 | 1 |
| log₂ n | 3.3 | 6.6 | 10 |
| n | 10 | 100 | 1000 |
| n log₂ n | 33 | 664 | 9966 |
| n² | 100 | 10000 | 1000000 |
| 2^n | 1024 | 1.27 × 10^30 | 1.07 × 10^301 |
| n! | 3628800 | 9.3 × 10^157 | 4.02 × 10^2567 |

n মাত্র 1000-এ গেলে শেষ দুটো গোনার নাগালের বাইরে চলে যায়। এই চেইনটা মুখস্থ করার নয়, বোঝার: প্রতি ধাপে আগেরটা ধুলো হয়ে যায়। প্রতিটা runtime-এর আলাদা আলোচনা [Common Runtimes](./common-runtimes.mdx)-এ।

## ভ্যারিয়েন্ট ৪: limit দিয়ে এক নিমেষে রায়

প্রতিবার সাক্ষী জোড়া (c, n0) বানানো ঝামেলার। শর্টকাট আছে: দুটো ফাংশনের **অনুপাত কোথায় যাচ্ছে** দেখো, n যখন অসীমের দিকে ছুটে:

| lim (n → ∞) f(n) / g(n) | রায় | মানে |
|---|---|---|
| ধনাত্মক ধ্রুবক c | f = Θ(g) | দুটো একই হারে বাড়ে |
| 0 | f = o(g), অবশ্যই O(g)-ও | f ধীরে বাড়ে |
| ∞ | f = ω(g), অবশ্যই Ω(g)-ও | f দ্রুত বাড়ে |

তিনটা পরিচিত মুখ দিয়ে চালিয়ে দেখো:

- (n² + 10n) / n² = 1 + 10/n, থামে 1-এ: **n² + 10n = Θ(n²)**। আমাদের হাতের (c = 2, n0 = 10) হিসাবের সাথে হুবহু মিল।
- n / n² = 1 / n, যায় 0-এ: **n = o(n²)**।
- 2^n / n³ অসীমের দিকে ছুটে: **2^n = ω(n³)**। ওপরের যন্ত্র যে c = 1000 দিয়েও হেরেছিল, এটাই তার কারণ।

দুটো সতর্কতা। এক, limit যদি থাকেই না (ফাংশন ওঠানামা করতে থাকলে), এই পদ্ধতি চুপ করে যায়; তখন আবার সংজ্ঞায়, মানে সাক্ষী জোড়ায় ফিরতে হবে। দুই, অনুপাত ধ্রুবকে থামলেই দুটো একই ঘরের, ধ্রুবকটা যত বড়ই হোক: 100n² + 10n + 1 আর n²-এর অনুপাত থামে 100-এ, তাই ঘর একই Θ(n²)। "শত গুণ বড়" বলেও class এক, কারণ Big-O-র চোখে ধ্রুবক গুণক অন্ধ।

## কোড ব্রেকডাউন: holdsFrom যন্ত্রটা

1. `holdsFrom(f, g, c, maxN)` চারটা জিনিস নেয়: ফাংশন দুটো, ধ্রুবক c, আর কতদূর স্ক্যান করবে। maxN = 200 মানে "আমি 200 পর্যন্ত দেখে সিদ্ধান্ত নিচ্ছি"।
2. বাইরের লুপ প্রার্থী n0 ঘোরায় 1 থেকে 200 পর্যন্ত।
3. ভেতরের লুপ চেক করে, সেই n0 থেকে 200 পর্যন্ত সর্বত্র f(n) ≤ c · g(n) কিনা।
4. এক জায়গায় ভাঙলেই `break`: এই প্রার্থী বাদ, পরের n0 দেখো।
5. সব মেনে গেলে সেই n0-ই ফেরত: সবচেয়ে ছোট সাক্ষী।
6. কেউ না জিতলে `null`: এই c-তে (অন্তত 200-এর ভেতরে) bound টেকে না।
7. `firstBreak` উল্টো দিকের যন্ত্র: প্রথম কোন n-এ bound ভাঙে, সেটা বলে দেয়; ব্যর্থতার নমুনা দেখানোর জন্য।
8. `tests` অ্যারের প্রতিটা সারি একটা দাবি: ফাংশন, দাবিকৃত g, আর c। তৃতীয় সারিতে c = 2 কেন? কারণ n² + 10n ≤ 2n² ⇔ n ≥ 10, তাই 2 যথেষ্ট, 1 নয়।
9. চতুর্থ সারিতে c = 1000-ও ব্যর্থ: 200 পর্যন্ত স্ক্যানে কোনো n0 টেকে না, কারণ 2^n শেষ পর্যন্ত সব বহুপদীকে ছাড়িয়ে যায়।

## Complexity

পাতার নিজের উদাহরণগুলো ধরে হিসাবটা পাকা করি:

- **3n + 5:** O-দিকে (c = 4, n0 = 5), Ω-দিকে (c = 3, n0 = 1); দুটো মিলে Θ(n)। অনুপাতের ভাষায়: (3n + 5) / n ধ্রুবক 3-এ থেমে যায়, তাই দুটো একই হারে বাড়ে।
- **n² + 10n:** O-দিকে (c = 2, n0 = 10), Ω-দিকে (c = 1, n0 = 1), যেহেতু n² + 10n ≥ n² সবসময়; মিলে Θ(n²)।
- **2^n:** নিজের সাথে Θ(2^n); কিন্তু কোনো বহুপদী n^k-এর O নয়, কারণ অনুপাত 2^n / n³ অসীমের দিকে যায়, কোনো c-ই আটকাতে পারে না। আমাদের যন্ত্র চতুর্থ সারিতে ঠিক এটাই দেখাল।
- **যন্ত্রটা নিজে:** `holdsFrom`-এ বাইরে maxN-টা প্রার্থী, ভেতরে সবচেয়ে খারাপে maxN-টা চেক, তাই O(maxN²) time আর O(1) space। maxN = 200 ধ্রুবক রাখায় বাস্তবে এটা একটা ছোট নির্দিষ্ট সংখ্যক কাজ, চোখ বুজে চালানো যায়।

Time বনাম space-এর এই যুগল হিসাবের অভ্যাস [Time vs Space](./time-vs-space.mdx)-এ আছে।

## সাধারণ ভুল আর edge case

**১. "O(n) সবসময় ভালো" ধরে নেওয়া।**
Big-O শুধু বড় n-এর কথা বলে। 100n আর n²-এর লড়াইয়ে n = 100 পর্যন্ত n²-ই সস্তা (n = 50-এ 2500 বনাম 5000)। ছোট ইনপুটে ধ্রুবকই জেতে; asymptotic হিসাব n বড় হলে কাজ করে, ছোটে নয়।

**২. O(2n) লিখে ফেলা।**
ধ্রুবক সহগ Big-O-তে রাখা হয় না: O(2n), O(n + 500), সবই O(n)। লিখলে ফল ভুল হয় না, কিন্তু দেখায় সংজ্ঞাটা পাকা হয়নি; ধ্রুবক গিলে ফেলাটাই notation-এর কাজ।

**৩. Big-O আর worst case-কে সমার্থক ভাবা।**
দুটো আলাদা অক্ষ: Big-O হলো bound বলার ভাষা, worst case হলো কোন ইনপুট নিয়ে কথা বলছি। Best case-ও O-তে বলা যায়: linear search-এর best case O(1), worst case O(n)। ভাষা আর পরিস্থিতি গুলিয়ো না।

**৪. Ω আর Θ গুলিয়ে ফেলা।**
Ω শুধু নিচের দেয়াল: 3n + 5 = Ω(1) বললেও সত্য হয় (অন্তত ধ্রুবক সময় তো লাগবেই)! কিন্তু সেটা কারও কাজের কথা নয়। Θ বলতে দুই দেয়ালই লাগবে। "অন্তত এত" আর "ঠিক এত" সম্পূর্ণ আলাদা দাবি।

**৫. f = O(g) মানে f ধীরে বাড়ে বলে ধরা।**
O-তে **সমানও ঢুকে**: 3n + 5 = O(n), অথচ দুটোই linear, কেউ কারও থেকে ধীরে না। "কঠোরভাবে ধীরে" বলতে হলে little-o লাগে। এই সমান-ও-চলে ব্যাপারটাই Θ-কে দরকারি করে তোলে।

## অনুশীলন

- **সহজ ১:** 7n + 3 = O(n) প্রমাণের জন্য এক জোড়া (c, n0) দাও। হিন্ট: c = 8 নাও; 7n + 3 ≤ 8n মানে n ≥ 3।
- **সহজ ২:** 5n² = O(n³) সত্যি কিনা যুক্তি দাও। হিন্ট: n ≥ 5 হলে 5n² ≤ n³; সাক্ষী (c = 1, n0 = 5)।
- **মাঝারি ১:** প্রমাণ করো: f = Θ(g) হলে f = O(g) এবং f = Ω(g) দুটোই। হিন্ট: Θ-এর সংজ্ঞার দুই পাশ (c₁ · g ≤ f ≤ c₂ · g) আলাদা করলেই দুটো সংজ্ঞা ফুরিয়ে পাবে।
- **মাঝারি ২:** Climbing Stairs (LeetCode 70)। সরাসরি recursion-এ O(2^n), memo দিলে O(n); দুটো bound-ই O-ভাষায় লিখে বলো কোনটা tight। হিন্ট: প্রতি ধাপে দুটো ডাক, tree-র গভীরতা n; memo-র কথা [Memoization](../recursion/memoization.mdx)-এ পড়ে এসো।
- **কঠিন:** প্রমাণ করো 2^n = O(n!), কিন্তু n! = O(2^n) নয়। হিন্ট: n ≥ 4 থেকে সরাসরি 2^n ≤ n! কাজ করে (c = 1, n0 = 4); উল্টোদিকে অনুপাত n! / 2^n প্রতি ধাপে (n + 1) / 2 গুণ বাড়ে, কোনো ধ্রুবকে থামে না।

## সারসংক্ষেপ

- O = "সর্বোচ্চ", Ω = "অন্তত", Θ = দুটো মিলে "ঠিক এত"।
- প্রমাণ মানে সাক্ষী: একটা c আর একটা n0 দেখাও, যেখান থেকে bound আর ভাঙে না।
- একই f-এর ঢিলা O-বিবৃতি অনেক সত্য হতে পারে; বলার সময় tight-টাই বলো, সেটাই Θ।
- Interview-তে Big-O রাজা, কারণ worst-case গ্যারান্টিই planning-এর ভিত্তি; কিন্তু Big-O আর worst case সমার্থক নয়।
- শ্রেণিবিন্যাস মাথায় রাখো: 1 < log n < n < n log n < n² < 2^n < n!।
- Limit পদ্ধতিতে অনুপাতের গন্তব্যই রায়: ধ্রুবকে থামলে Θ, শূন্যে গেলে o, অসীমে গেলে ω।
