## কী শিখব

- FIFO (First In, First Out) নীতি, আর stack থেকে এটা কোথায় আলাদা
- Naive queue (`shift()` দিয়ে) কেন প্রতি dequeue-এ O(n), সরানোর পুরো হিসাব
- দুই pointer (front/back) দিয়ে এমন queue যেখানে সব অপারেশন O(1)
- দুই version-এর পাশাপাশি dry run, পার্থক্য চোখে দেখা
- Queue আসলে কোথায় কোথায় লাগে: BFS, printer, scheduling
- Interview-তে ঘোরা ভুলগুলো

## ধারণা

টিকিট কাউন্টারের লাইনটা ভাবো। যে আগে দাঁড়িয়েছে সে-ই আগে টিকিট পাবে। নতুন কেউ এলে লাইনের একদম পেছনে দাঁড়াবে, আর টিকিট বের হবে লাইনের একদম সামনে থেকে। মাঝখানে ঢোকা বা বের হওয়ার সুযোগ নেই।

এটাই Queue, নীতির নাম **FIFO (First In, First Out)**: যে আগে আসে, সে আগে যায়। Stack-এর সঙ্গে পার্থক্যটা এক লাইনে: stack-এ ঢোকা-বেরা **একই প্রান্তে**, queue-তে **দুই প্রান্তে**, ঢোকে back দিয়ে, বের হয় front দিয়ে।

```text
front ↓                    ↓ back
      [ A ][ B ][ C ][ D ]
   বের হয় এখানে →      ← ঢোকে এখানে
```

কোথায় লাগে? Printer queue-তে যে ডকুমেন্ট আগে পাঠিয়েছ সেটাই আগে ছাপে। Call center-এ যে আগে ফোন করেছে তার কল আগে ধরা হয়। আর সবচেয়ে বড় কথা, [BFS](../graphs/bfs.mdx)-এর পুরো ইঞ্জিনটাই একটা queue: level ধরে ঘোরার ক্ষমতা ওই FIFO ক্রম থেকেই আসে। তাই queue ঠকালে graph-ও ঠকবে।

## সমস্যা: সহজ রাস্তাটা আসলে ফাঁদ

সবচেয়ে সহজে queue বানাতে গেলে array-ই মাথায় আসে:

```js
const q = [];
q.push("A");      // পেছনে ঢোকাল
q.push("B");
q.shift();        // "A": সামনে থেকে বের করল
```

কাজও ঠিকঠাক করে। তাহলে দুর্ভাগ্য কোথায়? মনে করো [Array Operations](../arrays/array-operations.mdx)-এর সেই সূত্র: **খরচ = কতজনকে সরাতে হচ্ছে**। `shift()` মানে সামনেরটা বের হয়ে গেলে বাকি **সবাইকে** এক ঘর বামে টানা। ১০ লাখ উপাদানের queue-তে প্রতি dequeue মানে প্রায় ১০ লাখ সরানো।

| queue-এর অবস্থা | `shift()` এর পর সরানো |
|------------------|------------------------|
| `[A, B, C, D]` | B, C, D বামে: ৩ সরানো |
| `[B, C, D]` | C, D বামে: ২ সরানো |
| `[C, D]` | D বামে: ১ সরানো |

n-টা dequeue-এ মোট সরানো প্রায় n + (n-1) + ... + 1 = n(n+1)/2, মানে **O(n²)**। Queue মনে করে বসে আছি, আসলে চালাচ্ছি চৌকো খরচের কিছু। BFS-এ লক্ষ লক্ষ node ঢুকলে এই পার্থক্যই ঘুম হারাম করবে।

## সমাধান: কাউকে সরাবো না, pointer সরাবো

চালাকি এখানেই: লাইনের মানুষদের সরানোর দরকার নেই, শুধু "সামনে এখন কে" সেটার দিকে একটা আঙুল (front pointer) এগিয়ে দিলেই চলে। আর পেছনে কোথায় নতুনজন দাঁড়াবে, তার জন্য আরেকটা আঙুল (back pointer)।

Dry run দেখো: `enqueue(A)`, `enqueue(B)`, `enqueue(C)`, `dequeue()`, `enqueue(D)`:

| ধাপ | অপারেশন | front | back | ভেতরের তালিকা (ফেলে দেওয়া ঘর ধূসর) | ফেরত |
|-----|---------|-------|------|-------------------------------|-------|
| শুরু | - | 0 | 0 | `{ }` | - |
| 1 | enqueue(A) | 0 | 1 | `{0: A}` | - |
| 2 | enqueue(B) | 0 | 2 | `{0: A, 1: B}` | - |
| 3 | enqueue(C) | 0 | 3 | `{0: A, 1: B, 2: C}` | - |
| 4 | dequeue() | 1 | 3 | `{1: B, 2: C}` (0 মুছে গেল) | A |
| 5 | enqueue(D) | 1 | 4 | `{1: B, 2: C, 3: D}` | - |

খেয়াল করো, ধাপ ৪-এ B আর C **এক ইঞ্চিও নড়েনি**, শুধু front 0 থেকে 1 হয়েছে। এটাই পুরো কৌশল: সরানো বন্ধ, গোনা চালু।

## কোড: দুই pointer-এর দক্ষ Queue

```js
class Queue {
  constructor() {
    this.items = {};   // index → মান
    this.front = 0;    // সামনের জন কোন index-এ
    this.back = 0;     // পরের জন কোন index-এ দাঁড়াবে
  }

  enqueue(x) {
    this.items[this.back] = x;
    this.back++;
  }

  dequeue() {
    if (this.isEmpty()) return undefined;
    const x = this.items[this.front];
    delete this.items[this.front];  // ঘর মুছে দাও, memory জমবে না
    this.front++;
    return x;
  }

  peek() {
    if (this.isEmpty()) return undefined;
    return this.items[this.front];
  }

  isEmpty() {
    return this.back === this.front;
  }

  size() {
    return this.back - this.front;
  }
}

const q = new Queue();
q.enqueue("A");
q.enqueue("B");
q.enqueue("C");
console.log(q.dequeue()); // A: আগে এসেছিল, আগে গেল
console.log(q.dequeue()); // B
console.log(q.peek());    // C
console.log(q.size());    // 1
```

## কোড ব্রেকডাউন: লাইনে লাইনে

1. `this.items = {}` : array না, object। কারণ array-তে সামনের ঘর ফেললে index-এর হিসাব গুলে যায়, object-এ index নিজেরাই চাবি, ফাঁকা রেখে এগোনো যায়।
2. `enqueue`-এ `this.items[this.back] = x; this.back++` : নতুনজন back-এর জায়গায় দাঁড়াল, back এক ঘর পিছিয়ে পরের জনের জন্য জায়গা রাখল। দুই লাইন, শূন্য সরানো, O(1)।
3. `dequeue`-এ আগে `isEmpty()` : খালি queue-তে সামনের জন নেই, স্পষ্টভাবে `undefined` ফেরাই, নইলে অদ্ভুত ডেটা নিয়ে এগিয়ে যাবে।
4. `delete this.items[this.front]` : এই লাইনটা অনেকেই বাদ দেয়। বাদ দিলে dequeue করা উপাদান object-এ চিরকাল জমে থাকে, লক্ষ বার dequeue-তে memory ফুলে যাবে।
5. `isEmpty()` তে `back === front` : দুই আঙুল একই জায়গায় মিলে গেলে লাইনে আর কেউ নেই। আর `size()` হলো দুটোর দূরত্ব, `back - front`।

## Complexity

| অপারেশন | Naive (`shift`) | Pointer version | কেন পার্থক্য |
|---------|-----------------|-----------------|--------------|
| enqueue | O(1) | O(1) | দুটোতেই পেছনে বসানো, সরানো নেই |
| dequeue | O(n) | O(1) | `shift` সবাইকে টানে; pointer শুধু সংখ্যা বাড়ায় |
| peek | O(1) | O(1) | দুটোতেই সরাসরি পড়া |
| size | O(1) | O(1) | length / দুই pointer-এর বিয়োগফল |

Derivation-টা এবার একদম পরিষ্কার। `shift()`-এর খরচ উপাদানসংখ্যার সঙ্গে বাড়ে, কারণ কাজ হলো "সবাইকে সরানো"। Pointer version-এ dequeue-র কাজ তিনটাই: একটা পড়া, একটা delete, একটা যোগ, কোনোটাই n-এর উপর নির্ভর করে না, তাই O(1)। আর সার্বিক হিসাবে n-টা অপারেশন naive-তে O(n²), pointer version-এ O(n): যখনই তুমি loop-এর ভেতরে dequeue করবে (BFS-এ যেটাই হয়), এই ফারাকটাই নির্ণায়ক।

পরিশীলিত সিস্টেমে একই ধারণা **circular buffer** দিয়ে করা হয়: fixed-size array, front/back শেষে গিয়ে আবার গোড়ায় ঘুরে আসে (modulo দিয়ে)। সেটা memory-ও ঠিক রাখে, আমাদের object version যেখানে front ক্রমশ বাড়তে থাকে। কঠিন অনুশীলনে সেটাই বানাবে।

## সাধারণ ভুল আর edge case

**১. `shift()` দিয়ে queue চালানো, "এক লাইনে তো হচ্ছে"।**
এক লাইন মানে সস্তা না। `shift()` ভেতরে থেকে লুপ, তাই লক্ষাধিক dequeue-র কাজে এটা O(n²)। Interview-এ queue বললেই দুই pointer-এর কথা মাথায় আনো।

**২. খালি queue-তে `dequeue()`/`peek()`।**
নিরবে `undefined`। সেটা নিয়ে এগিয়ে গেলে পরে টেরও পাবে না কোথা থেকে এল। অপারেশনের আগে `isEmpty()` চেক, অথবা ফেরত মান ব্যবহারের আগে যাচাই।

**৩. Pointer version-এ `delete` ভুলে যাওয়া।**
dequeue করলেও object-এ পুরনো চাবি জমে থাকে। ছোট প্রোগ্রামে টের পাবে না, সারাদিন চলা সার্ভারে memory ফুলে যাবে। বের করেছি মানে মুছেই দিই।

**৪. `size()` হিসাব ভুল করা।**
Object version-এ `items.length` বলে কিছু নেই (`Object.keys(items).length` O(n), আর delete ভুললে ভুলও)। সঠিক সূত্র `back - front`, কারণ দুই pointer-এর দূরত্বই লাইনে কেউ কেউ আছে।

**৫. Queue আর stack-এর প্রান্ত গুলিয়ে ফেলা।**
দুটোই তো array দিয়ে বানানো যায়, কিন্তু stack-এ ঢোকা-বেরা এক প্রান্তে, queue-তে দুই প্রান্তে। চাপে পড়ে `push`/`pop` দিয়ে queue বানিয়ে ফেললে পাবে LIFO, ফলাফল উল্টো যাবে, BFS হয়ে যাবে DFS। পুরো তুলনাটা [Stack vs Queue](./stack-vs-queue.mdx)-এ।

## অনুশীলন

- **সহজ ১:** কাগজে dry run: খালি queue-তে `enqueue(5)`, `enqueue(8)`, `dequeue()`, `enqueue(2)`, `peek()`, `dequeue()`। প্রতি ধাপে front, back আর ফেরত মান লিখো।
- **সহজ ২:** বন্ধুকে বোঝাও (লিখে): `shift()` দিয়ে বানানো queue আর pointer দিয়ে বানানো queue বাইরে থেকে একই দেখায়, তাহলে পার্থক্য কোথায়, আর কখন সেটা প্রাণঘাতী হয়?
- **মাঝারি ১:** Recent counter বানাও: `ping(t)` ডাকলে সেকেন্ড t-এর রেকর্ড জমে, আর ফেরত দেয় `[t - 3000, t]` সময়ের মধ্যে কতবার ping এসেছে। (হিন্ট: প্রতি ping enqueue, আর window-এর বাইরের পুরনোগুলো সামনে থেকে dequeue করে ফেলো। LeetCode 933।)
- **মাঝারি ২:** দুটো stack দিয়ে queue বানাও, যেখানে enqueue আর dequeue দুটোই amortized O(1)। (হিন্ট: একটা stack-এ ঢোকাও; বের করার সময় দ্বিতীয়টা খালি হলে প্রথমটা থেকে সব উল্টে আনো। পুরো বিশ্লেষণ [Stack vs Queue](./stack-vs-queue.mdx)-এ আছে, আগে নিজে চেষ্টা করো।)
- **কঠিন:** Fixed-size array দিয়ে circular queue বানাও: `enqueue`, `dequeue`, `isFull`, `isEmpty`, সব O(1), জায়গা এক ইঞ্চিও নষ্ট না। (হিন্ট: index শেষে গেলে modulo দিয়ে গোড়ায় ফেরাও; "খালি" আর "ভরা" আলাদা করতে হয় size রাখো নয়তো একটা ঘর ফাঁকা রাখো, কেন, ভেবে দেখো।)

## সারসংক্ষেপ

- Queue = FIFO: ঢোকে back দিয়ে, বের হয় front দিয়ে, দুই প্রান্তের খেলা।
- `shift()` দিয়ে queue মানে প্রতি dequeue-তে সবাই সরে: O(n) প্রতি বার, মোটে O(n²) ফাঁদ।
- দুই pointer (front/back) রাখলে কেউ সরে না, সব অপারেশন O(1)।
- Dequeue করা ঘর `delete` করতে ভুলো না, memory জমা ফাঁদ।
- BFS, printer, scheduling: যেখানে "আগে আসা আগে যাবে" সেখানেই queue, আর সেখানেই দক্ষ version-ই একমাত্র রাস্তা।
