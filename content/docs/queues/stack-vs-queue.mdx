## কী শিখব

- দুই নীতির পার্থক্য এক লাইনে, আর সেখান থেকে সব পার্থক্যের উৎস
- একই input দুই কাঠামোয় ঢোকালে আউটপুট কেন উল্টো আসে: পুরো dry run
- কখন কোনটা নেবে, সিদ্ধান্তের সূত্র
- Classic interview প্রশ্ন: দুই stack দিয়ে queue, dry run আর amortized হিসাবসহ
- ভুলগুলো, যেখানে দুটো গুলিয়ে যায়

## ধারণা

দুটোকেই তো আলাদা আলাদা দেখে এসেছ। এবার পাশাপাশি রাখি। পার্থক্যটা আসলে একটাই প্রশ্নে: **জিনিসটা কোন প্রান্ত থেকে বের হয়?**

- Stack: যে প্রান্তে ঢোকে, সেই প্রান্ত থেকেই বের হয়। ফল: শেষে ঢোকা আগে যায় (LIFO)।
- Queue: ঢোকে এক প্রান্তে, বের হয় উল্টো প্রান্তে। ফল: আগে ঢোকা আগে যায় (FIFO)।

এই এক পয়েন্ট থেকেই বেরিয়ে আসে সব: stack-এ রান্নার খেলার শেষ থালাটাই আগে ধুয়ে ফেলা হয়, queue-তে টিকিট লাইনের প্রথম জনটাই আগে যায়। কাঠামো বাছাইয়ের সিদ্ধান্তও এখানেই: তোমার সমস্যায় "সবচেয়ে সাম্প্রতিকটা আগে" লাগলে stack, "সবচেয়ে পুরনোটা আগে" লাগলে queue।

| দিক | Stack | Queue |
|-----|-------|-------|
| নীতি | LIFO | FIFO |
| ঢোকা | push, top-এ | enqueue, back-এ |
| বের হওয়া | pop, top থেকে | dequeue, front থেকে |
| প্রান্ত | একটাই | দুটো |
| ক্রমের ওপর প্রভাব | উল্টে দেয় | অক্ষত রাখে |
| আদর্শ প্রয়োগ | undo, bracket, DFS, call stack | scheduling, BFS, buffering |

## Dry run: একই input, দুই ভাগ্য

Input তিনটাই: `1, 2, 3`। দুই কাঠামোয় একই ক্রমে ঢোকাও, তারপর খালি না হওয়া পর্যন্ত বের করো:

| ধাপ | Stack-এর অবস্থা (ডানে top) | Queue-এর অবস্থা (বামে front) |
|-----|------------------------------|-------------------------------|
| সব ঢোকানোর পর | `[1, 2, 3]` | `[1, 2, 3]` |
| ১ম বের হওয়া | 3 | 1 |
| ২য় বের হওয়া | 2 | 2 |
| ৩য় বের হওয়া | 1 | 3 |
| পুরো আউটপুট | **3, 2, 1** (উল্টো) | **1, 2, 3** (অক্ষত) |

ভেতরে দুটোর তালিকা একই দেখাচ্ছিল, তবু আউটপুট উল্টো। কারণ পার্থক্য সংরক্ষণে না, **বের হওয়ার দরজায়**। Stack-এর দরজা যেখানে ঢোকা, queue-র দরজা ঠিক উল্টো পাশে। এই টেবিলটা ভালো করে দেখলে দুটো আর কখনও গুলবে না।

## কোড: পাশাপাশি demo

```js
const input = [1, 2, 3];
const stack = [];
const queue = [];

for (const x of input) {
  stack.push(x);      // stack-এ উপরে জমা হচ্ছে
  queue.push(x);      // queue-তে পেছনে দাঁড়াচ্ছে
}

const fromStack = [];
while (stack.length) fromStack.push(stack.pop());

const fromQueue = [];
while (queue.length) fromQueue.push(queue.shift()); // demo-তে shift, সরলতার জন্য

console.log("Input:", input);            // [ 1, 2, 3 ]
console.log("Stack (LIFO):", fromStack); // [ 3, 2, 1 ]
console.log("Queue (FIFO):", fromQueue); // [ 1, 2, 3 ]
```

## Classic কৌশল: দুই stack দিয়ে queue

Interview-র চেনা প্রশ্ন: stack দুটো দিলে queue বানাতে পারবে? চালাকিটা এমন: stack ক্রম উল্টে দেয়, তাহলে **দুইবার উল্টালে** ক্রম আবার ঠিক হয়ে যায়। ঠিক যেমন দুইবার পৃষ্ঠা উল্টালে লেখা আবার সোজা হয়ে যায়।

- `inbox`: নতুনজন এখানে ঢোকে (push)।
- `outbox`: বের হওয়ার দরজা এখানে (pop)।
- `outbox` খালি হলে তখনই `inbox`-এর সবাইকে উল্টে `outbox`-এ ঢোকাও।

Dry run: `enqueue(1)`, `enqueue(2)`, `enqueue(3)`, `dequeue()`, `enqueue(4)`, `dequeue()`, `dequeue()`:

| ধাপ | অপারেশন | inbox | outbox (ডানে top) | ফেরত |
|-----|---------|-------|--------------------|-------|
| 1 | enqueue(1) | `[1]` | `[ ]` | - |
| 2 | enqueue(2) | `[1, 2]` | `[ ]` | - |
| 3 | enqueue(3) | `[1, 2, 3]` | `[ ]` | - |
| 4 | dequeue() | `[ ]` (সব সরে গেল) | `[3, 2]` | 1 |
| 5 | enqueue(4) | `[4]` | `[3, 2]` | - |
| 6 | dequeue() | `[4]` | `[3]` | 2 |
| 7 | dequeue() | `[4]` | `[ ]` | 3 |

ধাপ ৪-এ জাদুটা: `inbox`-এ `[1, 2, 3]` উল্টে `outbox`-এ `[3, 2, 1]` হয়ে গেল, তাই top-এ বসে গেল 1, যে-ই আগে এসেছিল। আর ধাপ ৫-এর 4 কে আর কেউ সরায়নি, কারণ outbox তখনও খালি হয়নি। পরে dequeue চললে সে নিজের পালা পাবে।

```js
class QueueWithStacks {
  constructor() {
    this.inbox = [];
    this.outbox = [];
  }

  enqueue(x) {
    this.inbox.push(x);               // নতুনজন সোজা inbox-এ
  }

  dequeue() {
    if (this.outbox.length === 0) {   // দরজা খালি হলে তবেই...
      while (this.inbox.length > 0) {
        this.outbox.push(this.inbox.pop()); // সব উল্টে আনো
      }
    }
    if (this.outbox.length === 0) return undefined; // দুটোই খালি
    return this.outbox.pop();
  }
}

const q = new QueueWithStacks();
q.enqueue(1); q.enqueue(2); q.enqueue(3);
console.log(q.dequeue()); // 1
q.enqueue(4);
console.log(q.dequeue()); // 2
```

## কোড ব্রেকডাউন: QueueWithStacks, লাইনে লাইনে

1. `enqueue` শুধু `inbox.push(x)` : নতুনজনকে নিয়ে কোনো ভাবনা নেই, O(1)।
2. `dequeue`-এর প্রথম `if` : **শুধু** outbox খালি হলে সরানো হয়। outbox-এ কেউ থাকতে inbox-এর নতুনজন সরালে ক্রম ভেঙে যেত, কারণ নতুনজন পুরনোদের উপর চেপে বসত।
3. ভেতরের `while` : সবাই একবার উল্টো হলো। এটাই একমাত্র ব্যয়বহুল মুহূর্ত।
4. দ্বিতীয় `if` : সরানোর পরও খালি মানে পুরো queue খালি, স্পষ্ট `undefined`।
5. `outbox.pop()` : outbox-এর top হলো আসল front, কারণ উল্টানোর সময় সবচেয়ে পুরনোজন top-এ উঠে এসেছিল।

## Complexity: দুটোর তুলনা, আর two-stack-এর হিসাব

| অপারেশন | Stack | Queue (pointer) | Two-stack queue |
|---------|-------|-----------------|-----------------|
| ঢোকা | O(1) | O(1) | O(1) |
| বের হওয়া | O(1) | O(1) | O(1), amortized |

Two-stack queue-র dequeue-এর হিসাবটা সুন্দর। খারাপ সময়ে একটা dequeue O(n), যখন সবাই সরে। কিন্তু ভাবো প্রতি উপাদানের জীবন: একবার inbox-এ ঢোকে, সর্বোচ্চ একবার outbox-এ সরে, একবার বের হয়। মোট তিনবার ছোঁয়া, n উপাদানে 3n কাজ। তাই প্রতি dequeue-এ গড় খরচ constant: এটাই **amortized O(1)**, [Array Operations](../arrays/array-operations.mdx)-এর সেই একই যুক্তি, অন্য রূপে।

## সাধারণ ভুল আর edge case

**১. দুটোর প্রান্ত গুলিয়ে ফেলা।**
চাপে পড়ে queue বানাতে গিয়ে `push`/`pop` ব্যবহার করে ফেললে পাবে stack, BFS চালাতে গিয়ে চলে যাবে DFS-এ। কাঠামো বানানোর আগে বলে নাও: ঢোকা কোথায়, বের হওয়া কোথায়, একই না উল্টো?

**২. Two-stack queue-তে প্রতি dequeue-তে সব সরানো।**
শর্ত ভুলে প্রতিবার inbox → outbox সরালে amortized হিসাব নষ্ট, প্রতি dequeue O(n)। শর্ত একটাই: **outbox খালি হলে তবেই** সরানো।

**৩. Outbox-এ জিনিস থাকতে inbox থেকে সরানো।**
নতুনজন outbox-এ পুরনোদের উপর চেপে বসে, ফলে দেরিতে আসা আগে বের হয়ে যায়, FIFO ভেঙে যায়। এটাই দ্বিতীয় ভুলের বিস্ফোরণকারী রূপ।

**৪. `shift()` দিয়ে queue, আবার।**
তিন পেজ ধরে একই গল্প: demo ছাড়া কোথাও `shift()` দিয়ে queue চালাবে না। খরচের হিসাব হাতের কাছে রাখো।

**৫. "প্রয়োগ" না ভেবে কাঠামো টানা।**
Undo লাগলে queue, টাস্ক লাইন লাগলে stack: উল্টো পক্ষে টেনে না পারলে নীতি দিয়েই লড়তে হয়। আগে প্রশ্ন করো: আমার সমস্যায় কে আগে যাওয়ার কথা, সাম্প্রতিকটা না পুরনোটা?

## অনুশীলন

- **সহজ ১:** Input `A, B, C, D`। Stack আর queue-র আউটপুট আলাদা করে লিখো, কাগজে। তারপর `push A, push B, pop, push C, pop, pop, push D, pop` সিকোয়েন্সটা stack-এ চালাও, প্রতি pop-এর ফল লিখো।
- **সহজ ২:** বাস্তব জীবন থেকে তিনটা করে উদাহরণ লিখো: যেখানে LIFO ঠিক (যেমন রান্নাঘরের থালা), যেখানে FIFO ঠিক (যেমন বাসের লাইন)। প্রতিটায় বলো কোন "প্রান্তে" কী হচ্ছে।
- **মাঝারি ১:** উল্টো প্রশ্ন: দুটো **queue** দিয়ে stack বানাও। (হিন্ট: push-এ নতুন উপাদান এক queue-তে রেখে অন্যটার সবাইকে তার পেছনে সরিয়ে দাও, যাতে সামনে সবসময় নতুনজন থাকে। কোন অপারেশনটা এখানে দামি হলো, আর দুই-stack queue-র সঙ্গে তুলনা করো।)
- **মাঝারি ২:** `QueueWithStacks`-এ `peek()` যোগ করো। সাবধান: peek-এও outbox খালি থাকলে সরানো লাগবে, কিন্তু dequeue-র মতো বের করা যাবে না। দুটো method-এ কমন কোড বের করে helper বানাতে পারো কিনা দেখো।
- **কঠিন:** একটা **deque** দিয়ে stack আর queue দুটোই বানাও (wrapper দুটো লেখো)। তারপর ভাবো: deque যেহেতু দুটোরই বাপ, তাহলে আলাদা আলাদা stack/queue ক্লাস কেন রাখব? কাঠামোর সীমাবদ্ধতা কীভাবে bug কমায়, নিজের কথায় লেখো।

## সারসংক্ষেপ

- পার্থক্য একটাই: stack-এ বের হয় ঢোকার দিক থেকে, queue-তে উল্টো দিক থেকে।
- একই input-এ stack উল্টে দেয়, queue অক্ষত রাখে।
- সাম্প্রতিক আগে লাগলে stack (undo, DFS), পুরনো আগে লাগলে queue (BFS, scheduling)।
- দুই stack মিলে queue হয়: outbox খালি হলে তবেই সরানো, তাহলে amortized O(1)।
- কাঠামো বাছার আগে নীতি বাছো; নীতি ভুল হলে কোনো implementation বাঁচাবে না।
